一个插件目录包含清单，以及本地脚本或 MCP 服务的连接配置。先声明工具、输入输出、权限与凭据，再在本地测试，最后打包分发。

安装现成插件见[安装与使用插件](/docs/guides/plugins)，完整字段见[清单参考](https://github.com/Alndaly/Mosael/blob/main/docs/PLUGIN_MANIFEST.md)。

## 先决定一件事：脚本还是 MCP

判据只有一条：**对方有没有现成的 MCP 服务**。

有就别写脚本。再写一层把 stdin 的 JSON 翻成一次 HTTP 调用、再把结果翻回 stdout，是在重新
实现一个已经存在的东西，而且每加一个端点都要改代码。接 MCP 只要一份清单，零行代码 ——
[TikHub](/plugins/tikhub) 就是这么接的:它的清单里只写了 MCP 服务的地址和凭据。

没有，或者你要做的是本地计算（读文件、算东西、调一个私有 HTTP 接口），那就写脚本。
下面讲的是这一种。

## 五分钟：一个能跑的插件

建一个目录，两个文件：

```
my-plugin/
  mosael.plugin.json
  main.py
```

清单：

```json
{
  "id": "dev.yourname.my-plugin",
  "name": "我的插件",
  "version": "0.1.0",
  "runtime": { "kind": "process", "entry": "main.py" },
  "tools": {
    "expose": "all",
    "declare": [
      { "name": "shout", "description": "把一段文字变成全大写。", "read_only": true }
    ]
  }
}
```

脚本 —— **stdin 一个 JSON 进，stdout 一个 JSON 出**：

```python
import json, sys

def shout(payload):
    return {"text": str(payload.get("text", "")).upper()}

TOOLS = {"shout": shout}

request = json.loads(sys.stdin.read())      # {"tool": "shout", "input": {...}}
try:
    output = TOOLS[request["tool"]](request.get("input") or {})
    json.dump({"ok": True, "output": output}, sys.stdout, ensure_ascii=False)
except Exception as exc:
    json.dump({"ok": False, "error": str(exc)}, sys.stdout, ensure_ascii=False)
```

把这个目录放进插件目录（应用的插件页会告诉你它在哪 —— **别照着 `~/.mosael/plugins`
去找**，Windows 上那个路径不存在），点「扫描」。它就出现在列表里了。

`id` 用反写域名式的写法。它是**这台机器上的唯一键**：装进来的目录按它命名，重名会被当成
同一个插件。

## 规矩

- 进程 **60 秒**超时，stdout 上限 **1MB**，`output` 必须是个对象。
- 崩了、超时了、吐了非 JSON —— 失败的是**那一次调用记录**，不是应用。
- 每次调用都留痕（输入、输出、耗时），在插件页看得到。

## 要参数、要凭据

在清单里声明，用户在插件页填，运行时以**环境变量**注入。声明成 `credentials` 的加密存，
声明成 `config` 的明文存：

```json
"instance": {
  "credentials": [
    { "key": "MY_API_KEY", "label": "API Key", "required": true, "help": "在 xxx 后台生成。" }
  ],
  "config": [
    { "key": "MY_REGION", "label": "区域", "type": "enum", "required": false,
      "options": [{ "value": "cn", "label": "国内" }, { "value": "us", "label": "美国" }] }
  ]
}
```

```python
key = os.environ["MY_API_KEY"]
```

配置项的 `type` 可以是 `string`(默认)、`enum`、`number`、`boolean`,以及两种**一段代码**:`json`(代码编辑器,
保存前校验,错在第几行第几列当场说)和 `code`(代码编辑器,`language` 决定高亮)。一段 JSON 别写成多行文本框 ——
那样用户只看得见第一行,少一个逗号要等插件跑起来才知道。值照旧是字符串,你自己解析。`help` 里的占位符用反引号
写成行内代码。

**环境注入与系统权限是两回事。** 子进程只接收基础环境和自己声明的凭据，Mosael 不主动传入应用的模型密钥或会话令牌。但本地插件以当前用户权限运行，并不是操作系统沙箱；它仍可能读取该用户有权访问的文件。请明确声明所需权限，并避免在日志中输出凭据。

## 要交出一个文件

上面那条路只搬 JSON，1MB 封顶 —— 一个 2GB 的 mp4 塞不进去。要把文件交给素材库，在
`output` 里放 `artifact`，有两种交法：

```python
# 一、你自己下好了。必须写在给你的目录里
out = os.environ["MOSAEL_PLUGIN_OUTPUT_DIR"]
path = os.path.join(out, "video.mp4")
download_to(path)
return {"artifact": {"path": "video.mp4"}}

# 二、你只换到了下载凭据，让宿主去下
return {"artifact": {
    "url": "https://.../dlink?sign=...",
    "headers": {"User-Agent": "..."},    # 有些接口不带特定头就 403
    "filename": "video.mp4",
}}
```

**第二种通常更好。** 让插件负责换取凭据、宿主负责搬字节 —— 进度、取消、重试、失败隔离
全是现成的，你一行都不用写。而且你这一侧只有一次 60 秒的调用：自己下一个大文件必然超时，
就算不超时，用户也看不到进度、按取消也停不下来。

宿主收下之后，`artifact` 会被**换成** `asset_id`，调用方拿到的就是一个素材 id，和别的
产素材的工具一样。[百度网盘插件](/plugins/baidu-pan)走的就是第二种。

一次交出几份,就写 `artifacts`(一串,每一项和 `artifact` 同一种写法,最多 64 份):宿主全部收进素材库,返回值里
换成 `assets`(每份的 `asset_id`、名字,以及你在那一项上附带的标量说明)和 `asset_ids`,第一份同时记成 `asset_id`。

## 要**收**一个文件

反过来:你的工具要处理一份**已有的**素材 —— 传到网盘、发给外部服务转码。在
`input_schema` 里给那个字段标上 `"format": "asset"`:

```json
{ "name": "upload",
  "input_schema": {
    "type": "object",
    "properties": {
      "asset_id": { "type": "string", "format": "asset" },
      "path": { "type": "string" }
    },
    "required": ["asset_id", "path"]
  } }
```

调用方传素材 id，**你收到的是一个本地绝对路径**：

```python
local = payload["asset_id"]        # 已经是路径，不是 id
upload_to_somewhere(local)
```

你不知道素材库存在，也不需要知道。

给的是**副本**，不是库里那一份 —— 你改坏了或删掉了都伤不到用户的素材。调用结束即删，
所以别往那个路径写你想留下的东西（想留下就用 `artifact` 交回去）。

一次要几份:`{"type": "array", "items": {"type": "string", "format": "asset"}}`,收到的是一串路径。

为什么不让你自己去取：你的环境里没有数据库、没有 API 令牌、没有媒体目录 —— 那是隔离边界
的一部分，不是疏漏。

范例见[百度网盘插件](/plugins/baidu-pan)的 `pan_upload`。

## 要记住一点东西

插件**进程**是无状态的：环境变量进、JSON 出，跑完就没了，你自己没有任何写回的手段。对纯计算没问题，对要续期的凭据是个死结 ——
拿 refresh_token 换一个新的 access_token 很容易，难的是换完之后没地方放。

在响应里放 `state`（和 `output` 平级）：

```python
json.dump({
    "ok": True,
    "output": {"files": [...]},              # 回给调用方
    "state": {"MY_ACCESS_TOKEN": "新换的"},   # 宿主替你记住
}, sys.stdout, ensure_ascii=False)
```

**下一次调用它就在环境变量里了** —— 还是 `os.environ["MY_ACCESS_TOKEN"]`，你不需要知道
这个值是上次自己存的。存在哪儿由清单决定：声明成 `credentials` 的进加密库，声明成 `config`
的进明文配置。

**和 output 平级不是随手放的**：`output` 会交给调用方和模型，而刚续出来的令牌不该出现
在那里。

只能写清单里**声明过的**键。写了没声明的键直接失败，不是忽略 —— 忽略的话你以为存下了，
下次拿到旧值，而错误表现在几十分钟后的另一个地方。

**令牌作废了就明说。** 声明了 `oauth` 的插件，续不出新令牌(refresh_token 被拒、续过一次还是过期)时，
在失败响应里加一句 `"reauthorize": true`：插件页上这个连接会标成「需要重新授权」，按钮变成「重新授权」。
报错那句话只写在调用记录里，而用户看的是连接卡片。文件不存在、限流这类与令牌无关的失败别带它。

## 要跑久一点、要留下大东西

一次调用默认最多跑 **60 秒**。确实要更久的工具(渲染一段视频),在 `declare` 里给它写
`timeout_seconds`,上限 1800;写错(不是正数)就当没写。智能体那一侧单次工具调用最多等
180 秒,所以要给智能体用的工具请压在这以内 —— 更重的准备工作拆成单独一步。

插件目录**不能当存储**:更新插件就是把整个目录换掉。要攒下很贵的东西(几百 MB 的依赖、
下载好的模型),写进 `MOSAEL_PLUGIN_DATA_DIR`:每个插件一份,跨调用、跨更新都在,卸载时
随插件一起删。

```json
{ "name": "render", "timeout_seconds": 170, "input_schema": { … } }
```

范例见 [Remotion 插件](/plugins/remotion):依赖装在持久目录,渲染工具声明了自己的预算。

跑几分钟的工具再加一条 `"stream": true`:stdout 改成一行一个 JSON,进度写成
`{"event": "progress", "progress": 0.4, "message": "第 8/20 步"}`,最后一行照旧是结果。在工作流里跑时,
执行面板上看得到这句进度;任务被取消时 Mosael 先建一个取消文件(`MOSAEL_PLUGIN_CANCEL_FILE`),你去停掉远端的活
再退出,而不是被直接杀掉。给智能体用、又不用确认的长活,做成「只提交、交回任务号」+「按任务号取回」两个工具;
要确认的(花钱、对外、在本机跑代码)是开卡、批准后在后台跑,不占智能体那一次调用的等待。

## 替 Mosael 做生成

插件还可以当一家**生成供应商**:在清单里写 `"provides": ["generation"]`,让一个工具认领它。
Mosael 会调这个工具两种操作 —— `models`(这个连接有哪些模型、各收什么参数、有哪些参考图槽位)和
`generate`(做一次:收提示词、参数和参考图文件,一行一个事件地说进度、交回远端任务号,最后交回产出文件)。
取消时 Mosael 建一个取消文件(路径在 `MOSAEL_PLUGIN_CANCEL_FILE`),你看到它就去停远端的活。

这个工具只给 Mosael 自己调,不出现在智能体和工作流里;预算不写是 1 小时,最长可以声明 6 小时。
模型清单里再给一个 `fingerprint`(清单的指纹),并支持一个便宜的 `op: "fingerprint"`,Mosael 就每分钟问一次,
变了才重新拉清单 —— 用户在你那边新加的模型不用手动刷新就出现。参数的 `title` 可以按语言写
(`{"zh": "步数", "en": "Steps"}`),Mosael 给人看时再挑。
完整的协议和字段见仓库里的 `docs/PLUGIN_MANIFEST.md`「替宿主做生成」,随应用发的 ComfyUI 插件
(`plugins/bundled/comfyui`)是完整的范例。

## 让它进工作流

工具默认就能在智能体里用。要让它同时成为一个工作流节点，在那条工具上加 `node`：

```json
{ "name": "pull", "description": "拉一个文件",
  "node": { "label": "从网盘导入", "outputs": ["asset_id", "asset_name"] } }
```

`outputs` 里的键，下游节点用 `{{节点id.asset_id}}` 就能接上。

## 写说明

在插件目录里放一个 `README.md`。它会**原样渲染在插件详情页上**（比如
[百度网盘](/plugins/baidu-pan)），所以按给人看的写，别当成内部备忘。

两个坑：相对链接按仓库目录写就好（渲染时会改指回仓库），但**别指向不存在的文件**；
`<https://…>` 这种写法在 GitHub 上没问题，写成 `[链接](https://…)` 更保险。

## 发出去

插件市场的索引是一份普通 JSON，谁都能架 —— 包括公司内网：

```json
{"plugins": [{
  "id": "dev.yourname.my-plugin", "name": "我的插件", "version": "0.1.0",
  "description": "……", "author": "你", "homepage": "https://…",
  "download": "https://…/my-plugin.zip",
  "permissions": []
}]}
```

`download` 指向一个 zip，里面是你那个目录（外面套一层也认 —— 从 GitHub 下下来的包总是
套一层的）。用户在应用里换成你这个索引地址，就能装了。

官方索引里还有一种条目：`"bundled": true`、没有 `download` —— 那是随 Mosael 一起发的插件
（ComfyUI）。它列在市场里是为了搜得到，不是为了装：应用里它标「内置」，跟着应用更新。

**`permissions` 那一栏别写错。** 用户是照着它决定装不装的，而装插件是在他机器上放一份
会被执行的代码。
