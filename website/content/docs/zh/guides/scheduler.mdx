侧栏「定时任务」管理独立于工作流画布的执行计划。左栏选择任务，右侧查看触发方式、下次运行、上次运行、绑定工作流和最近运行记录。

![定时任务列表与详情](/media/screens/scheduler.png)

## 新建任务

点击「新建任务」，填写名称，选择工作流和触发方式：手动、定时或 Webhook。「每天（指定时间）」用时间选择器挑几点几分：左列是时、右列是分，选完分钟自动收起，方向键可以在列里移动。这里的几点按你这台电脑的时区算（详情里「计划」下面会写出任务按哪个时区；更早建的任务按 UTC 算，主人可以一键改成本地时区）。手动任务不会自动排期。

选好工作流后，弹窗里列出它开始节点的参数：到点就带着这里填的值跑，空着的用工作流里的默认值；标 `*` 又没有默认值的必须填，不填建不成。别的节点要填的东西（选素材、选连接）要先在工作流画布里填好。建好之后，详情里「工作流参数」一行能看到填了什么，主人可以「改参数」。

详情里的「绑定工作流」一行，点它打开的就是这个任务绑的那张工作流，而不是工作流页上次停留的那张。

## 运行与停用

任务详情可立即运行或切换启用状态。**改、启停、删除、重置触发密钥和立即运行只有任务的主人能做**：任务到点替主人跑、用主人的钥匙和额度，共享进工作区是让同事看得见它、看得见它跑得怎样，不是交给同事管。别人的任务这几样是灰的，悬停会说明原因。停用会停止后续自动触发；是否已有运行中的工作，要看运行记录。每条记录显示时间、耗时和结果，失败时查看具体错误后修正工作流。运行记录自己会刷新：不经过这个页面启动的运行 —— Webhook 触发、到点的排程 —— 也会出现，顶上的「上次运行」跟着更新，不必手动刷新页面。

![任务详情:每天的计划、下次 / 上次运行、绑定的工作流;运行记录里是一次「立即运行」的真实结果](/media/screens/scheduler-runs.png)

每次触发都先过一遍和工作流编辑器「运行」**同一套开跑前检查**：必填参数、对话模型、克隆引擎、数字人授权、引用的节点在不在……跑不起来就不开始、一分钱不花，运行记录写明原因，同时发一条通知「定时任务没跑起来：任务名」—— 到点触发时没人看着，不能只留一条安静的失败记录。

### 运行替谁用东西

定时触发、Webhook 触发和「立即运行」都**替任务主人**（建任务的人）跑：用他的模型钥匙、记他的
额度，也只能用他能用的发布账号和浏览器档案 —— 他自己的，或已共享进工作区的。图里引用了别人没共享的
账号或档案，那一次运行会失败并说明「属于别人且没有共享出来」，请主人共享，或换成任务主人自己的。

**被执行的那一版图也要算数。** 工作流同事也能改：主人的任务跑的是**别人改过的那一版**时，它要用的私有账号、
浏览器档案或这台电脑上的文件，改它的人也得用得了 —— 否则那次运行停下，说明「这一版是别人改的」。主人确认改动
没问题之后，在运行记录那一行点「认可这一版」，下次运行就照常用。认可不改图、不增版；只有自己用得了的东西，
自己的认可才算数。单机使用时作者和主人是同一个人，不会遇到这一步。

**AI 连接和插件连接也一样。** 它们花的是主人的钥匙和额度：别人改过的那一版要用到对话、生成、配音、翻译这类节点，
或者插件节点，就要主人认可之后才会花 —— 没认可之前，到点的那次在**开跑之前**停下，一分钱不花，任务照常启用，运行记录那一行
同样给「认可这一版」。不用任何连接的图（只有模板、条件、剪辑、本地渲染）不受影响。

- **点「立即运行」就算认可。** 主人就在现场：点的那一下记成对当前这一版的认可，这一次照常跑，以后到点的也照常跑。工作流
  编辑器里点「运行」、亲手同意智能体的「运行工作流」卡同理。实际会停下来等认可的，只有到点的、Webhook 触发的、智能体自动放行的那几种。
  认可的只是这张图的当前版：它调用的子流程是别人改过、你还没认可的，照样停下来请你认可那一版。
- **待你确认。** 有人改了你的任务绑着的工作流（或它调用的子流程），你会收到一条通知「定时任务等你确认工作流的新版本」；任务列表上
  这一项挂「待你确认」，详情顶上说清是哪条工作流的哪一版，就地点「认可这一版」。同事看到的是「待主人确认」——他点认可不算数，花的
  不是他的钱。改图的人在工作流编辑器顶上也会看到：这一版要你认可之后，你的任务才会接着跑。

调度由所连接的后端执行。本地模式下后端随应用运行，完全退出应用就不会按时触发；使用远程后端时由远端保持运行。不要把关闭窗口与彻底退出混为一谈。更多触发与变量说明见[工作流](/docs/guides/workflows)。

### 绑定的工作流被删除之后

删除一个工作流时，绑着它的定时任务会当场停用，不再按排程触发。任务本身和它的运行记录都保留，删不删由你决定。这样的任务开关打不开、「立即运行」点不动（悬停会说明原因），Webhook 触发也会被拒 —— 而不是每次都留下一条 0 秒就失败的运行记录。升级前就已经绑着被删工作流、仍处于启用状态的任务，升级后会自动停用。要继续用，新建一个任务绑到现有的工作流上。

## Webhook 触发与跟进

Webhook 任务的详情里有**触发 URL**。外部系统（CI、n8n、脚本）向它发 POST 就触发一次运行，不需要登录：URL 里的 `secret` 就是凭证。同一把密钥还能查这次运行到哪了、以及取消它 —— 所以外部系统触发之后不用干等。

**密钥只显示一次。** 后端只存密钥的哈希：建好 Webhook 任务、或者重置密钥之后，完整的触发 URL 只在那一刻显示，当场复制给外部系统；离开这一页之后它是遮住的，要新地址就重置。更早建的 Webhook 任务（密钥改成只存哈希之前），密钥曾经对工作区里所有成员可见，详情里会提醒主人重置一次 —— 外部系统手上的旧地址在重置之前照样能用。

展开触发 URL 下方的「调用说明」，三条命令都带着这个任务自己的地址（刚生成密钥时连同密钥，之后密钥处是 `<secret>` 占位），可以直接复制：

```bash
# 触发一次运行，返回 run_id
curl -X POST 'http://127.0.0.1:8800/api/hooks/scheduled-tasks/<task_id>?secret=<secret>'

# 查这次运行的状态和进度
curl 'http://127.0.0.1:8800/api/hooks/scheduled-tasks/<task_id>/runs/<run_id>?secret=<secret>'

# 取消这次运行
curl -X POST 'http://127.0.0.1:8800/api/hooks/scheduled-tasks/<task_id>/runs/<run_id>/cancel?secret=<secret>'
```

示例里是本机默认的后端地址；从「调用说明」复制的命令用的是你当前连接的后端。

- 触发返回 `run_id`。上一次运行还没结束、或绑的工作流已被删除时，触发会被拒绝（HTTP 409），不会开出新的运行。
- 查询返回 `status`（`queued` / `running` / `succeeded` / `failed` / `cancelled`）和 `progress`（0–1），以及 `message`、`error`；这两段文字按请求头 `Accept-Language` 的语言给出。被取消单独记成 `cancelled`，和「运行失败」分开：前者是你自己停的，后者可能需要报警或重试。
- 取消按节点粒度生效：正在执行的那一步跑完就停，由它派生出来的子任务一并取消。
- 一把密钥只够得着**这个任务自己的**运行。拿它去查、去停别的任务的 `run_id`，一律当作不存在。

密钥泄漏了（或者忘了），主人点触发 URL 旁的「重置密钥」。旧地址立刻失效，用旧密钥查进度、取消也一样失效，外部系统需要换成新地址；已经在跑的那次不受影响。
