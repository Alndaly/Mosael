侧栏「定时任务」管理独立于工作流画布的执行计划。左栏选择任务，右侧查看触发方式、下次运行、上次运行、绑定工作流和最近运行记录。

![定时任务列表与详情](/media/screens/scheduler.png)

## 新建任务

点击「新建任务」，填写名称，选择工作流和触发方式：手动、定时或 Webhook。「每天（指定时间）」用时间选择器挑几点几分：左列是时、右列是分，选完分钟自动收起，方向键可以在列里移动。先在工作流画布完成模型、素材和必填参数配置，再启用计划。手动任务不会自动排期。

详情里的「绑定工作流」一行，点它打开的就是这个任务绑的那张工作流，而不是工作流页上次停留的那张。

## 运行与停用

任务详情可立即运行或切换启用状态。停用会停止后续自动触发；是否已有运行中的工作，要看运行记录。每条记录显示时间、耗时和结果，失败时查看具体错误后修正工作流。运行记录自己会刷新：不经过这个页面启动的运行 —— Webhook 触发、到点的排程、同事点的「立即运行」—— 也会出现，顶上的「上次运行」跟着更新，不必手动刷新页面。

### 运行替谁用东西

定时触发、Webhook 触发和同事点的「立即运行」都**替任务主人**（建任务的人）跑：用他的模型钥匙、记他的
额度，也只能用他能用的发布账号和浏览器档案 —— 他自己的，或已共享进工作区的。图里引用了别人没共享的
账号或档案，那一次运行会失败并说明「属于别人且没有共享出来」，请主人共享，或换成任务主人自己的。

**被执行的那一版图也要算数。** 工作流同事也能改：主人的任务跑的是**别人改过的那一版**时，它要用的私有账号、
浏览器档案或这台电脑上的文件，改它的人也得用得了 —— 否则那次运行停下，说明「这一版是别人改的」。主人确认改动
没问题之后，在运行记录那一行点「认可这一版」，下次运行就照常用。认可不改图、不增版；只有自己用得了的东西，
自己的认可才算数。单机使用时作者和主人是同一个人，不会遇到这一步。

调度由所连接的后端执行。本地模式下后端随应用运行，完全退出应用就不会按时触发；使用远程后端时由远端保持运行。不要把关闭窗口与彻底退出混为一谈。更多触发与变量说明见[工作流](/docs/guides/workflows)。

### 绑定的工作流被删除之后

删除一个工作流时，绑着它的定时任务会当场停用，不再按排程触发。任务本身和它的运行记录都保留，删不删由你决定。这样的任务开关打不开、「立即运行」点不动（悬停会说明原因），Webhook 触发也会被拒 —— 而不是每次都留下一条 0 秒就失败的运行记录。升级前就已经绑着被删工作流、仍处于启用状态的任务，升级后会自动停用。要继续用，新建一个任务绑到现有的工作流上。

## Webhook 触发与跟进

Webhook 任务的详情里有**触发 URL**。外部系统（CI、n8n、脚本）向它发 POST 就触发一次运行，不需要登录：URL 里的 `secret` 就是凭证。同一把密钥还能查这次运行到哪了、以及取消它 —— 所以外部系统触发之后不用干等。

展开触发 URL 下方的「调用说明」，三条命令都带着这个任务自己的地址和密钥，可以直接复制：

```bash
# 触发一次运行，返回 run_id
curl -X POST 'http://127.0.0.1:8800/api/hooks/scheduled-tasks/<task_id>?secret=<secret>'

# 查这次运行的状态和进度
curl 'http://127.0.0.1:8800/api/hooks/scheduled-tasks/<task_id>/runs/<run_id>?secret=<secret>'

# 取消这次运行
curl -X POST 'http://127.0.0.1:8800/api/hooks/scheduled-tasks/<task_id>/runs/<run_id>/cancel?secret=<secret>'
```

示例里是本机默认的后端地址；从「调用说明」复制的命令用的是你当前连接的后端。

- 触发返回 `run_id`。上一次运行还没结束、或绑的工作流已被删除时，触发会被拒绝（HTTP 409），不会开出新的运行。
- 查询返回 `status`（`queued` / `running` / `succeeded` / `failed` / `cancelled`）和 `progress`（0–1），以及 `message`、`error`；这两段文字按请求头 `Accept-Language` 的语言给出。被取消单独记成 `cancelled`，和「运行失败」分开：前者是你自己停的，后者可能需要报警或重试。
- 取消按节点粒度生效：正在执行的那一步跑完就停，由它派生出来的子任务一并取消。
- 一把密钥只够得着**这个任务自己的**运行。拿它去查、去停别的任务的 `run_id`，一律当作不存在。

密钥泄漏了，点触发 URL 旁的「重置密钥」。旧地址立刻失效，用旧密钥查进度、取消也一样失效，外部系统需要换成新地址；已经在跑的那次不受影响。
