浏览器池集中保存平台账号和通用浏览器档案，供发布、工作流自动化、链接导入与智能体复用。每个档案拥有独立的登录状态、站点存储与代理配置；使用哪个身份由档案授权决定。

## 两类档案

- **发布账号**绑定平台（TikTok / YouTube / 抖音 / B站 / 小红书 / 视频号）。发布表单从这里选择，
  绑定这件事本身也是 Mosael 判断该走哪套上传流程的依据。
- **通用档案**对应任意其他站点，工作流的 RPA 节点和智能体的浏览器工具用它。

两类的建立方式一样：**添加账号 / 新建档案**，然后在内嵌浏览器窗口里像平时用 Chrome 一样登录。Mosael
不经手也不保存你的密码 —— 它留下的是站点发回来的那段会话。

## 登录，以及保持登录

卡片上有状态徽标：**已登录**、**需登录**、**检测中**。**复检**会打开站点，找一份「你确实还是
登录态」的证据，结果和时间戳落在卡片上。会话死了，卡片当场说，而不是留到下一次发布失败。

复检刻意采信证据而不是「页面打开了」：把加载成功当成登录成功，正是账号池一边坚称你已登录、
一边每次上传都失败的成因。

每个档案还能单独设**代理**，入口在卡片右键菜单里。会话和出口地址成对绑定，多数平台期望的
也是这个。

## 谁可以用一个档案

这一节值得读仔细。

- **发布**用的是绑在目标平台上的那个账号。绑定就是为这件事服务的，不再额外问你。
- **工作流**在节点上明写档案（`profile_id`，节点的会话模式为 `pool` 时必填），所以你搭出来的
  流程自己说清了用哪个身份。
- **智能体**在打开档案之前必须先问。借用登录身份被归为**外部**动作，会弹一张点名档案的确认
  卡 —— 你没交出去的身份，它够不着。

最后这条有两个细节值得知道，因为它们决定了一次批准到底买到了什么：

- 确认卡上有**「本会话始终允许」**。它按工具、按会话生效，而且是你点的，不是智能体能给自己
  设的档位。
- 批准针对的是**打开**这个动作。页面打开之后，智能体在里面的操作 —— 输入、点击、求值 ——
  被归为只读，不会各自再弹一张卡。所以一次通过的 `browser_pool_open`，读作「你可以在这个站点
  上以这个身份行事」，而不是「你可以做恰好一个动作」。

据此判断就好：这是一个关于「让智能体穿哪个身份」的决定，所以卡片上真正该问自己的是，愿不愿意
让它以那个账号的名义行事。

卡片上的开关关掉之后，这个档案对发布和智能体都不可见，但既没被删掉也没退出登录。

## 团队部署里的共享

自己拥有的档案可以从右键菜单**共享**进工作区。其他成员随后就能用它发布、在工作流里选它 ——
而凭据始终没有经过任何人之手，因为共享出去的是会话，不是密码。

## 数据在哪

会话落在 Electron 的用户数据目录（`Partitions/`）下，不在 SQLite 库里。它天然是**按机器**的：
一段浏览器会话绑定创建它的那个浏览器，所以切到团队后端不会把登录一起带过去。

## Passkey 与平台认证器

浏览器池已接入可发现凭据的账号选择，并按实际环境能力判断 WebAuthn。macOS 正式包通过 Developer ID 签名、专用描述文件和 Apple 公证，支持在兼容设备上通过 Touch ID 注册、使用设备绑定 passkey。需要 Mac 已设置指纹；从源码运行的未签名开发版不启用此能力。设备绑定凭据按浏览器档案隔离，不会从 iCloud 或手机自动同步；跨设备扫码 passkey 暂不可用。站点允许时可选择密码或其他登录方式。
