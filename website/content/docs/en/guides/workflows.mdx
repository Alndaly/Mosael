A workflow is **done once, run endlessly**: it turns something you did once into a process that runs again on new input, runs unattended, and runs at scale. Start-node inputs and templates make it reusable; it can carry media through the timeline, subtitles, export and publishing to a finished piece; loops, concurrency and branches handle batches and say which item failed; schedules, webhooks, the agent or other workflows can start it; and every run keeps each node's inputs, results and errors. The process itself is the product. While you are still looking, revising and picking between versions, use a [creative board](/docs/guides/boards).

Workflows connect media, models and tools into reusable steps. Configure node inputs and run the readiness check before starting a flow. Use schedules or webhooks for recurring work. Run history keeps node inputs, results and errors available for inspection.

## Download and import official templates

The [website workflow catalog](/workflows) includes Topic to finished video, Transcript-based video cleanup and Translated dubbing with subtitles.

1. Download a `.mosael-workflow.json` file; no extraction is needed.
2. Choose your workspace in the app, open Workflows, then use Import workflow to select the file.
3. Open the imported graph, choose your own providers and models, supply the required media and pass the readiness check before running.

Downloads contain no account secrets or private assets, and do not automatically select local default models. Importing needs
1.6.0 or newer. Template node names and prompts are currently in Chinese.

| Template | What it does | Needs |
| --- | --- | --- |
| Topic to finished video | Thesis → script and visual bible in parallel (defining the characters and locations) → **a turnaround sheet for every character and concept art for every location** → timed storyboard (shot size, lens, camera angle, camera move) → **a 3D blockout built automatically from the storyboard**, one set and one camera per shot, with the move on the camera's path → per shot (up to 3 at once): render the blockout's first/last frames and camera-move video → either **keyframes** (paint the first frame on the blockout, add a last frame for big moves, then generate) or **references** (turnarounds, location art and the blockout move go straight to the video model) — chosen per shot, limited to what the video model accepts; camera language (lens, height, dolly/pan/orbit) is **computed** from the blockout camera and added to the prompt → assembled in shot order → narration captions → export. The blockout stays in 3D Scenes for you to adjust. With a voice selected, narration is **placed at the second its shot starts**, sped up to fit when longer (at most 1.5×) | A chat model, an image model that takes reference images (e.g. Seedream 4) and a video model that takes a first frame or references (e.g. Seedance 2.0); narration is optional: a cloned voice |
| Transcript-based video cleanup | **Remove background hiss first** (built-in engine, music untouched; transcription gets more accurate) → timed transcript → diagnose pauses, fillers and repetition → ripple-cut high-confidence ranges in a new project → export. Denoising produces a new video; the source is untouched | A chat model, a transcription engine, a source video |
| Translated dubbing with subtitles | Transcribe line by line → translate each line (chat model, switchable to Google on the node) → lay subtitles on the original timecodes → dub each line and time-compress it into its slot → remove the original voice and keep the background music → export. If Remove voice is selected while separation is unavailable, the run fails explicitly before dubbing starts instead of switching to whole-track mute | A transcription engine, a chat model, a voice (cloned or a stock engine voice; Edge's free voices need no setup), and a voice separation engine installed in advance |

The reduce-noise node uses the built-in engine by default. For speech-led material with messy noise (keyboards, dishes, chatter)
switch it to `deepfilternet` (download it first under Settings → On-device engines → Noise reduction); it removes music as well.

## Canvas & nodes

![Workflow canvas: the official speech and interview cleanup template](/media/screens/en/workflows.png)

**Build a workflow from scratch** — use "Add node" to add media and LLM generation nodes, drag between ports to connect them, and configure each node in place; the built-in AI assistant can also build the graph for you:

![Demo: open the node catalog and inspect transcription parameters](/media/gifs/en/workflows.gif)

- The entry page is a gallery of workflow cards. Open one to enter the full canvas; return at the top left and manage nodes, runs and history from the top-right toolbar.
- **Add node** from the toolbar, grouped roughly by what they are for:

  | Group | Nodes |
  | --- | --- |
  | Flow | start, output, condition, delay, for-each loop, while loop, subgraph, call workflow |
  | AI | LLM, AI generate, translate, translate lines |
  | Audio | transcribe asset, text to speech, dub subtitles, separate voice and background, reduce noise |
  | Assets & timeline | asset, create project, create video project, append to timeline, add a track, clear timeline, inspect timeline, clean up time ranges, timeline advanced operations, generate subtitles, video to GIF, export timeline, find assets, tag assets, organize assets |
  | Knowledge | search notes, read note, save as note |
  | Publishing | publish, send notification |
  | Data | HTTP request, code, text template, JSON extract, text transform |
  | Plugins | plugin tool |
  | Browser | open / navigate / click / type / upload file / extract / wait / scroll / run script / close |
- **Edges** define execution order; drag from a node's right port to a downstream node's left port. The **condition** node has "true / false" outlets.
  A node hanging off one outlet runs only when that branch holds; a data connection it takes a value from elsewhere decides only the value, never whether it runs.
- A **for-each loop** runs one item after another by default. When items don't depend on each other (such as generating each shot), raise
  "Concurrency" to 2–4 under Advanced; results keep their original order. Once any item fails, **no new item starts** (items
  already running finish, and anything they submitted for generation is still collected), and the error lists every failed item and
  how many were not started. Without an iteration output,
  each item returns everything that round produced plus the item itself (`loop.item`), so a later loop can iterate over the results.
- **Text to speech and Dub subtitles** ask for the engine first, then the voice: with "Cloned voice" the voice list is your
  voice library; pick an engine and the list becomes that engine's voices. Changing the engine clears the chosen voice. The toolbar switches **edge shape** between curved (bezier) and stepped (right-angle); your choice is remembered.
- Click a node to open its **inspector** — it sits **directly below** the node, and a floating bar sits
  **directly above** it: content sections on the left (**Parameters** / **Advanced** / **Outputs**, plus
  **This run** once it has run — each shown **only when the node has it**), node actions on the right
  (open subgraph, delete). "Advanced" holds the knobs that **work fine left blank**, so the first screen
  isn't a wall of sampling parameters.

### Top toolbar

The order matches creative boards: add and undo/redo, comments, markers and their list, search and view controls, then the AI assistant. Readiness, run history and Run form a separate group on the right.

**More** contains rename, revision history, file export and deletion. The current version shows at the end of the revision-history row; deletion sits in its own group and still requires confirmation. Arrow keys move through the menu and Escape closes it. ⌘F finds nodes: matches are outlined on the canvas and Enter / ⇧Enter steps through them. In narrow windows, arrows reveal the remaining tools while the assistant, run controls and More stay visible.

Node panels follow the same soft surface style as creative boards. The upper bar switches content sections, while the lower form scrolls independently. Name and value fields use matching control heights.

### When something is buried

With dense nodes or stacked floating panels, select one and press **⌘/Ctrl + ]** to raise it or
**⌘/Ctrl + [** to send it down. Floating panels use the same pair, but **nodes can never cover a
floating panel** — otherwise the inspector would end up buried under the very node it's editing.

Node forms use a translucent, blurred surface above the canvas. When an assistant panel is open, selecting a node centers it in the unobscured canvas area. Media nodes have compact previews that open a larger player.

## Variables: wiring upstream outputs into downstream inputs

After a node runs it writes results into the context; output variables look like `{{nodeId.output}}` (e.g. `{{llm-1.text}}`).

Each field can switch between **two input modes** (the small pill at the right of the label row):

- **Manual**: type a value / pick an option; in template fields press **`@`** to pull up upstream variables (keep typing to filter), or click a variable chip to insert at the cursor.
  Fields that point at something (3D scene, shot, timeline, track, project, account, connection…) are dropdowns: this workspace's items first, then upstream outputs.
  You can also type a `{{…}}` reference into the search box (that is how `{{loop.item.…}}` inside a loop body is written); other free text is not accepted.
  A dropdown that follows another field (shot follows scene, track follows timeline) says its choices are known at run time when that field comes from upstream.
  When the node has nothing upstream yet, `@` says so instead of doing nothing.
- **Connected**: the field becomes a port; pick one from the **upstream outputs** dropdown — equivalent to binding `{{upstream.output}}`. Switching back to manual keeps the previous value.

## Readiness check / run gating

The toolbar's **readiness check** aggregates all blockers: missing required fields, unconfigured models / providers, disconnected nodes, references to deleted nodes, and so on.

- Problem nodes get a **warning badge** on the canvas (red = blocking, amber = advisory) with a tooltip listing the issues.
- With errors present the **Run** button is disabled; each issue is clickable and jumps to the node.
- After deleting an upstream node, fields referencing it are marked **stale** and can be re-pointed or cleared.

Once a run starts, the toolbar's **Run** button becomes **Stop**, and the run's detail dialog in the task
centre carries **Cancel task** as well. Cancelling is **node-grained**: it stops after the current step
finishes, whatever it already produced (assets, timelines, 3D scenes) is kept, and derived sub-tasks are
cancelled with it.

The **Available 3D props** node lists this workspace's 3D models (usually modelled in Blender and brought
back in) as a catalogue — each one's id, name and measured width/height/depth — to feed into the prompt of
the node that designs the blockout, so a set can hold real props instead of boxes and cylinders. Leave it
empty for every model in the workspace; models that cannot be read (compressed mesh, over the triangle
budget, missing file) are left out and noted.

The **Video to GIF** node takes a video asset id plus frame rate, width, start time and duration. It
outputs a **new GIF asset id** and never overwrites the source video.

## Triggers

Use [Scheduled tasks](/docs/guides/scheduler) to attach a plan and inspect its run history.

Workflows can be bound to scheduled tasks: manual, cron, or webhook. Batch runs of the same workflow are supported.

<Aside type="caution" title="Scheduled tasks need the app running">

The scheduler runs inside the local backend, which is a child process of Mosael — **fully
quitting the app stops scheduled tasks from firing at all.**

That is why closing the window only tucks the app into the tray rather than quitting; use the tray
menu or ⌘Q to actually exit. To have it standing by from boot, turn on **Launch at login** under
Settings → Backend. Tasks missed while the app was closed run once on next start (the next
occurrence is recomputed from now, so missed runs do not pile up).

</Aside>

### Versions someone else changed

Version history shows who saved each version. When a run uses a private publishing account, browser
profile or files on this computer, both the person running it **and the author of the version being run**
(or someone who approved it) must be able to use them — a workflow started by a Call workflow node
counts with its own version too. If a teammate's version would borrow something of yours, the run stops
and names the workflow and version; after reviewing the change, click **Approve this version** in the run
history or version history. Approving doesn't change the graph or add a version.

## Let AI build it

The toolbar's **AI assistant** uses the shared persistent session pool: describe the flow you want
in natural language and it builds / edits nodes for you; changes go through confirmation cards.
Its top-left title is the active conversation — click it to search or switch sessions — and the
panel can dock beside the canvas or float above it.

## Comments and markers

The comment and flag buttons enter separate, mutually exclusive modes. Escape exits. Their eye buttons independently show or hide all comments or markers without deleting them. Markers are not listed in Add node.

In marker mode, click empty space to place a position bookmark, then set its name and jump shortcut. Only one marker editor opens per canvas. Clear a binding beside the shortcut field or remove the marker using the footer action. In comment mode, click empty space to write a comment and mention workspace members with `@`. Submitted mentions keep their interactive labels. Use the pencil to edit your own comment. Adjacent comment pins remain directly clickable.

Switching modes or undoing preserves graph connections. Toolbar groups use separators. Comments and markers are collaboration overlays and do not execute as graph nodes.
