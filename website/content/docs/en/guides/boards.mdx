A creative board is where you **lay ideas out and work on them in plain sight**: put media, text and generations on one desk, then look, compare and revise until an idea takes shape. The content is the interface, and placement and groups are how you organize it; try one prompt on several models side by side and carry on with the one you like; every item remembers how it was made, so you can regenerate or run it again. When you want to lock a process in and have it run again by itself on new input, use a [workflow](/docs/guides/workflows).

Place sticky notes, documents, images, videos, audio and 3D scenes on a creative board, then organize them into groups. **A connection passes upstream content to a downstream input**: for example, a reference image to a video node or a document to a writing node — a line means "refer to this", not "then do this".

Drop a connection onto the visible **+** area on either side of a node. Select a node to open its actions above and its generation or editing form below.

## What a connection gives you

Connections are not decoration. The downstream node reshapes its form around what it receives:

| Upstream → downstream | What arrives |
| --- | --- |
| Note → image / video | The text fills in the prompt |
| Note → audio | The text is what gets read aloud |
| Note → note | The upstream text is sent as **material**, kept separate from your instruction |
| Image → image | Attached as a reference image |
| Image → video | One image becomes the first frame; several become references |
| Image / video → note | The model **looks at it** — images directly, video as sampled frames |
| Audio → note | Its transcript, if one exists, becomes material |

What flows in **never overwrites what you typed**: it only fills a box that is still empty, or one
that still holds the previous auto-filled text.

## Top toolbar

From left to right: add and undo/redo, comments and the discussion center, markers and their list, view and navigation, then the AI assistant. Thin dividers separate these groups.

To delete the board, open **More** and confirm the deletion. The toolbar switches **edge shape** between curved (bezier) and stepped (right-angle); boards remember their own choice. ⌘F finds nodes by name, text, prompt or type (named nodes are listed by their names): matches are outlined on the canvas, Enter / ⇧Enter jumps to the next / previous one, Escape closes.

In the board list, a card's ⋯ button and its right-click menu offer the same actions: open, rename, duplicate and delete (with confirmation). **Select** in the header enters multi-select with select-all and bulk delete; if some deletions fail, the message says how many and those cards stay selected. A duplicate leaves out cells that are still generating: they become empty slots with their prompts kept. In narrow windows, arrows scroll through the tools; the AI assistant and More stay visible.

## What each node can do

Select a node: the action bar sits above it, its form below.

- **Image / video** — while still empty, a prompt panel hangs underneath. Model, aspect ratio,
  resolution and duration are **driven by the model descriptor**, so switching models reshapes
  that row by itself. Once there is a result, the action bar offers Preview, Swap and Trim.
- **Note** — empty means "write it"; with text it means "change it the way I say", which is what
  this panel is used for most (you wrote something, now you want it half as long). Double-click
  still edits by hand.
- **Audio** — pick a voice and the text to read (voice-over). Once a generation model supports
  audio, the action bar above an empty audio item switches between Voice-over and Generate
  (music, sound effects).
- **Group frame** — fence things off and name them. Select a few nodes and press
  <kbd>⌘</kbd><kbd>G</kbd> to group them directly.

Prompt, model, duration, source references and run status live **inside the node's own data**.
Closing an inspector, selecting another node or reopening the board therefore cannot reconstruct a
different placeholder or lose the form. Failed jobs settle into a visible failed state instead of
spinning forever. Models that declare a continuous duration range get a numeric input for that range.

Every node also exposes its run state directly: queued uses a light primary outline, running adds an
animated glow, completed turns green, failed turns red, and cancelled uses a subdued dashed outline.
The signal is not confined to a spinner in an empty media slot, so a failed rerun remains visible even
when the node still has an older result. A new result or manual asset replacement rehydrates the form
from that node's saved data; failure and cancellation keep the inputs intact for retry.

### Naming nodes

The line above each node shows its name, or its type ("Image", "Video", "Group"…) while it has
none. With several images on a board, names are how you tell them apart. **Double-click that line
to rename in place**, or select the node and use the pencil (Rename) in its action bar:
<kbd>Enter</kbd> or clicking elsewhere confirms, <kbd>Esc</kbd> cancels, and the Enter that picks
a candidate in an input method never confirms early. Clear the name to go back to the type. Names
are up to 120 characters, and a rename is a single undo step.

Group frames use the same name as every other node, and it is what board search, the board list
thumbnails, duplicated copies and the AI assistant all see.

### Referencing assets with `@`

Press `@` in a prompt to reference something from the asset library; the menu follows the caret.
What you pick becomes an **inline chip in the sentence** — "put the person from @creator.png on
the street" reads as one sentence. On submit it splits in two: the name stays in the prompt (with
several images the model needs to know which one you meant) and the asset itself is sent as input.

### Trimming

Video gets a **filmstrip**, audio gets its **waveform**; drag either end to set the range. The
problem with typing numbers is not the typing — it is that you do not know what second 3.2 looks
like. When you do want frame accuracy, the number fields on the right are still faster.

**The original is untouched.** A trim produces a new asset in a new node — every step on a board
should be one you can walk back from.

## Tool items: turn what you have into something new

Besides generate, write, voice-over and trim, a board can **run a tool** that turns the item in front of
you into something new: video to GIF, speech in audio or video to text, translate, separate voice and
background, reduce noise, render references from a shot of a 3D scene, and the content tools plugins
provide — such as every workflow saved in ComfyUI, fetching a file back from object storage, or
importing one from a cloud drive.

A board **only holds these content-to-content tools**. Flow and data steps — calling a workflow, HTTP
requests, text templates, JSON extraction, string handling, note search — and plugin tools that only
list, report status or upload are not on boards; use them in a [workflow](/docs/guides/workflows).
Tool items of those kinds already on a board before the upgrade become a note saying the step now
belongs in a workflow, with the old settings attached; their connections and the results they made stay.

**Placing one**: in the toolbar's Add menu or the drag-out menu, tools are **grouped by the content they
work on** — New assets, Work on images, video, audio, text or 3D scenes — each with one line on what it
does (the menu has a search box that also matches a plugin tool's call name). A tool item grown out of
another item is already connected; that item is its input.

**The form only asks what a creator decides**: model, language, style, duration and the like, with rarer
knobs under "Advanced". Parameter mappings, raw JSON and code — fields meant for whoever builds a
workflow — are not on boards; a tool that requires one (such as an explainer video that needs a
structured list of steps) is used in a workflow or in chat. **Fields take upstream input** without any
`{{upstream.output}}` either; the input is whatever is connected:

| Upstream item | Fits which fields | What the run reads |
| --- | --- | --- |
| Note | Free-text fields (text to translate, a prompt) | The note's text; several notes join in connection order with a blank line |
| Document | Same | The pinned revision's text |
| Image / video / audio | Asset fields | That asset |
| 3D scene | Scene fields | That scene |

A field that can take upstream input has a Manual / Connected switch; once connected, the row below
lists the upstream items that fit, and you pick which ones to read from. **A required field is bound
to the first fitting upstream item by default**; you can change it and the choice is saved on the
item. Values are read **when you press Run**: edit the upstream note and the next run follows.
Delete the line and the binding goes with it.

**Results land to the right**: every run **adds a new column of items** to the right, each connected
by a line — images, videos and audio become those kinds of items, other files become a note naming
the file, text becomes a note, structured data becomes a code-formatted note. Earlier results stay;
nothing is overwritten. One run adds at most 12 items; anything beyond that is merged into the last note.

**While it runs** the item shimmers and shows a percentage when the tool reports progress; **Stop**
really stops the plugin process (and cancels the job in the task center). If it fails, the reason is
written on the item and the form stays as it was — adjust it and press "Run again".

**Whose connection**: a plugin tool runs with **the connection of whoever presses Run**. The panel says
"Runs with your connection “X”". On a shared board, pressing Run on a teammate's tool item uses your
own connection — if you have none, the panel names the plugin and links to the Plugins page to create
one. With several connections, pick one under Advanced.

## The AI assistant

The robot icon in the top-right opens it. It is **not a second AI**: sessions, messages and
confirmation cards are the same ones the global assistant uses; each message just carries one
extra line saying which board you are looking at.

The top-left title is the current conversation. Click it to search or switch sessions; the title
ellipsizes when space is tight instead of introducing another framed picker.

It can read the canvas (`get_board`) and change it (`edit_board`): add notes, rewrite text,
name nodes, connect, delete, move things. It sees the names you give nodes, so you can refer to
a node by its name. **Every change goes through a confirmation card** — nothing lands
until you approve it. It submits granular operations rather than a whole canvas, because a model
handed the whole thing gets it wrong on any non-trivial board: items go missing, or the positions
you arranged by hand get flattened.

### Letting the agent use tool items

The assistant can also place tool items, wire up their inputs and run them for you. It first looks at
the tools available (`list_board_producers` — the same tools, groups and fields you see in the Add
menu, with plugin tools only from **your own** connections). When it places a tool item it names the tool, fills in its
fields, says which fields take which upstream items, and connects them in the same batch
(`edit_board`). Placing and editing still go through a confirmation card, and a broken edit (no such
tool, no such field, a binding to an item that isn't connected, a note bound to an asset field) is
refused when the card is opened, not after you approve it.

**Running** (`run_board_item`) takes the same path as pressing Run yourself, with **the approver's own
connection**:

- **Tools that neither cost money nor reach outside run directly** (translate, transcribe, video to GIF,
  plugin tools that declare themselves read-only…) — no card;
- **Tools that cost money or act outside the app wait for you** — such as running a ComfyUI workflow,
  and plugin tools that declare outward effects. The card says which tool runs on which board, with which of
  your connections, and whether it costs money or reaches outside the app. Reject it and nothing runs.

Auto-approval still applies: in auto mode paid runs have a streak limit and outward-facing ones come
back to you; "Approve everything" approves everything. The read-only runs you weren't asked about are
still listed under "Auto-approved in this chat" in the session settings.

## Undo

<kbd>⌘</kbd><kbd>Z</kbd> undoes, <kbd>⌘</kbd><kbd>⇧</kbd><kbd>Z</kbd> redoes, and the toolbar has
buttons too. A continuous drag collapses into one step — dragging a node emits dozens of position
updates, and one-per-update would mean dozens of presses to get back.

## Comments and markers

The comment and flag buttons enter separate, mutually exclusive modes. Escape exits. Their eye buttons independently show or hide all comments or markers without deleting them. Markers are not listed in Add node.

In marker mode, click empty space to place a position bookmark, then set its name and jump shortcut. Only one marker editor opens per canvas. Clear a binding beside the shortcut field or remove the marker using the footer action. In comment mode, click empty space to write a comment and mention workspace members with `@`. Submitted mentions keep their interactive labels. Use the pencil to edit your own comment. Adjacent comment pins remain directly clickable.

Switching modes or undoing preserves graph connections. Toolbar groups use separators. Comments and markers are collaboration overlays and do not execute as graph nodes.

## Document and 3D references

Use Add → Document to select a fixed note revision. Dragging its text or embedded image moves the node, and its header keeps the same height across modes. Connect it downstream as reference text; update the revision or open the source from the footer.

Add → 3D scene selects a workspace scene. Generate images from its reference frame, or feed first/last frames or a camera preview into a video model. See [3D scenes & animation](/docs/guides/scenes).
