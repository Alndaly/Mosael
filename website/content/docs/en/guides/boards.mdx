A creative board is where you **lay ideas out and work on them in plain sight**: put media, text and generations on one desk, then look, compare and revise until an idea takes shape. The content is the interface, and placement and groups are how you organize it; try one prompt on several models side by side and carry on with the one you like; every item remembers how it was made, so you can regenerate or run it again. When you want to lock a process in and have it run again by itself on new input, use a [workflow](/docs/guides/workflows).

Place sticky notes, documents, images, videos, audio and 3D scenes on a creative board, then organize them into groups. **A connection passes upstream content to a downstream input**: for example, a reference image to a video node or a document to a writing node — a line means "refer to this", not "then do this".

Drop a connection onto the visible **+** area on either side of a node. Select a node to open its actions above and its generation or editing form below.

**Getting things onto the board**: drag images, videos or audio in from Finder or Explorer — each file goes into the asset library first, then lands as an item of its own kind where you let go. ⌘V / Ctrl+V works the same way: a screenshot or copied media file becomes one item each, and plain text becomes a sticky note in the middle of the view. While the cursor is in a note, a prompt box or any other text field, pasting goes there as usual and nothing is added to the canvas.

## What a connection gives you

Connections are not decoration. The downstream node reshapes its form around what it receives:

| Upstream → downstream | What arrives |
| --- | --- |
| Note → image / video | The text fills in the prompt |
| Note → audio | The text is what gets read aloud |
| Note → note | The upstream text is sent as **material**, kept separate from your instruction |
| Image → image | Attached as a reference image |
| Image → video | One image becomes the first frame; several become references |
| Image / video → note | The model **looks at it** — images directly, video as sampled frames |
| Audio → note | Its transcript, if one exists, becomes material |

What flows in **never overwrites what you typed**: it only fills a box that is still empty, or one
that still holds the previous auto-filled text.

## Top toolbar

From left to right: add and undo/redo, comments and the discussion center, markers and their list, view and navigation, then the AI assistant. Thin dividers separate these groups.

To delete the board, open **More** and confirm the deletion. The toolbar switches **edge shape** between curved (bezier) and stepped (right-angle); boards remember their own choice. ⌘F finds nodes by name, text, prompt or type (named nodes are listed by their names): matches are outlined on the canvas, Enter / ⇧Enter jumps to the next / previous one, Escape closes.

In the board list, a card's ⋯ button and its right-click menu offer the same actions: open, rename, duplicate and delete (with confirmation). **Select** in the header enters multi-select with select-all and bulk delete; if some deletions fail, the message says how many and those cards stay selected. A duplicate leaves out cells that are still generating: they become empty slots with their prompts kept. In narrow windows, arrows scroll through the tools; the AI assistant and More stay visible.

## What each node can do

Select a node: the action bar sits above it, its form below. Every form looks the same: a row of
upstream chips and attached media on top, the prompt or the text to work on as the body, and a bottom bar
with a few setting chips (model, voice, target language…), a **Settings** button holding the rest, and a
round send button on the right. However long the body gets, the bottom bar stays pinned.

- **Image / video** — while still empty, a prompt panel hangs underneath. Model, aspect ratio,
  resolution and duration are **driven by the model descriptor**, so switching models reshapes
  that row by itself. Once there is a result, the action bar is a row of icons: Preview, Trim, Swap, then
  the item's **abilities** (see "What an item can do with its content" below).
- **Note** — selecting a note **does not open the writing panel**; you usually select a note to move
  it or recolor it. Press **Ask AI to write** in the action bar when you want help: empty means "write
  it", with text it means "change it the way I say" (you wrote something, now you want it half as long);
  press it again to close. A note grown with "Write copy" opens it right away. Notes holding an ability's
  structured data (code-formatted) have no such button. Double-click still edits by hand.
- **Audio** — pick a voice and the text to read (voice-over). The action bar above an empty audio item
  switches between ways to fill it: Voice-over, Generate (music, sound effects) once a generation model
  supports audio, and generators from plugins (extra ones go under "…").
- **Group frame** — fence things off and name them. Select a few nodes and press
  <kbd>⌘</kbd><kbd>G</kbd> to group them directly.

Prompt, model, duration, source references and run status live **inside the node's own data**.
Closing an inspector, selecting another node or reopening the board therefore cannot reconstruct a
different placeholder or lose the form. Failed jobs settle into a visible failed state instead of
spinning forever. Models that declare a continuous duration range get a numeric input for that range.

Every node also exposes its run state directly: queued uses a light primary outline, running adds an
animated glow, failed turns red, and cancelled uses a subdued dashed outline. **Completion flashes once and
settles** — no lasting green ring; the content itself is the proof. **Every running item has Stop**
(generation, voice-over, writing, trimming, abilities); it stops that one job, though a provider may still bill
for a remote generation it already accepted. A failed item says "Generation failed" or "Run failed" plus
the reason, not "could not start".
The signal is not confined to a spinner in an empty media slot, so a failed rerun remains visible even
when the node still has an older result. A new result or manual asset replacement rehydrates the form
from that node's saved data; failure and cancellation keep the inputs intact for retry.

### Naming nodes

The line above each node shows its name, or its type ("Image", "Video", "Group"…) while it has
none. With several images on a board, names are how you tell them apart. **Double-click that line
to rename in place**, or select the node and use the pencil (Rename) in its action bar:
<kbd>Enter</kbd> or clicking elsewhere confirms, <kbd>Esc</kbd> cancels, and the Enter that picks
a candidate in an input method never confirms early. Clear the name to go back to the type. Names
are up to 120 characters, and a rename is a single undo step.

Group frames use the same name as every other node, and it is what board search, the board list
thumbnails, duplicated copies and the AI assistant all see.

### Referencing assets with `@`

Press `@` in a prompt to reference something from the asset library; the menu follows the caret.
What you pick becomes an **inline chip in the sentence** — "put the person from @creator.png on
the street" reads as one sentence. On submit it splits in two: the name stays in the prompt (with
several images the model needs to know which one you meant) and the asset itself is sent as input.

### Trimming

Video gets a **filmstrip**, audio gets its **waveform**; drag either end to set the range. The
problem with typing numbers is not the typing — it is that you do not know what second 3.2 looks
like. When you do want frame accuracy, the number fields on the right are still faster.

**The original is untouched.** A trim produces a new asset in a new node — every step on a board
should be one you can walk back from.

## What an item can do with its content

There are **no separate tool items** on a board. Turning an item into something new is **something the item itself
does**: select an audio clip and the action bar above it gains a row of icons — transcribe, separate voice and
background, reduce noise; a video also offers "Video to GIF"; a note or a document offers "Translate". Content tools
from plugins work the same way: a ComfyUI workflow that takes an image (upscale, background removal, face restore) sits
on image items, one that takes a video on video items. Built-in abilities come first and show directly; extra ones go
under "…". Hover any icon to see what it does to this item.

**Click an icon and its panel opens under the item; click another and the panel below switches to it; click the same
one again to close it** (<kbd>Esc</kbd> or selecting another item closes it too). Trim and Ask AI to write are icons in
the same row and replace the panel below in the same way. The top of the panel says what happens to which item —
"Reduce noise · Narration: clean the background noise out of audio or video" — **this item's content is the input**:
nothing to pick, nothing to connect. Below that are the ability's own settings:

- **The bottom bar holds the pick-one settings** ("Target language: English", "Engine"); a chip shows the chosen value,
  or the field name while nothing is chosen. Required ones come first, three at most; the rest are under **Settings**,
  whose button shows a dot while a required one there is still empty.
- **While something required is missing the round send button is grey**, and hovering it says what is missing —
  Translate needs a target language first.
- When a tool needs another input (say, audio to put under a video), **connect that item into this one**: the row of
  upstream chips at the top lets you pick which one feeds which field. Notes give their text, documents the pinned
  revision's text, images / video / audio the asset, 3D scenes the scene. Values are read **when you run**, so edit the
  upstream note and the next run follows; delete the connection and the binding goes with it.
- **Each ability's settings are stored on the item**, so reopening it shows what you used last time; the item's own
  content (image, text, prompt) is untouched.

**Outputs land to the right**: every run adds **a new column of items to the right of this one**, connected to it —
images, video and audio in items of their kind, other files as a note naming the file, text as a note, structured
data as a code-formatted note; this item itself does not change. Only the tool's **results** land: outputs meant for
wiring workflows (asset id lists, summaries, task ids) don't. Earlier outputs stay; nothing is overwritten. At most 12
items per run; the rest merge into the last note.

**While it runs**, the item keeps showing its content with a strip along the bottom — "Running · Transcribe asset",
progress and **Stop** (which really stops the plugin process and cancels its job in the task center). A failed run
doesn't paint the item red: select it and the strip says why, and so does the panel; adjust and run again.

**Plugin generators that take no board content** (a ComfyUI workflow that turns a prompt into an image, Manim /
Remotion animations) are not an ability of any item — they are **another way to fill an empty item**: add an empty
image (video, audio) item, switch it to that generator in the action bar above it, and the panel is the generator's
form; the image it makes fills this item and any other outputs (a caption…) land to the right.

A board holds **only content-to-content tools**. Flow control and data steps — calling a workflow, HTTP requests,
text templates, JSON extraction, string handling, note search — plugin tools that only list, report or upload, and
plugin tools that **fetch things by an id from another system** (importing ComfyUI outputs by task id, the drive by
fs_id, object storage by object key) are not on boards; use them in [workflows](/docs/guides/workflows) and chat, and
drag a file in from the asset library to put it on a board. Forms hold **only what a creator fills in**: parameter
mappings, raw JSON and code are not on boards; a tool that requires such a field (like an explainer video that needs
structured steps) is for workflows and chat.

**One thing, one entry.** When a plugin tool is the same thing as a generation model — say a ComfyUI workflow with
a single saved image / video / audio output node (preview nodes don't count), which is already a model in image and
video items — and you can use that model, it isn't listed separately: add an image (video, audio) item and pick that
model; the result lands in place, several at a time, with a longer wait.

**Fields that point at something are dropdowns, not ids to copy**: projects and connections are picked from this
workspace, with search once the list is long. A dropdown that depends on another field (a model that depends on the
connection) clears when its parent changes.

**Whose connection**: a plugin tool runs with **the connection of whoever presses run**. On a shared board, settings a
teammate saved still run with your own connection — if you have none, the panel names the plugin and links to the
Plugins page to create one. With several connections, pick one under Settings.

**Tool items from before the upgrade** move onto the item they were connected to: their settings are stored there, the
tool item goes away, and its earlier outputs stay, now connected from that item. A tool item that made assets from
parameters becomes an empty item of that kind with that generator selected; one with nothing to attach to (or whose
tool is no longer on boards) becomes a note spelling out its old settings, with its connections intact.

## The AI assistant

The robot icon in the top-right opens it. It is **not a second AI**: sessions, messages and
confirmation cards are the same ones the global assistant uses; each message just carries one
extra line saying which board you are looking at.

The top-left title is the current conversation. Click it to search or switch sessions; the title
ellipsizes when space is tight instead of introducing another framed picker.

It can read the canvas (`get_board`) and change it (`edit_board`): add notes, rewrite text,
name nodes, connect, delete, move things. It sees the names you give nodes, so you can refer to
a node by its name. **Every change goes through a confirmation card** — nothing lands
until you approve it. It submits granular operations rather than a whole canvas, because a model
handed the whole thing gets it wrong on any non-trivial board: items go missing, or the positions
you arranged by hand get flattened.

### Letting the agent use an item's abilities

The assistant can use an item's abilities for you. It first looks at what is available (`list_board_producers` — the
same list the action bar reads: which kinds of item each ability sits on, which field the item's own content fills,
and the other settings; plugin tools only from **your own** connections), then stores the ability's settings on that
item and says which other inputs come from which connected items, connecting them in the same batch (`edit_board`'s
`set_form`). Edits still go through a confirmation card, and a broken edit (the item has no such ability, no such
field, a binding to an item that isn't connected, a note bound to an asset field) is refused when the card is opened,
not after you approve it. It can no longer place separate tool items.

**Running** (`run_board_item`, naming the ability) takes the same path as pressing the send button yourself, with
**the approver's own connection**:

- **Tools that neither cost money nor reach outside run directly** (translate, transcribe, video to GIF,
  plugin tools that declare themselves read-only…) — no card;
- **Tools that cost money or act outside the app wait for you** — such as running a ComfyUI workflow,
  and plugin tools that declare outward effects. The card says which tool runs on which board, with which of
  your connections, and whether it costs money or reaches outside the app. Reject it and nothing runs.

Auto-approval still applies: in auto mode paid runs have a streak limit and outward-facing ones come
back to you; "Approve everything" approves everything. The read-only runs you weren't asked about are
still listed under "Auto-approved in this chat" in the session settings.

## Undo

<kbd>⌘</kbd><kbd>Z</kbd> undoes, <kbd>⌘</kbd><kbd>⇧</kbd><kbd>Z</kbd> redoes, and the toolbar has
buttons too. A continuous drag collapses into one step — dragging a node emits dozens of position
updates, and one-per-update would mean dozens of presses to get back.

## Comments and markers

The comment and flag buttons enter separate, mutually exclusive modes. Escape exits. Their eye buttons independently show or hide all comments or markers without deleting them. Markers are not listed in Add node.

In marker mode, click empty space to place a position bookmark, then set its name and jump shortcut. Only one marker editor opens per canvas. Clear a binding beside the shortcut field or remove the marker using the footer action. In comment mode, click empty space to write a comment and mention workspace members with `@`. Submitted mentions keep their interactive labels. Use the pencil to edit your own comment. Adjacent comment pins remain directly clickable.

Switching modes or undoing preserves graph connections. Toolbar groups use separators. Comments and markers are collaboration overlays and do not execute as graph nodes.

## Document and 3D references

Use Add → Document to select a fixed note revision. Dragging its text or embedded image moves the node, and its header keeps the same height across modes. Connect it downstream as reference text; update the revision or open the source from the footer.

Add → 3D scene selects a workspace scene. **A scene item renders its own blockout references**: select it,
pick a **Shot** in the panel's bottom bar (a scene with a single shot needs no pick — the chip shows it; a scene
with no shots greys the chip out, so open the scene and add one) and **What to render** (first and last frame,
camera-move video, or both), then press the round button. While it renders the item shows the same shimmer,
progress and Stop as any other item; the first frame, last frame and camera-move video **land as new items to
the right of the scene item**, connected to it, and the scene item and its thumbnail stay as they were. Render
again and you get a new column; the earlier one stays. **Edit scene** in the panel opens the scene page to
change the framing or add shots. Connect the rendered frames and video to image or video items as references.

This used to take a separate "Render blockout references" tool item next to the scene item, where you picked
the scene all over again — two halves of one thing. That tool item is off the board now (the workflow node is
unchanged). On upgrade, each such tool item moves its shot and render choice onto the scene item it was
connected to and goes away; what it already rendered stays and is now connected from the scene item. One that
has no scene item on the board becomes a note carrying its old settings. See
[3D scenes & animation](/docs/guides/scenes).
