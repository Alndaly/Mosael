Use **Notes** for scripts, research, transcripts and conversation excerpts. Notes belong to the workspace and support rich text, Markdown, source references and revision history. Saved content can be referenced by boards, workflows and agents. PDFs, Word files and slide decks don't live here: they enter the media library as [document assets](/docs/guides/documents), and **Save as note** turns one into a note when you need it.

## Getting things in

These places can turn content into a note, and everything written this way carries its **source**:

| From | What lands in the note |
| --- | --- |
| An answer in AI Studio | That answer, sourced back to the message |
| A sticky note on a board | The note text, sourced back to that board |
| Editor → Transcript | The whole transcript; with a selection, only the selected lines |
| Editor → Subtitles | The whole subtitle track; translations are written alongside the original |
| **Save as note** on a document asset | The parsed full text; the document's images enter the library at this point, sourced back to the original document |

The dialog can **create a note** or **append to an existing one**. Transcripts and subtitles add a
choice of **body shape**:

- **Prose** — consecutive sentences join into paragraphs, with a break after a pause longer than
  1.5 seconds. Pick this when the text is a draft you intend to rewrite.
- **Quotes with timecodes** — one quote block per line, followed by the asset name and time. Pick
  this when you want to check each line back against the video.

Both shapes **share the same sources**: provenance is a fact, and it does not change with layout.

Appending to a note **someone else is editing** does not interrupt them — the appended text merges
into their current draft and they keep typing, with no conflict prompt.

## Writing

The body is a what-you-see editor with one toolbar row: paragraph style (body text, headings one
through six), bold, italic, strikethrough, three list kinds (bulleted, numbered, task), an insert
menu (quote, code block, divider, image), web links, tables, and undo/redo.

A few things worth calling out:

- **Images** can be pasted, dragged in, or inserted from the toolbar; select one to edit its link
  and alt text in place.
- **Code blocks** take a language, get syntax highlighting in both light and dark themes, and have
  a copy button. They stay valid Markdown and participate in undo.
- **Type `@`** to reference another note. The reference **pins the revision it was made against**,
  but opens the latest content by default; use **View referenced version** to see the pinned one.
- The **Markdown** button at the top right shows the source; press it again to go back to editing.

The status at the top right, next to the Markdown button, says where you stand: `Saved` / `Saving…` / `Draft pending`. **Closing
the page loses nothing** — an unsaved draft stays on this device and comes back the next time you
open the note.

### If you hit a conflict

When two people change the same part of the same note, you see *This note has a newer version*.
**Neither side is overwritten**:

1. Press **Retry save** to try again, or
2. Press **Load the latest version** — it **exports your draft as a .md file first**, then pulls the
   server's copy.

So the worst case leaves you with an extra .md file, not with lost words.

## Keeping it tidy

The list on the left supports search (titles, body, tags) plus **Favorites**, **Trash** and
**Topic** filters. Drag its right edge to resize it; the width is remembered. Leaving the page and
coming back reopens the note you last had open in that workspace, and the **All notes** /
**Favorites** / **Trash** tab stays where you left it.

**Select notes** turns on multi-select: hold <kbd>Shift</kbd> for a range, select the whole current
list, then favorite, export Markdown, move to trash, restore or delete permanently in bulk.
Right-clicking one note offers open, rename and duplicate.

**Import Markdown** (the import icon, an arrow pointing into a tray) sits in the list header and accepts `.md` / `.markdown` / `.txt`, up to 500 KB
per file. Pick several at once, or drag files onto the Notes page: each file becomes a note and the last
one opens. Dragging only images into the body still inserts them as images.

A note in the trash opens with a notice at the top offering **Restore from trash** and **Delete permanently**.

**Delete permanently** removes the note **and all of its revisions**, with no way back. Existing
references stay where they are, but their source can no longer be opened.

## Revision history

Every change to the text is kept in the revision history. **More → Version history** opens a large
dialog: versions grouped by day (Today, Yesterday, a date) on the left, the selected one on the right at
reading width.

- **Consecutive manual edits make one revision**: one person typing in a row (pauses under 5 minutes, at
  most 30 minutes per revision) is kept as a single revision that autosave keeps updating. A pause over
  5 minutes, another person, or an assistant change, restore or Save to note in between starts a new one.
  Each revision says how much changed, such as "+120 −30 chars" or "Title changed"; hover the time to see
  when it was written.
- Favorites, moving to trash, tags and topics **don't create revisions**, and restoring a revision brings
  back the title, text and sources only, leaving those properties as they are now.
- Each entry says **how it came about**: Edited, Changed by the assistant, Saved to note, Restored from
  version N… Someone else's changes carry their name.
- Switch between **Preview / Compare with current / Compare with previous** on the right: removed text
  is struck through, added text is highlighted, long unchanged stretches fold away.
- The top entry is marked **Current version**. **Restore this version** asks first, then **creates a new
  revision**; every existing revision stays. **Copy this version's content** copies its Markdown text.
  Arrow keys move between versions in the list.

## Sources and properties

**More → Sources and properties** lists where this note came from, plus its **topics** and **tags**
(both comma-separated). Excerpts saved from assets, chats or boards appear here automatically, and
clicking one goes back to the original — asset excerpts carry their timecode with them.

## Getting back out: canvas and workflows

### Infinite canvas

A **document item** on a board references a note: select it and press **Choose a note** on the action bar (once a note is
referenced it reads **Choose another note**); it pins **that revision's** content and shows `v<revision>` at the bottom. Connect
it to a note, image, video or audio item and the content flows downstream as input. The bottom offers **Update to latest revision**
and **Open note**. **Ask AI to write** on the action bar writes a new note from scratch (saved and referenced) or rewrites the
referenced note as its next revision (the old one stays).

When the original is trashed or deleted, the node says **Note unavailable** instead of quietly
passing an empty string downstream.

### Workflows

The workflow **Knowledge** category has these nodes:

| Node | What it does |
| --- | --- |
| **Search notes** | Searches titles, content, tags and topics; returns cited excerpts |
| **Read note** | Outputs the full Markdown and a source link; leave the revision empty for the latest, or pin one |
| **Save as note** | Saves text or upstream output as a new note, **without** overwriting existing ones |
| **Document to Markdown** | Turns a PDF / Word / slides / spreadsheet asset into Markdown text, optionally only some pages (see [Documents](/docs/guides/documents)) |

**Search notes** returns excerpts rather than full text — connect it to **Read note** when you need
the whole thing. That keeps a search across dozens of notes from blowing up the context.

## Agent citations

Notes and web sources in an agent's answer are **clickable**, and open the exact revision that was
cited. What it searched and which version it used stay in the answer for you to check — you are not
asked to trust that it remembered correctly.
