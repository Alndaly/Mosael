# 链条审计:同一件事,在几条路上都成立吗

> 日期:2026-09-21 · 基准提交:`af6d19f0` 之后的工作区 · 版本 1.4.2(`package.json`)
> 方法:不逐行通读(76,700 行后端 + 131,200 行前端读不完,读完也记不住),而是**沿链条走** ——
> 挑出「同一份语义要在多处成立」的地方,逐条验证它在每一处都成立。凡本文说"实测",都是当场
> 跑过或量过的;凡改动,都在文末列了提交。
>
> 这一份**不取代** `architecture.md` 等五份分报告(2026-09-18 的快照,讲的是系统形态与各子系统
> 的机制)。它回答的是另一个问题:**那些形态,在今天的代码里还处处成立吗。**

---

## 0. 结论先写

这套代码的架构纪律是**真的在执行**,不是写在文档里的愿望:

- 「不写兼容分支,改数据形状就带迁移」—— 全仓搜 `兼容 / legacy / backward`,后端命中的全部是
  **一次性迁移**(`migrate_shared_venv`、`_migrate_*`),而且每一处都明写「不留兼容候选」。
  没有找到一处"读的时候两路都试试"。
- 「语义只能有一份定义」—— 11 份契约语料,每一份都**两侧各跑一遍**(实测:后端 11/11,
  另一侧分别在前端或 agent-sidecar)。
- 「看不出对错的东西拿棘轮钉住」—— 101 个测试文件带 `RATCHET` 标记,由
  `scripts/sync-ratchet-docs.py` 同步进 `docs/CONVENTIONS.md`。

**但链条上仍然会漏,而且漏的方式高度一致:一个值在链条的 N-1 环都在,最后一环没接上,
两边都不报错。** 本次审计找到的问题全是这一种。这不是巧合 —— 它是这套架构(一份语义、多处
实现、接缝在进程/层边界上)的**固有失败模式**,而现有的棘轮覆盖的是"两侧实现是否一致",
覆盖不了"这一环有没有接上"。

## 1. 本次发现:三条断链,一类失败

### 1.1 白模渲染器跳过导入的模型(已修)

**链条**:Blender 建模 → `blender_import_to_scene` → 场景里的 `kind="model"` 物体 →
`scene_render` 渲参考帧 → 交给图像/视频模型当构图参考。

**断点**在第四环:`scene_render/meshes.py` 里写着 `UNSUPPORTED = {"model"}`,后端渲染器把模型
物体**整个跳过**,只在 `skipped_models` 里记一个数。

**为什么看不出来**:工作台是 three.js,它**画得出**那份 GLB。所以用户在编辑器里看得见那件
道具,而自动流程渲出来的每一张参考帧里它是空的 —— 两边都不报错,只是少了一块。

**为什么是架构问题而不是一个 TODO**:它让「智能体在 Blender 里建模」这条链(inspect → execute
→ look → import)和「工作流自动出片」这条链**成了两座孤岛**。前者的产出进不了后者的画面,
于是前者只能人工在工作台里看 —— 那条链最贵的一段(agent 迭代建模)因此拿不到复利。

**修法**:新增 `scene_render/model_mesh.py`,把 glTF/GLB 读成渲染器认得的三角形。读和写用同一套
约定,测试让 `gltf.write_glb` 写出去的再读回来对表。渲不动的(Draco/meshopt 压缩、面数超预算)
**逐条报出原因**,而不是记一个数。

### 1.2 模型挂在场景下,而工作流每跑一次都新建场景(已修)

**链条**:导入模型 → 放进场景 → 工作流自动搭布景 → 参考帧里出现这件道具。

**断点在数据形状**:`Scene3DModel.scene_id` —— 模型是**场景的孩子**。而 `scene_create` 节点每跑
一次建一个新场景,那个场景在模型导入时还不存在。**所以 Blender 建的模型在结构上永远进不了
自动成片**,不是没做,是挂不上去。

同一个错位还长出了两处绕路,它们本身看着都合理:

- `create_scene` 里那句 `raise SceneDomainError("Import models after creating the scene")`;
- `create_scene_with_model()` —— 专为 Blender 接回而设的"场景+模型+修订一把落地"特例。

**修法**:模型改归工作区(和素材、字体、LUT 同一层),带自动迁移(表结构 + 文件目录,可重入)。
上面两处绕路随之删除 —— **这是判断"改对了"的标志**:一个正确的边界会让为错误边界写的补丁
自己消失,而不是多一层。

### 1.3 执行器返回了,但节点没声明(已修,并上棘轮)

`scene_render` 的领域函数返回 `model_warnings`(哪几件模型没渲进去、为什么),接口 schema 有它,
MCP 工具文档也写了它 —— **唯独 `NODE_TYPES["scene_render"]["outputs"]` 没有**。

后果:工作流里那条信息**等于不存在** —— 接不出去、`{{...}}` 引用不到、属性面板上没有。而
没有任何测试会红。

这是我自己在同一天里造的断链,而且是在刚修完 §1.1 之后 —— 说明**靠人记得把新键补到每一处
是不成立的**。

**修法**:`tests/test_executor_outputs_are_declared.py`,AST 静态对一遍执行器返回的键与声明的
outputs。写完先**故意把声明删掉验证它会红**(会,并点名 `scene_render(scenes.py): model_warnings`)
—— 第一版没红,因为只认 `return {字面量}`,而本仓库最常见的写法是 `out = {...}` … `out["k"] = v`
… `return out`。**一条在它该响的那次保持沉默的棘轮,比没有更坏。**

## 2. 同一类失败的另外两处(本次修掉)

它们不在后端链条上,但形状完全一样:**一个值在数据里,而某一条路上看不见它**。

| 断点 | 数据在哪 | 哪条路看不见 |
| --- | --- | --- |
| 一轮失败抹掉整轮过程 | `get_stream_state()` 里有完整 timeline,而且失败分支**已经**回存了 adapter_state(给模型的记忆) | 落库的失败分支从不整理 timeline;前端 `error ? 错误卡 : 过程` 又是二选一。结果:**模型知道自己做过什么,用户不知道** |
| `ask_user` 的结果卡 | `{status, answers}` 完整 | 卡片掉进通用键值摘要,显示「answers 2 个字段」—— 而这次调用的全部意义就是那个选择 |

第一处尤其值得记:代码里**紧挨着**就有一段注释写「失败也回存记忆(拿得到的话)」,理由写得
很清楚。同一个道理没有推广到给人看的那一份 —— 这不是疏忽,是**"给模型的"和"给人的"被当成
两件事**,而它们是同一件事的两个读者。

## 3. 一条没修的结构性观察:界面上的"谁说了算"

不是后端问题,但它是本次唯一一处**反复返工**的地方,值得单独记。

3D 场景页的物体列表,横向位置**同时由四处决定**:列表的负外边距、名字按钮的内距、行的
padding-right、外加一条"有箭头时把内距清零"的补丁。每加一个元素就得再调一处,而调错的表现是
高亮比行宽、箭头戳出面板、深层的行底色比浅层窄 —— **全都不报错**。

同样的形状在别处也出现过:面板高度(`flex: 1 1 auto`,basis 取内容高度 → 在一个面板里做任何事
都会改另一个面板的高度)、智能体时间线的字号(没有任何地方写下它,于是从外层继承成正文的 16px,
**同一个毛病犯了两次**,因为两次补的都是"那一处")。

**规律**:凡是"一个视觉属性由多处累加决定"的地方,都会在加第三个元素时崩掉。修法一律是
**收敛到一处**(一条 grid 定三格宽度、basis 取 0、字号挂在"一行"这个概念上),而不是再加一条
补丁。这三处现在都有测试钉住那几条关系。

## 4. 没有发现问题的地方(也是结论)

沿链条走过、确认处处成立的:

- **契约语料**:11 份,两侧都有测试在跑,无单侧孤儿(`context-meter` 的另一侧在 agent-sidecar,
  不在前端 —— 按契约自己的说明,对)。
- **工作流 / 智能体能力对等**:`test_agent_workflow_parity.py` 强制每个节点类型要么有对应的
  智能体工具,要么在 `NOT_A_TOOL` 里写明为什么。本次新增 `scene_props` 时它当场拦住了,
  并因此补出了 `list_scene_models` —— **棘轮在按设计工作**。
- **数据归属**(ADR-0003):`domain/ownership.py` 声明每张表归谁,行只在拥有方建。本次把
  `Scene3DModel` 从场景域移到工作区语义,归属声明跟着改,没有出现第二处建行的地方。
- **不写兼容分支**:见 §0。
- **孤儿引用**:本次删掉的 `create_scene_with_model` / `delete_scene_model_files` /
  `UNSUPPORTED`,全仓已无残留引用。

## 5. 给下一次的建议

1. **把"链条末端"当成一等检查项。** 本次三条断链都在最后一环。现有棘轮问的是"两侧一致吗",
   问不到"这一环接上了吗"。`test_executor_outputs_are_declared.py` 是这一类的第一条,值得再补
   两条同形的:领域返回的键 → 接口 schema 字段;接口字段 → 前端类型的消费点。
2. **"给模型的"和"给人的"要一起改。** §2 那两处都是只做了其中一半。凡是往
   `payload` / 工具结果里加信息,问一句:人在界面上从哪儿看到它。
3. **视觉属性只能有一处说了算。** §3 三处返工的共同解法。新加元素时如果发现"要再调一处别的
   才对齐",那说明这处属性已经是多源的,先收敛再加。
