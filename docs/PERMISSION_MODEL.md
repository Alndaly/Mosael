# 资源与权限:现状盘点

> 这份是**盘点**,不是设计。每一条都对着代码核过,能跑的都跑过 —— 结论后面括号里是复现方式。
> 目的是把「什么东西属于谁、谁能动它」摆平在一页里,再判断哪些地方对不上。
>
> 结论先行:**这套模型只有两层半,而它被当成三层在用。** 最重的一条在 §3.1 ——
> `ensure_instance_admin` 这个名字承诺的是「这台机器的管理员」,实际语义是「任何一个自己建过
> 工作区的登录用户」。

## 1. 资源挂在哪一层

对 `app/db/models.py` 里 60 张表按作用域列做的全量归类:

| 层 | 张数 | 有哪些 |
| --- | --- | --- |
| **工作区级**(有 `workspace_id`) | 35 | 素材、序列、片段、项目、工作流、知识库、发布账号、浏览器档案、定时任务、智能体会话与记忆、确认卡、用量事件、通知、字体、LUT、声音… |
| **用户级**(有 `user_id`、无 `workspace_id`) | 2 | `AuthSession`、`OAuthIdentity` |
| **实例级**(两者都没有) | 23 | 供应商档案与密钥、模型、默认模型、网络配置、TTS 配置、AI 运行时配置、知识库嵌入配置、插件包/实例/凭据/授权、`User`、`Workspace`,以及若干挂在父表下的从属表 |

两点值得先注意:

- **供应商与密钥是实例级的,不是用户级、也不是工作区级。** `ProviderProfile` 上既没有
  `workspace_id` 也没有 `user_id` —— 一台安装上所有工作区、所有成员共用同一批连接和同一份密钥。
- **用户级这一层几乎是空的。** 只有登录会话和第三方身份。也就是说「这是我的、不是团队的」这种
  东西在这套模型里没有位置 —— 偏好、私有密钥、私有工作区设置都无处安放。

## 2. 闸门有哪些

| 闸门 | 判据 | 写路由用它的条数 |
| --- | --- | --- |
| `ensure_workspace_access` | 是这个工作区的成员;**且当前请求是写方法时**额外要 `edit` | 43 |
| `ensure_instance_admin` | 在**任意**工作区里是 owner/admin,且在那里持有该权限 | 32 |
| `require_sequence_access` | 序列存在 + 上面那条 | 29 |
| `ensure_workspace_perm` | 点名某个权限位(`ai` / `publish` / `members` / `credentials`…) | 24 |
| `ensure_workspace_role` | 角色不低于某档(admin / owner) | 少数 |
| `ensure_graph_node_privileges` | 图里有 `code` 节点时 → `ensure_instance_admin` | 3 |
| `require_worker_key` | 本机 worker 的进程密钥(路由级依赖) | 3 组 worker 路由 |
| 确认卡 | 15 个智能体工具 → 用户逐张点头(或三档权限模式自动放行) | —— |

角色与权限位:`owner > admin > editor > viewer`;`editor` 默认持有除 `members` 外的**全部**权限位,
其中包括 `credentials`。

## 3. 对不上的地方

### 3.1 `ensure_instance_admin` 是自助的(已复现)

它的实现是「遍历此人的所有成员身份,任意一处 role ≥ admin 且持有该权限 → 放行」。而**任何登录
用户都可以新建工作区,并在自己新建的工作区里是 owner**。

复现:

```
viewer(只在别人的工作区里是 viewer)改实例级网络设置  -> 403
他自己新建一个工作区之后,再改一次                    -> 200
```

所以这道闸实际拦住的只有「一个工作区都没建过的人」。它守着的是:供应商密钥、TTS 解释器路径、
网络代理、插件启用、以及**工作流里的 `code` 节点**(那意味着在这台机器上跑任意 Python)。

这是本次盘点里最重的一条 —— 不是因为某个接口写错了,而是因为**这一层压根不存在**:
「这台机器的主人」在数据模型里没有对应物(没有 `User.is_admin`,也没有实例级的角色表),于是
`ensure_instance_admin` 只能用「在某处是管理员」来近似它,而那个近似是自助的。

### 3.2 供应商凭据对 viewer 可读(已复现)

`POST /agent/provider-credentials/{id}/acquire` 只要登录身份。它返回**明文** OAuth 凭据:

```
viewer 取供应商凭据 -> 200
响应里含明文 access token 吗:True
```

模块自己的说明是「能发起一轮对话的人本来就能用到这份凭据」—— 这个理由成立,但**它覆盖不到实际
能调到这个接口的人**:发起对话要 `ai` 权限位,而 viewer 没有;这个接口却不检查任何权限位。
理由和闸门之间差了一档。

### 3.3 写权限靠「当前请求是不是 POST」推断

`ensure_workspace_access` 读的是一个只在 ASGI 中间件里绑定的 ContextVar,默认 `"GET"`。它守着
43 条写路由。任何不经 HTTP 的调用路径(后台线程、队列消费、定时任务)拿到的都是默认值,于是
「写要 `edit`」这半条静默失效。

本轮已经把确认卡的批准/拒绝改成显式 `ensure_workspace_perm`(那条是授权路径,复现过 viewer 在
后台线程里批准成功且真的执行了)。**其余 43 条还是这个形状** —— 今天安全,因为它们都只从 HTTP
进来;它是一颗按「以后没人把它挪到后台」下注的雷。

### 3.4 `editor` 默认就有 `credentials`

`_ROLE_DEFAULTS` 里 editor = 除 `members` 外全部,所以它包含 `credentials`。这个权限位是
`ensure_instance_admin` 的第二个条件 —— 于是「角色 ≥ admin」成了唯一真正的判据,权限位那一半
在默认配置下不起作用。

### 3.5 三个概念用同一个词:`credentials`

它同时是:工作区权限位、`ensure_instance_admin` 的默认参数、以及插件凭据表的名字。三处含义不同
(能不能配供应商 / 是不是实例管理员 / 插件存的密钥),而它们在代码里长得一样。

## 4. 已经对上的地方

盘点不能只列问题,否则读的人会以为整套都在漏:

- **工作区边界是严的**:不是成员一律 404(不泄露存在性),35 张表全部按 `workspace_id` 过滤。
- **不可逆动作有专门的一档**:`external`(公开发布 / 对外写请求 / 本机跑代码),措辞和徽标都不同,
  三档权限模式下 auto 也不放行它 —— 要么规则命中,要么隔离判断者点头。
- **危险节点有独立闸门**:`code` 节点的四条落库路径(create / import / patch / 确认卡审批)现在
  全部要过 `ensure_graph_node_privileges`(第四条是本轮补的)。
- **凭据本身有周期**:`AuthSession` 现在会过期、会自清,服务令牌 30 分钟。
- **worker 通道不走用户身份**:本机 worker 用启动时下发的进程密钥,网页读不到那个文件。

## 5. 如果要修,顺序是

> **决定已经做了,见 [ADR 0008](adr/0008-three-principals.md)** —— 它把这里列的问题归到一个根上:
> 这套模型用一套角色去表达三类根本不同的主体(宿主主人 / 工作区成员 / 智能体),所以哪一层都不严。
> 下面这段是当时的依赖分析,保留为过程记录。


1. **先有「实例管理员」这个概念**(§3.1)。在它存在之前,3.2 / 3.4 都没有可收敛的目标 ——
   收紧任何一处都只是把「谁能自助升级」换个地方问一遍。最小形态可能是 `User.is_instance_admin`,
   由**第一个注册的用户**持有(本地优先的桌面应用里,那个人就是机器的主人),其余人由他授予。
2. 有了它,`ensure_instance_admin` 改成认它,`code` 节点、供应商密钥、网络代理、解释器路径、
   插件启用一起收紧,§3.4 自动消失(`credentials` 权限位退回它字面的意思:能不能在工作区里配连接)。
3. §3.2 单独可修,而且不依赖第 1 条:给凭据接口加上 `ai` 权限位,让闸门对上它自己写的理由。
4. §3.3 是逐条的机械改动(43 条),可以分批;判据是「这条路由以后有没有可能不从 HTTP 进来」。

## 6. 这份文档怎么核对

结论都来自可复现的检查,不是通读印象:

- 表的作用域:对 `models.py` 做 AST 扫描,按有没有 `workspace_id` / `user_id` 分类。
- 路由闸门:对 `app/api/routes/*.py` 做 AST 扫描,收集每个路由函数体(含一层本地辅助函数)里
  调用到的 `ensure_*` / `require_*`。**先用正则做过一遍,结论是错的** —— 正则在第一个空行处截断
  函数体,把一批有闸门的路由报成没有。
- §3.1、§3.2 的结论各有一次实跑,输出原样抄在上面。
