**DMG 公证了两次,第一份作废了。** 第一份(`4e77efd5-b68c-4713-b758-e6c7ddecd166`,Accepted)
只读挂载时发现卷内 `Mosael.app` 是 `drwx------`:release.yml 的 macOS 打包步骤开头有
`umask 077`,本意是保护解码出来的 provisioning profile,却罩住了整个 electron-builder 输出。
这样的包只有拖它进 `/Applications` 的那个账户打得开,同一台 Mac 的其他账户打不开。从
`823cd31c`(2026-09-09)起的 Mac 包都是这样。

这一版在 DMG staging 里 `chmod -R go+rX` 后重打。权限位不在代码签名的封印范围内;改完以后
`codesign --verify --deep --strict`、`verify-mac-signing.cjs`、`stapler validate`、
`bundle.smoke.mjs` 全部重跑通过,再签 DMG、公证、附票据。工作流本身的修正单独提交。

## 没做什么

- **本机没跑 Windows 安装包**:它由云端那次构建验证启动与数据库升级,附件按「同一次构建」
  收录,不声称它带 Windows 代码签名。
- **没有用真实云存储账号验证三个存储插件的上传和下载**:签名逻辑由
  `backend/tests/test_storage_plugins_share_one_core.py`(含 AWS 官方测试向量)和上面的本地 presign 覆盖,真实往返需要用户自己的桶和密钥。
