## 发布过程中修掉的两处

1. **`test / checks` 在「Website tests and production build」红了三次**(`21feec1cd` 那一轮):
   `capture-manifest.json` 的 `documentedVersion`、`release-copy.ts` 缺 `v1.9.11`、`website/README.md:99`。
   **根因**:改版本号时只 `sed` 了 `content/docs`,漏了同属 `versionBearingFiles()` 扫描面的 README / manifest / release-copy。
   修在 `44f5d7918`,官网测试 **90/90** 全绿。
2. **tag push 没有触发出草稿**:`draft` 的 `needs: [test]`,而 `test` 的 `if` 只在 **云端公证凭据齐全** 或 **`workflow_dispatch` + `notarization=local`** 时成立 ——
   所以 **tag push 这条自动发布路径只适用于云端公证**(`docs/RELEASING.md §2` 已写明)。本轮按 **§5 的指示**:先在本地打 tag 推上去,再 `gh release create v1.9.11 --draft` 手动建草稿、传附件、发布。
