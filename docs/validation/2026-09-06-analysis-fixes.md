## 兼容性变化

- 代码节点执行现在在所有平台都需要可用的 Docker 和预先准备的 `python:3.13-alpine` 镜像。编辑和保存代码节点不受影响。当前机器已验证真实 Docker 执行；运行环境使用容器内的 Python 标准库，不读取宿主机项目的虚拟环境。
- 通用外部 worker 需要带回 claim 返回的 `lease_token`，并至少每 20 秒按具体认领续租。旧 worker 应更新协议。发布器保留专用通道。详见 [worker 契约](../adr/0002-claim-report-worker-protocol.md)。
- 失联任务不会自动重新执行，避免重复计费或重复外部副作用；用户检查结果后重新发起。
- 发布取消可阻止后续浏览器动作；已经被平台接受的投稿不会因此自动撤回。发布流程验证使用替身适配器，没有向真实账号投稿。

## 沙箱边界复核

修改文件为 `backend/app/domain/sandbox/__init__.py`、`backend/app/core/child_process.py`，以及对应沙箱、输出预算测试和架构说明。

结果：`fixed`。共享边界仍是 `sandbox.run_code`，工作流代码节点和智能体代码执行使用同一入口。正常 JSON 输入、标准库计算、Unicode 输出和语法错误诊断保留。

原问题通过 scratch 外临时哨兵及符号链接复现；修复后均无法读出。stdout/stderr 连续无换行输出会在运行中触发预算，输入不被读取时也受截止时间控制。真实容器内核返回 256 MiB 内存、无额外 swap、64 进程限制，512 MiB 分配仅终止容器内工作，随后正常代码仍可执行。超时后检查容器不存在，脱离父进程的子进程一并移除。

独立复核另发现 Docker 会从宿主机配置自动注入代理变量；以临时代理凭据复现后，显式清空大小写代理变量，并增加实际容器回归。复核及复现使用临时标记，不读取真实业务文件。资源设置依据 [Docker 官方说明](https://docs.docker.com/engine/containers/resource_constraints/)。
