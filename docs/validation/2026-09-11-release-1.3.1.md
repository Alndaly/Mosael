## 构建过程中的两次红灯（均非产品缺陷）

- **`13 != 12`**：`test_排队的消息最终会跑起来` 多记一轮。上一条测试的 `_settle` 以 status 为判据，
  在「轮结束置 idle」与「drain 起下一轮」之间返回，那一轮活到了下一条测试里，并调用了它 patch 的
  `run_turn`。本机窗口太窄复现不了，把 drain 推后 0.25 秒后 100% 稳定复现，两处修复均在该条件下验证。
- **官网 `'1.3.0' !== '1.3.1'`**：漏了文档版本号。`documentedVersion` 与批次 `version` 是两回事，
  前者必须随发版更新。已在 RELEASING.md 中写清。
- **Windows 首轮启动冒烟失败**（后端未就绪，日志停在 `Mosael backend starting`，无 traceback）：
  重跑通过，判定为该 runner 上的偶发启动超时；同版本后端在 macOS 冒烟一次通过。

## 本机验证

- 应用公证 ID：`f5d30986-3f38-4476-8962-8b08c306bb18`，Accepted。
- 应用票据、深度签名及 Gatekeeper 验证通过，来源为 Notarized Developer ID。
- 正式应用启动与数据库升级检查通过：`bundle smoke passed (darwin, app 1.3.1)`；
  `WebAuthn configured=true, device available=true`。
- 签名时间戳一度失败。定位为本机代理（Clash Verge Rev）把 `timestamp.apple.com` 命中
  `DOMAIN-SUFFIX,apple.com → 🍎 苹果服务`，而该策略组选的是 DIRECT —— 该域名无国内节点，直连被拒
  （0.2 秒 Connection refused，非超时）；`www.apple.com` 有国内 CDN 故同规则可通。
  处理：只为 `timestamp.apple.com` 与 `apple-cloudkit.com`（stapler 取票据用）各加一条走代理的规则，
  写入 Verge 的 `Merge.yaml`，不改动「🍎 苹果服务」策略组，其余 Apple 流量保持原状。
  未关闭 TLS、时间戳或 Gatekeeper。（注：`curl` 对 `timestamp.apple.com` 的 GET 始终返回 000，
  不能作为该服务可用性的判据 —— 它只应答 RFC3161 的 POST；应以 `codesign` 本身为准。）
