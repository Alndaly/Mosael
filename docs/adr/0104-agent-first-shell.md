# 0104 AI Studio 是默认入口，剪辑降为项目 surface

- 状态：已采纳（阶段 1）
- 日期：2026-11-18

## 背景

产品以智能体为核心，但壳层仍把剪辑页当作“家”：

- 空 hash、未知页面都落到 `editor`；
- 切工作区回到 `editor`；
- `editor` 没有项目时渲染项目浏览器 `HomeView`，同一个页签同时承担首页、项目列表和编辑器。

结果是用户打开应用先看到剪辑，AI Studio 只是侧栏里的另一个 tab；Agent 也缺少一个明确的“当前项目/当前素材”工作上下文。这个入口和产品定位相反。

## 决策

### 默认入口

`#/ai` 是 AI Studio 的规范地址。冷启动、未知路由和切换工作区都落到这里；不再把 `editor` 当作缺省页。

### 剪辑只由项目打开

- `#/editor?p=<projectId>` 打开剪辑；
- `#/editor` 不带 `p` 视为“还没有项目”，规范化为 `#/projects`；
- `#/projects` 是独立的项目浏览 surface，不占侧栏一格；
- 侧栏「剪辑」在有当前项目时打开剪辑，没有项目时打开项目浏览页。

项目浏览页从编辑器的空态中拆出，避免“剪辑”同时是首页和项目列表。项目被删除、或地址里的项目失效时，回到 `#/projects`，不把空编辑器留给用户。

### 其他页面暂不变

媒体、笔记、画板、场景、工作流、发布、调度、插件、设置等仍保留自己的地址和侧栏入口；阶段 1 只收敛入口和空态。它们后续会作为可召回的 surface 接入 Agent 的 working set，而不是在这一阶段被塞进聊天窗口。

### 深链契约

`contracts/studio-views.json` 增加 `projects`；`STUDIO_VIEWS` 成为前端可路由页面的唯一清单。`mosael://` 深链白名单同步，`NAV_ITEMS` 仍只描述侧栏，因此项目浏览页有路由和面包屑名字，却没有侧栏图标。

## 后果

- 新用户打开应用先看到 AI Studio，而不是空剪辑器。
- 剪辑、项目浏览、AI Studio 三个概念分开：AI Studio 是控制面，项目浏览是项目管理 surface，剪辑是项目编辑 surface。
- 这一阶段还没有引入 Agent working set；当前项目仍由壳层的 `projectId` 保存，只是默认入口不再依赖它。
- 后续阶段要让 Agent 显式持有项目、选中素材和当前 surface，并把编辑器/画板/笔记等接入统一 surface host；那一步不能再用“页面决定项目语境”的全局规则。
