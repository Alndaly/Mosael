# ADR 0039:Mosael Cloud —— 充值在 Mosael 里,模型由平台配好;网关跑 Mosael 自己的适配器

## Status

Proposed — 2026-10-05。目标 2.0。文中法律部分只是方向性梳理,不是法律意见;上线前由律师确认主体、资质和协议文本。

## Context

维护者(2026-10-05):「如果我希望后续在 2.0 版本中上线 Mosael Cloud,用户可以自行充值使用,免去所有模型配置,提供一些常用
常见的模型,该怎么做……是否可以利用 new-api……如果我部署在海外呢？注意我希望充值这件事情本身就在 Mosael 内即可。」

今天用一个模型,要先去厂商那里开账号、充值、拿 Key,再回 Mosael 建连接。对只想出图、出视频的人,这一步就把他们挡在门外了。
Mosael Cloud 要做的,是让用户登录后充一笔钱,直接用平台挑好的那几个模型。

### 现在有什么

- **连接 = 每个人自己的钥匙。** `ProviderProfile` 存端点和非密配置,`ProviderCredential` 存某个用户的 Key / OAuth 令牌,
  读取方只拿 `ResolvedConnection`(`domain/providers/credentials.py`)。`credentials.pick` **没有回退** —— 曾经有过
  「部署管理员共享的那一把」兜底,因为没有界面、会读到别人的钥匙,已经删掉。
- **用量账本按回包实扣。** `ProviderUsageEvent` + 计价规则(带币种),`CostAmount` 规定不同币种的钱永远不相加、不换汇
  (`domain/billing/usage.py`)。1.9.0 / 1.9.1 把「按服务商回包核对」和「记到哪家」理顺了。
- **付费的远端任务不丢**([ADR 0019](0019-paid-remote-work-is-never-abandoned.md)):提交、等待、重启后接着等、取消。
- **参数来自适配器**([ADR 0015](0015-generation-parameters-come-from-the-adapter.md)):界面上能填什么,由适配器的声明决定,
  不在前端写死。适配器、契约、注册表在 `backend/app/ai/providers/`([ADR 0010](0010-provider-contracts-adapters-registry.md))。
- **社区服务 `community/` 有账号,但桌面端已经不接它了。** 社区服务里有短信 / 密码登录、轮换的刷新令牌、设备授权
  ([ADR 0026](0026-community-service.md))。不过 **ADR 0026 同日的修订把桌面端的接入整体拿掉了**:社区账号、分享、发布
  一起移除,接入时加的表和列由迁移 `migrate-drop-the-community-integration` 删掉,[DEPLOY_COMMUNITY](../DEPLOY_COMMUNITY.md)
  标着暂不可用。所以 Cloud 的账号要**重新接**,不是「已经能登录」。
- **合规上已有的两块**:成片导出时,用了 AI 素材就加显式和隐式标识(`domain/render.py`,[ADR 0028](0028-digital-humans.md) §5);
  克隆音色有授权声明(`domain/voices/consent.py`)。

### 外部事实(2026-10-05 查证)

- **new-api** 是 AGPL-3.0。它管的是「多渠道 → OpenAI 兼容接口」的转发,以及按倍率计费的用户和额度。
  如果修改了代码、再作为网络服务对外提供,就要向使用者公开修改后的源码。
- **CLIProxyAPI** 把 Claude Code、Codex、Gemini CLI 这类**订阅账号的登录态**包装成 API。拿订阅账号对外卖,违反这些厂商的
  服务条款,有封号、违约的风险。
- **在国内收费提供生成式 AI**(方向性):
  - 主体:公司;ICP 备案,收费的在线服务还要增值电信业务经营许可证(ICP 证)。
  - 生成式 AI:按《生成式人工智能服务管理暂行办法》。调用**已备案**大模型的接口做应用,一般走属地网信办的「生成式人工智能服务登记」。
    能给境内公众用的只有境内已备案的模型。
  - 深度合成与标识:《人工智能生成合成内容标识办法》(2025-09-01 施行)要求显式和隐式标识。还要做实名、内容审核、日志留存、
    投诉渠道;声音克隆、数字人要取得本人同意。
  - 淫秽色情内容:生成即违法,平台要拦。
  - 余额是预付款:写清不可提现、退款规则;不做可提现、可转让,免得沾上支付业务许可。要开发票。
  - 个人信息:隐私政策加同意;提示词和图片送去境外模型,属于数据出境。
- **部署在海外**(方向性):
  - 可以接 OpenAI / Anthropic / Google,但只能服务这些厂商支持的地区。
  - 收款可以用 Stripe,或用 Paddle / LemonSqueezy 这类代收方(Merchant of Record),由它们代办各国的增值税和销售税。
  - 合规:GDPR;欧盟 AI 法案的透明度义务(生成内容要标识)2026-08 起适用。主流支付都禁止成人内容。
  - **服务器放在海外,绕不开国内法**:只要面向中国大陆公众提供,国内的规定照样适用,《个人信息保护法》也有域外效力。

## Decision

### 1. 三块东西都在服务器上,桌面端只多一家供应商「Mosael Cloud」

```
 桌面端(每个用户自己的 Mosael)                       Mosael Cloud(维护者的服务器)
 ┌──────────────────────────────┐   设备授权登录     ┌───────────────────────────────────┐
 │ 连接「Mosael Cloud」          │ ─────────────────▶ │ 账号:社区服务 community/           │
 │  钥匙 = 这个人的云端令牌       │                     │ 钱包:余额、流水、充值单             │
 │ 适配器 mosael-cloud(薄)     │ ── 目录/任务/结果 ─▶ │ 网关:跑 Mosael 的适配器包           │
 │ 用量账本:记网关回的实扣        │ ◀── 实扣金额 ───── │  ├─ 图片/视频/配音/音乐:直连上游    │
 │ 「充值」:二维码 / 支付页      │ ── 下单 ──────────▶ │  └─ 大模型对话:内网 new-api 路由    │
 └──────────────────────────────┘                     │ 上游钥匙只在这里,不下发             │
                                                       └───────────────────────────────────┘
```

- 在桌面端看来,Mosael Cloud 就是**又一家供应商**:登录后自动建一条连接,钥匙是**这个人自己的**云端令牌。这正合「每个人自己的钥匙」,
  不需要把「共享钥匙」请回来。
- 上游厂商的钥匙归平台,只存在网关里,永远不下发到桌面端。
- 用户自己配的连接照旧。Cloud 是多出来的一个选项,不替换任何东西。

### 2. 账号:重新接社区服务的设备授权,只接登录这一件

- 桌面端「登录 Mosael」:在系统浏览器里打开授权页,用户确认「允许这台 Mosael 使用你的账号」,应用轮询拿到一对令牌。
  社区服务现成的 `/auth/device/*` 就是做这个的。
- 刷新令牌存在桌面后端的密钥存储里,按桌面用户各存各的。一台机器上有几个 Mosael 用户,就各自登录。
- 只接回「登录」。ADR 0026 修订里拿掉的分享、发布、社区插件来源不跟着回来;以后要接,按那时的需求另定。

### 3. 钱包:余额按最小货币单位记的预付款,先冻结、后结算

- 表:`wallets`(用户、币种、余额)、`wallet_entries`(只追加:充值、冻结、结算、释放、退款、人工调整,每条带关联的
  任务或充值单)、`topup_orders`(金额、渠道、状态、渠道单号)。余额是流水的结果,不单独改。
- **一个钱包一个币种**:国内版人民币,国际版美元。不换汇,沿用 `CostAmount` 的规矩。
- **提交时冻结,完成后按实扣结算**:
  1. 提交前按目录里的价格冻结一笔预估。视频按秒数、图片按张数、对话按上限 token。
  2. 完成后,按上游回包的实际用量 × 目录价结算,多退少补。
  3. 失败或取消、上游没收费的,全额释放。
  4. 余额不够冻结时直接拒绝,告诉用户还差多少。
- 余额不可提现、不可转让、不计息。

### 4. 充值就在 Mosael 里

- 应用里点「充值」,选金额,向云端下单:
  - **国内版**:微信 / 支付宝的原生二维码,显示在应用里,用手机扫。
  - **国际版**:代收方或 Stripe 的支付页,开在应用内的独立窗口里(单独的会话分区,不带用户别的登录态)。
- 支付渠道的回调只打到云端,由云端入账。应用里的余额靠云端推送更新;推送连不上时轮询,作为退路。
- Mosael 自己发 DMG / EXE,不经过应用商店,没有应用内购买的抽成和限制。
- 发票:国内版接电子发票服务;国际版由代收方出。

### 5. 网关:把适配器抽成包,桌面后端和网关都依赖它

- 把 `backend/app/ai/providers/` 里的契约、适配器、注册表抽成 `packages/mosael-providers`。这有先例:ADR 0026 把桌面端和
  社区服务都要的包格式抽进了 `packages/mosael-formats`。
- 抽出来的包不认识数据库、任务表、用户。它要的东西走显式的端口传进来:HTTP 客户端、媒体上传下载、用量回报、取消信号。
  桌面后端和网关各自实现这些端口。
- 网关是个独立服务,复用社区服务的账号和数据库,在适配器包之外只加四样:鉴权、冻结与结算、限流、审核。
  [ADR 0001](0001-no-network-microservices.md) 说的是应用内部不拆微服务,和这里不冲突:网关和社区服务一样,是另一个产品边界。
- **桌面端和网关之间用 Mosael 自己的协议,不用 OpenAI 兼容接口**:
  - `GET /catalog`:模型、生成声明、单价、生效时间;
  - `POST /jobs`:按种类提交;输入素材先拿签名上传地址传上去;
  - `GET /jobs/{id}`、`POST /jobs/{id}/cancel`;
  - 结果给短时效的签名地址;
  - 对话是 `POST /chat`,流式返回。

  OpenAI 兼容接口表达不了首尾帧、参考图角色、异步任务和回包核对,Mosael 现有的生成能力会在那一层丢掉。
- 桌面端的 `mosael-cloud` 适配器很薄:参数声明照搬目录里下发的([ADR 0015](0015-generation-parameters-come-from-the-adapter.md)
  不变);任务的提交、等待、重启后接着等,照 [ADR 0019](0019-paid-remote-work-is-never-abandoned.md);用量账本记网关回的
  实扣金额和币种。这家供应商**没有本地计价规则**,网关说扣多少就是多少。

### 6. 模型目录:平台挑,云端下发,按版本分

- 首批 5–10 个:对话、生图、视频、配音、音乐各一两个。
  - 国内版:只上境内已备案的模型,比如通义、豆包、可灵、MiniMax。
  - 国际版:可以上 OpenAI、Google、Anthropic,但只服务这些厂商支持的地区。
- 目录里写最终单价(已含平台加价)和生效时间。价格改动提前在目录里排好,已经冻结的任务按冻结时的价格结算。

### 7. new-api 只当内网的对话路由;CLIProxyAPI 不进收费链路

- new-api 放在网关后面,只做大模型对话的多渠道转发和故障切换:不对外,不管用户,不管余额,自身的计费关掉,网关用一把内部令牌调它。
  不改它的代码;真要改,就照 AGPL 公开改动。
- 图片、视频、配音、音乐都不经过 new-api,由网关直接用适配器调上游。
- CLIProxyAPI 不接进任何收费路径(理由见 Context)。维护者自用另说,和 Cloud 无关。

### 8. 内容安全与合规里,工程要做的部分

- **实名**:国内版充值和生成前,要绑定手机号(社区服务已经有短信)。
- **审核**:
  - 提示词和输入素材先过审核,上游自带的审核加上平台自己的文本 / 图像审核;
  - 产出按比例抽检,视频和数字人全检;
  - 拦下来的记原因,用户看到的是能看懂的说明。
- **NSFW**:云端一律拦。用户自己的 ComfyUI、自己的连接不受影响 —— 那是用户自己的事,云端是平台的责任。
- **标识**:云端产出的图片、视频、音频写入隐式标识(元数据);导出成片时的标识沿用现有逻辑。
- **留存与投诉**:生成日志留存不少于六个月;有投诉和举报入口;要有用户协议和隐私政策,用户同意后才能充值。
- **数据不出境**:国内版只连境内模型,不把用户的提示词和素材送到境外。

### 9. 两套部署:国内版和国际版,同一份代码

- 两个实例,配置不同:主体、域名、币种、支付渠道、模型目录、审核服务商。
- 账号和钱包不跨版本。用户在登录页选「中国大陆 / 其他地区」,默认按系统地区猜。
- 一个用户只属于一个版本。要换版本,就在另一边重新注册。

### 10. 分阶段

1. **主体与地区**(非技术):定主体,请律师确认国内的资质路线(ICP 证 + 生成式 AI 登记)、国际的代收方路线,起草协议文本。
2. **抽包**:`packages/mosael-providers`,桌面后端改为依赖它;行为不变,现有测试全绿。
3. **账号与钱包**:桌面端重接设备授权登录;钱包、流水、充值单;支付先接沙箱。
4. **网关与目录**:网关服务、桌面端 `mosael-cloud` 适配器、首批模型;冻结和结算按实扣核对。
5. **安全与上线**:审核、标识、日志、投诉;内测,然后先上一版。

## 待拍板

| # | 问题 | 选项 | 推荐 |
| --- | --- | --- | --- |
| 1 | 网关怎么复用适配器 | A 抽成 `packages/mosael-providers` 包;B 网关就是无界面的整个桌面后端;C 全部交给 new-api | **A**。B 会把沙箱、画板这些和网关无关的东西一起带上服务器,攻击面大;C 会丢掉 Mosael 的生成能力,计费也是两套 |
| 2 | 先上哪一版 | A 国内版;B 国际版;C 两版同时 | **A**,资质今天就开始办。主要用户在国内,而证照是最慢的一环;技术上两版是同一份代码,国际版随后跟上 |
| 3 | 平台加价怎么体现 | A 统一的加价比例;B 每个模型直接标最终单价 | **B**。用户看到的是「一张图 ¥0.2」,不是倍率;各模型的毛利也可以单独定 |
| 4 | 余额规则 | A 不过期,没用完的可以申请退回;B 设有效期 | **A**。对预付款最稳妥,也最少争议 |
| 5 | 国际版收款 | A 代收方(Paddle / LemonSqueezy);B 自己接 Stripe,自己处理税 | **A**。各国的税和发票由代收方代办,独立开发者最省事 |
| 6 | 任务失败但上游已经扣了钱 | A 平台承担,用户不付;B 照扣用户 | **A**。用户只为拿到的结果付钱;这笔损耗算进单价 |
| 7 | 没登录时 Cloud 怎么出现 | A 供应商列表里有它,点了引导登录;B 登录前不出现 | **A**。这是给不会配 Key 的人准备的入口,藏起来他们就找不到了 |

## 这一版不做

- 订阅、会员、团队钱包、可提现或可转让的余额。
- 云端 ComfyUI、租 GPU。
- 社区的分享、发布、社区插件来源(见 §2)。
- 改动用户自己的连接:自己的 Key 照旧可用,Cloud 只是多一个选项。

## Consequences

- 适配器层第一次被两个进程依赖。它对数据库、任务表的隐式依赖要先拆干净;拆的过程本身也让桌面端的耦合变少。
- 平台第一次替用户付上游的钱,也第一次持有用户的钱。冻结和结算必须和用量账本一样经得起对账,钱包流水只追加,不改写。
- 桌面端重新出现「Mosael 账号」。它只用来登录 Cloud,和 ADR 0026 修订之前那套社区接入不是一回事。
- Mosael 的定位多了一层:它仍然是本地优先的创作工具,同时也可以是一个付费服务的客户端。国内版、国际版的合规要求,会反过来约束
  云端能提供哪些模型、哪些能力。
