# 模型 ID 是系统 UUID，展示名才给人看

- 状态：已采纳
- 日期：2026-10-30
- 关联：ADR 0088 §3

## 背景

`cloud_gateway_models.id` 原先由管理员手填，同时承担三个角色：数据库主键、网关对外模型 ID、管理台列表和下拉框里的名字。结果是新建模型要先想一个永远不能改的字符串；通道下拉框只能显示这个 ID；两个模型同名时，界面上反而更难区分。

## 决策

| 字段 | 角色 |
| --- | --- |
| `id` | 系统生成的 UUID，只做内部主键与接口标识 |
| `label` | 人看的名称，允许重复 |

- 管理 API 的创建请求**不再接收 `id`**；服务端用 `new_id()` 生成。
- `catalog.display_labels` 给同名模型按 `(created_at, id)` 追加 `(1)/(2)`。只有重名才加序号；唯一名称原样显示。
- 管理端模型表、通道表、通道下拉框、价格弹窗、用量按模型统计全部显示展示名，不显示 UUID。
- 网关 `/v1/models` 的 `id` 是 UUID，`name` 是展示名；桌面端「Mosael Cloud」模型列表本来就以 `display_name` 为主，因此用户看到的是名称。
- CLI `model-set` 新建时自动生成 UUID，`--id` 只用于更新已有模型；新增 `model-list` 输出 UUID 与展示名。

## 迁移

`0017_model_ids_are_uuid` 为每个旧模型生成 UUID，克隆模型行，并把 `cloud_model_prices`、`cloud_upstream_channels`、`cloud_gateway_calls` 的 `model_id` 一起改写，最后删除旧行。名称与用量历史都保留。

这是数据值迁移，不再保留旧的手填 ID；客户端升级后需要重新同步一次模型目录。降级保留 UUID，因为旧名字没有留存、无法反推。

## 不选的做法

- **强制名称唯一**：同名模型在迁移、重建或不同 SKU 下都可能出现；强制唯一会让改名变成破坏性操作。
- **另加一个 `slug` 给人看**：等于把刚去掉的手填 ID 换个名字加回来，选择器还是要解释两套标识。
- **保留旧 ID、只给新建模型生成 UUID**：同一张表混两种语义，排序、审计和客户端缓存都会更复杂。
