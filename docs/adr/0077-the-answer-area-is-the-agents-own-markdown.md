# ADR 0077 · 答案区只放智能体自己的 Markdown 正文

- 状态:Accepted — 2026-10-22(维护者当场纠正上一版的做法)
- 相关:ADR 0021 / 0044(过程与结果)、ADR 0075(Computer Use)

## 要解决什么

之前「一轮回答的答案区」是**渲染器的固定规则**拼出来的:把最后那段正文和「这一轮做出来的素材」
(生成任务的产物、回执带来的图)、`show_widget` 的小界面,按时间线顺序织成一份「答案文档」。

维护者指出这不对:

> 是否应该在答案区域显示应该是智能体自行判断,不应该有什么固定显示在答案区域这种说法。
> 是最终回答的时候智能体自行回复 markdown、流式显示结果。比如智能体回答:
> 「这是我找到的图:![test.png](https://test.png)」。包括任何内嵌的 HTML 也应该是流式答案过程中
> 动态显示的。

问题不在「图该不该出现在答案里」,而在于**谁来决定**:固定规则让渲染器替智能体做决定,于是
- 工具做出来的图无论智能体想不想展示都会挂在答案下面;
- 同一张图可能先在工具行明细出现、又在答案区出现;
- 「图在文上还是文下」「先给图还是先给结论」由渲染顺序决定,而不是由写字的人决定。

## 决定

1. **答案区 = 智能体最后那段正文**,只此一样。它本来就是流式回来的 Markdown,边流边画。
   `ToolCalls.resultDocument` 只收 `splitTurn` 切出来的末尾正文块,不再收任何素材 / 小界面。
2. **要展示什么,智能体自己写进正文**:
   - 图:`![说明](mosael-asset:<asset_id>)`。asset_id 来自工具结果 / 回执(媒体元素加不了请求头,
     渲染前由前端换成本地可取的、带 token 的素材地址,见 `components/markdown/assetRefs`);
   - 少量内嵌 HTML:Streamdown 默认 `allowDangerousHtml` + `rehype-raw` + `rehype-sanitize` 渲染并清洗,
     所以模型可以直接写一小块 HTML,同样随流出现。
3. **工具产物与小界面留在过程里**:工具行明细照旧显示这一行碰过 / 做出来的素材,`show_widget` 的
   小界面画在发起它的那一行明细里 —— 过程是「它怎么做出来的」,可以翻看;答案只说结论。
4. **提示词写清楚这件事**:系统提示里加一段:你的回答就是流式 Markdown,答案区只有这段正文,
   要给人看图就自己贴 `mosael-asset:` 引用,不要指望工具产物自动出现。
5. 一并删掉因此没人用的辅助:`turnOutputs.producedByTool`、`receivedAssetIdsByMessage`、`turnWidgets`
   与答案区的素材/小界面渲染;`widgetOfTool` 保留(画在工具行明细里还要它)。
   回执与任务的素材仍在各自的步骤里看得见,**不会丢**,只是不再自动摆进答案。

## 后果

- 「答案」重新由内容决定,而不是由工具类型决定:一次「帮我看一眼这张图」的回答可以只有文字,
  一次生成图的回答可以自己把图贴在该在的位置;
- 智能体多了一件要学的事:想展示图 / 界面,要在正文里写引用或 HTML。提示词与工具说明里写清楚,
  没写出来的就不显示 —— 这是**有意的**,不再由渲染器猜;
- 旧的「结果区自动摆图」不再存在:此前保存的对话消息里那段正文照样渲染,素材并不丢(仍在工具行明细);
- 前端少了一条跨工具的隐式约定,渲染侧更简单;`design/` 的相关回归测试跟着改成新语义。
