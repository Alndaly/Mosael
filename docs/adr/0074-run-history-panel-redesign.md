# ADR 0074 · 「执行历史」面板重写：一层框、三段落、一条分隔线

- 状态：Accepted — 2026-10-21
- 取代：此前 8 次逐层微调（`aea76382c` … `0c59ef28e`）。那些提交都在**挪边、挪底、挪滚动**，
  每一次修好一处、弄坏另一处 —— 根子不是某一层写错了，而是**层次本身太多**。

## 问题

面板里同时叠了四圈边和三块底：待批段的玻璃面 → 卡片的边与底 → 正文区的边与底 → 按钮行的底。
于是：

- 看上去"框套框"，同一条边被画两次以上；
- 内容一长就撑出面板，按钮被裁掉（滚动写到哪一层都不对，因为**外框的 `overflow-hidden`
  和面板自己的 `overflow-y-auto` 是同一条 CSS 属性**，谁赢取决于 Tailwind 生成顺序）；
- 每一格的内边距各写各的，行的节奏不统一。

## 决定

**一个面板，三段落，一条分隔线。** 具体六条硬规矩：

1. **只有一层框**：面板一层 `rounded-xl border`；**里面任何块都不许再画整圈边** ——
   最多用「**左边条**」（待批段）或「**一条分隔线**」（段之间）。
2. **只有三块底色**：面板底、待批段的「浅强调底」、选中行的「强调底」；其余一律透明。
3. **间距只有三种**：段间 12px、段内块间 8px、行内 4px。不再出现第四种刻度。
4. **行高统一 44px**：列表行、步骤行都一样；状态徽章与耗时**右对齐**。
5. **滚动只有一个**：**面板根**滚 + 头部 `sticky top-0`；正文区保留它自己 `40vh` 的限高滚动
   （那一处是刻意的：整篇稿子不该把按钮推走）。外框**不许**再写任何 `overflow-*`。
6. **待批段永远在顶**，不被列表挤走；没有待批时这一段整块消失（不占位、不留线）。

### 两个待批段的形态（维护者选定）

- **左边条 + 浅底** ✓（不用整块卡片的边）；
- **详情默认展开**最后选中的那次运行 ✓（不是等用户点）。

## 布局

```
头 44px sticky：⟳ 执行历史 · 计数 · 悬浮/关闭
待批段：2px 强调左条 + 浅强调底；标题 / 正文(折叠 6 行 + 展开) / 元信息 / 备注 / 按钮右对齐
──────── 一条分隔线 ────────
运行列表：44px 行；图标 16 + 标题 13 + 右侧状态徽章 11；时间/版本作次要行
──────── 一条分隔线 ────────
选中运行的详情：步骤行 44px；耗时右对齐；当前步骤高亮
```

## 后果

- 面板的"层次"从四边三底压到一边三底，**跨层重复的视觉信号消失**；
- 滚动责任唯一（面板根），**不再依赖任何中间层的 `flex-1`**；
- 行高与内边距由一套刻度决定，**加行不会破坏节奏**；
- 强制约束：`tdd` 之外还要有 **DOM 级断言**（面板根是唯一滚动容器、里面没有第二圈 `border`）。

## 教训（写给下一次）

**先定"哪一层负责边、哪一层负责底"，再动手。** 一次反馈里连改三层，必然修一个坏一个 ——
这块 UI 因此连改八次。设计没定下来之前，**不要开始改样式**。

## 修订(2026-10-21 晚):去掉"待批段"这个彩色分区,改成**一条列表**

维护者看过落地效果后的原话：「**UI 方面你可以通过 ComputerUse 自行截图分析 然后希望你参考一下 dribbble 上一些 UI 的审美 避免奇怪的设计**」「**我这里说的是执行历史这个弹窗**」。

**问题**：`一层框 + 待批段(2px 强调左条 + 浅强调底)` 依然"怪"。原因是**分区本身就是多余的** ——
现代这类面板(Linear / Height / Notion 的通知栏)都是**一条行列表**，用**行内的状态图标**表达状态，
只用分隔线分组。**一条彩色左条 + 一整块浅底**在窄面板里读起来像"错误提示条" ✗。

**决定（v2）**：

1. **只有一条列表**：待批那一项就是**第一行**，和其它运行记录**同一个行高(44px)**，靠
   **行首的状态图标**(⚠ / ⟳ / ✕ / ✓)与**行尾的次要信息**区分，**不再有彩色分区** ✗；
2. **正文默认折叠**：行内只留**标题 + 一行摘要**；点这一行**就地展开**（accordion），
   展开体里才是正文（`40vh` 限高滚动）+ 备注 + 按钮；
3. **按钮**：展开体底部**右对齐**，主按钮实心、次按钮 `ghost`（**不再有边框** ✗）；**不用 sticky** ✗ ——
   因为展开体本身就是"用户主动打开"的，滚到按钮是天经地义；
4. **行内元素**：图标 16 / 标题 13(500) / 次要 11(400)；行尾耗时与徽章 11，右对齐；
5. **分隔线**：行与行之间**不画线**（靠 44px 行高与 hover 底色分组）；只在**列表与展开区之间**画一条；
6. **颜色**：面板底 + hover 底 + 选中底，**三档，不再出现第四种**；强调色只给**主按钮与行首告警图标**。

**自查**：改完用 Computer Use / agent-browser 截图，**320 / 480 / 720 三种宽度**，深浅色各一张，
问三句：「有没有两条边在说同一件事」「有没有第二种间距刻度」「强调色用了几处」。

## 修订 v3(2026-10-21 夜):确认卡**不再单独占一段**,放进它实际卡住的那一步里

维护者原话：「**确认卡请你放到实际的那一步的内部即可**」。

现在「这一步在等你确认」是列表**上方**独立的一段 —— 但它说的其实就是**某一次运行的某一步**
（`job-run` 里那行「等人确认」、状态 `pending`）。单独一段等于把同一件事说了两遍：
上面一张卡 + 下面一行"等人确认"。而且待批段一高，就把列表挤下去（之前所有滚动问题都由此而来）。

**决定**：

1. **删掉顶部待批段**（`RunApprovalNotice` 不再是 aside 的独立子项 ✗）；
2. **确认卡挂到那一步的行内**：列表里点开那一次运行 → 详情里「等人确认」那一行**本身就是折叠的卡** ——
   点它展开 → 里面是 正文 / 备注 / 确认·拒绝 按钮；**收起时那一行和别的步骤行一样高（44px）**；
3. **列表行只给一句状态**（「等待确认：…」+ 耗时 ✓，不再重复正文 ✗）；
4. **没有待批时**那段自然不存在 ✓（不再有"整块消失"的特殊分支 ✓）；
5. 滚动结构沿用 v1 已验证的性质 ✓：**面板根唯一滚动** + 头部 sticky + 正文 `40vh` 限高 ✓。

**为什么这样更好**（写给下一轮，别再绕）：
- 一件事只说一遍 ✓；
- 待批卡的高度**只影响它自己那一行** ✓，不会再挤掉列表 ✓；
- "它在哪一步停的"由**位置**回答 ✓，不需要一段专门的标题来说明 ✓。

**实施注意**：详情区的步骤行现在是列表 ✓ —— 要把 `RunApprovalRow` 渲染在 `node_id === 那一步` 的行内 ✓，
并且**保留** v1 那五条实测性质 ✓（根滚动 / 头部 sticky / 按钮可达 / 行高 44 / 无第二圈边 ✓）。
