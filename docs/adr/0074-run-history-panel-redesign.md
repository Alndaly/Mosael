# ADR 0074 · 「执行历史」面板重写：一层框、三段落、一条分隔线

- 状态：Accepted — 2026-10-21
- 取代：此前 8 次逐层微调（`aea76382c` … `0c59ef28e`）。那些提交都在**挪边、挪底、挪滚动**，
  每一次修好一处、弄坏另一处 —— 根子不是某一层写错了，而是**层次本身太多**。

## 问题

面板里同时叠了四圈边和三块底：待批段的玻璃面 → 卡片的边与底 → 正文区的边与底 → 按钮行的底。
于是：

- 看上去"框套框"，同一条边被画两次以上；
- 内容一长就撑出面板，按钮被裁掉（滚动写到哪一层都不对，因为**外框的 `overflow-hidden`
  和面板自己的 `overflow-y-auto` 是同一条 CSS 属性**，谁赢取决于 Tailwind 生成顺序）；
- 每一格的内边距各写各的，行的节奏不统一。

## 决定

**一个面板，三段落，一条分隔线。** 具体六条硬规矩：

1. **只有一层框**：面板一层 `rounded-xl border`；**里面任何块都不许再画整圈边** ——
   最多用「**左边条**」（待批段）或「**一条分隔线**」（段之间）。
2. **只有三块底色**：面板底、待批段的「浅强调底」、选中行的「强调底」；其余一律透明。
3. **间距只有三种**：段间 12px、段内块间 8px、行内 4px。不再出现第四种刻度。
4. **行高统一 44px**：列表行、步骤行都一样；状态徽章与耗时**右对齐**。
5. **滚动只有一个**：**面板根**滚 + 头部 `sticky top-0`；正文区保留它自己 `40vh` 的限高滚动
   （那一处是刻意的：整篇稿子不该把按钮推走）。外框**不许**再写任何 `overflow-*`。
6. **待批段永远在顶**，不被列表挤走；没有待批时这一段整块消失（不占位、不留线）。

### 两个待批段的形态（维护者选定）

- **左边条 + 浅底** ✓（不用整块卡片的边）；
- **详情默认展开**最后选中的那次运行 ✓（不是等用户点）。

## 布局

```
头 44px sticky：⟳ 执行历史 · 计数 · 悬浮/关闭
待批段：2px 强调左条 + 浅强调底；标题 / 正文(折叠 6 行 + 展开) / 元信息 / 备注 / 按钮右对齐
──────── 一条分隔线 ────────
运行列表：44px 行；图标 16 + 标题 13 + 右侧状态徽章 11；时间/版本作次要行
──────── 一条分隔线 ────────
选中运行的详情：步骤行 44px；耗时右对齐；当前步骤高亮
```

## 后果

- 面板的"层次"从四边三底压到一边三底，**跨层重复的视觉信号消失**；
- 滚动责任唯一（面板根），**不再依赖任何中间层的 `flex-1`**；
- 行高与内边距由一套刻度决定，**加行不会破坏节奏**；
- 强制约束：`tdd` 之外还要有 **DOM 级断言**（面板根是唯一滚动容器、里面没有第二圈 `border`）。

## 教训（写给下一次）

**先定"哪一层负责边、哪一层负责底"，再动手。** 一次反馈里连改三层，必然修一个坏一个 ——
这块 UI 因此连改八次。设计没定下来之前，**不要开始改样式**。
