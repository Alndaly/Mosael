# ADR 0091 · 参考库:外部图集只读接入,姿势与服装进资产库

- 状态:**已采纳**(2026-11-01)。维护者 2026-10-31 提出:「这个网站的资源对生图似乎有非常大的帮助,构思一下可以如何接入 ——
  是否可以重构优化、扩充资产库的概念」(看到 [RuiC-PoseAtlas](https://hruiccc.github.io/RuiC-PoseAtlas/) 后);
  草案写成后让「变速部分完成之后开始做 ADR 0091」。文末待拍板四项:1、2、4 按本文推荐执行;
  3 由维护者 2026-11-01 定:「仅仅是引用的情况下是不违反协议的」—— 插件只引用原站、不带图、不镜像,
  属于「参考与创作使用」,不是再分发;插件照常进插件市场(见 §7 修订)。
- 关联:ADR 0027(资产库)、ADR 0012(生成能力目录与声明)、ADR 0033 / 0034 / 0035(目录类能力、模型库、工作流库)、
  ADR 0038 §9(NSFW 判断与预览图设置)、ADR 0067 / 0068(引用即发送)、ADR 0029(3D 场景当生成参考)、ADR 0026(社区)。

## 背景

### 那个网站给了什么

RuiC-PoseAtlas 是一个纯静态的图集(GitHub `hruiccc/RuiC-PoseAtlas`),整理自日本作者公开的三个项目,分三本:

| 图集 | 规模 | 画面 | 数据 |
| --- | --- | --- | --- |
| 姿势 | 288 组 / 1,439 张 | 去脸灰色人台线稿(3:4),每组五个视角:正面、斜侧、侧面、俯视、仰视 | `data/poses.json`:编号、系列、分类(站 / 坐 / 跪趴 / 卧)、中英日三语名称、每个视角的缩略图与原图路径 |
| 服装 | 1,407 套 | **没有人体**的整身穿搭(2:3) | `data/costumes.json`:八个分类、十个品类、主色、单品标签(颜色、材质、版型、配饰,三语) |
| 人像 | 1,499 张 | AI 生成的虚构人物(4:5),脸部 893 / 造型 606 | `data/faces.json`:分区、发型、风格、尺寸 |

全部是 AI 生成的虚构参考素材。对生图有用的地方很具体:**姿势定构图、服装定造型**,而且每一项都带着能直接检索的
三语名称和细颗粒标签 —— 人可以按「抱膝坐」「三分之四侧」找,智能体也可以。

### Mosael 这边缺的两块

ADR 0027 把「素材」(文件)和「资产」(有名字的东西)分开了,资产目前三种:人物、场景、道具
(`domain/entities/catalog.py` 的 `KINDS`)。拿这份图集一对,缺口有两个:

1. **少了两种「套在任何人物身上」的参考。** 一个姿势不是一件东西,是一种体态 —— 张三能摆,李四也能摆;
   一套衣服也是。今天想让张三摆某个姿势,只能把那张线稿当普通「参考图」挂上,而参考图的语义是
   「照着它的风格和主体来」(`backend/app/ai/providers/contracts/generation.py` 的 `REFERENCE_IMAGE`),于是灰色线稿的画风也跟着进了成片。
2. **没有「外部参考目录」这一层。** 资产全是工作区自有、可编辑的。一份几千项的外部图集不该被整批导进每个工作区:
   它应当**只读、可浏览、可检索**,用到哪一张才取哪一张,并且记得它从哪来。

### 两个约束,决定了能怎么接

- **许可。** 仓库是 MIT,但 LICENSE 的 SCOPE NOTICE 写明 MIT 只覆盖代码;**图片、原始名称与分类数据不在其内,
  版权归原作者**(姿势、服装:ギア @giaaibusi;人像:あぎ @agi_aibusi),「仅供参考与创作使用,禁止再分发、
  转载或转售图片数据本身」。人像原站是 CC0,但原站请求不要转载图片文件。
  → **Mosael 不能内置这些图,不能镜像到 R2 / Cloud / 社区,也不能做成「官方资产包」。**能做的是:在用户本机、
  由用户发起,从原站浏览和取用,标明出处;取进工作区的那一份供他自己创作用。
- **内容。** 姿势里「性感」一系列 80 组,部分名称带明确的性暗示;服装有「性感」「内衣」两类;另有「双人」55 组。
  这些必须走现成的 NSFW 处理,而不是另起一套。

## 决定

### 1. 资产按两个维度看:是什么 × 从哪来

| | 工作区自有(今天的资产库) | 外部参考目录(新) |
| --- | --- | --- |
| 人物 / 场景 / 道具 | 有 | —— |
| **姿势**(新) | 有:自己存的、从目录取进来的 | 有:例如 PoseAtlas 的姿势图集 |
| **服装**(新) | 有 | 有:例如 PoseAtlas 的服装图集 |

「从哪来」不是资产的一个字段,而是**两个地方**:资产库照旧是工作区里的那一份;参考库是插件提供的只读目录,
取用时才在工作区里落下一份素材(和可选的一个资产),并带着出处。

### 2. 两种新资产:姿势、服装

`KINDS` 加 `pose`、`costume`。它们和人物 / 场景 / 道具共用 `entities` 与 `entity_references` 两张表,
**不建新表**;老数据不受影响(没有任何已有行要改形状),所以不需要数据迁移,只放开接口里种类的取值。

- **姿势**:提示词描述写体态本身(「坐姿,抱住一侧膝盖,背部后仰」);参考图按**机位**标角度。
  今天的角度词表里有 `front`、`side`,缺的三个加进 `ROLES`:`three_quarter`(斜侧)、`high_angle`(俯视)、
  `low_angle`(仰视)。专有字段:体位(站 / 坐 / 跪趴 / 卧)、人数(单人 / 双人)。
  挑参考图的先后(`ATTACH_PRIORITY`)对姿势**跟着这一镜的机位走**:先挑与镜头角度相同的那一张,没有再按
  正面 > 斜侧 > 侧面 —— 姿势参考的价值在「同一个机位下长什么样」。
- **服装**:提示词描述写单品(颜色、材质、版型、配饰);参考图角度用 `front`、`back`、`detail`。
  **「给张三换上这套」= 在张三下面建一个变体**(ADR 0027 §1 的变体机制):变体继承张三的提示词描述与音色,
  参考图里多一张这套服装,服装描述并进变体的提示词。服装资产本身不挂在任何人物下,可以反复套。

### 3. 外部参考目录:一项新的目录类能力 `reference_library`

和 `model_library`、`workflow_library` 同一族(ADR 0033 §1:目录类能力不进工具表),加进
`mosael_formats.plugin_manifest` 的 `CATALOG_CAPABILITIES`。认领它的工具按 `op` 回答:

| `op` | 回答什么 |
| --- | --- |
| `collections` | 这个目录有哪几本(姿势 / 服装 / ……),每本的种类、条目数、筛选维度(分类、视角、颜色……) |
| `search` | 按关键词与筛选翻页列条目;关键词跨语言命中(三语名称、标签) |
| `item` | 一个条目的全部:三语名称、标签、每个视角的缩略图与原图地址、`nsfw` 及依据、出处 |

每个条目都带**出处**:原作者、原始链接、许可说明(一句人话,例如「仅供参考与创作,禁止再分发」)。
宿主在每一处显示条目的地方都把它摆出来,不靠插件自觉。

宿主侧:

- **参考库**是资产页里的第二个页签(「资产库 | 参考库」),也出现在生成表单、画板和智能体挑参考的地方。
  浏览时只拉缩略图,缓存在本机,走普通的 HTTP 缓存。
- **取用**是单条、由人发起的:点「用这一张」或「存为资产」时,宿主才把原图下到工作区,成为一份素材,
  素材记下出处(目录、条目 id、原链接、作者、许可说明);「存为资产」再在其上建一个姿势 / 服装资产。
  **不做整本导入。**
- **出处就是边界**:带外部出处的素材与资产**不能进社区分享包**(ADR 0027 §4 的 `mosael.asset/1`),也不会被
  Mosael Cloud 同步;分享时说明「这几张来自外部参考库,不随包分发」,接收方自己从目录里取。

### 4. NSFW 走现成的那一套

条目的 `nsfw` 由插件按数据给出(PoseAtlas:姿势的 `sexy` 系列、服装的「性感」「内衣」两类),宿主按
ADR 0038 §9 已有的预览图设置(`show` / `blur` / `hidden`,`modelPreviewSettings`)处理:默认模糊,
可以在同一个设置里改成隐藏或显示。参考库**不另起一个开关**。条目名称里的露骨措辞同样按这一档处理(模糊时只显示编号)。

### 5. 生成时:新增素材角色 `pose_reference`

`SOURCE_ROLES` 加 `pose_reference`:**只约束体态与构图,不传画风和长相**。它和 `reference_image` 必须分开,
理由与 `first_frame` 和 `reference_image` 分开相同 —— 混成参考图的话,灰色人台的线稿画风会被照搬进成片,
而用户看不出哪里不对。

- **由模型声明收不收**(ADR 0012 的描述符)。ComfyUI 的工作流把它接到 ControlNet:线稿可以直接走 lineart,
  或者在工作流里先过 DWPose 预处理再走 OpenPose —— 预处理是工作流的事,宿主只交图。
- **不收的模型不悄悄降级。** 按 ADR 0068 的能力闸:提示词里 `@` 了一个姿势、而这个模型不收 `pose_reference` 时,
  当场说清楚,并给一个明说的选项「改成参考图发送(线稿画风可能会带进去)」;不自动替人改角色。
- **组合引用**:`@张三 @坐姿P024 @服装SXY-0039` 分别展开为张三的提示词描述与参考图(`reference_image`)、
  姿势按机位挑出的那一张(`pose_reference`)、服装的参考图与单品描述。展开沿用 `domain/entities/mentions.py`
  的那一处,按种类各取各的,ADR 0067 / 0068 的「引用即发送」照旧成立。

### 6. 智能体与画板

- 智能体多一个宿主工具 `search_references`(读 `reference_library`,返回条目摘要与出处,不下图);
  `create_entity` / `attach_entity_reference` 接受两种新资产。「从主题到完整视频」可以按分镜挑姿势。
- 画板上的资产格认两种新资产;姿势格连到生成格时,默认角色是 `pose_reference`。

### 7. PoseAtlas 本身怎么接

做成一个~~可安装、不内置~~**随应用内置**的插件(`dev.mosael.poseatlas`,修订 2026-11-01:维护者「这个插件作为内建插件吧」,
放在 `plugins/bundled/` 下,随应用装好、卸不掉,不用连接时停用即可):认领 `reference_library`,
从原站读 `poses.json` / `costumes.json` 与缩略图,在插件自己的数据目录里缓存;只接姿势与服装两本。

~~**上架官方插件市场之前,先取得许可。**~~ **修订(2026-11-01)**:维护者判断「这种情况下其实也不是分发,
仅仅是引用的情况下是不违反协议的」。插件包里没有一张图,浏览时显示的是原站的缩略图,取用时从原站下用户选中的那一张、
只进他自己的工作区 —— 和用户自己打开原站下载同一件事,落在原作者写明的「参考与创作使用」之内。插件因此照常进
`registry.json` 和插件市场;README、条目出处、素材的 `external_source` 都写着原作者、原站和「禁止再分发图片本身」。

## 不做(以及为什么)

- **人像那一本不接。** 它和人物资产高度重叠,又涉及肖像:虽然是虚构人物,原站仍请求不要转载;人物资产已经有
  真人 / 虚构声明与授权那一套(ADR 0027 §4),不必为一份外部人像库再开一条路。
- **不在 Mosael 的任何服务器上存这些图**(R2、Cloud、社区),也不随安装包分发。
- **宿主里不做骨架提取。** 从线稿抽 OpenPose 骨架是 ComfyUI 工作流的事;把姿势变成 3D 白模里人偶的关节
  (ADR 0029 的人偶)要先有关键点,另起一份 ADR。
- **不做整本导入。** 几千项一次塞进工作区,和 ADR 0036「中间产物不进素材库」是同一个问题:人找东西时被淹没。

## 实施步骤

1. **许可**:联系作者(维护者)。不阻塞 2、3,阻塞 5 的上架。
2. **资产两种新种类**:`KINDS`、`ROLES`、`ROLES_BY_KIND`、`ATTACH_PRIORITY` 与接口校验放开;资产页、资产格、
   `@` 展开认得它们;服装「换上」生成变体。
3. **素材角色 `pose_reference`**:加进 `SOURCE_ROLES` 与描述符;ComfyUI 工作流表单能把一个输入标成它;
   能力闸与「改成参考图发送」的明说选项。
4. **`reference_library` 能力与参考库界面**:清单格式、宿主路由、缩略图缓存、单条取用与出处、NSFW、
   分享包排除外部出处。
5. **PoseAtlas 插件**:先作为示例插件;许可到位后再进插件市场。
6. **智能体工具** `search_references`,以及「从主题到完整视频」按分镜挑姿势。

每一步各自一个提交、各自带测试;2、3 不依赖 4、5,可以先做(自己画的姿势、自己拍的服装照样用得上)。

## 实施记录

- **改为内置(2026-11-01)**:维护者「这个插件作为内建插件吧」。目录从示例挪到 `plugins/bundled/poseatlas`,随应用装好、卸不掉;
  它有配置项(成人内容开关)又要联网权限,所以和 MinerU 一样**不自动建连接**,每个人在插件页接一次(授予 `network:github`)。
  参考库的空态因此改成直接指路:「随应用内置的 PoseAtlas 在插件页接一下就能用」,并带一颗去插件页的按钮。

- **取用按视角(2026-11-02)**:`fetch` 协议加 `role`(取哪个视角,空 = 第一张)。「存为资产」此前只取第一张,姿势资产只有正面,
  而姿势按机位挑图 —— 斜侧、俯拍的镜头里永远发不出去;现在每个视角各取一张、按视角挂成参考图(第一张当封面)。
  「用作素材」取详情里选中的那一张,智能体的 `use_reference` 用 `angle` 点名。顺带:取进来的名字跟着读的人的语言
  (`reference_library.display_name`,确认卡同一个),素材不再整份复制两遍,插件交回的形状不对时照实说而不是 500,
  `search_references` 的 `limit` 是总数。资产页没有参考库连接时整块不出现(7b23152b2),参考库视图里那块
  「去插件页接一个」的空态因此走不到,删掉。PoseAtlas 0.2.0。
- **补齐每个生成入口(2026-11-02)**:审计发现姿势参考只在 AI Studio 接通了 —— 画板生成格、工作流「AI 生成素材」节点、
  智能体 `generate_image` / `generate_video` 都不发机位,而漏斗没有机位就不挂姿势,这三处 `@` 姿势永远发不出去。
  改为一个共同形状 `entities.mentions.PoseUse`(`shot_angle` + `as_reference`):生成接口的 `pose`、画板生成表单的 `pose`、
  工作流节点的「这一镜的机位」「姿势当参考图发」、智能体工具的 `shot_angle` / `pose_as_reference` 交的都是它;
  `create_generation_job` / `attach_entities` 只收这一样。「机位」词表收成 `entities.shot_angles` 一处,3D 场景镜头的字段改名
  `shot_angle`(和故事板 schema 里摄影术语的 `camera_angle` 分开),「按文字搭 3D 场景」的布景 schema 也让模型逐镜标它;
  老场景和老生成记录由迁移 `shot-angle-replaces-camera-angle` 改到新名字。回执里没发姿势的两种原因(没选机位、
  这个姿势没有这一机位的图)补上了界面文案。
- **第 6 步(2026-11-01)**:智能体两个工具,只发给接了参考库的人(`needs="reference_library"`)。
  `search_references`(只读):在这个人每个参考库、每本图集里找,返回名字、标签、机位、缩略图和出处;**标了成人内容的
  条目一条都不交给智能体**(循环在领域层 `reference_library.search_everywhere`,工具只是转一手)。

- **第 5 步(2026-11-01)**:插件 `dev.mosael.poseatlas`(先放在示例目录,同日改为内置,见下一条)。纯标准库进程插件,认领

  `POSEATLAS_ADULT` 控制,默认关、关着时根本不返回;打开后标 `nsfw`。插件包里没有图。
