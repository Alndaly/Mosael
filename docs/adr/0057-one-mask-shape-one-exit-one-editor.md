# ADR 0057:蒙版重构 —— 一种数据形状、一个写出口、一个编辑器

## Status

Accepted — 2026-10-14。维护者提:「彻底重构蒙版能力,重新设计『画蒙版』弹窗」,并报了一个缺陷:
「ComfyUI 工作流的完整表单传不了蒙版,精简表单可以」。本 ADR **修订 ADR 0056**:决定 1(契约)、
决定 2(蒙版和源图是一对)、决定 4(表单只挑已有节点)、决定 5(编辑落成素材、不存笔触历史)照旧;
决定 3 里「编辑器不做扩张 / 收缩」那一句作废(见下面决定 3);决定 6 的后端那一步并进统一的写出口。

## Context

读代码时看到的是**同一种东西有两种形状、三个入口**:

| 谁产出蒙版 | 走哪条路 | 存下来是什么 |
| --- | --- | --- |
| 编辑器(画出来的) | `POST /api/assets/import`,表单里带调用方自己说的 `derived_from=[{op:"mask"}]` | 浏览器 `canvas.toBlob` 出的 **RGBA** PNG;文档长边封顶 4096,源图更大时**尺寸和源图对不上** |
| 素材库「生成蒙版」 | `POST /api/assets/{id}/mask` | 后端 `L` 模式 PNG、和源图同尺寸 |
| 智能体 `create_mask` | 同上那个领域函数 | 同上 |

后果:

1. **两种形状**。RGBA 那份的 alpha 恰好全满,所以今天能用 —— 但它靠的是编辑器里那套"每次写都验一遍不透明"
   的守卫,而不是数据本身(`L` 模式的 PNG 根本没有 alpha 可以出错)。尺寸对不上的那份到了局部重绘节点要靠
   工作流自己缩放。
2. **导入接口多了一道后门**。`derived_from` 是为蒙版加到通用导入上的:任何调用方都能把任何文件说成"从那张图
   画的蒙版",既不归一、也不查那张源图看不看得到。
3. **编辑器缺东西**:不能缩放 / 平移(大图上画不了细处),没有扩张,三节控件挤在一条右栏里、取消 / 保存也在
   右栏底,工具和参数分不清。
4. **完整工作流入口填不了蒙版**。AI Studio 通用那一栏按模型种类手列素材角色(图像只列参考图),提交那一半
   却按 `SOURCE_ROLES` 全量发 —— 描述符声明了蒙版、手列里没有,于是完整入口那一格**根本画不出来**;精简表单
   那一栏按表上的角色画,所以能填。插件那一侧两个入口走的是同一条 `wire_inputs`,没有差别。

## Decision

### 1. 一种数据形状

**蒙版素材 = 一张 `L` 模式(单通道、没有 alpha)的 PNG,白 = 要改的地方。** 有源图时:

- **像素尺寸和源图一模一样**(按 EXIF 摆正之后的那个尺寸 —— 浏览器显示的就是摆正的);
- 出处 `derived_from = [{asset_id: <源图>, op: "mask"}]`;
- 名字「蒙版 · <源图名>」。

没有源图(新建一张空白蒙版)时尺寸就是它自己的,不带出处,名字「蒙版 · 空白」。源图只能是**图片**:
编辑器只画得出图片底图,视频的局部重绘不在这一版里。

### 2. 一个写出口

`app/domain/assets/masks.write_mask_asset` 是**唯一**登记蒙版素材的地方:落 `L` 模式 PNG、按决定 1 起名、
记出处。上游只有两种生产者,各自把像素交给它:

- **画出来的**:`POST /api/assets/masks`(表单:`workspace_id`、可选 `source_asset_id` / `project_id`、文件)。
  后端把上传的图**归一**成决定 1 的形状:按契约读**红通道**(透明的地方当黑 = 不改),尺寸不同就按双线性
  缩放到源图尺寸。编辑器在浏览器里只管画,不再自己负责"导出的 PNG 合不合契约"。
- **按配方算的**:`POST /api/assets/{id}/mask`(阈值 → 反选 → 扩张/收缩 → 羽化)与智能体的 `create_mask`,
  算出单通道字节后交给同一个出口。

`POST /api/assets/import` **不再收 `derived_from`**:它只为蒙版而加,留着就是第二个写出口。

### 3. 一个编辑器

`components/generation/MaskEditor` 是唯一的画蒙版组件(AI Studio 的蒙版槽从这里进,别处要画蒙版也用它)。

- **文档与视口分开**。文档 = 源图的像素网格(长边封顶 4096,只为浏览器的画布内存;出口会缩回源图尺寸);
  视口 = 一台相机(缩放 + 平移),底图永远按原始比例画。适应窗口 / 100% / 放大缩小 / 滚轮、捏合、空格拖动、
  中键拖动都只动相机,不碰像素。滚轮的语义跟随全局的画布操控方式(触控板:双指平移、捏合缩放;鼠标:滚轮缩放),
  只读不改(见 `canvasInputMode`)。
- **工具**:画笔、橡皮、矩形、椭圆;**命令**:撤销、重做、反选、清空、扩张 / 收缩、羽化、从底图按亮度 / 透明度起手。
  每条命令一步撤销。
- **扩张在编辑器里做**(作废 ADR 0056 决定 3 那一句):维护者要的就是在画的地方调边缘。扩张和羽化是一次"应用到
  蒙版"的破坏性操作,先扩张再羽化 —— 和后端配方同一个次序;不引入非破坏的属性栈(ADR 0056 决定 5 照旧)。
- **像素运算只有一份规则**:阈值、反选、扩张、羽化在 `lib/maskPixels`(前端)和 `app/media/masks`(后端)
  各有一份实现,由 `contracts/mask-cases.json` 逐字节钉成同一个结果 —— 扩张从此两侧都跑。
- **版式**:画布占满主体;画布上方一条浮动工具条(`CanvasToolbar`,`sm` 档:工具 | 撤销重做 | 反选清空 |
  缩放);右侧一栏参数按「画笔 / 边缘 / 从底图起手 / 显示」分组(`md` 档);底栏左边是尺寸与缩放、右边是唯一的
  主动作「存成蒙版」。

### 4. 素材角色只有一条路

AI Studio 通用那一栏画哪几格素材,和提交发哪几格是**同一个判据**(描述符声明了这个角色:
`lib/sourceFrames.panelSourceRoles`),每一格都经同一个 `sourceField` 画。精简表单和通用那一栏只在
「哪几个角色、什么次序」上不同,控件(包括蒙版的「画一张」)是同一个。

## 迁移

库里已有的蒙版(出处里有 `op = "mask"` 的图片素材)在启动时归一成决定 1 的形状(迁移步骤
`migrate-mask-files-are-one-shape`,文件系统那一相):读红通道、透明当黑、按源图尺寸缩放、写回 `L` 模式 PNG,更新 `media_info` 里的
宽高与大小,重做缩略图。已经是那个形状的跳过;文件不在的跳过 —— 可以重复跑。

## Consequences

- **好处**:蒙版是什么只有一句话可说;拿到一张蒙版素材不用再猜它有没有 alpha、尺寸对不对得上;编辑器能在大图上
  画细处;同一张工作流两个入口填蒙版的能力一样。
- **代价**:画出来的蒙版多一次上传后的解码与缩放(一张 4096 的图几十毫秒);导入接口少了一个参数(只有编辑器在用)。
- **需要记住的**:契约仍然是**黑白图 + 红通道**。新的蒙版生产者一律交给 `write_mask_asset`,不要另起一条
  `register_file_asset(..., derived_from=derived(MASK, …))`。
