# ADR 0036:中间产物不进素材库 —— 素材记着自己是不是工序的零件

## Status

Accepted — 2026-10-05。

## Context

维护者报上来:「素材页面打开非常慢,因为素材过多的原因吗?」

查下来是两件事叠在一起:

- **列表不分页**。`GET /api/assets` 一次交回整个工作区的每一份素材、带着完整的 media_info,素材页把它们一次全画出来,
  筛选、排序、计数全在浏览器里做。(分页、虚拟化是同一轮的另外两个提交,不在这份 ADR 里。)
- **素材库里大半不是素材**。真实的库 1228 份,1009 份叫「zh-TW-HsiaoChenNeural · 配音」这样的名字:字幕配音一条字幕配
  一段音频,每一段都登记成一份素材。它们是配音这道工序的**零件** —— 时间线、配音轨要用它们,人在素材库里找东西时
  不需要,而且一千份名字一模一样,根本没法挑。

同样形状的还有:对口型(ADR 0028 阶段 3)切出来交给改口型的原片块、配音块和改好口型的块;长稿分段配音拼进一段之前的
那一句一句。导出的成片、AI 工作台里单独念的一段、分离出来的人声和背景音、白模的首尾帧,都是人要的结果,不算。

现有的概念都对不上:

- `source`(tts、generated、exported……)说的是**怎么来的**:同样是合成(tts),字幕配音的一句是零件,AI 工作台念的
  一段是结果。
- `derived_from`(ADR 0027 前后加的出处)说的是**从哪来**,导出的成片也有出处。
- 代理文件(`proxy_key`)根本不是素材行,是素材目录里的附属文件。
- media_info 里的 `dub_line`(那一句念的什么、谁念的)是给改口型认句子用的缓存键,而且是近来才写的 —— 拿它当判据,
  更早的那些就认不出来。
- 「角色」(role)这个词在生成那边已经是「这份素材挂在哪个槽上」(首帧、参考图……),再拿来说这件事会混。

## Decision

### 1. 素材行上记着它是不是中间产物、是哪一种

`assets.intermediate`(字符串,非空):空串是素材库里的正常素材;否则是中间产物的种类,取值收在
`domain/assets/intermediates`:

| 取值 | 是什么 |
| --- | --- |
| `dub_line` | 逐句配音的一句:字幕配音给每条字幕合成的那一段;长稿分段配音拼进一段(或补过静音)之前的那一句 |
| `lipsync_chunk` | 对口型的一块:切出来交给改口型的原片块、配音块,和改好口型、还没接回整段的那一块 |

### 2. 谁做零件,谁在登记时说

不靠名字、不靠 media_info 里的标记事后去猜:

- `register_file_asset(..., intermediate=...)`:对口型切块时直接说;
- 合成是公共服务,`start_synthesis(intermediate=...)` 写进任务,合成登记产出时照它登记 —— 字幕配音给每一句都这么排;
  AI 工作台、智能体、工作流里单独念的不说,照旧进素材库;
- 登记时说不了的(改好口型的块由生成漏斗登记;长稿分段要等分好组才知道哪几句被拼掉),由那道工序在它知道的那一刻标上。

### 3. 默认不列,点名才列,按 id 照常用

- 素材库列表、各种类数量(`GET /api/assets`、`/api/assets/facets`)默认只算素材库里的;`intermediate=dub_line` 只看那一种。
  数量那边另交回每种中间产物各几份。挑素材的弹窗、剪辑台素材池、智能体的 `list_assets` 都走这一条,所以都默认不列。
- 时间线、监视器、检查器按时间线取它用到的素材(`GET /api/sequences/{id}/assets`),详情按 id 取 —— 中间产物照常在。
- 素材页类型页签旁边一枚「配音片段 985」,按下去看的就是它们:上面一句话说清它们是什么、时间线上照常在用,一键回到素材库。
  它是「这一刻在看什么」,不记住。逐句配音的一句名字都一样,卡片上写着念的那句话,也按这句话搜得到。

### 4. 老数据一次迁移

`migrate-assets-know-if-they-are-intermediate` 加列和索引(工作区 + intermediate + 导入时间,素材库列表正好按它筛、按它排);
`backfill-intermediate-assets` 把推得出的标上:记着 `dub_line` 的;更早的、由字幕配音任务派出的合成交回的,或放在配音轨上的
合成音频;是另一段合成音频的拼接 / 补静音出处的合成音频;记着对口型块键的;来源 derived、出处是截取 / 混音的(只有对口型
这样登记过)。推不出的留在素材库。真实的库上:1009 份「· 配音」里 985 份标成配音片段,24 份是单独念的,留在素材库。

## Consequences

- 素材库回到「人要的东西」:真实的库从 1228 份变成 243 份;配音片段在一个按得到的入口后面,不会让人以为丢了。
- 删一份中间产物和删别的素材一样(时间线上那一段变成脱机占位)。素材页切到配音片段时照样能删、能下载。
- 新的逐条工序要加一种中间产物:在 `domain/assets/intermediates` 加取值,做零件的那一步登记时说,前端「显示」里写上名字和说明。
  漏说的后果是它进了素材库 —— 看得见、改得掉,不是丢数据。
- 「分镜关键帧」这类按需做出、人会挑着用的产物不算中间产物;代理文件不是素材行,不涉及。
