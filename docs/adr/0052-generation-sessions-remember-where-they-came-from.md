# ADR 0052:生成会话记出处 —— AI Studio 分得清哪条是自己在这里开的

## Status

Accepted — 2026-10-09,已实现(见文末「实现记录」)。体检 UC-03 的长远修法;UC-03 的前一半(创作页没选过会话时停在「新的一条」、
「+」草稿先行)已随 ADR 0045 修订之一那批修复做了,这里是「会话记出处」这一半。文末待拍板 1–7(D41–D47)由维护者 2026-10-09
全部照推荐拍板。

## Context

### 之前怎么做的:每跑一次生成,没点名会话的入口都新开一条

`generation_sessions` 只记工作区、主人、标题、分组、连接、模型、种类,**不记从哪来**。生成的漏斗(`generation/operations.py` 的
`_resolve_session`)在调用方不点名会话时现开一条,标题取提示词前 40 字。不点名会话的入口:

| 入口 | 位置 |
| --- | --- |
| 画板格子的「生成」 | `domain/boards/actions.py` |
| 工作流的 AI 生成、补全多角度、人物说话节点(也在画板上的能力、资产详情页上跑) | `domain/workflows/executors/subjobs.py`、`entities.py`、`talking.py` |
| 定时任务 | `domain/scheduler/executors.py` |
| 智能体的出图、出片、出音乐、念字、播客(批准确认卡之后) | `domain/agent/confirmable/generation.py` |
| ComfyUI 工作台的「运行」 | `domain/workflow_library.py` 的 `run_canvas` |

AI Studio 的会话列表按 `updated_at desc` 列全部会话,看不出哪条是用户在这里开的、哪条是画板那一次。维护者库里(2026-10-08,只读查的)
生成会话 65 条,60 条恰好只有一次生成 —— 绝大多数是上面那几个入口每跑一次开的。

### ADR 0044 已经有「地方」这个概念

对话记着家(`home_kind` + `home_id`),AI Studio 和各处面板按家分;0044「这一版不做」明写了生成会话不在此列。生成会话的出处和对话的家
说的是同一类事:**这条线程是在哪一处开出来的**。

## Decision

### 1. 记出处:和对话的家同一个形状(D41)

`generation_sessions` 加两列:`origin_kind VARCHAR(16) NOT NULL DEFAULT 'studio'`、`origin_id VARCHAR(700) NOT NULL DEFAULT ''`,
建的那一刻定、之后不变;不设外键(一列指几种表,要的正是「东西删了,会话照旧」)。取值(`domain/generation/origins.py`):

| `origin_kind` | `origin_id` | 谁写 |
| --- | --- | --- |
| `studio` | 空 | 创作页自己开的 |
| `audio_page` | `speech` / `podcast` | 「以前的语音 / 播客」(ADR 0055 的迁移并进来的那两条) |
| `board` | 画板 id | 画板格子的生成、画板上跑的能力 |
| `workflow` | 工作流 id | 工作流里的生成类节点 |
| `entity` | 资产 id | 资产详情页的「补全多角度」「生成表情」「说话」 |
| `schedule` | 定时任务 id | 定时任务 |
| `agent` | 对话 id | 智能体的生成工具 |
| `comfyui` | `<连接 id>/<路径>` | ComfyUI 工作台的「运行」(和 0044 的 `comfyui` 地方同一种写法) |

漏斗 `create_generation_job` / `voiced.create_speech` / `create_podcast` 收一个**必传**的 `origin`,每个入口说自己是哪儿,漏斗不猜。
工作流执行器按作用域定:`RunScope.id` 是 `board:<id>`(画板上的能力)、`entity:<id>`(资产详情页)或工作流 id。

### 2. 一个出处一条会话,不是一次一条(D42、D43)

没点名会话时,别处的生成接着用**这个人在这一处**的那条会话(`sessions.session_at`),没有才开;创作页没点名照旧每次新开(草稿第一次
提交)。别处开的会话**标题空着**,列表写那一处现在叫什么(画板改了名跟着变);用户改过名就用他起的。智能体那一路按对话分:一段对话里
批准的出图、念字、播客都在一条里。

一处一条**不分族**:锁族是创作页的规矩(ADR 0055 §2),一块画板上本来就有图有歌;会话记着的种类照旧是最后一次的。

### 3. ComfyUI 工作台的运行进生成会话,改名不跟着走(D44)

出处 `comfyui` + `<连接 id>/<路径>`:那台连接上那张工作流的运行都进一条。工作流改了名、挪了文件夹,出处不跟(出处是开的那一刻)——
和对话的家不同(0044 §9 的家跟着挪)。

### 4. AI Studio 的列表:默认只列在这里开的,别处来的收进一组(D45)

创作页左栏上面是 `studio`、`audio_page` 的会话;下面一组「来自别处」默认合着、带个数,展开每一行写那一处的名字;那一处还在就有
「回到那里」(画板、工作流、ComfyUI 那张走对话的家那一套;资产去资产库、定时任务去定时任务页并选中、对话去对话分区)。点开照常看、
照常能接着生成。搜索照旧搜全部,命中了「来自别处」就展开着。两摞**各取一份条数上限**:合在一份上限里的话,老库里几十条一次一条的
别处会话会把用户自己开的挤出列表。

### 5. 老数据按事实归,查不到是 studio,不合并(D46)

迁移看每条会话的**第一条**生成记录(开出它的那一次):

- 任务还在:祖先任务里最近的那个说了在哪跑的(工作流、画板上的能力、资产详情页、定时任务;定时任务跑的工作流归那张工作流),否则看
  任务上的回执(画板格子、智能体的对话),否则是工作台跑的(记录上 `workbench`),否则是创作页开的;
- 任务被「清空已结束」删了:工作台跑的照记录认;确认卡的结果里记着这条记录的,是那段对话;会话只有这一条、它的产出摆在某块画板的
  格子上的,是那块画板(引用表);别的是 `studio`。

老会话不合并(合并要改写生成记录的 `session_id`,而老会话里可能已经被用户接着生成过,合错了说不清),保留各自的标题(提示词开头),
出处写在副标题上。之后同一处的新生成接着用这个人在那一处最近用过的那条。

### 6. 画板 / 工作流删了之后那条会话照留(D47)

标题写「已删除的创意画板」「已删除的工作流」……(和 0044 的家一样),不跟着删。看的人看不见那一处(别人的私有对话、定时任务)时只说
「一段对话」「一个定时任务」,名字和 id 都不给(ComfyUI 的 id 里就是那台机器上的文件路径)。

### 7. 「以前的语音 / 播客」按读的人的语言写,查得到出处的归回去

ADR 0055 的迁移给那两条写死了中文标题。这里标成 `audio_page`(`origin_id` 是 `speech` / `podcast`)、标题清空,界面按读的人的语言写。
那次一并收进来的画板「念出来」、智能体念的(任务载荷上有画板格子 / 对话的回执)挪进那个人在那一处的会话(有就进最近用过的那条,没有
就开一条);查不到的(笔记朗读没记是哪篇)留在原地;挪空了的那条删掉。

## 否掉的备选

- **不记出处,只在 AI Studio 里藏掉一次一条的会话**:「只有一次生成」不等于「别处来的」(用户也会只试一次),藏错了找不回来。
- **别处的生成不建会话**:「再来一次」、脚注、花费都按会话读,留空就从 AI Studio 里消失。
- **复用对话的 `home_*` 两列名**:家会跟着 ComfyUI 改名走,出处不跟;同名不同义更容易混。
- **智能体那一路按对话的家分**:和画板自己跑的混在一起,分不清是谁生成的。
- **老的全记 `studio`**:最简单,但左栏照旧被老的那几十条占着。

## Consequences

- AI Studio 的左栏不再被画板、工作流的运行刷满;用户自己开的会话在上面。
- 画板、工作流、定时任务每一处有一条会自己长的会话:创作页打开一条会话先取最近 40 条记录,往上点「显示更早的」再多要一页
  (`GET /generation/jobs?limit=`)。
- 「地方」有了两个用处(对话的家、生成会话的出处):按 id 批量取名字的那一半抽到 `domain/place_names`,两边共用;生成那一层不认识
  智能体那一层(智能体的工具要调生成,反过来就成环)。
- 画板的「念出来」、笔记朗读这些配音任务照旧不进创作会话(ADR 0055 只把创作页和智能体的语音记成记录);迁移挪回画板那条的是
  0055 一并收进来的老记录。

## 实现记录(2026-10-09)

- 库版本 14:`migrate-generation-sessions-get-an-origin`(SCHEMA 之前,加列;很老的库这时还没有 `owner_user_id`,索引等下一步建)、
  `migrate-generation-sessions-origin-from-facts`、`migrate-earlier-speech-and-podcast-find-their-origin`(SCHEMA 之后,排在 ADR 0055
  并会话那一步之后、引用表对账之前)。
- 比草稿多出的一种出处:`entity`(资产详情页跑补画、说话的那几个节点,作用域是资产自己,草稿的入口表里漏了它)。
- `GenerationSessionOut` 多 `origin_kind` / `origin_id` / `origin_name` / `origin_state`,名字按看的人现查(`origins.describe_origins`)。
- ADR 0055 §14 留下的「创作页打开一条来自别处的会话时下拉怎么列」:照旧跟着那条会话最后一次的种类那一族 —— 在创作页里接着生成就是
  创作页的规矩(`lock_family`);别处往里放什么种类不受它管。
- 前端:`features/ai-studio/generationOrigin.ts`(标题、副标题、回到那里),`SessionList` 的 `aside`(「来自别处」那一摞),
  创作页按页取记录;定时任务页收「选中这一个」的请求(`OPEN_SCHEDULED_TASK_EVENT`)。
