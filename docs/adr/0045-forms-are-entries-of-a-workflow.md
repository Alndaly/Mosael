# ADR 0045:表单是工作流的入口 —— 完整工作流永远在,名字分主次两层

## Status

Accepted — 2026-10-08,两步都已实现(第一步插件 1.20.0,第二步 1.21.0)。方向由维护者定(见「维护者定的方向」);文末待拍板
1–12 全部照推荐拍板(1–9 第一步、10–12 第二步,都是 2026-10-08);13 另开一项,已由 ADR 0042 那一路做完(ADR 0044 修订:工作台
那一轮只发用得上的工作流工具,长下拉不进定义);14、15 是第二步实现时冒出来的,按推荐做着、待维护者定。两步的实现见文末两节
「实现记录」。

分两步:**第一步**(两层名字 + 把「完整工作流」作为入口加回来,表单入口的 id 现在就定死)不改 ComfyUI 上的存储格式;
**第二步**(一张工作流多张表单)动了存储格式(v2,ComfyUI 上已有的文件由维护者确认一次、整台改写)和两处编辑器。

## Context

### 现在怎么做的:有表单时,表单整个替掉这张工作流

ComfyUI 插件把 ComfyUI 上每张保存的工作流报成两样东西:一个**生成模型**(`op: models`,id 是 `workflows/` 下的路径,如
`krea2-text-2-image.json`)和一个**工具**(`op: tools`,工具名 `wf_<12 位>`,取 ComfyUI 写进图里的 id,改名、挪目录都不变)。
作者可以给一张工作流做一张**表单**(ADR 0038 §2,界面上以前叫「精简表单」「应用表单」,现在统一叫「表单」):挑出几项、起名、排序,
存在这张工作流自己的 JSON 里 —— 图上 `extra.mosael = {"version": 1, "app": {"title", "description", "graph_items"}}`,
节点上 `properties.mosael = {"expose": {<输入名>: {label, order, main?, choices?}}, "result"?: true}`。

有表单时,**表单替掉了这张工作流**:模型 id、工具名还是工作流的,但描述的、跑的都是表单。

| 哪里 | 读的是 | 有表单时 |
| --- | --- | --- |
| 名字 | `graph.Form.named`(`plugins/bundled/comfyui/tools/graph.py`) | 表单标题,没有标题才是文件名去掉 `.json` |
| 生成目录(AI Studio、画板、工作流的生成节点) | `models.catalog` → `graph.describe(…, form_of(entry))` | 只有表单上那几项,按表上的顺序和名字;多一份 `form`(ADR 0038 §4) |
| 跑一次生成 | `run.generate` → `app_form.resolve` | 参数只认表单上的键(存着的别的键丢掉);主提示词只写表单标了 `main` 的那几格;表单里没挑种子时照工作流自己的设定(固定的不换);素材按表单的槽位顺序接 |
| 每张图的工具(工作流节点、画板格子的能力、智能体工具) | `tooling.shape_of` → `models.form_of` | 入参只剩表单那几项,都摆在第一屏;工具的 `label` 是「工作流 · 表单标题」 |
| `list_workflows`、工作流库的「识别出的输入 / 参数」 | `workflows.inspect(…, form)` | 表单那几项 |
| 宿主 | `provider_models.display_name` → `generation_options` 的 `model_label` | 表单标题 |

### 维护者的例子和三个问题

工作流文件 `krea2-text-2-image.json` 上做了一张表单「快速用krea2生图」(提示词 + 画幅两项)。Mosael 里到处叫「快速用krea2生图」,
工作流名看不到了:

1. **认不出是哪张图**:AI Studio、画板里叫表单名,工作流库和 ComfyUI 里叫文件名,两边联系不起来;出了问题不知道该改哪张工作流。
2. **有了表单就拿不到全部参数**:想临时调步数、种子,只能回去改表单。
3. **一张工作流只能一张表单**(存储是一张图一份):同一张图常想要几种用法(「快速出图」只露提示词,「精调」再露尺寸和步数;
   RunningHub 上一张工作流也能发布好几个应用)。

### 否掉的:「工作流名 · 表单名」拼成一个字符串

太长(再加上 ComfyUI 服务器的地址,下拉里放不下);文件名常常不能看(「Unsaved Workflow (2)」);两个概念拼进一个字符串之后,
搜索、排序、分组都只能拆字符串。

### 维护者库里现在有什么(2026-10-08,只读查的)

两条 ComfyUI 连接;有表单的工作流只有一张:`192.168.3.15:8188` 上的 `krea2-text-2-image.json`(工具 `wf_0ef16828a002`,表单
「快速用krea2生图」:提示词、`10.aspect_ratio` 两项,没挑种子 / 尺寸 / 跑几遍)。存着它的地方:

| 表 | 存的是 | 条数 |
| --- | --- | --- |
| `provider_models` | 模型行(`display_name` = 表单标题,启用) | 1 |
| `generation_sessions` | AI Studio 生成会话选着的模型 | 2 |
| `boards.canvas` | 一块画板上两个图片格子 `form.model`(参数是空的) | 1 块画板 / 2 格 |
| `workflows.graph` | 一个工作流节点 `plugin.dev.mosael.comfyui.wf_0ef16828a002`(`instance_id` 空,填了 `prompt`、`aspect_ratio_10`) | 1 |
| `workflow_revisions.graph` | 老修订(里面还有一个选它的 `ai_generate` 节点) | 6 |
| `plugin_capabilities` | 工具开关(开着) | 1 |
| `generation_jobs` / `generated_assets` / `provider_usage_events` / `jobs.payload` | 生成记录、素材、用量、任务回执 | 4 / 4 / 4 / 4 |
| `plugin_invocations` | 工具调用日志 | 2 |
| `provider_defaults` | 默认模型 | 0(图片默认是别的模型) |

这张图存着的种子是 `randomize`、表单标的主提示词就是自动认出来的那一格(节点 6 的 `text`)—— 在这一张上,把这些引用当成
「完整工作流」跑和当成表单跑,提交的图一样;差别只在界面(画板格子和 AI Studio 右栏会从两项变成全部参数)。但这只是这一张的巧合,
见 §6。

## Decision

### 维护者定的方向(2026-10-08)

1. **表单是工作流的入口**。一张工作流有:一个**完整工作流**入口(全部能填的项,就是现在的缺省表单 `default_form`,永远在);零个或
   多个**表单**入口(各自的标题、挑的项、顺序)。
2. **名字分主次两层,不拼在一起**:主名 = 表单入口用表单标题,完整入口用工作流名;副名(第二行或灰色小字)=「来自 krea2-text-2-image ·
   ComfyUI <服务器名>」之类。只有一行地方的,显示主名,副名进 tooltip 或淡色后缀。搜表单标题、工作流名、文件名都搜得到。
3. **列表里按工作流分组**:同一张工作流的完整入口和它的几张表单排在一起。
4. **内部编号稳定**:完整入口沿用工作流现有的 id;表单入口用「工作流 id + 表单 id」。改标题、加减表单不影响已经存好的东西。
5. **存储**:几张表单仍存在这张工作流文件里;格式从「一张图一张表单」改成「一张图一串表单」,节点上的标记按表单分开记;插件带迁移,
   改写 ComfyUI 上的文件前要维护者确认一次。

第一步做 2 和「完整入口回来」,并把 4 的 id 定死;第二步做 1、3、4、5 的其余部分。

### 1. 入口和 id

一张保存的工作流 = 一个**完整入口** + 它上面的每张表单各一个**表单入口**。内置文生图只有完整入口(它没有表单)。

| | 完整入口 | 表单入口 |
| --- | --- | --- |
| 生成模型 id | `<路径>` —— 今天的 id,原样:`krea2-text-2-image.json` | `<路径>#<表单 id>`:`krea2-text-2-image.json#app` |
| 工具名 | `wf_<12 位>` —— 今天的,原样:`wf_0ef16828a002` | `wf_<12 位>_<表单 id>`:`wf_0ef16828a002_app` |
| 工作流节点类型 | `plugin.dev.mosael.comfyui.wf_0ef16828a002` | `plugin.dev.mosael.comfyui.wf_0ef16828a002_app` |
| 智能体工具名 | `plugin__<连接 id>__wf_0ef16828a002` | `plugin__<连接 id>__wf_0ef16828a002_app` |
| 跑的时候 | `default_form`(全部能填的项)+ 工作流上标的结果 | 那张表单(和今天有表单时一样) |
| 内置文生图 | `builtin:txt2img` / `wf_builtin_txt2img` | 没有 |

**表单 id**:小写字母和数字,1–8 位(`[a-z0-9]{1,8}`),只在这张工作流里唯一。

- 第一步:今天那唯一一张表单(v1 存在 `extra.mosael.app`)的 id 固定是 **`app`** —— 取它在文件里的键名;第二步把文件改写成新格式时
  就写成 `{"id": "app", …}`,第一步存下的 `#app`、`_app` 一个都不用再改。
- 第二步新建的表单:6 位随机(`[a-z0-9]`,和这张工作流已有的撞了就重抽)。**不按标题起**(标题会改),**不按序号起**(删掉第 2 张再加一张,
  新的又叫 2,存着的引用悄悄指向另一张表单 —— 和 `tooling.tool_names` 宁可「找不到」也不张冠李戴是同一条理由)。
- 长度:智能体工具名上限 64(`MAX_AGENT_TOOL_NAME`),`plugin__` + 32 位连接 id + `__` + `wf_` + 12 + `_` + 6 正好 64 —— 6 位是放得下的最长;
  `app` 是 61。

**模型 id 怎么拆**(插件里一处):以 `.json` 结尾的是完整入口(路径里本身带 `#` 的也是,如 `a#b.json`);否则在**最后一个** `#` 切开,
前一半以 `.json` 结尾、后一半是合法的表单 id,才是表单入口;别的都不是这台 ComfyUI 的模型。

**名字不靠 id**:工具名、模型 id 只用来认和存;给人看的名字永远现查(画布上的插件节点早就不写死名字了,见迁移
`_migrate_plugin_node_names_follow_the_plugin`)。

**一个已知的、本 ADR 不动的事**:模型 id 是路径,在工作流库里改名、挪文件夹,存着的生成引用就断了(工具名按图里的 id 起,不受影响)。
表单 id 让「改表单标题」不影响引用;「改工作流文件名」不影响引用要换成按图 id 起模型 id,是另一件事。

### 2. 插件这一侧(第一步)

`graph.Form.named` 删掉 —— 「一张图叫什么」不再是一个答案。换成「一张图有哪几个入口,各叫什么」:

- `app_form.resolve` 交回**完整入口的表单**(`default_form` + 工作流上标的结果)和**每张表单**(第一步至多一张,id `app`),外加失效项;
  `models.form_of` 跟着改成按入口取。
- `models.each` 照旧一张图一项(拉一次、转一次);新加一个「这张图的入口」(完整的在前、表单按存的顺序),每个入口带:
  入口 id(模型 id)、**主名**(完整入口:文件名去掉 `.json`;表单入口:表单标题,没起标题的叫「表单」)、**所属的工作流**(路径、文件名去掉
  `.json`)、它的 `graph.Form`。
- `models.catalog`:每张交得出文件的图出**它的每个入口**一项。`describe` 读入口的表单,`label` 是主名,多一格 `group`(§3)。
- `models.load(model_id)` 按上面的规则拆 id;表单入口找不到那张表单时报「这张工作流上已经没有这张表单了」(工作流还在、表单删了)——
  和「工作流不在了」分开说。
- `run.generate`:表单入口和今天有表单时一模一样(只认表单上的键、`main` 那几格、种子照工作流设定、按表单槽位接);完整入口和今天
  **没有表单**的工作流一模一样。
- **工具**(`tooling`):
  - `tool_names(entries)` 从「模型 id → 工具名」变成「入口 id → 工具名」:完整入口照旧 `wf_<12 位>`(图 id,撞了 id 退到路径哈希,
    规则不变);表单入口是完整入口的名字加 `_<表单 id>`。一张图退到路径哈希时,它的表单入口跟着退(`wf_<路径哈希>_app`)。
  - `_remember` 记的对照表从 `{工具名: 模型 id}` 变成 `{工具名: 入口 id}`(值里可以有 `#`);`_resolve(工具名)` 先查表拿到入口 id、
    拆出路径和表单 id、拉那一张,再按这张图的入口重算一遍工具名核对(图 id 变了就整个重扫,和今天一样)。1.20 之前留下的对照表里
    `wf_X → x.json` 在新规则下就是完整入口,不用清。
  - `tool_for(入口)`:`label` 照旧「工作流 · <主名>」(前缀是「这是一张工作流的工具」的标记,和 `list_workflows` 这些同一个插件的工具
    区分开);多一格 `group`;说明里写全两层 —— 表单入口:「用表单「快速用krea2生图」跑 ComfyUI 工作流 krea2-text-2-image.json(只填表单上
    那几项)」;完整入口:「原样跑 ComfyUI 工作流「krea2-text-2-image」(全部能填的项)」。说明是给模型读的,写在一句话里没关系。
  - `replaces`:完整入口照旧(取代选了这张图的 `run_workflow`、取代以前按路径哈希起的 `wf_<路径哈希>`);表单入口只取代
    `wf_<路径哈希>_<表单 id>`(老文件在新版 ComfyUI 里再存一次有了图 id,表单入口的工具名也跟着从路径哈希变过来)。
  - `mirrors.generation_model` 是入口自己的模型 id。
  - 有表单的工作流,它的**完整入口不进智能体的工具表**(`agent: false`,§5)。
- `list_workflows`(给智能体):一张工作流一项,`id` / `label` 是工作流的,`tool` / `model` 是完整入口的;多一串
  `forms: [{id, title, model, tool}]`。按表单标题、工作流名、路径都搜得到。
- 工作流库(插件那一侧的 `workflow_library.describe`、`app`):「识别出的输入 / 参数」改成说**完整工作流**(那是文件本身的事实);表单在
  「表单」那一节里说(标题、几项、失效几项)。

### 3. 两层名字:字段怎么带

**插件 → 宿主**(`op: models` 的每个模型、`op: tools` 的每个工具,同一个形状;写进 docs/PLUGIN_MANIFEST):

```jsonc
{
  "id": "krea2-text-2-image.json#app",      // 工具这里是 "name": "wf_0ef16828a002_app"
  "label": "快速用krea2生图",                 // 主名(工具:「工作流 · 快速用krea2生图」)
  "group": {
    "id": "krea2-text-2-image.json",          // 同一样东西的几个入口,这一格相同
    "label": "krea2-text-2-image",            // 那样东西自己的名字(可以按语言分)
    "entry": "form"                           // "full" = 这样东西本身(全部参数);"form" = 它上面的一张表单
  },
  "form": { … }                               // 只有模型的表单入口有(已有,ADR 0038 §4)
}
```

- `group` 是**通用**的:「这一项是某样东西的一个入口」。宿主不认识「工作流」,只认「同一组」「本身 / 表单」。没有 `group` 的模型、工具
  (别的插件、内置文生图)照今天的样子。
- 每张保存的工作流的入口都带 `group`(没有表单的也带,`entry: "full"`):搜文件名、按组排序要用。
- **宿主不拼字符串**:后端只存、只转结构化的几格,两层怎么摆是前端的事。
  - 模型行:`provider_models` 加一列 `declared_group`(JSON,`{id, label, entry}` 或空),和 `declared_capabilities` 一样只由插件目录写
    (`replace_declared_catalog`);加列的迁移不补数据 —— 插件版本进了指纹,升级后第一次刷新就写上。
  - 生成选项(`GenerationOptionOut`):多一格 `group: {id, label, entry} | null`(`label` 按看的人的语言挑好,和 `_for_reader` 同一处)。
    `model_label` 照旧是主名、`profile_name` 照旧是连接名;后端拼好的 `label`(「连接名 · 主名」)删掉(§4 末尾)。
  - 工具:`group` 进 `dynamic_tools._KEPT`,跟着 `discovered_tools` 存;插件页工具表、节点注册表(`node_meta`)、画板能力清单把它原样带给前端。
- **副名**由前端按这几格拼(用户语言的一句话,不进库):

  | 这一项 | 主名 | 副名 |
  | --- | --- | --- |
  | 表单入口 | 表单标题(「快速用krea2生图」) | 来自 krea2-text-2-image · <连接名> |
  | 完整入口,这张工作流有表单 | 工作流名(「krea2-text-2-image」) | 完整工作流 · <连接名> |
  | 完整入口,没有表单 | 工作流名 | <连接名>(和今天一样) |
  | 没有 `group` 的 | 显示名 | <连接名>(和今天一样) |

  「连接名」是连接自己的名字(`profile_name`,默认「ComfyUI · http://192.168.3.15:8188」,用户能改成「家里那台」);节点、工具清单这些按包
  聚合、不分连接的地方不写连接名。

**排序和分组**:生成选项按(连接名、组名或主名、完整在前、表单按插件给的顺序)排 —— 同一张工作流的几个入口挨在一起;下拉里同一组的
表单入口缩进一格挂在完整入口下面(第一步只有一张表单,挨着就够;第二步表单多了才需要组标题,见 §7)。

**搜索**:有搜索框的地方都搜 主名 + 组名 + 模型 id(就是文件路径)+ 连接名:搜「krea2」两个入口都出来,搜「快速」只出表单入口。

### 4. 每个界面怎么显示

清点时看到的三件事,决定了下面怎么改:

- **今天四处各拼各的**:生成页用后端拼好的 `label`(「连接名 · 显示名」);画板格子是 `${model_label} · ${profile_name}`(倒过来);工作流
  检查器是 `${model_label} · 种类`(不带连接);设置页默认模型是 `${provider_name} · ${display_name}`。第一步统一成一个两层的样子,
  这四种拼法都删掉。
- **有一处在拆字符串**:模型库「用它生成」的 `workflowName()`(`features/plugins/modelLibraryView.ts`)从 `label` 里剥掉
  「连接名 · 」前缀取工作流名 —— 正是「拼进一个字符串之后只能拆」的样子。改成读结构化的几格,这个函数删掉。
- **插件节点、画板能力按包聚合,不按连接**(`plugins/nodes.plugin_node_types`:同一个工具名只留一份,用哪台服务器是节点上的
  `instance_id`)。所以「添加节点」和画板能力这两处,副名里**没有连接名**,只写「来自 krea2-text-2-image」/「完整工作流」。

「两行」= 主名一行、副名一行淡色小字;「一行」= 只写主名,悬停写两层。名字都由前端按 §3 的几格摆,后端不拼。

| 界面 | 在哪 | 今天 | 第一步 |
| --- | --- | --- | --- |
| **AI Studio** 模型下拉 | `ai-studio/GenerateWorkspace.tsx` 的 `SearchableSelect`(按种类分组,有搜索;组件本来就支持第二行、分组、`keywords`) | 一行 `label` | **两行**;同一张工作流的入口挨着,表单入口缩进;`keywords` 加组名、模型 id、连接名 |

### 5. 智能体的工具:有表单的工作流只给表单入口

- ComfyUI 连接的插件工具属于 `comfyui` 那一份(ADR 0044 §8,`tool_manifest._PROVIDES_KIT`),**只在工作台里那一轮发**;在别处,智能体
  跑 ComfyUI 工作流走 `generate_image` 这一类生成工具,模型 id 是数据,不占工具定义。
- 推荐:**有表单的工作流,它的完整入口不进智能体的工具表**,只给表单入口。理由:表单就是作者给「别人」(包括智能体)准备的那张表,
  作者做表单常常正是因为全部参数太长;今天有表单的工作流在智能体那里也只有这一个工具,这样改之后每轮发的工具定义一个字节都不多。
  智能体真要全部参数,用 `generate_image` 带完整入口的模型 id(`list_workflows` 里有),或者在工作台里直接改画布。
- 做法:插件在这种完整入口的工具上写 `agent: false`(新的通用键:「不进智能体工具表;工作流节点、画板、插件页照常」),宿主在
  `tool_manifest._plugin_tool_specs` 跳过它。**不借开关**:插件页上的工具开关同时管智能体、工作流节点面板和插件页(`plugins.tools.exposed`),
  关掉完整入口就从「添加节点」里也消失了,和「两个入口都能选」相反。`agent: false` 和运行时工具不许带的 `internal` 不是一回事:它只让工具
  少出现在一处,插件页照样列着、照样能开关、工作流和画板照样能跑,不是藏起来只给宿主调。
- 第二步每张表单一个工具:表单入口一般只有几项(维护者那张 1.4K 字符,约 0.4K token),表单多几张也在预算里。
- **和「工作台那一轮只发用得上的工作流工具」(ADR 0044 修订,插件 1.19.0 的 `workflow: {path, name}`)怎么合**:一张工作流的几个入口
  `workflow.path` 相同、`name` 各是各的主名,所以画布上开着这张、对话里调过它、用户说到它的文件名,表单入口都会被挑上;完整入口在这之前
  就被 `agent: false` 筛掉。按路径找工具的两个宿主工具 `comfy_workflow_inputs` / `comfy_run_workflow`(agent/workflow_tools;ADR 0044
  修订之二起并成通用的 `plugin_tools` / `run_plugin_tool`,在 agent/plugin_lookup)也只认
  进得了智能体工具表的那几个:按路径找到的是表单入口,点完整入口的工具名报「找不到」—— 这条路不把 `agent: false` 的绕回来。第二步一张
  工作流几张表单时,按路径找到的是第一张表单;要别的那几张,智能体用 `list_workflows` 里的 `forms[].tool`。

**顺带查到的、本 ADR 不解决的预算问题**:每张工作流一个工具,入参里带着整张下拉表(一个 LoRA 下拉几百项)。维护者那台 ComfyUI 上开着的
24 个 `wf_*` 工具,说明加入参约 52 万字符,按 3.5 字符一个 token 约 **15 万 token** —— 在工作台里每轮都发,远超 ADR 0044 的 38.4K 预算。
预算测试接的假 ComfyUI 上一张工作流都没有,所以是绿的。要另开一项处理(见待拍板 13)。

### 6. 老引用:id 的含义变了,要迁

**变化**:一张今天已经有表单的工作流,它的模型 id `<路径>` 和工具名 `wf_<12 位>` 今天指的是**表单**;第一步之后它们指**完整工作流**,
表单搬到 `<路径>#app` / `wf_<12 位>_app`。没有表单的工作流什么都不变。

**存着这个 id 的地方**(代码里逐个找的,不只维护者库里有的;和 `_migrate_comfyui_connections_become_plugin_instances` 当年改写的是同一批):

| 存着的 | 在哪 | 按完整入口跑,和今天(按表单)比 |
| --- | --- | --- |
| 生成格、生成节点、定时任务里的 (连接, 模型) | 画板 `boards.canvas` 的格子 `form`(`provider_profile_id`、`model`、`parameters`);工作流 `ai_generate` 节点的 `config`(含循环体、子图);节点里按生成选项 id 存的那几格(`<连接 id>:<种类>:<模型 id>`,如资产的「补全多角度」用的 `reference_image_models`);`scheduled_tasks.payload` | **会不一样**,见下 |
| AI Studio 生成会话选着的模型 | `generation_sessions.model` | 右栏从表单变成全部参数;生成时同下 |
| 默认模型 | `provider_defaults.provider_model_id` → 模型行 | 没点名模型的地方用的从表单变成完整工作流 |
| 模型行上用户自己的设置 | `provider_models` 这一行的 `enabled` | 停用过的表单,变成停用了完整工作流 |
| 工作流节点(每张图的工具) | `workflows.graph` 的节点类型 `plugin.<包>.wf_<12 位>` + `config` | **会不一样**,见下 |
| 画板格子上的能力 / 生成器(只交出文字的图,没有生成模型) | `boards.canvas` 的 `form.abilities`、`form.producer` = `node:plugin.<包>.wf_<12 位>` | 同上 |
| 工具开关 | `plugin_capabilities (连接, 工具名)` | 开着的是表单的开关,会变成完整工作流的开关 |
| 生成记录、素材的生成参数、用量、任务回执 | `generation_jobs.model`、`generated_assets.model`、`provider_usage_events.model`、`jobs.payload` | 记录脚注写成完整工作流的名字(实际跑的是表单);「用同样的参数再来一次」按完整工作流跑 |
| 工具调用日志、对话里的工具调用、工作流的老修订 | `plugin_invocations`、`agent_messages`、`workflow_revisions` | 只是历史,不再被拿来跑(恢复老修订见下) |

**按完整入口跑,哪里会不一样**(插件 `run.generate` / `tooling.run_tool` 两条路逐项比):

- **参数**:键都是 `<节点 id>.<输入名>`(工具里是 `<输入名>_<节点>`),同一项在两个入口里是同一个键 —— 存着的值照样接得上。但表单入口
  只认表单上的键:格子、节点里存着的、表单以外的旧键(做表单之前填的)今天被丢掉,换成完整入口就会写进图。
- **主提示词落在哪**:表单入口写作者标了 `main` 的那几格;完整入口写自动认出来的提示词格。作者标的不是自动认出的那格(或者表单
  里根本没有主提示词、提示词是 `none`)时,同一句提示词会写进别的格子,或者从「不写」变成「必须写」。
- **种子**:表单里没挑种子时照工作流自己的设定(存着 `fixed` 的,每次都是那个种子);完整入口没给种子就每次随机。存着 `fixed` 的图,
  结果从「每次一样」变成「每次不同」。
- **素材槽位**:表单入口按表单的槽位顺序接(作者可能只露了一部分、换了顺序);完整入口按自动推出来的全部槽位接。
- **「结果取自」**:两个入口都按工作流上标的结果,一样。
- **界面**:画板格子、AI Studio 右栏、工作流节点的入参从表单那几项变成全部参数(维护者那张:参数从 1 项变成 17 项,用插件现在的代码对着那张图和那台的节点定义算的)。
- 工具的键名在少数情况下也会变:两项算出同一个键时后来的那项加哈希后缀,表单和全部参数里「后来的」可能不是同一项。

维护者那一张恰好全对得上(种子 `randomize`、主提示词就是认出来那格、格子参数是空的),但这些差别在一般的表单上都可能出现,
**证明不了行为不变 —— 所以迁**:把上表里指着「今天有表单的工作流」的引用改成指表单入口,跑起来和今天一模一样;之后再新加的引用,
选哪个入口就是哪个入口。

**谁来迁(推荐 A)**

- **A. 插件报一次性的「改名」,宿主每个连接只做一次**(推荐)。哪些工作流今天有表单、表单入口叫什么,只有插件看得到(文件在 ComfyUI 上);
  宿主的缓存里看不全(下面 B 的漏洞)。所以:
  - 插件在 `op: models`、`op: tools` 的回答里多一串 `moved: [{"key": "form-entries", "from": "<旧 id>", "to": "<新 id>"}]`(通用的契约:
    「从这一版起,`from` 说的那件事改叫 `to`,`from` 这个名字以后另有所指」)—— 1.20 起每次都报当下有 v1 表单的那几张;
  - 宿主收到后,**这个连接**上没做过这个 `key` 就做一次,做完记在连接上(`plugin_instances` 加一列 `applied_moves`,JSON,
    `{"generation": ["form-entries"], "tools": ["form-entries"]}`),以后再报也不做 —— 升级之后才做的表单,它的完整入口就是完整入口,不会被改走;
  - 模型的改名在 `replace_declared_catalog` **之前**做:先把模型行 `from` 原地改名成 `to`(行 id 不变 → 默认模型、停用、用户的设置都跟着
    表单走),再对齐目录(会新建一行 `from`,也就是完整入口,默认启用);再按连接改:生成会话、画板生成格、工作流生成节点(追加一版
    `source = "migration"` 的修订,作者沿用上一版,和 `plugin_references` 同一个做法)、定时任务、生成记录 / 素材 / 用量 / 任务回执;
  - 工具的改名和新清单在同一笔里提交(改名在保存点里做,没改成只撤它,清单照样存下)、在按推荐补开关之前:工作流节点类型、画板格子的能力和生成器从 `wf_X` 改成 `wf_X_app`(`config` 一格不动 ——
    表单入口的工具就是升级前那个工具,键一样);节点上没选连接(`instance_id` 空)的,照 `plugin_references` 的规矩:有这个工具的连接
    说法都一样才改;工具开关复制一份给 `wf_X_app`(开着的照旧开着),`wf_X` 的开关原样留给完整入口;
  - 每个领域改自己的数据(画板域改画板、工作流域改工作流……),在组装根登记成「连接的模型 / 工具改了名」的监听,和 `dynamic_tools.on_refreshed`
    同一个方向;插件域不认识它们。
  - **代价**:改名要等这个连接升级后第一次刷新目录(启动时、指纹变了 —— 插件版本在指纹里)。ComfyUI 那时没开就等它开了再做;在那之前那些
    引用按完整入口跑(而 ComfyUI 没开时本来就跑不了)。从连上到下一次刷新之间(至多一次指纹轮询)有一个很窄的口子。
- **B. 宿主在启动时一次性迁**(`migrations.py`,和当年 ComfyUI 搬进插件那一步一样)。看缓存:模型行的描述符里有 `form` 的就是有表单的
  媒体工作流;工具靠缓存里的 `mirrors.generation_model` 对到模型。好处是没有那个口子,ComfyUI 没开也迁得动。**否掉**:①只交出文字的

  节点会悄悄变成完整入口;②宿主要写死 `#app`、`_app` 这套 ComfyUI 的编号 —— 插件契约里「ComfyUI 的知识只在插件里」(`replaces` 就是为此)。

### 7. 第二步:一张工作流多张表单

**存储格式 v2**

```jsonc
// 图上
"extra": {"mosael": {"version": 2, "forms": [
  {"id": "app",    "title": "快速用krea2生图", "description": "", "graph_items": {}},
  {"id": "k3x9a2", "title": "精调",          "description": "", "graph_items": {"size": {"order": 1}, "seed": {"order": 3}}}
]}}
// 节点上:每张表单在这个节点上露哪几格,按表单 id 分开
"properties": {"mosael": {
  "forms": {
    "app":    {"text": {"order": 0, "main": true}},
    "k3x9a2": {"text": {"order": 0, "main": true}, "steps": {"order": 2, "label": "步数"}}
  },
  "result": true
}}
```

- `forms` 的顺序就是表单在各处列出来的顺序;一张图最多 20 张表单;`id` 规则见 §1。v1 的 `expose` 不再读。
- **「以后只要这张」(`result`)还是按工作流记**,不按表单:它说的是这张图哪个输出是成品,完整入口和每张表单都按它(推荐,待拍板 10)。
- 读:只认 v2(ADR 0038 §2 的规矩不变:只认当前版,不留认旧版的分支);v1 的图按「没有表单、要升级」报出来(`status: "unsupported"`,
  已有的那条路)。节点上指着不存在的表单 id 的标记不进任何表单,列成失效项,下次保存时清掉;`forms` 里 id 重复、不合规的丢掉、列出来。
- 写:`app_form.apply` 收**全部表单**(`[{id?, title, description, items, graph_items}]`)+ 结果,整个重写 `mosael` 那几处;没给 id 的是新表单,
  插件起 id。编辑器每次交全部表单 —— 它手里本来就有全部,不用为「只改一张」另开一条路。

**ComfyUI 上已有文件的迁移(v1 → v2)**

- 插件新 op `upgrade_marks {paths: [{path, modified}]}`:逐张读、改、带着读到时的改动时间覆盖写回(和 `annotate` 同一套:那台机器上在这之间
  改过就跳过,回 `stale`;照原来的排版写回,只动 `mosael` 那几处,`json_style.dumps_like`)。v1 有表单的:`forms: [{"id": "app", …原来的}]`,
  节点上的 `expose` 搬进 `forms.app`;v1 只有结果标记的:`forms: []`,`result` 原样。
- **怎么让维护者确认**:1.21 第一次刷新这个连接的目录、发现有 v1 的工作流时,发一条通知「ComfyUI <连接名> 上有 N 张工作流的表单是旧格式,
  升级之后才看得到它们的表单」;工作流库顶上一条横幅,同一句话 +「查看并升级」→ 弹窗列出这台服务器上要改的文件、写明「只改每张里
  Mosael 的标记(`extra.mosael` 和节点上的 `properties.mosael`),别的一个字节不动;ComfyUI 里刚改过的那张会跳过」→ 确认一次,整台改完,
  报改了几张、跳过几张。**每个连接确认一次**(文件在各自的服务器上)。
- **从 1.20 之前直接升到 1.21 的人**:1.21 不读 v1,升级前那段时间里不报 `form-entries` 的改名;改写成 v2 之后,id 是 `app` 的
  那张表单照旧报 `{"key": "form-entries", "from": <路径>, "to": <路径>#app}`(工具同理)—— 宿主在这个连接上没做过这个 key 就做一次,
  老引用照样改到表单入口;做过了就不再做。所以 1.21 起插件对 id 为 `app` 的表单一直报这条。
- **升级前的那段空档**:没升级的 v1 图没有表单入口 —— 指着 `#app` 的格子、会话会说「这张表单不在了」(插件按 `unsupported` 说清楚:
  「这张工作流的表单是旧格式,到工作流库里升级」)。不在读的一侧认旧版来填这个空档(那就是兼容分支);靠通知和横幅把空档压短。

**编辑器管多张表单**

- 工作台「表单」页签(`AppPanel`):顶上一排表单(标题,没起的写「未命名表单」)+「新表单」;选中哪张,下面就是哪张的编辑器(还是
  `AppFormEditor`)。新表单三种起法:空白、「按推荐先挑一版」(已有)、「复制这张」。每张能改标题、复制、删除。写还是经桥改画布上的
  标记(`app_marks` 交全部表单),存盘还是 ComfyUI 自己的保存。
- 工作流库详情的「表单」一节:列出每张表单(标题、几项、失效几项)+「新表单」;点哪张,打开那张的编辑弹窗(`WorkflowAppEditor`,弹窗顶上
  也有同一排表单可以切换)。存还是 `annotate`(交全部表单),确认框照旧写明哪台服务器上的哪个文件。
- 「以后只要这张」从表单编辑器里挪到工作流那一级(两处都在表单那一排上面单独一块),因为它不属于哪一张表单。
- **删表单**:确认框写出 Mosael 里有几处在用它(宿主按 `<路径>#<id>` 和 `wf_X_<id>` 数画板格子、工作流节点、AI Studio 会话),删了它们会说
  「这张表单已经没了」。不自动换成完整工作流 —— 悄悄换掉就回到了「名字没变、跑的东西变了」;那几处显示缺失,用户自己换。
- 第二步起表单必须有标题(多张表单时「表单」「表单」分不出来);第一步那张没起标题的,升级时标题照旧空着,列表里写「未命名表单」,
  打开编辑器时提示起一个。
- **列表按工作流分组**(维护者第 3 条):有表单的工作流在下拉、添加节点、画板能力里是一组 —— 组标题是工作流名(+ 连接名),下面「完整工作流」
  和每张表单各一行;没有表单的照旧一行。搜索命中组里任何一行,整组留着、命中的那行高亮。

**智能体:每张表单一个工具,「本会话始终允许」按入口记**

- 表单入口各是一个工具(`wf_<12 位>_<表单 id>`,完整入口 `agent: false` 照旧不给智能体,§5)。ADR 0044 修订之二把「本会话始终允许」记在
  卡替调的那个工具名下(`ConfirmableTool.allowance_tool`,通用的 `run_plugin_tool` 记在它替调的那个名下),所以**同一张工作流的两张表单
  各问一次**:允许了「快速出图」,智能体第一次调「精调」还会弹卡。
- 这是想要的(2026-10-08 确认):两张表单露的格子不一样(一张锁着种子和大模型、一张把大模型也露出来),答应了跑这一张不等于答应跑那一张;
  多问一次的代价是每张表单一张卡。不另做「按工作流记」的一层 —— 那要宿主认得「这几个工具是同一张图」,插件契约里没有这层意思,
  也用不着加。

## 这一版不做

- 模型 id 改成按图 id 起(改文件名不断引用):另一件事,见 §1 末尾。
- 每张工作流一个工具在工作台里的预算问题(§5 末尾):另开一项。
- 表单按标签、文件夹组织;表单单独分享、单独导出(它跟着工作流文件走)。
- 生成记录里存下当时的两层名字(表单删了以后记录仍写得出名字):第二步也没做 —— 删表单之前确认框写出在用的几处;记录是历史,不跟着改。

## Consequences

- 认得出是哪张图:表单入口的副名写着来自哪张工作流、哪台服务器;完整工作流和它的表单在列表里挨在一起;按文件名搜得到表单。
- 有表单也拿得到全部参数:选完整入口。
- 表单入口的 id 现在就定死(`#app` / `_app`),第二步加多表单时已存的引用不用再改第二次。
- 一次性的迁移把「今天有表单的工作流」的老引用改到表单入口,升级后跑的、界面上看到的和今天一样;这需要插件契约多一样通用的东西(`moved`),
  宿主多一张「连接做过哪些改名」的账。
- 插件契约多三样通用的键:`group`(一项是哪样东西的哪个入口)、`agent: false`(不进智能体工具表)、`moved`(一次性改名)。
- 模型行多一列 `declared_group`、连接多一列 `applied_moves`;生成接口的模型 id 上限放到 160。
- 一张工作流能有几张表单,各是一个入口、一个工具;「本会话始终允许」也按入口记(§7)。
- ComfyUI 上的标记换成 v2:上一版的文件要连接的主人确认一次整台改写,改写之前那几张的表单入口不在(指着它们的地方说清楚去升级)。
- 插件契约再多三格:`group.order`(同一样东西的几个入口谁先谁后)、`op: models` 回答里的 `library_upgrades` 和 `unavailable`
  (几张要升级;认得、现在用不了的模型和原因)。

## 待拍板

每条后面是推荐。1–15 维护者 2026-10-08 全部照推荐拍板(**已定**;13 另开一项,已做完,见 Status;14、15 是第二步实现时提出的,维持现状)。

1. **(已定)第一步那张表单的 id 叫什么。** 推荐 `app`:v1 把它存在 `extra.mosael.app`,第二步改写文件时原样写成 `{"id": "app", …}`,第一步存下的
   `#app` / `_app` 不用再改。(备选 `main`、`1`:没有更好的理由,`1` 还会让人以为第二张是 `2`。)
2. **(已定)表单入口的编号。** 推荐模型 `<路径>#<表单 id>`、工具 `wf_<12 位>_<表单 id>`;第二步新表单 6 位随机小写字母数字,不按标题、不按序号(§1)。
3. **(已定)老引用迁不迁。** 推荐迁:今天有表单的工作流,它的老引用改指表单入口 —— 一般的表单上按完整入口跑会变(提示词落的格子、固定种子、
   旧参数、素材槽位,§6),而且画板格子和 AI Studio 右栏会从几项变成全部参数。维护者库里只有一张、跑出来恰好一样,但这证明不了一般情况。
4. **(已定)谁来迁。** 推荐 A:插件在目录里报一次性的 `moved`,宿主每个连接、每个 `key` 只做一次(插件契约多一样通用的东西,宿主多一张账)。
   备选 B:宿主启动时按缓存迁(没有升级后到第一次刷新之间的口子、ComfyUI 没开也迁得动),但只交出文字的工作流看不出有没有表单,
   宿主还要写死 `#app` / `_app`。
5. **(已定)历史记录跟不跟着改。** 推荐生成记录、素材的生成参数、用量、任务回执一起改到表单入口(它们跑的就是表单;记录脚注和「用同样的参数
   再来一次」读它们);工具调用日志、对话里的工具调用、工作流老修订不改(只是历史)。
6. **(已定)智能体拿哪个。** 推荐有表单的工作流只给表单入口(完整入口 `agent: false`,§5):每轮的工具定义和今天一样多。备选两个都给:工作台里
   每张有表单的图多一个完整工具,大的图上万 token。
7. **(已定)副名里的服务器怎么写。** 推荐直接用连接名(默认「ComfyUI · http://192.168.3.15:8188」,用户能在插件页改成「家里那台」),一行放不下就截断、
   tooltip 里写全;不另造一个「服务器短名」。
8. **(已定)没有表单的工作流,副名写不写「完整工作流」。** 推荐不写:只有一个入口时这四个字是噪音,和今天一样只写连接名;有表单时才写,用来和表单分开。
9. **(已定)没起标题的表单叫什么。** 推荐第一步主名叫「表单」(副名写着来自哪张工作流);第二步起编辑器要求起标题,老的那张升级后写「未命名表单」。
10. **(已定)第二步「以后只要这张」按工作流记还是按表单记。** 推荐按工作流(它说的是这张图哪个输出是成品,完整入口和每张表单都按它);编辑器里挪到
    表单那一排上面单独一块。
11. **(已定)第二步删一张有人在用的表单。** 推荐确认框里写出在用的几处,删了之后那几处显示「这张表单已经没了」,不自动换成完整工作流。
12. **(已定)第二步旧格式的空档。** 推荐不在读的一侧认 v1(ADR 0038 §2 的规矩);1.21 第一次刷新发现 v1 就发通知、工作流库挂横幅,每个连接确认一次整台改写。
13. **(另开,已做完)工作台里每张工作流一个工具的预算问题**(§5 末尾,维护者那台约 15 万 token)。推荐另开一项,不并进本 ADR;方向可以是工作台里只发画布上开着的
    那张和用户点过名的几张、其余靠 `list_workflows` + `generate_image`。

14. **(已定,维持现状)升级前那段空档里,表单入口的模型行留不留。** 现在是删(目录就是答案,`replace_declared_catalog`),升级后重新建:留着的行会
    出现在下拉里、选了必然失败;代价是挂在那一行上的默认模型被置空、停用回到启用,升级后要重设(维护者库里那一行上什么都没挂,见第二步的试跑)。

15. **(已定,维持现状)工作流库卡片上的「Mosael 里谁在用它」、最近一张产出要不要把表单入口算进去。** 现在只算完整入口;表单入口的用处在删表单的
    确认框里一处一处列(`form-usages`)。推荐维持现状(卡片是文件的样子,一张卡挤不下每张表单各自的用处)。备选:卡片上合计全部入口。

### 和设计不一样、或设计没写到的

- **「用不了」的说法走目录,不走跑一次**:§7 写的是「插件按 `unsupported` 说清楚」。实现时插件在 `op: models` 的回答里多两格 ——
  `library_upgrades`(几张工作流的表单是上一版格式)和 `unavailable`(`[{id, reason}]`,认得、现在用不了的模型 id 和中英原因);宿主存进
  `capability_status.generation`,生成时选着这样的模型回 `genErr_modelUnavailable`(带插件的原因),`GET /api/generation/unavailable`
  给界面:画板格子、AI Studio 的会话、工作流生成节点上写「选着的模型现在用不了」,悬停是插件那句原因(「到工作流库里点『查看并升级』」)。
