# ADR 0056:蒙版 —— 认得出来,画得出来

## Status

Accepted — 2026-10-12。方向由维护者提(「ComfyUI 中有时候是会有蒙版编辑和蒙版属性的操作的,目前 Mosael 没有蒙版相关的操作」),
两轮构思后按维护者「先落 ADR,然后开工」拍板:**先做编辑(第二步)、再做属性归组(第一步)、后端那一步按需**。
本 ADR 只钉**三条边界**和**分工**,不发明新契约。

**2026-10-14 由 [ADR 0057](0057-one-mask-shape-one-exit-one-editor.md) 修订**:蒙版素材只有一种形状(`L` 模式、和源图同尺寸)、
只有一个写出口;编辑器重做并做扩张(决定 3 里「扩张/收缩不自己做」那一句作废)。

## Context

### 维护者说的问题

ComfyUI 里蒙版有两件事:**画**(在图上刷出要改的那一块)和**调属性**(扩张、羽化、模糊、阈值、反选、拼接)。
Mosael 这边他看不到蒙版相关的操作。

### 读代码确认的现状

- **蒙版已经是生成契约里的一等角色**,而且**语义早就定死了**:`ai/providers/contracts/generation.py` 的
  `MASK` 原话是「和要改的那张图一起给,**白色是要改的地方**(局部重绘)。它不是参考图 —— 参考图说「照这个来」,
  蒙版说「只动这一块」」。前端 `lib/sourceFrames.ts` 的 `SOURCE_ROLES` 里有 `mask`,文案齐(蒙版 / 上传蒙版 / 蒙版 URL)。
- **插件这边三条路都通了**:`LoadImageMask` 在 `_LOADERS` 里认成 `("mask", "image")`;`LoadImage` 的 MASK
  输出被接下去时(`alpha_masks`)也算一张蒙版;工作流只有 alpha 那条路时 `wire_inputs` 会**注入**一个
  `LoadImageMask(image=<上传的>, channel="red")` —— 读**红通道**,因为宿主的蒙版是黑白图、**没有透明通道**
  (`_MASK_CHANNEL`)。蒙版输出不会被当成成图(`_NOT_FINAL_MARKS`)。
- **今天已经能做**:把一张黑白 PNG 当素材传进蒙版槽,生成就走局部重绘;工作流里 `GrowMask` / `FeatherMask` /
  `MaskBlur` / `ThresholdMask` / `MaskComposite` 的控件**也已经能调**(它们是普通节点的控件,按普通参数发下来)。
- **缺的三件**:① 那些控件顶着节点标题混在普通参数里,Mosael 不认它是"蒙版属性";② 没有地方画蒙版(只能上传
  一张已经画好的);③ 批量 / 智能体那条路(按亮度、按颜色自动生成)前端做不了 —— 它读不到原图像素。

### 为什么不能照搬 ComfyUI 的做法

ComfyUI 的蒙版编辑器把蒙版**写进图的 alpha 通道**(`clipspace/…` 那张副本),因为它的 `LoadImage` 同时给 IMAGE
和 MASK 两路。Mosael 的蒙版是**独立的一份黑白图**、走红通道 —— 两者不是同一种东西,照搬会把契约搞成两套。

## Decision

### 1. 蒙版就是宿主契约说的那种东西,不另立

**灰度 PNG、白 = 要改的地方**,独立成一份素材。编辑器、插件注入的 `LoadImageMask`、以后后端那一步,产的都得是这一种。
不带 alpha 语义(带 alpha 的图传进蒙版槽会被当整块不透明读,什么都不重绘 —— 这正是 `_MASK_CHANNEL` 那条注释在防的)。

### 2. 蒙版和它的源图是一对

契约原话就是「和要改的那张图一起给」。所以三处界面里蒙版槽**挨着**它那一组素材槽(中间不隔断),「编辑」入口开在**原图**上,
生成详情里"看一眼这张蒙版"和看一眼原图是同一件事的两面。

### 3. 属性走工作流节点,像素编辑走浏览器 canvas —— 两边不重叠

- **属性(非破坏)**:`GrowMask` 的 `expand`、`FeatherMask` 的 `left/right/top/bottom`、`MaskBlur.amount`、
  `ThresholdMask.value`、`MaskComposite.operation/x/y`、`ImageToMask.channel` —— 值是**工作流自己算的**,
  Mosael 只负责(一)认出来、(二)给它们人话名字与单位、(三)把它们归到「蒙版属性」这一组摆在蒙版槽下面。
  `InvertMask` 没有控件:不画开关,只说一句"这张工作流会反选"。
- **编辑(破坏性的那一下)**:刷子、橡皮、矩形/椭圆、撤销、清空、反选、羽化,在**浏览器 canvas** 上做一次,
  产出一张灰度 PNG。扩张/收缩**不自己做** —— 那是 `GrowMask` 的活,已经在上面那一组里了。
- **不重复实现**:同一种运算只有一处。前端画得出来的(反选、羽化、阈值)后端不再做一遍;工作流算得出来的
  (扩张、拼接)Mosael 不自己算。

### 4. 表单只挑已有节点,不替工作流加节点

「蒙版属性」这一组里出现的,永远是工作流里**本来就有**的那些节点的控件。要在工作流里加一个 `GrowMask`,仍然在
ComfyUI 里加 —— 表单编辑器只挑已有节点,这是既有约定(ADR 0038 / 0045)。工作流没有的属性,界面就说没有,
不画一个点了没用的开关。

### 5. 编辑的输出落成素材

一次编辑 = 一张新素材,名字带来源(「蒙版 · <原图名>」),进蒙版槽。**不打标签**:标签是用户自己的词表
(界面上就是一排 chip),往里塞一个随界面语言变的词,中文用户和英文用户会得到两份不一样的数据。**不引入"蒙版文档"**:不存笔触历史、不存非破坏的
属性栈 —— 第一次保存就是那张 PNG,要改就在它上面继续画。理由:笔触历史的存储与版本是另一套东西,而蒙版本身是
过程性产物(它只对这一次局部重绘有意义)。开着编辑器时可以先「按 alpha / 亮度阈值初始化」(`MaskFromColor` 的等价物,
浏览器 canvas 上取像素、阈值、二值化,一次就够)。

### 6. 后端那一步的边界(先不做)

`POST /api/assets/{id}/mask`(源素材 + 阈值/形状 → 新蒙版素材,实现放 `app/media/masks.py`,和缩略图/波形同一层)
**只在真需求出现时**才做:批量给一批图配同一块区域、或智能体说"按亮度抠个蒙版" —— 那是前端读不到像素的场景。
前五条不依赖它。

### 7. 顺序

**先 2(编辑)、再 1(属性归组)**。属性那一组今天已经**能调**,只是没归组;而"能画"是现在完全没有的能力,
且它纯在浏览器里(不碰后端、不碰描述符)。

### 非目标

不做图层;不做「蒙版文档/版本」;不做 diffusers 级的局部重绘算法(模型自己会做);不把蒙版算成产出(插件已经把
蒙版输出排除在成图之外,那是既有决定);不因为蒙版改动生成契约本身。

## Consequences

- **好处**:蒙版从"要先去别处画好一张图再传进来"变成应用里能做的一件事;属性和编辑各归其位(值由工作流算的不会被
  烘焙进图片,而烘焙进去的那一下是用户自己按的)。
- **代价**:蒙版素材会变多(每画一次一张)。缓解:名字带来源(「蒙版 · <原图名>」)、选择器按标签过滤、跟别的素材一样可删。
- **需要记住的**:契约是**黑白图 + 红通道**。任何"顺手用 alpha 表示蒙版"的改动都会让整块蒙版失效,而且是静默失效
  (读出来全空 = 什么都不重绘)。

## 实现记录

- **第二步(编辑)已实现**(2026-10-12):`components/generation/MaskEditor.tsx`(全屏对话框:笔刷/橡皮/矩形/椭圆、
  撤销重做、清空、反选、羽化、按亮度/alpha 从底图起手、显示底图开关),像素运算全在纯函数 `lib/maskPixels.ts` 里
  (`r=g=b`、alpha 填满 255 —— 契约那两条就守在这里);导出走离屏画布,落成素材(名字「蒙版 · <原图名>」)。
  入口:`FrameSlotField` 的可选 `onDrawMask` / `onEditMask`(空槽多一格「画一张」,已填的格子角上一支铅笔),
  由 `GenerateWorkspace` 在 `role === "mask"` 时接上;底图取同一组里第一张已填的素材。
  底图经 fetch → blob → 对象 URL 再进画布:直接把后端源给 `<img>` 会污染画布,`getImageData` / `toBlob` 全抛
  SecurityError,而"按阈值初始化"和导出两件事都要它。
- **第一步(属性归组)已实现**(2026-10-12):判据是**沿 MASK 这条线走**,不是一张「类名 → 属性名」的表(维护者否掉的正是后者:
  「一旦控件名称变了就出问题了」)。插件 `graph.mask_path`(`mask_sources` 从已经认成蒙版的槽位出发:LoadImageMask/alpha 那一路,
  `mask_outputs` 按 `object_info` 里声明的**类型**认哪个输出是 MASK)交回这条线上的节点,**按沿线先后**;`graph.items` 给这条线上
  每个节点**能在表单上调的格子**标一个 `mask_property`(1 起数的位置 —— 位置而不是一个是非:items 本身的顺序是常用程度,
  界面那一组要按沿线摆)。名字一个都不新起:还是既有的命名链(见 labels)。宿主 `WorkflowFillableOut.mask_property` 原样透出;
  前端精简表单的「工作流里能填的」那一列把这几格归成头一组「蒙版属性」(SourcePanel / `workflowAppForm.sourceGroups`)。
  测试:改了类名和控件名的节点照样进组、只是名字里带 mask 的不进、顺序按沿线。
- **补:一张图两用时的蒙版槽**(2026-10-12):维护者那张 Qwen 图里 `LoadImage` 一个节点两用 —— IMAGE 输出喂参考图、
  MASK 输出喂 Inpaint Crop 的 `mask`;此前只在「这张图**只**被当蒙版用」时才认成蒙版来源,于是它只落成了参考图,
  表单上没有能换蒙版的那一格。判据改成**连线两头的声明类型**(`graph.wired_mask_sources`:`mask_outputs` 那一头是
  MASK、`mask_inputs` 那一头也是 MASK 就算,不记类名/控件名/中文词),`graph.slots` 于是给同一个节点**两格**
  (参考图那格指着 `image`、蒙版那格指着 `mask` —— 两格两个 key,应用表单的标记和描述符的 `source_keys` 才分得开),
  既有那条(alpha 那一路,`alpha_masks`)不回退,没接到任何 MASK 输入的图不多出蒙版槽。给的蒙版另起一个读红通道的
  `LoadImageMask` 接在**那个节点声明成 MASK 的输出**上(那张图自己的那一格不动,`wire_inputs` / `put_input`),
  跟着图一起来的蒙版不给也能跑(不是「必须给」)。
- **补:蒙版槽里的彩色图是参考底图,不是底稿**(2026-10-16,维护者拍板):蒙版那一格的 `accept` 是 `image/*`,
  用户能把一张**彩色**的图传进去。**灰度的**照旧 = 「已有的那张蒙版」,当底稿接着画(决定 5);
  **彩色的**不再当底稿 —— 它当**参考底图**(和 `source` 那一格同一个槽位),蒙版从空白开始画,屏幕上看到的
  就是那张彩色的图。判据在 `MaskEditor` 的 `isGrayscaleImage`:每个像素任意两通道相差 ≤ 2 才算灰度
  (灰度 JPEG 解码后各通道会差 1,不能因此判成彩色)。`source`(参考图 / 首帧)在的时候**它就是**底图,
  彩色 initial 不抢,只被忽略成底稿。存回去的仍然是灰度蒙版(决定 1 不变);`maskPixels.paste` 的
  `normalizeGray` 留着当兜底 —— 容差之内的近灰图照样当底稿铺进蒙版,那一下归一就是它兜的。
