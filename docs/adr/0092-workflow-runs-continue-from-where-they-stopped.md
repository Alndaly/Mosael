# ADR 0092 · 工作流运行从中断处继续

- 状态:**已采纳**(2026-11-04)。维护者要做任意长度的视频:30 段跑到第 20 段断了,不能全部重来。
- 关联:ADR 0047(运行要主人认可的那一版)、ADR 0063(控制边)。「等人确认」的检查点见 `workflows/graph_run.GraphResume`。

## 背景

运行失败、被取消、被后端重启打断之后,只能重新跑一遍。前面已经付过钱的节点再付一次。

「等人确认」已经有一份现场(`GraphResume`),但它解决不了这件事:

- 现场在暂停那一刻整份写一次。失败和重启不会预告,等不到那一刻;
- 只有顶层。一条长循环是**一个**顶层节点,断在第 20 轮时,顶层看到的是这个节点没跑完,里面 19 轮全部作废。

## 决定

### 1. 每个节点落定时记一行

新表 `workflow_run_steps`:`(job_id, scope, node_id) → outputs`。

- **和节点自己的工作同一个事务**(引擎 `run_node` 里 `node_db.commit()` 之前)。产物和这一行要么都在,要么都不在;
- `scope` 是这个节点在哪一层图:顶层空串,循环第 4 轮 `L/#3`,嵌套往下接。同一个体内节点每一轮是不同的一步;
- 存完整产物,不是事件里的有界快照:下游插值要的是完整值;
- 运行成功也留着(重做要用),随任务级联删除。

### 2. 继续就是再跑一遍,每一层图先读回自己落定的节点

`run_graph` 开跑前按 `scope` 读回 `recorded`,并进 `context` / `executed` / `done`,和 `GraphResume` 同一条路。

循环不用另写续跑逻辑:跑完的那几轮里节点全部落定,这一轮瞬间走完,交出的还是当时那份,`loop.previous` 也就接上了。
被条件分支跳过的节点不用记:调度时照原来的产物算出同一个结果。

### 3. 还是同一条运行、同一版图

`POST /workflows/{id}/runs/{job}/continue`:`jobs.reopen_job` 把任务拨回排队,接着跑的线程拿钉住的那一版修订。花费和执行历史都接在这一条上。
拨回是一条带条件的 UPDATE,点两下只有一次生效。

**不用当前版的图**:节点 id 对得上、含义却可能已经变了,接上去的产物和新图对不上。要改图就重新跑。

### 4. 交出去的单接回来

节点等子任务时被打断,节点没落定,但那张单还在跑、钱也在花。节点下单时记下这张单(`held`),接着跑时认它,不下第二次单。
单失败或被取消了才重新下。

**一张单按「要的是什么」认,不按第几张认。** `held` 是「要求的指纹 → 子任务 id」,一个节点可以记好几张:

- 单节点的单,要求就是解析后的节点配置。调整参数再继续时配置变了,旧单认不上,下新单,不会把旧参数的产物当成调整后的结果;
- 改口型一块一块下单,要求是块的缓存键。第二遍时改好的块走缓存不下单,按序号认的话第二块会认到第一块的单上;
- 资产补角度按角度和提示词认,调起子工作流按传入的参数认。

所有 `wait_for_job` 的节点都走 `run_steps`(配音、转写、导出、截取、发布、分离、降噪、字幕配音……),由测试扫一遍:
新节点自己下单不记账,接着跑就是第二次付钱。例外是解析文档,它认的是素材上那条进行中的解析。

### 5. 调整之后继续,从第几轮重做

续跑时常常要改点什么:花费到了上限、尾巴比模型的下限短。`params` 改开始参数,**只影响还没落定的节点**。

`redo` 从顶层循环的第几轮重做:忘掉那一轮及之后的步骤、循环自己和它的下游,之前的几轮留着;`item` 换掉那一轮的内容,
记在任务载荷上。成功的运行也能重做。下游要重摆时间线的模板把生成和上时间线分成两个循环,时间线先清空。

### 6. 调起的子工作流接着跑

`call_workflow` 记下它调起的子运行。外层接着跑时,子运行失败了就继续它,成功了就用它的结果,不重新调。

### 7. 重启之后不自动继续,等人点

`reconcile_orphaned_jobs` 照旧判失败。打断时在跑的节点要重跑一遍,而它可能是发布、发消息、操作浏览器这种有外部效果的动作,
重做不重做要人来定。

## 不做

- **别的工作流调起来的子运行不单独继续**:由外层接着跑时带着它走。
- **插件工具不接回**:它在节点线程里同步跑一个插件进程,后端一断进程就没了,没有一张还在跑的单可认,接着跑时只能重跑。

## 后果

- 每个节点多写一行 JSON。产物存不成 JSON 的节点不记,继续时重做,并记一条警告日志。
- 运行的步骤记录留到任务被保留清理删掉。

## 实测(2026-11-04)

逐段续写是这件事的第一个用户(模板 `long_take_video`),真机跑出来的结论:

| | 万相 2.7 i2v(`first_clip`) | ComfyUI H3(`MiniMaxH3AddGuide` 第 0 帧) |
|---|---|---|
| 成片开头 | 是那段尾巴,但被压缩约 7%(59 帧占 55 帧) | 是那段尾巴的近似重绘(PSNR 约 29–34),长度不变 |
| `duration` / `length` | 含尾巴的总长 | 含重叠的总长 |
| 尾巴下限 | 2 秒(`duration should be at least 2s`) | 5 / 22 / 39 帧 |
| 接缝 | 按画面找:跳变 8.6,片内运动 13.4;按固定秒数截:30.5 | 跳变是片内运动的 1.2–1.4 倍 |
| 走样 | 只跑了两段 | 5 段人物一致,亮度随场景上升,末帧清晰度 5.5 → 3.8 |

所以接缝不按秒数算,在画面里找(`media/seam.py`、节点 `video_seam`)。

一次真实运行还验证了本文的流程:续写因尾巴太短失败,改参数、从第 1 轮重做后跑完,第一段没有重新付钱。

## 整片模板:超长的一镜接着往下拍

每镜秒数超过模型一次能出的,这一镜自动分段(模板 v14,`_shot_chain`):

- `chain_plan` 算每段几秒、续写几次,放得下就一段。只有几档时长的模型取够长的最短一档,多出来的上时间线时截掉;
- 第一段还是原来的 `generate_clip`(首尾帧、参考那两条路不变),之后逐段续写,嵌在每一镜的循环里;
- `video_join` 接成**一份素材**。时间线、口播对齐、字幕都还是一镜一份,不知道它是接出来的。

续写用同一个模型:收 `first_clip` 交尾巴,否则交最后一帧。两样都不收、或者还没挑模型(官网副本)就不分段,超了由运行前检查拦。
嵌套循环的 `loop.previous` 是内层自己的,外层照样能三镜同时跑。

**每一段只演自己那一截(v15)。** 第一次真跑(Seedance,一镜 35 秒拍两个 18 秒)接缝是断的:第 18 秒老人已经到门口,下一刻又回到街上。
两处都错在把整镜的东西交给了每一段:

- 尾帧交给了第一段,它在 18 秒里把 35 秒的戏走完;
- 分镜提示词写的是整镜的节拍,第二段照着从头再演一遍。

现在尾帧落在最后一段(`chain_plan` 的 `last_frame`),每段的提示词写明演第几秒到第几秒、不重演之前的。

同一次运行还发现一镜几十秒时口播一条上屏,出了画面:`generate_subtitles` 加了 `break_long_lines`,在标点处切成一行放得下的几条,时间按字数分。

## 越拍越不像时拉回来:锚点帧

段段相接,走样也段段相传(实测 H3 五段,清晰度 5.5 → 3.8)。模型收尾帧(万相 2.7 收 `first_clip + last_frame`)、又有收参考图的
图片模型时,「任意长度的连续视频」(v4)多一格 `anchor_every`:每 N 段照上一段的最后一帧和点名的资产画一张,当这一段的尾帧。

- 默认 0,不画:每张都是一次付费出图;
- 「到了哪一轮」是条件节点新的比较方式 `every`,循环里通用,左边填 `{{loop.index}}`;
- 没到那一轮时画图的节点跳过,`{{anchor.asset_id}}:last_frame` 展开成空,漏斗丢掉这一项,这一段和没开时一样;
- 估算费用不算这几张图,花费上限按实际花的算,所以照样拦得住。

整片模板的超长一镜不加:它一镜接两三段,还走不到要拉回来的长度。

## 隧道断一下不让运行失败

经隧道连远端 ComfyUI 时,连接时不时被掐断。实测 ComfyUI 一直正常,是请求没到它那边:本机端口连得上,收不到回答。此前提交只发一次、读只重试一次,抖一下整条运行就失败。

插件在跑任务时(`Comfy.ride_out_drops`)隔 2、5、10、20、30 秒再试,都不通才算连不上。列表、探活不开这一条,要立刻说清连不连得上。

提交不能盲目重发:没等到回答不等于没收到。任务号由插件定好带上(`prompt_id`),断连后先问队列和历史,到了就认,没到才再发。老版本 ComfyUI 不认这个字段时,回答丢了会在那台机器上多跑一遍。

断得比这久(实测有十几分钟的半死状态)重试也没用,靠「从中断处继续」。

## 真跑验证(2026-11-04)

- **万相整片(一镜 22 秒,拍成 13 + 13):** 接缝连续,人物从街上走到门口、进店,故事没有重演;尾帧落在第二段;字幕切成几条,都在画面内。
- **万相长片的锚点帧(`anchor_every` 1,三段):** 每段都画了图,`first_clip + last_frame` 百炼收下,人物全程一致。
- 这两次抓到几个只有真跑才露出来的问题,都已修:百炼严格校验尾巴下限(1.999932 秒被拒,尾巴多留 0.1 秒);音轨比画面长时「最后一帧」落在画面结束之后;
  尾巴几乎不动时接缝取到了平台开头,画面重放约 1.5 秒(改成取平台末尾)。
- **MiniMax H3 在 Mosael 里跑通(5 段 18.6 秒):** 接缝都在第 22 帧,全片和每段原片都检测不到切点,人物一致。
  只写「接着发生什么」时模型会在尾巴结束处硬切、人物样子也变;每段带上开场描述之后消失,只改这一条前后对比过。
- H3 的续写工作流没有接尾帧,`anchor_every` 对它不起作用,长片走样还没有解法。
- 模型心算段数不可靠:只说「总时长约多少」时交回过空的 `next`,要 18 秒只出了 4.46 秒。现在 `chain_plan` 先算好写进提示词。
