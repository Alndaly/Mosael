# 0110 图片格上的「裁切」和「重绘」：一个框定范围、一个画出要改的地方

- 状态：已采纳
- 日期：2026-11-24
- 相关：ADR 0025（能力住在内容格上）、ADR 0056 / 0057（蒙版：一种形状、一个编辑器）、ADR 0107（画板上的蒙版槽）、
  ADR 0108（打光：主控件摆在面板主体里）、`nodeForms/stageEditors`

## 背景

维护者：「重绘也应该作为一种能力，以及图片的裁剪」。图片格的操作条上已有放大、扩图、宫格切分、看图写字、灯光，
却没有最常用的两件：**框一块留下来**（裁切），**涂一块让模型改**（局部重绘）。

此前要做局部重绘只有一条绕路：开一个生成格、选一个声明了蒙版的模型、在蒙版槽里画（ADR 0107），再把原图连过去当参考。
而且目录里内置的图片模型**没有一个开放蒙版这个角色**（`generation_catalog/descriptors/image.py` 的注释），只有
ComfyUI 上读蒙版的工作流会出现 —— 多数人根本走不通。

## 决定

两个内置节点，都是 `surfaces: ["workflow", "board"]`：画板上照 ADR 0025 自动成了图片格的能力，工作流、智能体也能用。
产出都落成右边新的一格，原图不动（来源链记一笔，`assets/lineage` 新增 `crop`、`inpaint` 两种操作）。

### 1. 裁切 `image_crop`：四个数，本机切，不花钱

| 字段 | 范围 | 意思 |
| --- | --- | --- |
| `crop_x` / `crop_y` | 0–1 | 框的左上角，占**摆正后**原图宽 / 高的比例 |
| `crop_width` / `crop_height` | 0–1 | 框的宽 / 高，同上 |

- 用比例不用像素：同一份设置换一张图（工作流里上游换了）照样说得通；智能体说「留中间一半」不用先查尺寸。
- 后端（`assets/image_crop.py`）先按 EXIF 摆正（和宫格切分同一条，否则框到的是侧着的那一边），再把比例换成像素、
  夹进图里；切出来不足 16 像素一边的报错。格式随原图（JPEG 还是 JPEG，其余 PNG）。
- **框的比例锁不进数据**：「1:1」「16:9」这些是控件上一键摆好一个最大的、居中的框，并在拖的时候保持比例 —— 摆好之后
  数据里只有那四个数。同一件事只有一种写法。

控件 `CropFrameField`（`editor: "crop_frame"`，另外三格 `edited_by: "crop_x"`）：原图铺满卡片宽（按原图宽高比定高，面板高了自己滚），框外压暗；拖框内移动，
拖四角 / 四边改大小；图的左下角是切出来的像素尺寸（放在比例那一排后面会折行、被面板底栏压住）；下面一排比例（自由、原图、1:1、4:3、3:4、16:9、9:16）。和打光的方向球一样
是**主控件**：画板能力面板摆在面板主体里，工作流检查器里是表单的一行。工作流里还没有具体的图时，按 4:3 画一块空的底。

智能体用新的 `crop_image`（确认卡，参数同样是四个比例），和 `split_image_grid` 同一个做法：本机切、确认完直接交回那张。

### 2. 重绘 `image_inpaint`：画出要改的地方，写一句改成什么，换回来的只有那一块

字段：`asset_id`（宿主，要改的图）、`mask_asset_id`（蒙版：白色是要改的地方）、`prompt`（那一块改成什么，必填）、
`model`（选项来源 `inpaint_models`）。

**蒙版就地画**：`mask_asset_id` 声明 `editor: "mask_paint"`，主控件是一张压了蒙版色的原图缩略和一颗「画要重绘的地方」
（有蒙版时是「接着画」）。点开就是 ADR 0057 的那个编辑器（`MaskEditor`），底图是这一格的图 —— 不另写编辑器，蒙版槽
（ADR 0107）用的也是它。存下来是一份新的蒙版素材（ADR 0056），出处是这张图。

**主控件的字段由控件自己填**：画板上不给它一组上游芯片，也不默认接上游（`composerFields`、`boardTools.defaultBindings`）——
连进来的图默认是参考，是不是蒙版只由人说，和 ADR 0107 同一条。

**模型：能改图的都能用，收蒙版的排在前面。** 只认收蒙版的模型，内置目录里一个都没有，这项能力就是摆设。所以：

- `inpaint_models`：收参考图、能跑起来（`requires_source` 每一条都由参考图或蒙版满足）的图片模型；**收蒙版的排前面**，
  留空时先用他设的默认（够格的话），否则用第一个收蒙版的，再否则第一个收参考图的（和打光挑模型同一处：`executors/reference_models.py`）；
- 下单（`executors/image_edit.py`，裁切的执行器也在这里）：原图是参考图；模型收蒙版就同时交蒙版（`role: "mask"`），提示词就是那一句；
  不收蒙版的，蒙版作为**第二张参考图**一起给（模型收得下两张时），提示词前面加一句「只改第二张图里白色标出的地方，
  其余保持原样」（按界面语言写，文案在 `node_catalog`）；画幅取原图宽 × 高（ADR 0094，同打光）。

**换回来的只有那一块（本机合成，`assets/inpaint_composite.py`）。** 无论哪种模型，结果都按蒙版贴回原图：生成图缩放到
原图尺寸，蒙版边缘羽化（短边的 1%，至少 2 像素），蒙版外逐像素是原图。通用改图模型会顺手改动别处（肤色、背景、
构图微移），收蒙版的模型也常把整张重新编码一遍 —— 「只改这一块」由合成保证，不由模型自觉。产出那一格就是合成的那张；
来源链记 `inpaint`，出处是原图、生成的那张、蒙版（含 AI 由生成的那张继承，见 lineage）。生成的那张照常留在素材库里
（是这次生成的记录），但记成中间产物 `inpaint_draft`（`assets/intermediates`）：素材库默认不列，画板上也不单独落一格。

### 3. 要大地方拖的那几项,点开就是一个弹窗(修订 ADR 0108 §4)

维护者:「有些交互应该变成点击弹窗的形式」,接着:「目前还是先有底部弹窗再点击弹窗中的按钮再弹窗,有些交互底部弹窗就可以
不用了」。裁切框、打光的方向球挂在格子下面的小面板里拖不准、在会滚动的面板里拖把手容易变成滚面板,还把下面那句挤到面板外;
从面板里再点开一层弹窗又多一跳。

于是主控件声明一个去处(`stageEditors` 的 `opens`):

- `dialog`(裁切框、方向球):点操作条上那一项**直接是一个弹窗**(`BoardComposerShell` 的 `dialog`),里面还是同一个样子 ——
  第一行是这一下对哪一格做什么,大控件、补的那句、「参数」、发送键都在里面;发出去就关,产出照常落在右边。弹窗的标题只给读屏,
  不再在第一行上面重写一遍;
- `panel`(重绘的蒙版):照常挂在格子下面。画蒙版本来就是一个整屏的编辑器,面板上要写的是那句「改成什么」。

工作流检查器里大控件照常是表单的一行(同一张表、同一个控件)。

## 不做

- 不在格子上直接涂（选中图片就地画）：ADR 0107「不做」里那条照旧 —— 涂完的蒙版落在哪、怎么和能力连起来都要另想；
  在能力面板里点开编辑器，底图就是这一格，路径已经够短。
- 裁切不带旋转、拉直、翻转：那是修图，不是「取一块」。要的时候另开一项。
- 重绘不做「按文字自动圈出要改的东西」（分割模型）：圈错了是一次付费生成白跑；蒙版编辑器里已有按颜色 / 亮度取的工具。

## 后果

- 图片格操作条多两项：裁切（`Crop`）、重绘（`Brush`）。
- 新增节点进节点目录和文案表；官网节点文档、画板指南跟着同步。
- 选通用改图模型时，重绘效果取决于它读不读得懂「第二张图是蒙版」；合成保证了蒙版外不变，蒙版里画得好不好看模型。
