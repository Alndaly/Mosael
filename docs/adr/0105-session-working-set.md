# 0105 会话持有关注上下文，不绑定项目

- 状态：已采纳（阶段 2）
- 日期：2026-11-18
- 相关：ADR 0104（AI Studio 默认入口）

## 背景

阶段 1 把 AI Studio 设为默认入口，但 Agent 仍没有“现在在操作什么”的显式状态。项目是壳层的一个全局 `projectId`，编辑器、项目列表和 Agent 各自推断；用户在 AI Studio 里换项目时，Agent 只能靠当前页面或对话内容猜。

这会让“把这段剪短”这类话缺少稳定指代，也无法让手机或其他客户端接续同一个工作上下文。

## 决策

`AgentSession` 新增 `working_set` JSON 列，当前形状：

```json
{ "project_id": "<project id>", "surface": "ai" }
```

- `project_id` 为空串表示没有指定关注项目；不继承壳层的全局项目，也不是“必须绑定”。
- `surface` 是当前关注面板（AI Studio、剪辑、素材、笔记、画板、场景、工作流、发布、调度、插件、项目浏览）。
- 会话创建和 PATCH 都可写；整份替换，不做字段级合并。
- 系统提示只在有项目或非 AI Studio 面板时注入一段上下文；它只用于理解“这个项目/这段/这里”等指代，不是权限、归属或作用域限制。Agent 仍可列项目、选项目、跨项目操作。
- 现有库通过一次性迁移补列，默认 `{}`；没有 nullable/回退读取分支。

阶段 2 不加入选中素材、时间线选区或面板宿主；这些在后续阶段扩展同一个结构。

后续补充：`selection` 可选字段只承载“当前选区”这类指代信息（如 sequence_id / clip_ids、asset_ids / preview_asset_id），不构成项目绑定；编辑器和素材库的选区变化会同步到会话。

## 后果

- AI Studio 不提供手动项目选择器：项目由 Agent 自己分析、选择;会话的 `working_set` 留给 Agent/其他客户端写入。
- 关注上下文不依赖壳层全局 projectId；没有手动选择器，不会让用户误以为会话被绑在某个项目上。
- 会话从旧版本升级后默认没有关注项目；这是真实状态，不伪造成某个项目，Agent 按请求自行查找/选择。
- 权限模型不变：关注上下文只提供指代，写操作仍走工具、角色与确认卡。
