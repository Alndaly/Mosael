# ADR 0103 · 智能体能「听」音频:能量的由代码量,判断交给模型

- 状态:**已采纳**(2026-11-16)
- 关联:ADR 0100(按能力挑生成)、`app/media/loudness.py`(铺配乐按实际响度定增益)、
  `analyze_asset`(看图 / 看视频,只收 image / video)。

## 背景

做小红书推广片时,智能体给片子配了一段 BGM,维护者一听「明显是有问题的」。智能体重做了一版,然后只能说:
「我这里没有办法真正试听音频,音乐的听感只能由你判断,麻烦你听一下」。

它确实听不到:`analyze_asset` 只收图和视频,音频素材直接拒掉;会话用的对话模型(Kimi、DeepSeek、本地模型)
大多也不收音频输入。于是配音、配乐、音色挑选这几件事,**每一版都要人去听**才知道对不对。

而维护者让 Claude 在会话外看那两段 BGM 时,不靠耳朵也说清楚了问题在哪:被否掉的那版峰值 +0.1 dBFS(削波),
4.4–5.8 秒几乎全空,13–16 秒三下孤立的满频带脉冲(爆音);新的那版鼓点均匀、没有断、结尾自然淡出,
但时间线上裁成 22 秒的那份是硬切的。这些全是**量出来的**:响度、峰值、静音段、频谱图。

## 决定

### 1. 量和判分开

和 video-shots 拉片同一条分工:**能量的都由代码量**(ffmpeg 解码 + numpy,确定、免费、离线、毫秒到秒级),
模型只做它真正该做的判断(这段适不适合这支片子、两个音色哪个更像旁白)。每一条「问题」都带时间点和量到的数,
模型复述时有据可查,而不是凭印象说「听起来不错」。

### 2. 量什么

`app/media/listening/`(纯测量,不碰数据库,输入一个文件路径和可选的 [起, 止)):

| 模块 | 量什么 | 给谁用 |
|---|---|---|
| `levels` | 整体响度 LUFS、响度范围 LRA、真峰值 dBTP、削波样本数、直流偏移、声道相关性(单声道 / 反相) | 太轻太响、破音、左右抵消 |
| `gaps` | 中途的断(低于门限且超过 0.3 秒)、头尾静音、结尾是淡出还是硬切、孤立的爆音 | 「断断续续」「啪一下」 |
| `rhythm` | 起音强度包络 → 速度 BPM、节拍稳定度 | 卡点、和画面节奏对不对得上 |
| `timbre` | 频谱质心(明亮度)、滚降、平坦度(像噪声还是像乐音)、低 / 中 / 高三段能量占比、基频(中位数与范围、有声比例) | 音色差异、男声女声、闷不闷、刺不刺耳 |
| `sections` | 每 2 秒一格的响度与明亮度 | 前奏、高潮、段落起落 |
| `findings` | 由上面的数按固定阈值得出的问题清单(严重度、时间点、量到的数、文案 key) | 模型和界面直接读 |
| `spectrogram` | 一张带图例的频谱图(PNG) | 收图的模型自己看;界面卡片上给人看 |
| `compare` | 两段以上时,音色特征的差异表和距离 | 「这两个声音差在哪」 |

不引第三方音频库:解码交给已有的 ffmpeg,计算用已有的 numpy;librosa 一类会把 numba / llvmlite 带进桌面包。

### 3. 一个工具:`listen_to_audio`

- 参数:`asset_ids`(1–4 个,音频或视频 —— 视频听它的音轨)、可选 `start` / `end`(秒,只听一段)。
- 只读、不花钱、不确认(`effect="reads"`,素材的读闸);结果按 (文件, 窗口, 测量版本) 缓存在素材目录里,
  同一段再问不重算。
- 返回:每段一份报告(上表各项 + 问题清单)、两段以上时附比较表;频谱图作为图片块交给模型 ——
  **选中的模型收图才交**(sidecar 既有规则),不收图的模型照样读得到全部数字。
- `analyze_asset` 的说明里把音频指到这里;它自己仍然只看图和视频。

### 4. 界面

对话里这张工具卡按结果的形状认出来(`listening`),每段一行:时长、响度、峰值、速度,问题按严重度列出,
带时间点;下面是同一张频谱图(`GET /api/assets/{id}/spectrogram`,读同一份缓存)。

## 不做(这一版)

- **把音频原样交给收音频的模型**(Gemini、部分 MiniMax / Qwen-Omni 接口)。那是「按能力挑」的另一条路
  (ADR 0100 的思路:会话模型声明了 audio 输入才交),等会话里真的接上一个收音频的模型再做;到时这份测量报告
  仍然一起交过去,给它的判断一个可核对的底。
- 不做「好不好听」的打分:那是审美,不是测量。

## 后果

- 智能体配完 BGM、配音之后能自己发现削波、断档、爆音、硬切、响度不合平台,不必每一版都请人去听;
  拿得出时间点和数字,人去听的时候也知道听哪儿。
- 音色比较有了依据(明亮度、基频、三段能量),挑旁白声音时能说出差别,而不是复述音色名。
- 测量是确定的:同一个文件同一个窗口永远同一份结果,能写测试钉住阈值。
