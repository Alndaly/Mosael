# ADR 0088:MosaelCloud 官方中转 —— 在 Mosael 里登录、按月 / 年订阅、积分为主 + 模型卡;网关只跑 Mosael 自己的适配器

## Status

Accepted — 2026-10-29(待拍板四条均按推荐:积分为主 + 模型卡、按月分批带有效期、先上预付周期、打包版默认官方地址)。修订 [ADR 0039](0039-mosael-cloud.md) 的「钱包 / 充值」一节,并**撤掉**它 §7「new-api 只当内网的对话路由」:
维护者 2026-10-29 定下**不接入 new-api**,网关对话与生成类都只跑 Mosael 自己的适配器。账号、合规、两套部署照旧。
法律部分仍只是方向性梳理,上线前由律师确认。

## Context

维护者(2026-10-29):「分析一下当前的 MosaelCloud 架构……注意现在打包版本的 MosaelCloud 有问题,显示『要接,设置环境变量
MOSAEL_CLOUD_URL』。后续打算官方接入常用的供应商作为中转,用户只需要在 Mosael 内登录 MosaelCloud 即可根据实际需求使用,
按月 / 年订阅,每个订阅有不同的模型的额度。先写一份文档,以及如果利用 new-api 是否会更容易。」

### 现在的 MosaelCloud 是什么样

```
 桌面端 Mosael(用户电脑)                         MosaelCloud(mosael.com,维护者的服务器)
 ┌──────────────────────────────────┐           ┌──────────────────────────────────────────┐
 │ 渲染层  设置 →「MosaelCloud 账号」 │           │ nginx: /api/cloud/* → 127.0.0.1:8901      │
 │   │                               │           │        /           → 官网 Next.js :3000    │
 │   ▼                               │  HTTPS    │ cloud/(FastAPI + SQLAlchemy,独立进程) │
 │ 本地后端 /api/cloud/v1/*  ────────┼──────────▶│  账号:邮箱验证码 / 密码 / GitHub / Google │
 │  · domain/cloud_binding           │  同源头 +  │  会话:HttpOnly cookie(cloud_sessions)  │
 │  · cloud_login 表:按本地用户存     │  会话cookie│  社区:分享、点赞收藏评论、通知、官方内容  │
 │    云端会话 cookie(密文)         │           │  库:PostgreSQL(生产)/ SQLite(开发)  │
 └──────────────────────────────────┘           └──────────────────────────────────────────┘
```

- **两套身份,互不引用**(`docs/CLOUD_ACCOUNTS.md`):本地 `users` 管这台机器;Cloud 的 `cloud_users` 管官网账号。
  桌面端经本地后端**反代**到 Cloud(Cloud 只认官网同源、不开 CORS),登录后云端会话 cookie 按本地用户加密存进 `cloud_login`,
  渲染层看不到它。
- **Cloud 现在只有「账号 + 社区分享」**:没有模型、没有计量、没有钱。ADR 0039 设想的钱包、网关、`packages/mosael-providers`
  **一样都还没做**。
- **线上是通的**:`https://mosael.com/api/cloud/v1/health` → `{"status":"ok"}`(2026-10-29)。

### 打包版为什么显示「要接,设置环境变量 MOSAEL_CLOUD_URL」

- 根因在默认值:`backend/app/core/config.py` 的 `cloud_url: str = ""`,空串在 `cloud_binding.require_configured()` 里就是
  「这个部署没接 Cloud」(503 `cloud_not_configured`),界面据此把登录按钮置灰并显示那句提示。
- 开发环境靠 `scripts/dev-services.sh` / 手写的 `MOSAEL_CLOUD_URL` 接上;**打包的 Electron 启动后端时没有注入这个变量**,
  安装版里它永远是空的。也就是说:**每一个安装版用户都看到了这句话**,而它让普通用户去设环境变量,本身也不该出现在产品里。
- 修法(和本 ADR 的方向一致,可以先单独做):
  1. **产品默认就是官方地址**:`cloud_url` 默认 `https://mosael.com/api/cloud/v1`,环境变量照旧能覆盖(开发指向本地 :8901、
     团队自部署指向自己的 Cloud);显式设成空 = 这个部署不接 Cloud(离线 / 内网部署)。
  2. **文案按读者分**:普通用户只看到「暂时连不上 MosaelCloud」;「设置 `MOSAEL_CLOUD_URL`」只出现在部署管理员能看到的地方
     (管理页 / 日志),不放在每个人的设置页里。
  3. 打包冒烟加一条:安装版的 `/api/cloud/v1/me` 不回 `cloud_not_configured`。

### 评估过的:new-api(2026-10-29 查证,结论是不接入)

- AGPL-3.0;擅长多上游渠道(多把 Key、优先级 / 权重、重试、故障切换)、OpenAI / Claude / Gemini 兼容接口、异步任务插件、按模型计价。
- 它的订阅额度是**全站一个池子**,不能按分组隔开([issue #3388](https://github.com/QuantumNous/new-api/issues/3388),
  另有跨分组扣额度的报告 [issue #5200](https://github.com/QuantumNous/new-api/issues/5200)),做不了按月分批的积分与模型卡。
- 对外接口是 OpenAI 兼容那一套,表达不了 Mosael 生成侧要的首尾帧、参考图角色、异步续等与回包核对(ADR 0039 §5)。
- 所以它能帮上的只剩「对话的多 Key 轮询与故障切换」。为这一件事多运维一个 AGPL 组件、多一套账号与计价的心智,不划算;
  这部分由网关用 Mosael 适配器自己做(§4)。取舍见文末「否决的方案」。

### 参考:TapNow 的套餐(2026-10-29 查证,官方定价页)

- **国内 / 国际是同一个产品**:国际版 `app.tapnow.ai`(Tamar AI Inc.,美元),国内版 `app.tapnow.media`
  (深圳盛健科技有限公司,粤ICP备2025482606号,人民币);前端同一版本、四档套餐与积分完全一样,¥7 ≈ $1。
  **两边都能切「银行卡 / 支付宝」**,列出的付款方式都是 Visa、Mastercard、银联、支付宝、Apple Pay、Google Pay(国内版也没有微信支付),
  看起来是同一家跨境收单、按站点换币种。
  同一批模型在国内页换了名字(Banana → Tap Nano)—— 那是它的合规判断,我们不照搬(ADR 0039:国内版只上境内已备案模型)。
- **统一积分(Tapies)为主**:每个模型标「多少积分一张 / 一秒」,定价页再折算成「最多能出多少张图、多少秒视频」给人看。
- **模型卡叠在积分之上**:套餐附送、也可单买「某模型无限用 N 天」(期间不扣积分,同一模型同时只跑一个免费任务),
  以及只能用在某个模型上的「模型积分」。
- **分批与有效期**:年 / 季 / 月付都**按月发放**,每批 60 天有效;单独充值的 3 年;新人赠送的 30 天;扣的时候先扣快到期的。
- 高档位充值有赠送比例、并发数与队列优先级不同;订阅原则上不退款,年付升级按已用月数折算。

## Decision

### 1. 产品形态:在 Mosael 里登录,订阅一个套餐,直接用官方配好的模型

```
 桌面端 Mosael                                 MosaelCloud(mosael.com)
 ┌──────────────────────────────┐            ┌─────────────────────────────────────────────────┐
 │ 设置 → MosaelCloud 账号       │  登录       │ 账号(已有)                                       │
 │  套餐 / 剩余额度 / 续费        │ ─────────▶ │ 订阅:套餐、周期、订单、支付回调                     │
 │ 供应商「Mosael Cloud」(自动)  │            │ 额度:积分(按月一批)+ 模型卡,预占 → 结算          │
 │  钥匙 = 这台设备的云端令牌      │ ─ 调用 ──▶ │ 网关 /gateway/v1:跑 packages/mosael-providers      │
 │  模型 / 参数 = 云端目录下发     │            │  对话 / 图片 / 视频 / 配音 / 音乐,同一套适配器       │
 │ 用量账本:记积分 / 模型卡扣减    │ ◀─ 用量 ── │  上游通道:每个模型若干条(多 Key、按优先级换下一条)  │
 └──────────────────────────────┘            │ 上游 Key 只在服务器上,从不下发                      │
                                             └─────────────────────────────────────────────────┘
```

- 在桌面端看来,「Mosael Cloud」就是**又一家供应商**:登录后自动出现一条连接,钥匙是**这台设备、这个本地用户**的云端令牌
  (不是会话 cookie:令牌可单独吊销、带作用域、不随网页登出失效)。用户自己配的连接照旧,Cloud 只是多一个选项。
- 用户在 Mosael 里看得到:当前套餐、每个模型这个周期还剩多少、何时重置 / 续费、升级入口。

### 2. 订阅与额度:积分为主 + 模型卡,Cloud 自己记,是唯一的事实来源

额度由 Cloud 自己记,是唯一的事实来源。形态是两层(参考 TapNow,见 Context):

- **积分**:一个通用钱包。每个套餐每月发一批积分;目录给每个模型标价(如「图片 50 积分 / 张」「视频 20 积分 / 秒」
  「对话 1 积分 / 千 token」),用哪个扣哪个,用户自己决定怎么花。设置页和定价页把积分折算成「约 N 张图 / N 秒视频」给人看。
- **模型卡**:只发给少数主打或贵的模型,做卖点,不必每个模型都开一格:
  - **次数卡**:「Kling 视频 30 条」,用卡时不扣积分,用完回到扣积分;
  - **无限时长卡**:「Kling 无限用 5 天」,期间不扣积分;**同一模型同时只跑一个免费任务**,防刷。
  - 卡随套餐附送(档位越高天数越多),以后也可单独购买。

| 表 | 内容 |
| --- | --- |
| `plans` | 套餐:名称、周期(月 / 季 / 年)、价格与币种、每月积分、是否在售、生效时间 |
| `plan_card_grants` | 套餐附送的模型卡:哪个模型(或模型族)、次数卡还是时长卡、次数 / 天数、发放节奏 |
| `subscriptions` | 用户订阅:套餐、状态、本周期起止、是否自动续费、支付方的订阅号 |
| `credit_batches` | 一批积分:来源(套餐月度 / 赠送 / 以后的加购)、数量、发放时间、到期时间;**余额是流水的结果** |
| `model_cards` | 一张模型卡:用户、模型、次数卡剩余次数或时长卡起止、来源、到期时间 |
| `usage_entries` | 只追加:预占、结算、释放、过期清零、人工调整,每条带调用 / 任务 id 和扣的是哪批积分或哪张卡 |
| `orders` | 购买与续费的订单、支付渠道单号、状态 |
| `device_tokens` | 桌面端令牌:用户、设备名、哈希、最近使用(库里叫 `cloud_device_tokens`;作用域等网关有了第二种调用方再加) |

- **一次调用怎么扣**(沿用 ADR 0039 §3 的冻结 / 结算思路,只是扣的是积分和卡,不是钱):
  1. **先看卡**:这个模型有可用的无限时长卡、且没有免费任务在跑 → 不扣积分;有次数卡 → 预占 1 次。
  2. **没卡扣积分**:按目录单价估算预占(对话按上限 token、图片按张、视频按秒),**先扣快到期的那批**。
  3. **都不够**就当场拒绝,告诉用户还差多少积分、下一批何时发放、可以升级哪一档。
  4. 完成后按上游回报的实际用量结算,多退少补;失败、取消、上游没收费的,全额释放(次数卡退回那 1 次)。
- **按月一批、带有效期**:年付 / 季付也按月发放,每批积分有效 60 天(当月没用完还能再用一个月,不无限累积),到期由流水
  记一笔「过期清零」。赠送的积分有效期更短(如 30 天)。具体天数是运营参数,写在 `plans` / 发放规则里,不写死在代码里。
- **单价可调、按时间生效**:模型的积分单价放在目录里,带生效时间;已经预占的调用按预占那一刻的单价结算。
- 平台成本另记一本:每次调用把上游的实际花费(适配器回包里的用量 × 上游价目)记下来,用来核对每个套餐、每个模型的毛利,
  不影响用户的积分。

### 3. 网关:Cloud 里多一个模块,对外是 Mosael 自己的协议

- 位置:`cloud/src/cloud/gateway/`,和账号同一个进程、同一个库(ADR 0039 让网关复用社区服务的账号;如今账号在 `cloud/`,网关就跟着
  `cloud/` 走)。前缀 `/api/cloud/v1/gateway`,鉴权只认 `device_tokens`。
- 接口沿用 ADR 0039 §5:`GET /catalog`(模型、参数声明、**积分单价**,以及**这个用户的积分余额与模型卡**)、`POST /chat`(流式)、
  `POST /jobs` / `GET /jobs/{id}` / `POST /jobs/{id}/cancel`(生成类,结果给短时效签名地址)。
- 桌面端的 `mosael-cloud` 适配器很薄:参数声明照目录下发(ADR 0015)、任务等待与重启续等照 ADR 0019、用量账本记「积分 / 模型卡扣减」
  —— 这家供应商**没有本地计价规则**,也不记人民币。

### 4. 上游通道:网关自己管,不接 new-api

- **对话也走 Mosael 适配器**:和生成类同一套 `packages/mosael-providers`(ADR 0039 §5),不另起一个转发服务。
  桌面端已有的对话适配器(OpenAI 兼容、Anthropic、Gemini 等)原样复用,流式、工具调用、思考档位这些能力不在中间丢一层。
- **上游通道表** `upstream_channels`:每个模型挂若干条通道(哪家、哪把 Key、哪个端点、优先级、启用与否、备注);Key 加密存,只在网关里解开。
- **故障切换只做最小的一版**:按优先级挑第一条可用通道;上游回 429 / 5xx / 超时就**在还没开始计费前**换下一条,
  并把那条通道冷却一会儿。权重分流、余额探测这些等真有多把 Key 跑满了再加,不预先做。
- **平台成本**:适配器回包里的用量 × 上游价目(桌面端已有的计价规则那一套)记进成本账,和用户扣的积分分开记。
- 管理入口:上游通道的增删、冷却状态、每日成本,先只给维护者在 Cloud 的管理接口里用,不做面向用户的界面。

### 5. 和别的方案比

| | 网关自己管上游(**本 ADR**) | 网关后面放 new-api 做对话路由 | 全交给 new-api |
| --- | --- | --- | --- |
| 积分按月分批、有效期、模型卡 | 能 | 能(额度在 Cloud) | **做不到** |
| 对话 / 生成同一套适配器与语义 | 是 | 对话一套、生成一套 | 生成语义丢失 |
| 要运维的东西 | Cloud 一个服务 | Cloud + new-api(AGPL) | new-api + Cloud 账号两套 |
| 多 Key 故障切换 | 自己写最小版本 | 现成 | 现成 |
| 上手速度 | 中 | 中 | 最快(只适合验证付费意愿) |

结论:多 Key 故障切换是 new-api 唯一真正省下的那一块,而它的最小版本只要几十行;换来的是少一个组件、一套适配器、一本账。

### 6. 支付与续费

- **国内版**:先做「按周期预付」(买一个月 / 一年,到期不自动扣),微信 / 支付宝原生二维码在应用里扫。自动续费(微信 / 支付宝的
  周期扣款)要单独的商户资质,且有到期前提醒、一键取消等要求,放到第二步。
- **国际版**:Paddle / LemonSqueezy 这类代收方(Merchant of Record)的订阅产品,它们代办各国税务与发票,回调到 Cloud 发放额度。
- 支付回调只打到 Cloud;Cloud 按月发放积分批次与模型卡,应用里的套餐和额度靠轮询或推送刷新。
- 退款:未开始的周期全额退;已开始的周期按 ADR 0039 待拍板 #4 的思路写进用户协议(比如按未用天数或不退)。

### 7. 合规

ADR 0039 §8、§9 原样适用:国内版只上境内已备案的模型、ICP 证与生成式 AI 服务登记、实名、内容审核、生成内容标识、
日志留存六个月、投诉入口;国际版走代收方与 GDPR / 欧盟 AI 法案的透明度义务。订阅多出来的一条:**自动续费规则**
(国内要求显著提示、到期前通知、可随时取消),所以先上「按周期预付」。

### 8. 分阶段

0. **先修打包版的 Cloud 地址**(Context 那三条):不依赖本 ADR 的其余部分,下一个版本就能带上。**已完成(2026-10-29)**:`cloud_url` 默认官方地址、显式空 = 不接;用户文案改为「请联系部署管理员」;`/api/health` 报 `cloud`,打包冒烟要求 `configured`。
1. **设备令牌**:Cloud 加 `device_tokens`,桌面端登录后换一枚令牌存进本地密钥存储,「Mosael Cloud」连接出现在供应商列表里
   (未登录时也列出,点了引导登录 —— ADR 0039 待拍板 #7)。**已完成(2026-10-29)**,落地时定下的几处:
   - 令牌 `mct_` + 256 位随机串,库里只存 sha256;不过期,失效靠吊销(桌面端登出 `DELETE /device-tokens/current`、
     `DELETE /device-tokens/{id}`、删号级联)。**不是 Cloud 迁移 0004 拆掉的设备绑定**:没有设备码、没有官网确认配对;
   - 桌面端登录拿到会话 → `POST /device-tokens` 换令牌 → 立刻退掉那份会话,**本地只存令牌**(`cloud_login.device_token`,
     加密列;本地库 v45 迁移删掉旧的 cookie 形状,已登录的人重新登录一次)。社区分享等账号接口也改用令牌 ——
     账号接口两条路都认(浏览器 cookie / 桌面 Bearer),**一个请求只走一条**;网关 `/gateway/*` 只认令牌;
   - 网关第 1 步只有 `GET /gateway/me`(这枚令牌是谁、哪台设备),目录与对话随第 2 步加;
   - 供应商列表顶上的「Mosael Cloud」那一行跟着登录走、不可增删;部署关掉 Cloud 时不出现。
2. **抽包 + 目录 + 对话 + 积分**:先把 `backend/app/ai/providers` 抽成 `packages/mosael-providers`(桌面后端改依赖它、行为不变),网关才能复用对话适配器;`plans` / `subscriptions` / `credit_batches` / `usage_entries`(模型卡等生成类上了再加);
   网关 `/catalog`、`/chat`,`upstream_channels` 接 2–3 家对话模型;套餐先由管理员手动开通(不接支付),给内测用户。
3. **支付**:国内二维码预付、国际代收方订阅;订单、回调、发放与续期。
4. **生成类**:网关 `/jobs` 接图片 / 视频 / 配音 / 音乐,按秒 / 张扣积分;`plan_card_grants` / `model_cards` 随之上线。
5. **上线前**:审核、标识、日志留存、投诉入口、用户协议与隐私政策;先内测,再开放。

| 1 | 额度的形态 | A 每个模型一份(严格按模型);B 纯积分;C 积分为主 + 模型卡(少数主打模型送次数 / 无限时长) | **C**。账只有「一个积分桶 + 几张卡」;用户自己决定怎么花,不会出现 A 模型用完、B 模型额度闲着;主打模型的「无限用」是最直接的卖点(TapNow 同款) |
| 2 | 年付怎么发放 | A 一次发一年;B 每月一批、每批有效期(如 60 天) | **B**。避免年付几天用光;有效期让积分不无限累积,对账和成本都可控(TapNow 同款) |
| 3 | 先上哪种支付 | A 预付周期;B 自动续费 | **A**。资质少、合规要求少;自动续费第二步 |
| 4 | 打包版 Cloud 地址 | A 默认官方地址、可覆盖;B 继续要求设环境变量 | **A**(已按此修完,见 §8 第 0 步) |

## 否决的方案

- **全交给 new-api**(用它的用户、订阅、支付,桌面端接一条 OpenAI 兼容连接):最快,但额度是全站一个池子,做不了积分分批与模型卡;
  两套账号;Mosael 的生成语义在 OpenAI 兼容接口那一层丢掉。
- **new-api 只做网关后面的对话路由**(本 ADR 初稿、ADR 0039 §7 的做法):它省下的只有多 Key 故障切换,代价是多运维一个 AGPL 组件、
  对话与生成两套上游接法、成本账要从两处拼。2026-10-29 维护者决定不接。

## 这一版不做

- 团队 / 组织订阅、子账号共享额度。
- 单独充值积分 / 加购积分包、单独购买模型卡:积分与卡的表结构已经留了来源字段,上线订阅之后再开。
- 云端 ComfyUI、租 GPU。

## Consequences

- Cloud 第一次替用户付上游的钱、第一次收用户的钱:额度流水与订单必须只追加、可对账;平台成本另记一本,用来看每个套餐赚不赚钱。
- 适配器包第一次被两个进程依赖(桌面后端与网关):它对数据库、任务表的隐式依赖要先拆干净(ADR 0039 Consequences 同一条)。
- 上游通道由我们自己管:某家挂了、Key 被限流,靠通道冷却与换下一条兜住;没有备用通道的模型会直接不可用,目录要能暂时下架它。
- 桌面端多一家「没有本地价格」的供应商:用量账本要能记「积分 / 模型卡」而不只是货币(`CostAmount` 之外加一种扣减记录)。
- 打包版默认连官方 Cloud:离线 / 内网部署要显式关掉,文档写清楚。
