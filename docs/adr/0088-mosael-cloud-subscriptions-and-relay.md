# ADR 0088:MosaelCloud 官方中转 —— 在 Mosael 里登录、按月 / 年订阅、每个套餐按模型给额度;new-api 只做内网的上游路由

## Status

Proposed — 2026-10-29。修订 [ADR 0039](0039-mosael-cloud.md) 的「钱包 / 充值」与「new-api 的位置」两节;账号、合规、两套部署、
网关跑 Mosael 自己的适配器这几条照旧。法律部分仍只是方向性梳理,上线前由律师确认。

## Context

维护者(2026-10-29):「分析一下当前的 MosaelCloud 架构……注意现在打包版本的 MosaelCloud 有问题,显示『要接,设置环境变量
MOSAEL_CLOUD_URL』。后续打算官方接入常用的供应商作为中转,用户只需要在 Mosael 内登录 MosaelCloud 即可根据实际需求使用,
按月 / 年订阅,每个订阅有不同的模型的额度。先写一份文档,以及如果利用 new-api 是否会更容易。」

### 现在的 MosaelCloud 是什么样

```
 桌面端 Mosael(用户电脑)                         MosaelCloud(mosael.com,维护者的服务器)
 ┌──────────────────────────────────┐           ┌──────────────────────────────────────────┐
 │ 渲染层  设置 →「MosaelCloud 账号」 │           │ nginx: /api/cloud/* → 127.0.0.1:8901      │
 │   │                               │           │        /           → 官网 Next.js :3000    │
 │   ▼                               │  HTTPS    │ cloud/(FastAPI + SQLAlchemy,独立进程) │
 │ 本地后端 /api/cloud/v1/*  ────────┼──────────▶│  账号:邮箱验证码 / 密码 / GitHub / Google │
 │  · domain/cloud_binding           │  同源头 +  │  会话:HttpOnly cookie(cloud_sessions)  │
 │  · cloud_login 表:按本地用户存     │  会话cookie│  社区:分享、点赞收藏评论、通知、官方内容  │
 │    云端会话 cookie(密文)         │           │  库:PostgreSQL(生产)/ SQLite(开发)  │
 └──────────────────────────────────┘           └──────────────────────────────────────────┘
```

- **两套身份,互不引用**(`docs/CLOUD_ACCOUNTS.md`):本地 `users` 管这台机器;Cloud 的 `cloud_users` 管官网账号。
  桌面端经本地后端**反代**到 Cloud(Cloud 只认官网同源、不开 CORS),登录后云端会话 cookie 按本地用户加密存进 `cloud_login`,
  渲染层看不到它。
- **Cloud 现在只有「账号 + 社区分享」**:没有模型、没有计量、没有钱。ADR 0039 设想的钱包、网关、`packages/mosael-providers`
  **一样都还没做**。
- **线上是通的**:`https://mosael.com/api/cloud/v1/health` → `{"status":"ok"}`(2026-10-29)。

### 打包版为什么显示「要接,设置环境变量 MOSAEL_CLOUD_URL」

- 根因在默认值:`backend/app/core/config.py` 的 `cloud_url: str = ""`,空串在 `cloud_binding.require_configured()` 里就是
  「这个部署没接 Cloud」(503 `cloud_not_configured`),界面据此把登录按钮置灰并显示那句提示。
- 开发环境靠 `scripts/dev-services.sh` / 手写的 `MOSAEL_CLOUD_URL` 接上;**打包的 Electron 启动后端时没有注入这个变量**,
  安装版里它永远是空的。也就是说:**每一个安装版用户都看到了这句话**,而它让普通用户去设环境变量,本身也不该出现在产品里。
- 修法(和本 ADR 的方向一致,可以先单独做):
  1. **产品默认就是官方地址**:`cloud_url` 默认 `https://mosael.com/api/cloud/v1`,环境变量照旧能覆盖(开发指向本地 :8901、
     团队自部署指向自己的 Cloud);显式设成空 = 这个部署不接 Cloud(离线 / 内网部署)。
  2. **文案按读者分**:普通用户只看到「暂时连不上 MosaelCloud」;「设置 `MOSAEL_CLOUD_URL`」只出现在部署管理员能看到的地方
     (管理页 / 日志),不放在每个人的设置页里。
  3. 打包冒烟加一条:安装版的 `/api/cloud/v1/me` 不回 `cloud_not_configured`。

### 外部事实:new-api(2026-10-29 查证)

- **许可证 AGPL-3.0**:改了代码再对外提供网络服务,要向使用者公开改动后的源码。不改源码、只用配置和插件不触发这一条。
- **它擅长的**:多上游渠道(同一家多把 Key、优先级 / 权重、重试、故障切换)、OpenAI / Claude / Gemini 兼容的对话与 Responses、
  图片 / 语音 / 向量,异步任务插件(视频、图片,rc.39 起图片生成也走插件,rc.47 起常规渠道与任务插件按优先级一起选),
  按模型倍率或表达式计价、用量日志、上游余额查询,用户 / 分组 / 令牌,OAuth 登录,多个带作用域的管理令牌(rc.41)。
- **它有「订阅」,但额度是全站一个池子**:订阅扣的是同一份额度,**不能按分组隔开**([issue #3388](https://github.com/QuantumNous/new-api/issues/3388),
  仍开着);还有「跨分组模型也能扣订阅额度」的报告([issue #5200](https://github.com/QuantumNous/new-api/issues/5200))。
  **没有「一个套餐里每个模型各一份额度」这种结构。**管理员可以按套餐 / 按用户重置订阅额度([PR #5952](https://github.com/QuantumNous/new-api/pull/5952))。
- 它对外的接口是 OpenAI 兼容那一套:**表达不了** Mosael 生成侧要的首尾帧、参考图角色、异步任务的接着等与回包核对
  (ADR 0039 §5 已经论证过,这一条没有变)。

## Decision

### 1. 产品形态:在 Mosael 里登录,订阅一个套餐,直接用官方配好的模型

```
 桌面端 Mosael                                 MosaelCloud(mosael.com)
 ┌──────────────────────────────┐            ┌─────────────────────────────────────────────────┐
 │ 设置 → MosaelCloud 账号       │  登录       │ 账号(已有)                                       │
 │  套餐 / 剩余额度 / 续费        │ ─────────▶ │ 订阅:套餐、周期、订单、支付回调                     │
 │ 供应商「Mosael Cloud」(自动)  │            │ 额度:套餐 × 模型 的额度桶,按周期发放,预占 → 结算    │
 │  钥匙 = 这台设备的云端令牌      │ ─ 调用 ──▶ │ 网关 /gateway/v1                                  │
 │  模型 / 参数 = 云端目录下发     │            │  ├─ 对话:→ 内网 new-api(多渠道、故障切换)         │
 │ 用量账本:记「订阅额度」扣减     │ ◀─ 用量 ── │  └─ 图片 / 视频 / 配音 / 音乐:→ Mosael 适配器包      │
 └──────────────────────────────┘            │ 上游 Key 只在服务器上,从不下发                      │
                                             └─────────────────────────────────────────────────┘
```

- 在桌面端看来,「Mosael Cloud」就是**又一家供应商**:登录后自动出现一条连接,钥匙是**这台设备、这个本地用户**的云端令牌
  (不是会话 cookie:令牌可单独吊销、带作用域、不随网页登出失效)。用户自己配的连接照旧,Cloud 只是多一个选项。
- 用户在 Mosael 里看得到:当前套餐、每个模型这个周期还剩多少、何时重置 / 续费、升级入口。

### 2. 订阅与额度:Cloud 自己记,是唯一的事实来源

new-api 的订阅做不到「每个模型各一份额度」,而这正是需求本身,所以额度**不交给 new-api**,由 Cloud 记:

| 表 | 内容 |
| --- | --- |
| `plans` | 套餐:名称、周期(月 / 年)、价格与币种、是否在售、生效时间 |
| `plan_allowances` | 套餐 × 模型(或模型族)的额度:单位(次 / 张 / 秒 / 千 token / 积分)、每周期数量 |
| `subscriptions` | 用户订阅:套餐、状态、本周期起止、是否自动续费、支付方的订阅号 |
| `allowance_buckets` | 某订阅某周期某模型的桶:发放量、已用、预占;**余额是流水的结果** |
| `usage_entries` | 只追加:预占、结算、释放、人工调整,每条带调用 / 任务 id |
| `orders` | 购买与续费的订单、支付渠道单号、状态 |
| `device_tokens` | 桌面端令牌:用户、设备名、哈希、作用域、最近使用 |

- **一次调用 = 预占 → 结算 → 释放**(沿用 ADR 0039 §3 的冻结 / 结算思路,只是扣的是额度桶不是钱):
  1. 提交前按目录估算预占(对话按上限 token、图片按张、视频按秒);桶里不够就当场拒绝,告诉用户差多少、何时重置。
  2. 完成后按上游回报的实际用量结算,多退少补。
  3. 失败、取消、上游没收费的,全额释放。
- **年付也按月发放**额度(年付 = 12 个月的桶,每月重置),避免一次性发一年的量被几天用光。
- **不跨模型挪用**:A 模型用完不扣 B 模型的桶。要不要加「通用积分桶」兜底(用完专属额度后按单价扣积分)见待拍板 #2。
- 平台成本另记一本:每次调用把上游的实际花费(new-api 日志 / 适配器回包)记下来,用来核对每个套餐的毛利,不影响用户的额度。

### 3. 网关:Cloud 里多一个模块,对外是 Mosael 自己的协议

- 位置:`cloud/src/cloud/gateway/`,和账号同一个进程、同一个库(ADR 0039 让网关复用社区服务的账号;如今账号在 `cloud/`,网关就跟着
  `cloud/` 走)。前缀 `/api/cloud/v1/gateway`,鉴权只认 `device_tokens`。
- 接口沿用 ADR 0039 §5:`GET /catalog`(模型、参数声明、单位、**这个用户套餐里的额度**)、`POST /chat`(流式)、
  `POST /jobs` / `GET /jobs/{id}` / `POST /jobs/{id}/cancel`(生成类,结果给短时效签名地址)。
- 桌面端的 `mosael-cloud` 适配器很薄:参数声明照目录下发(ADR 0015)、任务等待与重启续等照 ADR 0019、用量账本记「订阅额度扣减」
  —— 这家供应商**没有本地计价规则**,也不记人民币。

### 4. new-api 放在网关后面,只做对话的上游路由

- **做什么**:对话类请求由网关转给内网的 new-api,用它的多渠道、多 Key 轮询、故障切换、上游余额查询;它的用量日志作为平台成本的对账来源。
- **不做什么**:不对公网开放、不开注册、不管 Mosael 用户、不卖订阅、不收钱。网关用一把带作用域的内部令牌调它;new-api 里只有
  「Mosael 网关」这一个用户,额度设成不限。
- **不改源码**:只用配置与任务插件。真要改,就照 AGPL 公开改动。
- 图片 / 视频 / 配音 / 音乐**先不走** new-api:用 Mosael 适配器包直连上游(ADR 0039 §5 的 `packages/mosael-providers`),
  保住首尾帧、参考图角色、异步续等这些语义。等 new-api 的任务插件覆盖了我们要上的模型、又不丢语义时,再按模型逐个评估迁过去。

### 5. 「全用 new-api」能不能更快:能,但只适合做内测验证

| | A. 全交给 new-api | B. Cloud 自己记订阅额度 + new-api 做对话路由(**推荐**) | C. 全部自建(不用 new-api) |
| --- | --- | --- | --- |
| 上手速度 | 最快(一两周):开 new-api 的注册 / 订阅 / 支付,桌面端加一条 OpenAI 兼容连接 | 中:订阅、额度、网关要写;上游路由现成 | 最慢:多渠道、重试、故障切换也要自己写 |
| 每个套餐按模型给额度 | **做不到**(全站一个额度池) | 能 | 能 |
| 在 Mosael 内登录、购买 | 两套账号(new-api 一套、Cloud 一套),或另做 SSO | 一套账号:Cloud | 一套账号 |
| Mosael 的生成语义 | 丢:首尾帧、参考图角色、续等、回包核对 | 保留 | 保留 |
| AGPL | 用户直接用的就是它,改一点就要公开 | 内网组件、不改源码 | 无 |
| 运维 | 一个组件 | 两个组件 | 一个组件,代码最多 |

**结论:new-api 让「接上游、管 Key、切故障」容易很多;让「订阅 + 按模型额度 + 在 Mosael 里买 + Mosael 的生成语义」更难。**
所以只把它用在前一件事上。如果想先用最少的代码验证有没有人愿意付费,可以先用 A 跑一个**只有对话、只给内测用户**的版本
(用 new-api 自带的订阅与支付),验证完再换成 B —— 但要接受 A 期间的账号、订单之后要迁移。

### 6. 支付与续费

- **国内版**:先做「按周期预付」(买一个月 / 一年,到期不自动扣),微信 / 支付宝原生二维码在应用里扫。自动续费(微信 / 支付宝的
  周期扣款)要单独的商户资质,且有到期前提醒、一键取消等要求,放到第二步。
- **国际版**:Paddle / LemonSqueezy 这类代收方(Merchant of Record)的订阅产品,它们代办各国税务与发票,回调到 Cloud 发放额度。
- 支付回调只打到 Cloud;Cloud 发放 / 续期额度桶,应用里的套餐和额度靠轮询或推送刷新。
- 退款:未开始的周期全额退;已开始的周期按 ADR 0039 待拍板 #4 的思路写进用户协议(比如按未用天数或不退)。

### 7. 合规

ADR 0039 §8、§9 原样适用:国内版只上境内已备案的模型、ICP 证与生成式 AI 服务登记、实名、内容审核、生成内容标识、
日志留存六个月、投诉入口;国际版走代收方与 GDPR / 欧盟 AI 法案的透明度义务。订阅多出来的一条:**自动续费规则**
(国内要求显著提示、到期前通知、可随时取消),所以先上「按周期预付」。

### 8. 分阶段

0. **先修打包版的 Cloud 地址**(Context 那三条):不依赖本 ADR 的其余部分,下一个版本就能带上。**已完成(2026-10-29)**:`cloud_url` 默认官方地址、显式空 = 不接;用户文案改为「请联系部署管理员」;`/api/health` 报 `cloud`,打包冒烟要求 `configured`。
1. **设备令牌**:Cloud 加 `device_tokens`,桌面端登录后换一枚令牌存进本地密钥存储,「Mosael Cloud」连接出现在供应商列表里
   (未登录时也列出,点了引导登录 —— ADR 0039 待拍板 #7)。
2. **目录 + 对话 + 额度**:`plans` / `plan_allowances` / `subscriptions` / `allowance_buckets` / `usage_entries`;
   网关 `/catalog`、`/chat`;内网 new-api 接 2–3 家对话模型;套餐先由管理员手动开通(不接支付),给内测用户。
3. **支付**:国内二维码预付、国际代收方订阅;订单、回调、发放与续期。
4. **生成类**:抽 `packages/mosael-providers`,网关 `/jobs` 接图片 / 视频 / 配音 / 音乐,按秒 / 张 / 次扣额度。
5. **上线前**:审核、标识、日志留存、投诉入口、用户协议与隐私政策;先内测,再开放。

## 这一版不做

- 团队 / 组织订阅、子账号共享额度。
- 按量付费的钱包(ADR 0039 的预付余额)—— 待拍板 #2 选 C 时,积分桶由套餐发放,不单独充值。
- 云端 ComfyUI、租 GPU。

## Consequences

- Cloud 第一次替用户付上游的钱、第一次收用户的钱:额度流水与订单必须只追加、可对账;平台成本另记一本,用来看每个套餐赚不赚钱。
- new-api 成为线上依赖之一:它挂了,对话不可用但生成类不受影响;要给它单独的健康检查与告警。
- 桌面端多一家「没有本地价格」的供应商:用量账本要能记「额度单位」而不只是货币(`CostAmount` 之外加一种扣减记录)。
- 打包版默认连官方 Cloud:离线 / 内网部署要显式关掉,文档写清楚。
