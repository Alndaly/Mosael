# ADR 0078 · 发布自动化失败时,让智能体接手看清现场

- 状态:Proposed — 2026-10-23
- 相关:ADR 0076(内容形状)、ADR 0075(Computer Use)、ADR 0044(确认卡与措辞)
- 代码位置:`electron/browser/`(适配器与执行器)、`backend/app/domain/publish/`、`backend/mcp_server.py`

## 要解决什么

发布执行器是**写死的 RPA**:选择器 + 文案 + 几步固定动作。平台一改版,它就在某个没人预料到的地方停住,
而且**失败现场是一张截图加一句话** —— 用户看到「正文编辑器没有接受填入的描述」,却不知道页面当时长什么样、
还差什么。2026-10-23 一天里就撞了三种:

- 图文任务落在视频 tab 上(默认档不是图文),平台回一句「请先切换到图片tab」;
- 文案判据写错(页面上根本没有那句),于是「切过去了」被判成「没切过去」;
- 富文本把 `1. …` 变成有序列表,`innerText` 多了换行,「文字明明在编辑器里」被判成没填进去。

三次都不是"选择器过时"这种简单事,而是**我们对那一页的理解错了一点**。这类错误靠再加一层选择器修不掉。

## 决定

### 1. 失败时先留「可判读的现场」,再谈兜底

执行器每次失败,往 `browser-trace.log` 落一份 `publish-failure` 现场:

- 截图(整窗,已经归一化到 CSS 尺寸);
- 当前 URL、`document.title`、页面可见文字前 2000 字;
- 这一步期望什么(适配器声明的那一小段:目标选择器、期望文案、判定表达式);
- 页面上**候选元素**清单:与目标文案相近的前 10 个可点元素(标签、文字、位置),以及所有 `input[type=file]`
  的 `accept`。

有了它,失败从「一句话」变成「一页事实」。用户自己看也能明白,智能体分析也有了原料。

### 2. 兜底不是"让它自己发",是"让它给出下一步动作"

确认卡上多一条:**「让智能体看这一步」**。点了之后:

1. 取第 1 条的现场(截图 + 事实),交给一个**受限**的智能体回合:它只有 Computer Use 的
   `computer_screenshot` / `computer_click` / `computer_type` / `computer_scroll`(ADR 0075),
   没有发帖权、没有登录权、不能改任务参数;
2. 它要么**说明为什么卡住**(人话,进任务行),要么**给出下一步动作**:点哪个坐标、在哪个框里输入什么;
3. 动作执行后**回到执行器重跑这一步**(不是重跑整条任务),成功就继续,失败就把这次尝试也记进现场;
4. 全程最多 N 次(默认 3),超了就停在「需要人处理」并保留现场。

**为什么不是让智能体直接接管整条发布**:发布是 external 档、一次不可逆。让它在人已经确认过参数之后
只负责"这一步该怎么点",风险面小得多;而"发什么、发给谁"仍然由用户与执行器决定。

### 3. 学到的东西要留下

智能体给出的动作一旦成功,记进 `browser-trace.log` 的 `publish-heal`:
`platform / kind / step / 它做了什么 / 成功与否`。这不是自动改代码,而是**给下次改选择器的人一份证据**:
同一处反复 heal,就该把那条写进 `selectors.ts`。适配器仍然只有一份选择器表,智能体不进那张表。

### 4. 借鉴开源实现的四条硬约束

读 [social-auto-upload](https://github.com/dreammis/social-auto-upload)(`uploader/xiaohongshu_uploader/main.py`)、
[MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 这类项目,它们的存活策略是一致的,我们照抄:

1. **优先直达带参数的地址**(`?target=image`),而不是「进去再点 tab」;
2. **输入框按 `accept` 挑**,不要假设页面上只有一个;
3. **等待「成功的样子」而不是等固定秒数**(标题框出现 = 素材传完);
4. **可选步骤失败要能跳过**(话题候选没出现就跳过,并把已键的字退格删掉),别让增强项拖垮整条发布。

这四条已经是执行器的默认做法;第 4 条(标签跳过)**本轮补上**。

## 不做的

- 不让智能体自己决定「发不发、发给谁」;
- 不让智能体改任务参数(标题、正文、素材)—— 它只能执行/解释当前这一步;
- 不自动改写 `selectors.ts`( healed 的动作只进日志);
- 不做「无人值守的自我修复」:每次兜底都要用户点那一下确认卡。

## 后果

- 平台改版从「任务失败、用户困惑」变成「任务失败、现场可读、点一下可能就过去了」;
- 多一层确认卡与一次模型调用,只在**失败之后**发生,正常路径一分钱不花;
- 风险从"自动化能不能点中"转移到"模型会不会乱点" —— 用受限工具集 + 最多 3 次 + 每次回到执行器验证来兜住;
- 与 ADR 0076 的关系:内容形状是**能力**,本 ADR 是**失败时的降级路径**,两者独立可发。
