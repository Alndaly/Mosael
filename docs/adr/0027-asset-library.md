# ADR 0027:资产库 —— 人物、场景、道具

## Status

Accepted — 2026-09-27。维护者定了:资产按工作区管;资产能分享到社区。「风格」这一种先不做。

**修订 2026-09-27(同日):「分享到社区」暂缓。** 桌面应用对社区的接入整体拿掉了(见 ADR 0026 的修订),§4 和阶段 3 里
应用侧的「分享到社区 / 从社区导入」随之移除;分享包格式 `mosael.asset/1` 和社区服务那一侧的资产条目留在仓库里。
先把资产库本身做好(阶段 4、5 照旧)。

## Context

维护者提出(2026-09-27):「现在只有素材的概念,缺少资产管理的概念,比如人物资产、场景资产、道具资产 ——
这样做视频能便利很多,也方便后续的数字人。」

现状:

- **素材(`assets`)是文件**:一张图、一段视频、一段音频,靠标签和项目归类。它回答「这个文件是什么」,
  回答不了「这是谁」—— 同一个角色的正面照、侧面照、三视图、表情图是五个互不相识的文件。
- **「从主题到完整视频」模板每跑一次都重新造一遍角色和场景**:视觉圣经里写角色描述、画三视图、画场景设定图,
  之后每一镜都带着它们当参考。这些东西在那一次运行结束后散在素材库里,下一部片子要同一个角色,只能重新画、
  重新挑图,画出来还不一定像。
- **和「人」有关的东西各管各的**:可灵的主体库(2–4 张图建一个主体,`kling/elements.py`)、配音库的音色、
  3D 场景里的人偶颜色、数字人方案里的「形象」(`docs/design/digital-humans.md`)—— 说的都是同一个人,却没有
  一个地方把它们串起来。
- 提示词里能 `@` 素材(`mentioned_asset_ids`),但 `@` 的是一张图,不是一个角色。

## Decision

### 1. 资产是「一个有名字的东西」,素材是它的图

新增**资产**(界面上叫「资产」,和「素材」并列),三种:

| 种类 | 是什么 | 专有的东西 |
| --- | --- | --- |
| **人物** | 一个角色 / 一个人 | 音色(配音库)、授权声明(真人时,见数字人方案)、白模里的人偶颜色、服装 / 形态变体 |
| **场景** | 一个地点 | 关联的 3D 场景(白模、机位)、时间 / 天气 / 光线的说明 |
| **道具** | 一件物品 | 关联的 3D 模型素材 |

每个资产都有:

- 名字;
- 一段**描述**(给人看);
- 一段**提示词描述**(给模型看:外貌、服装、材质……,生成时自动带上);
- 一组**参考图**,每张标着角度或用途(正面 / 侧面 / 背面 / 三视图 / 特写 / 全身 / 表情 / 设定图 / 细节);
- 一张**封面**;
- 标签。

资产**属于工作区**,不挂在某个项目下:同一个角色常常跨项目用,归类靠标签。

参考图**就是素材库里的素材**,资产只是引用它们,不复制文件。一张图可以同时是素材库里的一个文件、也是某个
人物的「正面」。删资产不删素材;删素材时,引用它的资产少一张参考图,界面上提示。

**变体**:同一个人物的冬装、古装、少年时期,是挂在它下面的子资产。变体继承母体的提示词描述和音色,只换参考图
和服装描述 —— 「张三 · 冬装」和「张三」是同一个人,不是两个人。

### 2. 数据形状

两张新表(数据形状变化照例走迁移,[ADR 0006](0006-migrate-instead-of-branching.md)):

- `entities`:`id`、`workspace_id`、`kind`(`character` / `location` / `prop`)、`parent_id`
  (变体的母体,可空)、`name`、`description`、`prompt`、`cover_asset_id`、`attributes`(按种类的专有字段:
  人物的 `voice_id`、`blockout_color`、`consent`;场景的 `scene_id`、`time_of_day`;道具的 `model_asset_id`)、
  `tags`、时间戳。
- `entity_references`:`entity_id`、`asset_id`、`role`(角度 / 用途)、`position`。

表名用 `entities` 而不是 `assets`,因为 `assets` 已经是素材表;界面文案叫「资产」。

### 3. 用在哪里

**生成**(AI 工作台、画板、工作流的生成节点、智能体):

- 提示词里 `@张三`,就把张三的**提示词描述**拼进提示词,并按这个模型能收几张参考图,从他的参考图里挑最合适的
  几张(优先顺序:三视图 > 正面 > 全身 > 其余)挂成参考素材。
- 模型的参考图上限来自生成描述符(`source_limits`),**不猜**。挂不下时说清楚挂了哪几张。
- 可灵这类「先建主体再引用」的模型:用人物的参考图自动建主体,名字照旧按内容哈希算(`elements.py` 的做法),
  不另存映射表。

**画板**:

- 新的格子种类「资产格」:显示封面和名字,可以作为上游连给生成格,也可以在提示词里 `@`
  (和 [ADR 0025](0025-board-recipes-versions-and-ports.md) 的引用同一套)。
- 它的能力(按内容格能力的做法,挂在格子上):「补全多角度」(用一张正面图生成三视图 / 侧面 / 背面,新图直接挂进
  这个资产的参考图)、「生成表情」、人物的「让它说话」(数字人)。

**工作流**:

- 新的字段类型「选一个人物 / 场景 / 道具」(字段声明点名种类,和选 3D 场景同一种下拉)。
- 新节点「取资产」输出它的提示词描述和参考图,接到生成节点上。
- 「从主题到完整视频」改成**先认已有的资产**:视觉圣经里的角色和场景,能对上资产库里已有的,就直接用它的参考图、
  不再重画;新出现的,画完三视图 / 设定图后**存成资产**。于是第二部片子里的同一个角色,是同一张脸。

**3D 场景**:

- 场景资产关联一个 3D 场景(白模、机位);人物资产的人偶颜色在白模里沿用;
- 道具资产关联的 3D 模型可以一键放进场景。

**数字人**:人物资产就是数字人方案里的「形象」—— 一张脸(参考图)、一把嗓子(音色)、一份授权声明。
[数字人方案](../design/digital-humans.md)里的 `personas` 表不再单独建,改为人物资产上的字段;那份文档随本 ADR 修订。

**智能体**:`list_entities`、`get_entity`、`create_entity`、`attach_entity_reference` 几个工具;写提示词时会用
`@人物`,而不是挑图。

### 4. 分享到社区

资产可以发到社区([ADR 0026](0026-community-service.md)),别人一键导入到自己的工作区。

- **分享包** `mosael.asset/1`:种类、名字、描述、提示词描述、标签、种类的专有字段里**可以公开的那部分**
  (人物的白模颜色,场景的时间 / 天气说明)、参考图(文件 + 角度)与封面、变体(同样的形状,嵌在母体里)。
  **不带**:音色样本与音色 id、授权声明的原文、关联的 3D 场景与 3D 模型(那是另一种东西,另走分享)、本机 id。
  文件走 ADR 0026 的三步上传,按内容哈希去重。
- **真人肖像**:人物资产要声明是真人还是虚构。
  - 虚构人物、场景、道具:提交即上架,和工作流一样。
  - 真人:**必须**有「这是我本人」或「已取得本人同意公开」的授权声明才能提交,并且**先进审核队列**
    (和插件一样由 `moderator` 通过),审核界面并排显示参考图和声明。
  - 这对应《互联网信息服务深度合成管理规定》第十四条要求的单独同意(见[数字人方案](../design/digital-humans.md)
    的合规一节)。被举报冒用肖像的,下架并通知提交者。
- **社区侧**:新增条目种类 `asset`(列表按人物 / 场景 / 道具分),详情页是参考图墙和描述,有下载、点赞、举报、
  版本;官网社区多一个「资产」页签。
- **导入**:应用里「从社区导入」把参考图作为素材导入工作区,再建一个同样的资产(记下社区来源和版本,
  社区上有新版本时提示);导入的真人人物在本机默认标为「授权待你确认」,不能直接用于数字人,
  要本机用户自己确认后才解开。

### 5. 界面

- 左侧导航「素材」旁边加「资产」:
  - 上面按「人物 / 场景 / 道具」分页签;
  - 列表是封面卡片;
  - 详情页是一面参考图墙,每张标着角度,可以拖进来、换角度、设封面。
- 详情页旁边是描述、提示词描述、种类的专有字段(音色、3D 场景、授权……),再往下是**在哪里用过**(哪些画板、
  工作流运行、生成记录)和变体。
- 素材详情里多一行「属于哪些资产」;素材库里右键一张图「设为某个人物的正面」。

## 分阶段

1. 数据模型与迁移、资产页(列表、详情、参考图与角度、变体)、素材 ↔ 资产的双向显示、真人 / 虚构与授权声明、
   智能体工具。
2. 生成里的 `@资产`(提示词描述 + 按上限挑参考图,可灵自动建主体)、画板的资产格与引用。
3. 分享到社区:分享包、社区服务的 `asset` 条目与真人审核、官网「资产」页签、应用的发布与「从社区导入」。
4. 资产格的能力(补全多角度、生成表情)、工作流的字段类型与「取资产」节点、「从主题到完整视频」认已有资产并回存。
   - 已做:「取资产」「存成资产」节点;「补全多角度」「生成表情」是两个节点(`entity_angles` / `entity_expressions`),
     画板上是资产格的能力,资产详情页的参考图墙上也有(`POST /api/entities/{id}/draw` 起一个 `entity_draw` 任务跑同一个执行器)。
     每一张是一次 `@` 着这个资产的图片生成,只用收参考图的模型;画好按角度挂回。
   - 已做:「从主题到完整视频」先用「列资产」把库里的人物、场景交给定角色那一步(是同一个就原名沿用),角色 / 场景循环里
     「取资产」按名字认,有图就用、没有才画,画完「存成资产」(人物挂成三视图,场景挂成全景)。
   - **三种资产不是一个模板**(修订 2026-09-27):参考图的角度按种类分(`ROLES_BY_KIND`,场景的角度是机位:全景 / 反打 /
     俯视),生成时挑图的先后也按种类;能力按宿主字段声明的种类挂(「生成表情」只挂在人物上,`host_entity_kinds`)。
5. 数字人:人物资产上的音色与「让它说话」(接数字人方案的阶段 1–2)。
