# ADR 0095 · 成片配乐:时间线上的一条「配乐」轨,带货口播按它铺一首

- 状态:**已采纳**(2026-11-09)。真跑带货口播后维护者说「生成的视频中背景音乐也没了」,选了「铺一条统一配乐」。
- 关联:ADR 0094(画幅;同一种「按节点输入的名字认」的约定)、`domain/voices/original_audio`(闪避)、
  `media/render_plan._duck_windows`(渲染时按闪避压低)。

## 背景

带货口播每一拍的视频是静音的(v7 起:画外音在说话,视频自带的声音会和它打架;Seedance 还顺手关掉出声省钱),
模板里也没有配乐这一步 —— 成片只剩旁白,两拍之间是空白。H3 的片段本身带配乐(素材里单独预览听得到),所以
维护者觉得「没了」。

## 决定

### 1. 「铺配乐」是时间线上的一件事

`domain/sequences/background_music.lay_background_music`,工作流节点 `timeline_background_music`(「铺背景音乐」):

- 一条**配乐轨**:`Track.role == "music"`,按用途认、不按名字认(和配音轨 `dub` 同一个理由);再铺一次清空它、
  换上新的那首,不叠第二条(重跑、从中断处继续都会再铺一次);
- 从 0 秒**铺满到现有内容的末尾**(画面、旁白、音效的最后一秒;字幕和配乐轨自己不算),**不加速** ——
  `timeline_append` 的「最长占几秒」会加速,音乐被拉快就变调了。曲子长了按出点截;**短了首尾接着再铺一遍**,
  接缝两边各淡 0.25 秒,最后剩不到 1 秒就不再起一遍、让上一遍淡出收尾。
  - 起初是「放完为止、不循环」。同一个音乐模型、同一段描述,第一次出了 20 秒,第二次只出了 6 秒 —— 10 秒的成片
    后 4 秒没了配乐,维护者一听就说「背景音乐有问题」。音乐模型给的长度不可控(`max_duration` 只是上限),
    只能铺的时候兜住;
- 垫在下面,**按听感定音量**:量这首曲子实际铺上的那一段的整体响度(`media/loudness.integrated_loudness`,
  EBU R128),把增益定到垫底 **−23 LUFS**(`BED_LOUDNESS`,夹在 0.1–4 倍;量不出来就原样);配乐轨标「闪避」,
  有旁白的地方渲染时再压约 10.5 dB;开头淡入 0.5 秒、结尾淡出 1.5 秒。节点上给了音量就照给的。
  - 起初是「固定 × 0.35 再闪避」。真跑出来的那首拆掉人声的伴奏只有 −22.8 LUFS,两层一叠落到约 −42,
    旁白(TTS,−20 LUFS)底下 22 dB —— Demucs 拆成片,伴奏那一轨 −49 ~ −60 dB,和「没有」听不出区别。
    生成的曲子响度差得很远(同一首带人声的原曲 −16.5),固定倍数总有一头不对。
  - −23 是 EBU R128 的参考响度:没有旁白的地方略低于人声,有旁白的地方落在旁白底下十二三 dB。

放在内容都铺好之后、导出之前:它按那一刻的末尾截。智能体用 `edit_timeline` 的加轨 / 插片段 / 音量 / 淡变 / 闪避
就写得出同样的东西,不另开工具。

### 2. 带货口播(和数字人带货)在有音乐模型时铺一首

- 建图时挑音乐模型(`templates_models._music_model`):明说出音乐的(`text-to-music` / `text-to-bgm`)优先;
  退一步挑「从文字出音频」且写得进曲子描述的(ComfyUI 的音乐工作流都报成插件缺省的 `text-to-audio`)。
  一个都没有就**不加这两步** —— 和「每一拍动起来」同一个挑法,不让整条模板用不了;官网导出的那份不带(模型空着,
  导入的人得先删掉它们才跑得起来)。
- 「生成一首配乐」在脚本写好之后就开始(和逐拍出图同时跑),「配乐只留伴奏」紧跟着它,「铺上配乐」在字幕之后、导出之前。
- 曲子怎么写(`templates_models.music_request`),按节点输入的名字认(同 ADR 0094 的 `aspect_ratio`):
  - 有 `caption` 输入的音乐工作流(MiniMax Music / ACE-Step):描述写进 `caption`、**提示词留空** —— 真跑时 MiniMax Music
    表单版的「提示词」接的是 **Lyrics**,描述写进提示词会被唱出来,caption 还是默认的「女声抒情歌」;
    `lyrics` 写 `[Instrumental]`(完整工作流的歌词默认是一段示例说唱),`max_duration` 写 60 秒(默认 240);
  - 没有 caption 的(内置音乐服务)走提示词,有「纯器乐」开关就打开。
- **会唱的模型后面接一步「配乐只留伴奏」**(`separate_audio`,本机 Demucs),铺上去的是伴奏那一轨。
  实测 MiniMax Music3:歌词写 `""` / `[Inst]` / `[inst]` / `[Intro][Inst][Outro]` / `[Instrumental]`,描述里也写明
  「no vocals」,五次出来都有整段人声(Demucs 拆出的人声轨占了大头)—— 这类模型「纯器乐」说了不算,只能事后拆。
  判断「会唱」按输入的名字认(`templates_models.music_may_sing`:有 `caption`、没有纯器乐开关);内置音乐服务有
  纯器乐开关,不加这一步。
  分离引擎**明说缺了**才连配乐一起不加(和 `requirement_problem` 同一条线:还没探测过的照常加,真缺时那一步说清)——
  铺一首带人声的歌在旁白底下,比不铺更糟。
- 模板升一版(带货口播 9、数字人带货 9)。

### 3. 带货口播的字幕铺念出来的那句画外音(同日,模板 10)

真跑成片里,第一拍听到的是「夏天最怕闷?这件 100% 亚麻衬衫,透气还藏肉」,屏幕上写的却是「100%亚麻,宽松不挑身材」
(「宽松不挑身材」是第二拍才说的)。模板铺的是脚本里另写的「屏幕短句」(`caption`),不是旁白 —— 维护者说「字幕是错误的」。

- 字幕改成念出来的那句(`loop.item.narration`),按画外音**实际落在时间线上的那一段**(`beat_voice_place` 的起止:
  加速过就是加速后的起止,裁过尾巴就到裁完为止)铺,长句按一行放得下的宽度切开、时间按字数分(没有词级时间,
  和整片、混剪同一个估法);没有画外音的那一拍不上屏,一拍都没有就一条都不加。
- `caption` 只剩「这一拍的小标题」:给素材起名、在「画外音被裁了」的提醒里指出是哪一拍,不上屏。
- 带货口播、数字人带货各升一版(10)。

## 后果

- 混剪、整片、数字人长片要配乐时用同一个节点(整片已经铺了,见 ADR 0096);它们本来就有自己的声音(现场声、配音),要不要铺另说。
- 挑模型时不看连接通不通:建图时挑中的连接当下连不上,要在节点上换一个(真跑时就是这样)。
- 视频节点的时长、画幅这类「意图」写在模型参数里时,换模型会丢(带货口播的每拍秒数换到 H3 后没绑上);画幅已经
  有了节点自己的一格(ADR 0094),时长还没有。
