# 0106 本机文件按信任目录放行，不按目录放宽代码执行

- 状态：已采纳
- 日期：2026-11-18
- 相关：ADR 0006（旧数据用迁移）、`domain/host_files`、`mcp_server` 文件工具

## 背景

智能体需要一个可用的本地文件面：读目录、读文本、写文件、看信任目录。此前没有路径级文件工具，只能走
`run_host_code`。代码执行能访问整台机器，无法用“当前工作目录”限制，所以每次都必须弹确认卡。

直接把“目录”当成 `run_host_code` 的授权条件是不成立的：代码可以 `cd /`，也可以直接写绝对路径。

## 决策

### 路径级文件工具

新增：

- `host_trusted_dirs`
- `host_list_dir`
- `host_read_file`
- `host_write_file`

它们只通过 `host_files.ensure_trusted_path` 放行，路径先 realpath，再判断是否落在信任目录内。

### 默认信任目录

部署管理员默认信任：

```text
~/Documents/Mosael
~/Downloads/Mosael
```

成员不继承部署机的家目录，只能使用管理员共享的目录。未来可以在共享目录设置里继续添加。

### 确认边界

- 信任目录内的列目录、读文本、写文本不弹确认卡；
- 写入默认不覆盖已有文件，需要 `overwrite=true`；
- 删除、覆盖、移动到敏感位置仍走确认（后续文件工具扩展时保持）；
- `run_host_code` 仍然是整台机器的操作，永远单独确认，不因当前目录在信任目录内而放宽。

### 安全约束

- 根目录、家目录本身永远不信任；
- `..`、软链接、大小写绕路都按 realpath 后判断；
- 二进制文件只返回元数据；
- 读文本分片，单文件上限 8 MiB；写入上限 1 MiB。

## 后果

- Agent 可以在默认/共享目录里连续读文件、写结果，不再每个动作弹卡。
- 不在信任目录内的路径会被明确拒绝，而不是靠确认卡“批准整机代码”。
- 需要更广的本地能力时，仍走 `run_host_code` 的确认路径；不能把目录信任当成代码沙箱。
- 信任目录配置目前是默认值 + 管理员共享目录；后续再加入自定义目录 UI。
