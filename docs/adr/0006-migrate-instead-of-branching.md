# 兼容用迁移,不用读取期分支

**我们能改写的数据,升级时就地改写**(`core/db.py` 的 `_migrate_*`、`config.py` 的目录/库改名、
`domain/plugins/migrations.py` 的清单迁移),读取代码里因此只认一种形状。**我们改写不了的**
(别的进程发来的报文、用户自己保管的导出文件、启动时给的环境变量)才允许在**边界**上认两种,
而且只在那一处认、进门就归一。

读取期的 `if 老写法 elif 新写法` 是一笔永久的税:每加一个字段都要想"另一种形状下它在哪",
而两条分支里总有一条平时没人走、坏了也没人发现 —— 它不会报错,只会在某天给出一个安静的错值。

**判据是「这份数据归谁」**:

| 数据 | 归属 | 做法 |
| --- | --- | --- |
| 数据库的表与列 | 我们 | 启动时迁移(`core/db.py`) |
| 数据目录、库文件名 | 我们 | 启动时改名(`core/config.py`) |
| 插件清单 | 我们(在插件目录里) | 扫描时就地改写 + `.bak`(`plugins/migrations.py`) |
| 插件的配置 / 凭据分类 | 我们 | 扫描时搬到新位置(`instances.reconcile_fields`) |
| 工作流导出的 `.json` | 用户(可能在任何地方) | 导入时归一,不改用户的文件 |
| 进程间的报文头 | 对端(版本可能不同步) | 收侧认两个名,发侧只发新名 |
| 环境变量 | 用户的启动方式 | 启动时镜像成新名 |

**迁移必须幂等**,跑第二次不再改动;改用户磁盘上的文件先留一份 `.bak`。

**Considered options**:一直保留读取期兼容 — 拒绝:见上,税是永久的而收益只在升级的那一天;
迁移脚本单独发一个命令让用户手动跑 — 拒绝:本地优先的桌面应用没有运维,没跑过的人得到的是
一个坏掉的装机;写版本号做多分支读取器 — 拒绝:那是把同一笔税换了个名字收。
