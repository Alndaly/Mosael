# ADR 0050:「清空已结束」的保留语义与用量归属 —— 清空是从我的面板拿掉,花的钱自己记着是谁花的

## Status

Accepted — 2026-10-09。草稿 2026-10-08(体检 UM-01 后半、UM-11);六个待拍板点由**维护者 2026-10-09 按推荐拍板**(体检编号
D27–D32,对应下面「待拍板」1–6)。实现与本篇同一次提交,见文末「实现记录」。止血早先已经做了(管理类页面那一路第一批,`fix(jobs)`):点「清空已结束」先弹
确认框,写明会删几条、几条是别人发起的、留下几条(后端预览和真删是同一份计划);工作流运行、留着运行产出全文的任务、记过用量的
任务整棵留下。本篇定「清空」到底是什么,以及「谁在花钱」怎么算。

和后端架构那一路的 BA-06(清空 / 事件清理改成集合式 SQL、分批提交)是同一处代码:本篇定语义,BA-06 定怎么删得快;两边合的时候
按本篇的语义落。

## Context

### 「清空已结束」此前做了什么

任务中心角落一个小按钮,权限 `edit`,一次点击、没有确认,把**整个工作区**(所有成员的)已结束的顶层任务连同子任务**物理删除**:

| 跟着没了 / 变了的 | 怎么没的 | 维护者库副本上一次点击的量 |
| --- | --- | --- |
| 任务行(工作流页的「执行历史」就是 `kind=workflow` 的任务) | 直接删 | 3541 个 |
| 任务事件(执行时间线) | 删任务时一起删 | 13020 条 |
| 工作流运行产出全文(能复制 / 下载的模型回复) | `workflow_run_outputs.job_id` 级联 | 150 条(27 次运行) |
| 用量事件挂在哪个任务上 | `provider_usage_events.job_id` 置空 | 1070 条 |
| AI Studio 生成记录、定时任务运行、发布任务挂的任务 | `job_id` 置空 | 49 条生成记录…… |
| 统计页「任务活动」、管理概览「任务活动」 | 两张图都按 `jobs` 表逐日数 | 清零 |
| 管理概览「谁在花钱」 | 按人分组要顺着 `job_id` 连到 `jobs.created_by` | 「还没有产生花费」,而旁边写着花费 US$9.33 |

按钮叫「清空已结束」,和通知面板的「清空已读」长得一样、挨得一样近 —— 用户读到的是「把我的面板收拾干净」。

### 「谁在花钱」本来就漏了大半(UM-11)

按人统计的那条查询内连 `jobs`:没有 `job_id` 的用量一条都进不来,也没有「未归属」一行。维护者库近 30 天:合计 US$9.33,按人列出的
只有 US$0.53;没挂任务的 220 条里,智能体对话 US$5.83、工作流节点 US$1.83、画板 US$0.34、素材 US$0.19…… —— **94% 的美元花费归不到人**。

用量事件上已有的线索(副本里各种 `source_type` 的条数):

| `source_type` | 条数 | 能找到人的线索 |
| --- | --- | --- |
| `job` | 1019 | `job_id` → `jobs.created_by`(1014 条有) |
| `agent_message` | 302 | `agent_message_id`(188 条有)→ 会话 → `agent_sessions.owner_user_id`;没有的看 `source_id` |
| `generation_job` | 111 | 生成记录 → 生成会话的主人;一半有 `job_id` |
| `workflow` | 39 | `source_id` 既不是任务也不是现存的工作流,**找不到人** |
| `board` / `asset` | 21 | 只有资源 id,不知道是谁点的 |
| `note_read_aloud` / `voice_preview` | 6 | `source_id` 就是用户 id |

结论:**读的时候连表找人这条路走不通**(线索各不相同、被删的东西一删就断),得在**写的时候**记下是谁花的。

## Decision

### 1. 「清空已结束」= 从我的任务中心面板拿掉,不删任何东西

每人每个工作区一条**水位线**(`job_center_marks(user_id, workspace_id, cleared_at)`):任务中心只列「还在跑的」和「结束于水位线之后
的」顶层任务。点「清空已结束」= 把我的水位线挪到现在。

- 别的成员的面板不受影响;工作流的执行历史、运行产出、统计、生成记录、用量归属都不受影响;
- 不需要确认框(可逆:没有删东西;要找回来就是一个「显示已清掉的」开关,见待拍板 2);
- 现在的 `DELETE /jobs/finished` 改成「挪水位线」(按项目惯例不留兼容的旧语义,前后端一起改),预览接口随之退役。

### 2. 真删交给保留策略,由部署管理员定

物理删除只发生在一处:后台的保留清理(和现有的任务事件清理同一个循环,BA-06 那一路正在把它改成集合式 SQL)。规则:

- 事件:照现在(30 天,工作流任务保留完整时间线);
- 任务行:结束超过 N 天删掉(部署管理员在「管理 → 部署设置 → 数据与诊断」里设,默认见待拍板 3),**不删**被定时任务运行记录、
  生成记录还在引用的、记过用量的;
- 运行产出全文跟着它的任务走(任务删了它才删),不再被别的操作顺带级联。

### 3. 用量事件自己记下是谁花的

`provider_usage_events` 加一列 `user_id`(不设外键,和 `owner_user_id` 一样是审计信息),**写入时必填**:`record_usage` 加一个
没有默认值的 `user_id` 参数,由调用方给出「替谁花的钱」—— 跑的人(`current_actor`):手动操作是点的人,定时任务 / webhook 是任务
主人,智能体是会话主人。仿照现有的棘轮,调用点不许传 None 常量。

回填迁移按上表逐类找人(`job` → 任务的发起人;`agent_message` → 会话主人;`generation_job` → 生成会话主人;`note_read_aloud` /
`voice_preview` → `source_id`),找不到的留空。

### 4. 「谁在花钱」按 `user_id` 分组,剩下的列「未归属」

管理概览按人的那张图直接按 `provider_usage_events.user_id` 分组,不再连 `jobs`;找不到人的那部分单列一行「未归属」,让条形加起来等于
合计。统计页「AI 用量」的按供应商分摊不变。

## 否掉的备选

- **只加确认框、照旧物理删除**(止血版):还是一个成员能删掉全工作区共享的历史;统计和归属照样被抹掉。只适合过渡。
- **每个任务一个软删标记(`deleted_at`)**:仍是全工作区共享的状态(一个人清了大家都看不见),每条读任务的查询都要记得过滤;
  每人一条水位线更小、也不改变任务本身。
- **读的时候连表找人**:见 Context 最后一段,线索各不相同、一删就断,`workflow` / `board` / `asset` 那几类根本找不到人。
- **保留策略交给每个成员**:保留多久是这台部署的磁盘和合规问题,和「设置里谁能改什么」那条一致,归部署管理员。

## Consequences

- 任务中心的查询多一个水位线条件;面板上「清空」变成纯个人的、可逆的操作。
- `jobs` 表不再被一个按钮清空,增长由保留策略控制(维护者一个月约 2500 个任务,一年三万行级别,BA-06 的集合式清理要能吃下)。
- 用量归属从写入时就对:智能体对话、工作流节点、画板这些此前归不到人的花费都有主;「未归属」只剩回填找不到的历史部分。
- 迁移两步:新表(水位线)、新列 + 回填(用量)。都要先在维护者库副本上试跑(按惯例)。

## 分步

1. 水位线:新表、任务中心按它过滤、按钮语义改掉、预览接口退役;前端去掉确认框、加「显示已清掉的」。
2. 用量 `user_id`:加列、`record_usage` 必填、调用点逐个补、棘轮、回填迁移;「谁在花钱」改按它分组 + 「未归属」行。
3. 保留策略:部署设置里的保留天数,接进 BA-06 改好的清理循环;运行产出不再被别的路径级联删除。

## 拍板(2026-10-09,全按推荐)

D27 = 1、D28 = 2、D29 = 3、D30 = 4、D31 = 5、D32 = 6。下面是当时的选项,留作记录。


1. **清空 = 每人一条水位线?** 推荐:是(最小、可逆、不碰任务本身)。备选:每人每任务一条「拿掉」记录(能单条拿掉,但行数和任务数同量级)。
2. **要不要「显示已清掉的」?** 推荐:要,任务中心底部一个开关,打开后列出水位线之前的(只读)。备选:不要(清掉就去别处看:工作流历史、定时任务运行记录)。
3. **任务行默认保留多久?** 推荐:365 天,部署管理员可改为 90 / 180 / 永久;被引用的、记过用量的不删。备选:永久保留、只删事件(最省事,库会一直长)。
4. **用量记谁?** 推荐:「替谁花的钱」= 跑的人(定时任务是主人,智能体是会话主人),和钥匙、额度用谁的是同一条归属(见 ADR 0047)。
   备选:记发起请求的那个登录用户(定时任务、webhook 没有这个人)。
5. **回填找不到人的那部分怎么办?** 推荐:留空,在「谁在花钱」里列「未归属」。备选:归给工作区 owner(猜错了比空着更糟)。
6. **统计页的「任务活动」看不看水位线?** 推荐:不看 —— 统计是工作区的事实,水位线只管个人面板。
