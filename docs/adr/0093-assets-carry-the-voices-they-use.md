# ADR 0093 · 素材记下自己用到的克隆嗓子,派生素材从出处继承

- 状态:**已采纳**(2026-11-09)。排查数字人长片硬切时(ADR 0092)发现,维护者 2026-11-09 让在同一会话里修。
- 关联:ADR 0028 §4、§5(数字人的两道授权声明)、ADR 0037(配音库的嗓子在远端念)、ADR 0087(VoiceRef)、
  `domain/assets/lineage`(来源链与「含 AI」的继承)。

## 背景

做数字人时,生成漏斗(`generation.operations.check_digital_human_rights`)要查驱动音频是不是用克隆音色配的:
是的话,那把嗓子要声明过是谁的(本人、已获同意或虚构)。漏斗只读**驱动音频素材自己** `media_info.voice_id`
里记的那一把,而这个键只有克隆音色的配音产出写:

- 截取(`assets/trim`)、拼接、混音、补静音、压停顿……做出来的新素材都不带它,要靠每道工序手抄。
  抄了的只有三处(对口型的拼接与补静音、压缩停顿),截取没抄;
- **数字人长片模板每段的驱动音频正是截出来的**:授权检查读到的是空,等于没查。用一把没声明的克隆嗓子配一段稿子,
  跑「任意时长的数字人」就能做成数字人;
- 对口型拼接时只有「几句都是同一把嗓子」才记,混了两把就一把都不记 —— 同样查不到。

问题不在哪一道工序漏抄,而在「这份素材里有谁的嗓子」被当成了每道工序各自的责任。

## 决定

和 `ai_generated` 同一个形状:**登记素材时定下,从出处继承**。

1. `assets` 新增一列 `voices`(JSON,配音库 `voices.id` 的列表,去重排序)。
2. `register_file_asset` 多一个 `voices=`:克隆音色的配音产出说自己是哪把(本机克隆、远端念配音库里的嗓子两条路);
   其余一律不说。登记时 `voices` = 自己说的 ∪ 全部出处的(`lineage.inherited_voices`)。截取、拼接、混音、
   补静音、压停顿……不需要知道这件事。
3. 授权检查逐把核对驱动音频的 `voices`;任一把没声明就拒。
4. 删掉三处手抄的 `voice_id`,`media_info.voice_id` 不再存在。

### 为什么登记时定,而不是检查时顺着来源链往上找

顺链查不改数据形状、不用迁移,但**出处被删了链就断**:截出一段之后把原配音删掉,检查就又查不到了 —— 正是要堵的那个口子。
登记时写进素材,出处删了它还在(和 `lineage` 顶上「含 AI」那段说明同一个理由)。代价是一次迁移和一列。

### 为什么是列,不是 `media_info` 里的键

`media_info` 是探测出来的技术信息(时长、尺寸、有没有缩略图),会被各处合并改写;「用到了谁的嗓子」是出处,
和 `derived_from`、`ai_generated` 同一类,登记时由领域决定。放成列,继承和查询都不必解一层 JSON 再挑键。

## 迁移

`_migrate_assets_record_their_voices`(建表之前,库版本 46 → 47):

- 加列 `voices JSON NOT NULL DEFAULT '[]'`;
- 每份素材的 `voices` = 自己 `media_info.voice_id` 记的那把 ∪ 全部出处的 `voices`,顺着 `derived_from` 反复传到不再变;
- 去掉 `media_info.voice_id`;迁完还有残留就当场报错。

维护者的库上(开发后端重载时跑的,升级前有自动快照 `mosael-v46-to-v47-…`):71 份素材记上了嗓子,其中包括
数字人长片截出来的各段驱动音频(此前都是空的);`media_info.voice_id` 一条不剩。

## 后果

- 新的派生方式(以后再加一种「把音频加工一道」)不用记得抄字段,登记时说清出处就够 —— 那本来就是 `lineage` 要求的。
- 一段音频拼进了没声明的嗓子,整段都不能拿去做数字人;要做就先给那把嗓子补声明,或者换掉那几句。这是对的:
  成片里确实有那个人的声音。
- 对口型(`dub_lipsync`)在切片、花钱之前拿配音轨上原来那几句查的那一步保留:它在第一分钱之前拒,而且原片那一半
  (人物授权)只能这样查;混出来的新 wav 现在也继承嗓子,漏斗那一道也查得到。
