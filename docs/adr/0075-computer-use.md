## 要解决什么

「补 computer use 能力」不是一个工具问题，而是**范围问题**：能点到的地方每扩大一层，风险就差一个
量级。所以先分层，不一次做到「控整个桌面」。

| 层 | 能操作什么 | 风险 | 执行面 |
|---|---|---|---|
| **L1 只控 Mosael 自己** | 它的按钮、面板、画板 | 最低（同一进程内） | Electron `webContents` + `capturePage()` |
| **L2 浏览器里的网页** | 任意站点的页面 | 中（第三方站点、用户的登录态） | CDP（`PageDriver`）+ 可信输入 |
| **L3 整个桌面** | 任何 App | 最高（密码管理器、终端） | 系统级截屏与输入注入（见 ADR 0081） |

**推进顺序固定为 L1 → L2 → L3**，每一层都要能在前一层不成立时**独立关掉**。

## 决定 1 · L1 的执行面：主进程截图 + 回环桥

```
模型 ── computer_* ──→ 确认卡 ──→ 本地后端 ──127.0.0.1 回环桥──→ Electron 主进程 ──→ 真动作
     ←── {image, width, height, scale} 或执行结果
```

- **截屏与输入都在 Electron 主进程**：它们是原生能力，主进程已经有窗口、权限、单实例那套；
  后端只负责「工具 → 确认卡 → 桥」，和现有 `confirmable` 体系同形。
- **桥是本仓库里唯一一条「后端 → 壳」的同步通道**：只绑回环、每进程随机令牌、只认几个通道名
  （`computer:screenshot` / `click` / `type` / `scroll` / `end`）；壳拉起的后端拿
  `MOSAEL_HOST_BRIDGE_PORT` / `MOSAEL_HOST_BRIDGE_TOKEN`，`pnpm dev:backend` 单独起的后端读数据目录里的
  `host-bridge.json`（0600）。**两样都没有时工具回一句人话**，不假装截了张图（独立部署、远程团队服务器
  就是这个情况）。
- **缩放放在后端**：壳拍原图，后端按 `scale` 缩小再交给模型 —— 模型看的是布局，不需要 5K 像素；
  模型给的坐标是「它看到的那张图」上的像素，后端除以 `scale` 换回窗口 CSS 像素。
- **只有一个窗口**：应用主窗口。**没有「选哪个窗口」这一维** —— 曾经还有 `publish`（发布器自己的
  BrowserWindow），但发布器早就是应用里的页面与内嵌浏览器，那个名字后面没有窗口，成了一条永远
  走不通的分支（2026-10-24 维护者指出：文档写着白名单 `main` / `publish`，代码里只传 `{ main }`）。
  内嵌网页也不在这里 —— 那是 L2。
- **`computer:end` 不是急停**：它只是「这一轮结束了」，让壳把「被控制中」熄灭；下一轮还能动。
  急停是另一条路（决定 3）。

## 决定 2 · L1 的能力边界：只碰自己的 UI，不碰别人的站点

L1 的四个动作 —— 截图、点击、滚动、输入 —— 都只作用在**应用自己的渲染**里：

- 截图不需要 macOS 的屏幕录制权限（`capturePage()` 拍的是自己的渲染输出）；
- 点击/输入用 `webContents.sendInputEvent`，事件是**可信**的（`isTrusted === true`），不是 `.click()`；
- **L1 不提供**「点别的 App」「读别的 App 的界面」—— 那是 L3；也**不提供**「让模型点网页里的按钮」——
  那是 L2。

## 决定 3 · 安全模型（一次说清）

1. **只读的自动放行**：截图与滚动不改状态，直接放行。
2. **动手的走确认卡，档位是 `edit`**：点击与输入每张卡上写清要发生什么（坐标与按钮 / 要输入的字）。
   它**不声明「每次都问」**（维护者 2026-10-22）：和「改时间线」同一档 —— 「本会话始终允许」按 edit 记、
   auto 档直放、bypass 生效。越是被自动放行，「看得见」和「停得下」这两条越要紧。
3. **被控制中必须可见**：托盘图标变色、屏幕四角描边、窗口内提示条（带「停止」按钮）。
   **空闲 30 秒自动退出**被控制状态（`computerUseGuard` 的 `idleMs`）—— 忘了停不该一直亮着。
4. **急停一直挡到 `resume()`**：全局热键，**不依赖 App 在前台**；挡住之后再来一次点击/输入一律拒
   （状态机在收到动作时第一道就拒，和放行与否无关）。
5. **黑名单属于 L3，动作已实现**：密码管理器、钥匙串、系统设置、终端等受保护应用直接拒绝输入；
   截图打码与回放清理仍随 P3 推进。L1 只截自己的窗口，不受这一条影响。

## 决定 4 · L2 的方向：任意网站，但先确定性、后模型

维护者 2026-10-24 明确：**「让模型点网页」这个能力要加** —— 目标就是「任何网站上的任何事都能做」。
顺序上仍然先确定性：

1. **已建成的那一半是确定性自动化**：发布域的 `PageDriver` + 平台契约 + 判定原语 + 浮层策略
   （ADR 0080）能在具体站点上稳定完成具体动作，而且可测（`fakePage` + 管道测试）。
   这条路的代价是「每个站点要写一份契约」，收益是不用模型、不会误点、失败可定位。
2. **要加的那一半是模型驱动的兜底**：没有契约的站点、或者契约没覆盖的步骤，让模型看页面、
   点元素。它和 L1 共用同一套确认卡、急停、可见性；感知优先用 DOM / 可访问性树上的**元素令牌**
   （而不是纯像素），像素只做兜底 —— 像素坐标一旦页面重排就会点错，而令牌失效会直接报错。
3. **两层同一套策略**：确认卡、权限档、被控制中、急停 —— 不因为「这次是模型点的」而放宽。

## 决定 5 · 回放：元数据、截图、输入的字都记（维护者 2026-10-24）

每一步都落一条记录到 `payload.timeline`，**四样东西都记**：

| 记什么 | 为什么 |
| --- | --- |
| 动作元数据（层 / 工具 / 目标 / 按钮 / 结果 / 耗时） | 复盘「第几步开始不对」 |
| **截图**（动作前后各一张，按显示宽度缩放） | 只看文字记录无法判断「当时那一屏到底长什么样」 |
| **输入的字**（原样，不脱敏） | 「它到底写了什么」是这类问题最常见的争点 |
| 判定结果（哪一条判据成立、原文是什么） | 区分「没做成」和「做成了但我判错」 |

边界（写在这里，因为记全量必然涉及隐私）：

- **只在本机**：不进团队同步、不上传；和会话数据同一个生命周期（删会话即删回放）。
- **用户可见、可删**：时间线是用户点开就能看的，不做隐藏采集；提供「清空回放」。
- **不采集之外的东西**：不抓剪贴板、不抓键盘全局钩子、不后台持续录屏 —— 只在动作前后各一张。
- L2 / L3 里被系统或平台标成「受保护」的窗口（密码管理器之类）**截图打码、动作直接拒**，
  这条属于 L3 的白名单实现（ADR 0081）。

## 后果

- 先有「能看见」再谈「能动手」，最危险的一半被延后；
- L1 不需要任何系统级权限（屏幕录制 / 辅助功能），所以它是**默认可用**的那一层；
- L2 / L3 才需要用户授权与逐层开关，届时确认卡、急停、可见性三样照旧；
- 回放记全量（含截图与输入的字）是**有意的取舍**：可复盘 > 少存一点。代价是本地存储变大、
  屏幕内容可能含敏感信息 —— 所以只在本机、可删、不持续录。
