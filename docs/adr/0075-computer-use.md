# ADR 0075 · Computer Use：分三层推进，先只碰 Mosael 自己的窗口

- 状态：Proposed — 2026-10-21（P0 已开工）
- 相关：ADR 0021 / 0044（确认卡与效果）、ADR 0032（宿主能力）、ADR 0038（工作台）

## 要解决什么

维护者要"补 computer use 能力"。它是一个**范围问题**而不是一个工具问题：能点到的范围有多大，
风险就差一个量级。所以先分层，不一次做到"控整个桌面"。

| 层 | 能操作什么 | 风险 | 复用 |
|---|---|---|---|
| **L1 只控 Mosael 自己** | 它的按钮、面板、画板 | 最低（同一个进程内） | Electron `webContents` |
| **L2 自己 + 发布器浏览器** | 网页上的任何东西 | 中（第三方站点） | `pageCapture` + `executeJavaScript` 已有 |
| **L3 整个桌面** | 任何 App | 最高（密码管理器、终端） | 系统级截屏与输入注入（全新） |

**推进顺序固定为 L1 → L2 → L3**，每一层都要能在前一层不成立时独立关掉。

## 架构（三层共用一条）

```
模型 ── computer_* ──→ 确认卡(ADR 0044) ──→ 本地后端 ──IPC──→ Electron 主进程 ──→ 真动作
     ←── {image, width, height, scale} 或执行结果
```

- **执行放在 Electron 主进程**：截屏与输入注入都是原生能力，主进程已经有窗口、权限、单实例那套；
  后端只负责「工具 → 确认卡 → IPC」，和现有的 `confirmable` 体系同形。
- **工具结果的图片通道已经存在**（`mcp_server._with_images`），视觉回路不用新建。
- **新能力进能力表**（ADR 0032），插件也能声明"我需要 computer use"。

## 安全（一条都不能省）

1. **默认每步确认**：`permission="edit"` + `effects=["screen"]`；**只有截图与滚动可以自动放行**；
2. **"被控制中"必须可见**：菜单栏图标变色 + 屏幕四角描边；
3. **急停**：全局热键，**不依赖 App 在前台**；
4. **黑名单**：密码管理器、钥匙串、系统设置、终端 —— **截图打码、点击直接拒**；
5. **可回放**：每一步（截图 + 动作 + 结果）进 `payload.timeline`。

## P0 的范围（现在做）

**只做 L1 的只读一半**：一个 `computer_screenshot`（截 Mosael 自己的窗口，返回图与尺寸），
**没有任何输入注入**。它证明的是**回路**：工具 → 图 → 模型 → 下一步。等这条通了再接 `click` / `type`。

**P0 明确不做**：L2、L3、任何鼠标键盘注入、屏幕录制权限申请。

## 后果

- 先有"能看见"再谈"能动手"，**把最危险的一半延后**；
- L1 的截图走 `webContents.capturePage()`，**不需要系统屏幕录制权限**；
- L3 才需要用户授权（macOS 辅助功能 + 屏幕录制），届时每步都要确认，且**自动放行永不开放**。

## 修订(维护者,2026-10-22):动手的两张卡也走「本会话始终允许 / 自动放行 / bypass」

P1(点击、输入)最初按「安全 1」把两张卡声明成 `always_asks`(每一步都问,任何口子都放不过)。
维护者要求它们也必须支持「本会话始终允许」、自动放行与 bypass —— 于是改为**普通的 edit 档确认卡**
(`permission="edit"`,`always_asks` 去掉):

- 卡上仍然写清要发生什么(坐标与按钮 / 要输入的字),区别只在「问不问」由谁决定;
- 「本会话始终允许」按 edit 档记(和改时间线同级),只放行不高于那一档的卡;
- auto 档的 edit 直放、bypass 对它们生效;被急停挡住时仍然一个动作都不发(状态机在收到点击/输入时
  第一道就拒,和放行与否无关);
- 屏幕四角描边、托盘换红、窗口内提示条与全局急停热键照旧 —— 越是被自动放行,「被控制中必须可见」
  和「随时能停」这两条越要紧。
