# ADR 0055:语音、播客是创作会话 —— AI Studio 分成「对话 | 创作」

## Status

Accepted — 2026-10-08,已实现(见文末「实现记录」)。方向由维护者定(「语音」「播客」两页要彻底重新设计,顶部分区改成「对话 | 创作」);
文末待拍板 1–7 由维护者 2026-10-08 全部照推荐拍板。**修订 ADR 0022 决定 2**:语音的引擎、音色、合成照旧是配音那一族自己的(不做成生成适配器),
只把「会话 + 记录」并进生成那一套。一批实现,见文末「实现记录」。

## Context

### 维护者说的问题

AI Studio 顶上是「对话 | 生成 | 音频」三个分区,「音频」里又分「语音 | 播客 | 音乐」三格。维护者截图指出:

1. 语音、播客两格和别处长得不一样:一张固定的表单加一列「最近生成」,不是会话;没配好时是一个虚线大框。
2. 「最近生成」里每一条都是 `0:00 / 0:00`,点了播放才知道多长。
3. 名字露原始 id:`zh-CN-XiaoxiaoNeural · 配音`、千篇一律的「播客对话」。
4. 播客没有像样的稿子输入:「照稿念」只是一大段字,后端按句号拆开、两个人轮流念。
5. 图像、视频、音乐、语音、播客是同一件事(写一句、挑一个引擎、出一份素材、改一改再来),却分在三个地方、三种样子。

### 读代码确认的现状

- **0:00 的原因**:`AudioWorkspace` 的「最近生成」用 `<AudioPlayerBar preload="none">`,不点播放就不取元数据。音乐那一格用的结果卡
  `GeneratedAudioList` 是 `preload="metadata"` 加波形,没有这个问题。
- **名字的原因**:后端登记素材时写的是 `f"{engine_voice} · 配音"`(`voices._synthesize_remote`),播客写死「播客对话」。
- **语音、播客不在生成会话里**:语音是 `kind="tts"` 的任务(`voices.start_synthesis`),播客是 `kind="podcast"`(`start_podcast`),
  产出是 `source="tts"` / `"podcast"` 的素材。没有会话、没有记录:「最近生成」只是按 source 从素材库里捞。请求参数只在任务行的 payload
  里,而且文字只存前 200 字(播客 500 字);任务行被「清空已结束」删掉,这些就没了。播客对谈稿(`result.texts`)也只在任务行里。
- **音乐走标准生成管线**:`generation_sessions` + `generation_jobs`,`kind="audio"`(ADR 0022)。生成记录的表本身装得下语音:有
  provider、model、kind、request(JSON)、result_asset_id、error 三列、job_id;「已停止」和失败摘要从记录自己的列算。
- **失败原因抄到记录上**靠落终态监听 `generation.runner.record_failure`,它只认 `job.kind == "ai_generation"`。
- **价格**:生成记录的价格取 `source_type="generation_job"` 的用量事件;语音、播客的用量记的是 `source_type="job"`。
- **还有别处在调语音合成**:笔记朗读、智能体 `generate_audio`、工作流 tts 节点、画板「念出来」、字幕配音(逐句的中间产物)。
- **老毛病**:`goToPlace(studio)`、`openAgentSession` 只跳 `#/ai`,落在哪个分区取决于上次停在哪 —— 上次停在「生成」「音频」的话,
  「回到那段对话」落错地方。

### ADR 0022 决定 2 为什么还成立

「TTS 不做成生成适配器」的理由没变:音色是每个引擎自己的一张表(带克隆、带远端副本、按账号现拉),不是描述符里的一个参数;字幕
配音一个任务要念很多句。变的只是界面上的「会话 + 记录」—— 那是用户怎么组织自己做过的东西,和引擎怎么念是两回事。

## Decision

### 1. AI Studio 两个分区:「对话 | 创作」

- 「创作」是一个工作台:左边会话列表,中间这条会话的记录流,右边「引擎参数」—— 和现在的生成页同一个壳、同一套组件。
  图像、视频、音乐与音效、语音、播客五种都在这里。
- 会话列表上面一排筛选:**全部 · 图像 · 视频 · 语音 · 播客 · 音乐**,按会话的 `kind` 在服务端筛(列表有条数上限,界面筛会把别的
  挤出去)。左栏 240px 一行摆不下六个,**放不下就折行**(横着滚的话滚动条藏着,后两种看不见)。每一行带种类小标(图标 + 一个词)。
  筛选记在本机(`mosael:tab:ai-studio-create-filter`)。
- 「上次开着哪条会话」只有一个键 `mosael.generation.session.<工作区>.create`。
- 筛选的空态按种类说(「还没有语音会话 —— 在下面写一段字、挑一个音色」)。

### 2. 会话的种类与「族」

- `generation_sessions.kind`、`generation_jobs.kind` 多两个值:`speech`、`podcast`。不加新表。
- **新会话的种类由选中的模型决定**(和现在一样)。模型下拉分组列出:图像 / 视频 / 音乐与音效 / 语音(各 TTS 引擎)/ 播客。
  语音和播客的选项由界面从 `GET /tts/engines` 拼出来,不进生成目录(引擎仍分开)。
- **会话锁「族」**(待拍板 1):视觉(图像 + 视频,保留「拿上一张图生视频」)、音乐、语音、播客四族。已经有记录的会话,下拉只列同一族;
  想换族就新开一条。后端在两处守着:**创作页的入口**往点了名的会话里生成(`create_generation_job` / `voiced.create_*` 的 `lock_family`,
  只有创作页的三个路由传 True)、改会话的种类(`PATCH /generation/sessions/{id}`),不同族一律 422「这条是 X 会话,换成 Y 要新开一条会话」。
  **锁族是创作页的规矩,不是会话本身的**:不写死「会话一定是创作页开的」—— 按出处归的会话(ADR 0052:一块画板一条、一段智能体对话一条)
  里本来就有图有歌,画板、工作流、智能体往自己那条里放什么不受它管。
- **会话的 `kind` 记最后一次用的种类**,筛选按它归(待拍板 2):往会话里生成一次,会话的 kind 就改成这一次的。

### 3. 一条语音 / 播客记录存什么

| 列 | 语音 | 播客 |
| --- | --- | --- |
| provider | 引擎 id(`builtin:edge` / `builtin:clone` / 插件连接 id) | `builtin:volcano-podcast` |
| provider_profile_id | 远端引擎用的那条连接(有的话) | 播客那条连接 |
| model | 音色一格(克隆是嗓子 id,别的是引擎自己的音色) | `dialogue` |
| request | `{prompt: 要念的字, voice, voice_label, engine_label, speed, clone_engine?, clone_model?}` | `{mode, prompt: 材料或主题, turns: [{speaker, text}], speakers: [{value, label}], speed}` |
| job_id | 那个 `kind="tts"` 的任务(任务种类、任务中心的叫法都不变) | 那个 `kind="podcast"` 的任务 |

会话记着的「模型」:语音、播客会话的 `model` 是引擎 id;音色、语速从这条会话最后一条记录的请求里接着用。

### 4. 入口在生成那一侧,依赖方向是生成 → 配音

- 两个用例 `generation.voiced.create_speech` / `create_podcast`,两个路由 `POST /api/generation/speech`、`POST /api/generation/podcast`
  (回 `{generation, job}`,和 `POST /generation/jobs` 同形)。它们调 `voices.start_synthesis` / `start_podcast` 建任务,同时写这条记录
  (没点名会话就现开一条)。配音那一族不知道有生成记录。
- 远端引擎念配音库里的嗓子要先同意上传(ADR 0037):`RemoteConsentRequired` 原样透出 409,界面照旧弹确认框。
- **谁写记录**(待拍板 3):创作页写;智能体的 `generate_audio` / `generate_podcast` 也写(每次一条新会话,和它出图一样)。画板「念出来」、
  工作流 tts 节点、字幕配音、笔记朗读**不写** —— 它们的产物属于那张画板、那条时间线、那篇笔记,写进来只会把会话列表刷满。
  它们照旧走 `/tts/synthesize`、`/voices/{id}/synthesize`。
- `/tts/podcast` 只有「音频」页在用,随它删掉(`PodcastRequest`、前端 `generatePodcast` 一起);智能体走领域用例。

### 5. 结果、失败、价格同步回记录

- **产出在同一个事务里挂上记录**:`start_synthesis` / `start_podcast` 多收一个 `on_asset(db, asset_id)`(调用方给的收尾:生成那一侧
  拿它写 `result_asset_id` 和一行 `GeneratedAsset`),在素材登记之后、任务落「成功」之前调。不用落终态监听:那是提交之后另开一个事务,
  中间那一下界面会读到「任务成功了、记录上没有产出」,画成一张一直在排队的占位。
- **失败、停止**照现有做法抄到记录上:`record_failure` 去掉 `ai_generation` 的限定,改成「凡是挂着生成记录的任务」。于是「已停止」
  和失败摘要自然就有了(失败卡本身不动,ADR 0045 那一路在改)。「重新取回」只对能接着取的生成任务成立,语音、播客的 `retrievable` 恒为假。
- **价格记在记录上**:两个入口多收一个 `usage_source`,记录那条路传 `("generation_job", 记录 id)`。不按 `job_id` 去对 —— 任务被清掉
  之后 `job_id` 置空,脚注里的价格会跟着消失。没走记录的调用方照旧记 `("job", 任务 id)`。
- 界面的任务列表改成「挂着创作记录的任务」:`GET /api/jobs?recorded=true`。按种类列 `tts` 会把字幕配音的几百句零件一起拉回来,
  每秒一次。

### 6. 播客稿

火山播客有三种动作:改写材料(0)、按 `nlp_texts` 照念(3)、联网查主题再讨论(4)。没有「只出稿不出声」(待拍板 6:不另做)。
输入框顶上三档:

| 档位 | 动作 | 输入 |
| --- | --- | --- |
| 改写材料 | summarize | 一大段材料 |
| 聊一个主题 | research | 一行主题 |
| 照稿念 | read | 逐段稿子编辑器 |

- **照稿念的编辑器**:每一段一行,左边 A / B 切换发音人,右边一个文本框。回车新起一段,发音人换成另一位。粘贴多行文字自动拆段,认得
  `A:` / `B:`(全角冒号也认)和发音人名字的前缀。显示「12 / 60 段」,每段超过 280 字标红(接口的上限)。
- 后端 `start_podcast` 收 `turns: [{speaker: 0|1, text}]`,直接映射成 `nlp_texts`,前后端都按 60 段 / 每段 280 字 / 发音人下标校验。
  智能体的 `generate_podcast` 照读一段字时(它给的是 `text`),由工具那一侧按句拆成轮流的几段再交进来 —— 领域只认 `turns`。
- **对谈稿跟着音频走**:产出素材的 `media_info.dialogue = [{speaker, text}]`、`media_info.speakers = [{value, label}]`。任务清掉了也还在。
- **闭环**:改写、讨论出来的结果卡下面有一块可展开的「对谈稿」(按发音人分色),点「改稿再念」把稿子按 A / B 装进照稿念编辑器;
  改完再念,这一次只花播客合成的钱。
- 发音人没给时,默认播客目录里的前两位(发音人不花钱,不是替人挑一个要付费的东西)。

### 7. 新产出的素材名(待拍板 5)

- 语音:「音色名 · 文本开头」(音色名去掉括号里的说明:「晓晓(女·温暖)」→「晓晓」;文本开头 16 字,长了加「…」)。克隆的嗓子用它在
  配音库里的名字;远端引擎的音色用目录里的名字,界面给了名字以界面的为准(火山按账号现拉的音色目录只有界面那边有)。所有调用方一样
  (字幕配音的零件也是,它们本来就藏在素材库外面)。
- 播客:「主题或材料开头 · 播客」(英文界面 `· Podcast`,按发起时的语言)。
- 老素材名不改。

### 8. 老数据迁移(一次性,数据库版本 10)

`migrate-speech-and-podcast-join-creation-sessions`,幂等:

1. 取 `jobs.kind in ('tts', 'podcast')`、状态 succeeded、顶层(`parent_job_id` 为空)、`created_by` 不为空、`payload.intermediate` 为空、
   `result.asset_id` 指着一份还在的、不是中间产物的素材、还没有生成记录指着它的任务。
2. 按(工作区、`created_by`、种类)各建一条会话(待拍板 4),标题「以前的语音」/「以前的播客」,主人是 `created_by`。每个任务一条记录,
   时间用任务的时间;request 从 payload 拼;文字只剩前 200 / 500 字的,记录上标 `truncated: true`(界面写「只保留了开头」)。
   补一行 `GeneratedAsset`。
3. 播客的 `result.texts` 抄进素材的 `media_info.dialogue`(还没有的才抄),发音人从 payload 抄进 `media_info.speakers`。
4. 任务行已经被清掉的老产出,素材上没记是谁做的,建不了私人会话:**留在素材库里,不进会话**。
5. 分不出来源的老任务(画板「念出来」、笔记朗读也是顶层 tts 任务)一并收进「以前的语音」—— 宁可多收几条,不丢。

### 9. 本机存储与深链

- `lib/localMigrations` 加一步 `ai-studio-create`(幂等、迁完删旧键,不留兼容分支):
  - `mosael:tab:ai-studio` 的 `generate` / `audio` 改成 `create`,`chat` 不动;
  - 旧值是 `audio` 时,`mosael:tab:ai-studio-audio` 的 speech / podcast / music 变成筛选 speech / podcast / audio;旧值是 `generate` 时筛选
    设成 all;然后删掉 `ai-studio-audio`;
  - `mosael.generation.session.<ws>.visual` / `.audio` 合成 `.create`:上次停在音乐那一格的取 audio,否则优先 visual、没有才 audio;
    已经有 `.create` 的不覆盖。
- **深链** `#/ai?tab=chat|create[&session=<生成会话 id>][&kind=<筛选>]`,读完把地址还原成 `#/ai`(会话 id 和筛选经信箱交给创作页,
  和画板的 `?board=` 同一条路)。应用启动时把 hash 写回规范样子的那一步(`app/hashRoute.writeHash`)给 `ai` 留着参数 —— 页面按需加载,
  第一次提交时 AI Studio 还没挂上,先抹了它就读不到(笔记、画板、场景、资产早就是这样)。
  - `openAgentSession`、`goToPlace(studio)`、内嵌浏览器「交给智能体」→ `?tab=chat`(修掉落错分区)。
  - 模型库「用它生成」→ `?tab=create`,筛选经信箱换成那一种,不再写两个分区键。
  - 任务中心「前往」:生成、`tts`、`podcast` 任务的 payload 记着 `session_id`(`job_catalog` 的 `record_field`),落在 `?tab=create`、打开那条会话。
  - 资产详情「在哪里用过」→ 那条创作会话。
  - 智能体 `open_view("ai")` 去对话;`open_view("ai", <生成会话 id>)` 去那条创作会话。工具说明跟着改,`studio-views` 契约不动。
- ADR 0044 里 AI Studio 这个「地方」仍然只是对话分区;创作分区不是一个地方,语义不变。

## 否掉的备选

- **把 TTS 做成生成适配器**(语音进生成目录、走 `POST /generation/jobs`):0022 决定 2 的理由仍成立,而且要把音色表、克隆、远端副本、
  同意上传都塞进描述符。
- **新开一张「语音会话」表**:会话列表、分组、分享、批量删、记录流全要再写一份,而生成会话那一套原样装得下。
- **价格按 `job_id` 去对用量事件**:任务清掉之后 `job_id` 置空,价格跟着没了。
- **用落终态监听写产出**:提交之后另开事务,界面会短暂读到「成功但没有产出」(见 §5)。
- **会话不锁族**:一条会话先念字后出图,记录流里两种输入框、两种右栏来回换,筛选也归不了类。
- **播客「只出稿」模式**(待拍板 6,维护者:不做):要接一个对话模型、多一种记录形状;「改稿再念」已经能用现有接口走通。

## Consequences

- 语音、播客的结果卡和音乐同一张(波形、真时长、下载、在素材库里打开),0:00 消失。生成中的占位、停止、已停止、失败、价格脚注都
  照记录流那一套。
- 「音频」分区、`AudioWorkspace` 和它的测试删掉;`SettingsHint` 那种虚线大框换成右栏的提示条(和「还没有可用的生成模型 —— 去配置」
  同一个组件)。
- 语音、播客的任务在任务中心里照旧叫「配音」「播客」,点过去落在创作分区。
- 智能体 `generate_audio` / `generate_podcast` 的回执多一个 `generation_id`;每次一条新会话。
- 官网 AI Studio 指南(中英文正文、截图)跟着改,记进 RECAPTURE。

## 待拍板(2026-10-08 全部照推荐拍板)

1. 会话按「族」锁定(视觉 / 音乐 / 语音 / 播客):已有记录的会话里只能选同族模型。**推荐锁** —— 拍板:锁。
2. 筛选「图像」「视频」分开,按会话最后一次的种类归。**推荐** —— 拍板:照推荐。
3. 哪些入口写创作记录:创作页、智能体写;画板「念出来」、工作流 tts 节点、字幕配音、笔记朗读不写。**推荐** —— 拍板:照推荐。
4. 老产出按「每人每种一条『以前的语音 / 播客』」并进会话;任务行已被清掉的老产出留在素材库。**推荐** —— 拍板:照推荐。
5. 新素材名「音色名 · 文本开头」/「主题 · 播客」;老素材名不改。**推荐** —— 拍板:照推荐。
6. 播客要不要另加「只出稿」。**推荐不加** —— 拍板:不加。
7. 新 ADR 修订 0022 决定 2(引擎仍分开,会话和记录合一)。**推荐** —— 拍板:照推荐,编号 0055。
8. 迁移在维护者库的副本上试跑:合并时由协调者做;实现这一侧用造的、形状照真实数据的老任务行测(见「实现记录」)。

### 和设计不一样、或设计没写到的

1. **产出挂记录在同一个事务里**(`on_asset`),不靠落终态监听 —— 见 §5。失败、停止才走监听(`record_failure` 去掉 `ai_generation` 的限定)。
2. **价格记在记录名下**(`usage_source`),不按 `job_id` 去对 —— 见 §5。没走记录的调用方(画板、工作流、字幕配音、笔记朗读)照旧记在任务名下。
3. 创作页的任务列表是 `GET /api/jobs?recorded=true`(挂着创作记录的任务);按种类列 `tts` 会把字幕配音的零件一起拉回来。
4. 任务的 payload 记 `session_id`,`job_catalog` 给生成、`tts`、`podcast` 配 `record_field`:任务中心「前往」落在 `#/ai?tab=create`、打开那条会话。
   没走记录的 `tts` 任务(画板念的)「前往」也落在创作分区 —— 此前同样落在 AI Studio。
5. 内置音色名(`builtin_voice_label`)放在 `voices/voice_labels`:合成要它给产出起名,目录要它给下拉写名字,放在任一边都和另一边成环
   (`test_import_layering` 当场红过)。
6. 素材名的文本开头:中文 16 字,纯西文 28 个字符(同样的长度在英文里只够半句)。
7. 播客没给发音人用目录里的前两位;改写、讨论要两位不同的发音人,照稿念的段数、每段字数、发音人下标在建任务之前判(领域里也判,不只靠请求体)。
8. 智能体的 `generate_podcast` 照读给的是一段字:工具那一侧用 `split_podcast_rounds` 拆成两人轮流的几段再交进来,领域只认 `turns`。
9. 迁移步骤名照惯例带 `migrate-` 前缀;会话标题写死中文(迁移是历史快照,不读会变的文案表);音色名只写配音库里的嗓子(内置音色表是会变的代码),
   别的由界面按引擎的音色目录认 —— 播客对谈稿里的发音人同样从目录认。
10. **筛选折行**,不横着滚(真界面里撞到:240px 一行只露得出三个半,后两种被裁在栏外)。
11. **启动时规范 hash 的那一步会抹掉 `#/ai?…`**(真界面里撞到:深链落在对话分区):`writeHash` 挪进 `app/hashRoute`,给 `ai` 留参数,配了测试。
12. **`useSpeechDraft` 不把每次渲染都换新的 setter 放进依赖**(真界面里撞到:右栏挑了云希,下一次渲染又回到晓晓 —— 换引擎会清掉选好的音色)。
13. 左栏的标题从「生成会话」改叫「创作会话」(英文「Creations」),搜索框、空态同。
14. 锁族只挂在创作页的入口上(`lock_family`),不挂在「点了名的会话」上:ADR 0052 要把画板、工作流、智能体对话的生成按出处归进各自
    一条会话,那几条里种类混着,不能被锁。创作页打开一条「来自别处」的会话时下拉怎么列,留给 0052 定(现在是跟着那条会话最后一次的种类那一族)。
15. 在念的时候任务上那句「合成《…》配音中」写音色名,不写音色 id(建任务时那一句本来就是名字,开始念时被改回了 id)。
16. `/tts/podcast`、`PodcastRequest`、前端 `generatePodcast` 删掉;`/tts/synthesize`、`/voices/{id}/synthesize` 留着(笔记朗读、画板等在用)。

### 迁移怎么验的

- `tests/test_speech_podcast_join_creation_sessions.py`:照真实形状造的老任务行 —— payload 截断(400 字的旁白只剩 200、720 字的材料只剩 500)、
  `result.texts`、本机克隆(`voice_id` → 配音库名字)、零件(任务标了素材没标、素材标了任务没标两种)、工作流派的子任务、失败的、产出删了的、

  孤儿留在素材库,对谈稿抄到素材上,界面里时长、音色名、对谈稿都对。
