# ADR 0094 · 按要的画幅出图出视频;首帧、尾帧交给视频模型之前摆正

- 状态:**已采纳**(2026-11-09)。真跑官方工作流时维护者指出「生图和视频尺寸不一致时有畸变」,同日让先做这一步。
- 关联:ADR 0027(资产挂参考图)、ADR 0029(3D 参考现渲成素材)、`domain/assets/lineage`(来源链)、
  `domain/assets/intermediates`(工序零件)。

## 背景

带货口播、整片两条模板都是「先出一张图、再拿它当首帧出视频」。真跑时出图那一步交回的是方图
(千问编辑 2048×2048、gpt-image-2 1024×1024),视频那一步要 9:16 / 16:9。图交过去之后,
ComfyUI 的 H3 工作流把它**直接缩放到目标宽高** —— 实测带货口播的衬衫整件被横向压窄,成了「瘦长款」;
别家的视频服务遇到画幅不对的首帧各有各的处理(拉伸、自己裁、报错),结果不可控。

时间线合成不是问题:片段放上时间线一律保比例(裁满 / 留边 / 模糊底),只会裁掉一点边。

## 决定

**生成漏斗**(`generation.operations._create_generation_job`)在校验之前,把视频请求里的首帧、尾帧按这次的
目标画幅**居中裁满**,裁好的一份登记成派生素材,替换请求里原来那份;改了什么记在请求的 `fitted_frames` 里。
所有入口(AI 工作台、画板、工作流、智能体)、所有供应商都从这里过,各家不用各自处理。

1. **目标画幅从这次的参数里读,按这个先后**:
   - 宿主的 `aspect_ratio`(`adaptive` = 视频跟着首帧走,不摆);
   - 名字就叫 `aspect_ratio` 的节点输入(ComfyUI 工作流的 `115.aspect_ratio` 这类)—— 和宿主同一个名字,按名字认;
   - 宿主的 `size`(`宽x高`)。
   值只认开头的「宽:高」(`9:16 (Portrait Widescreen)` → 9:16)。**读不到就不动** —— 不猜。
2. **只摆首帧、尾帧**。参考图是「看着它画」,不是「从它开始」,模型自己会构图,裁它反而丢信息。
3. **差 1% 以内不动**:H3 出 1056×608 这类「按 32 的倍数取整」造成的小偏差不值得一刀。
4. **居中裁满**。留边、模糊底(时间线合成那另外两种)对首帧不合适:黑边和模糊会被模型当成画面内容一起动起来。
5. 裁出来的一份:来源链 `fit`(按画幅裁)指回原图,`intermediate = fitted_frame`(素材库默认不列,
   「显示」里切过去看得到),AI 标记照常从原图继承。这次生成随后被拒时和 3D 参考渲出来的素材一样删掉。
6. 读不了的图(格式不认、没有尺寸)原样交出去 —— 摆正是兜底,不是新的拒绝理由。

### 为什么不在 ComfyUI 工作流里改缩放

用户的工作流各式各样,宿主不该假定里面有哪个缩放节点;别家视频服务也有同样的问题。漏斗这一处管住所有模型。

### 为什么登记成素材,不是临时文件

生成记录要说得清「模型收到的是哪张图」:「再来一次」照原样再发、事后排查为什么构图被裁,都要那一份还在。
和 3D 参考现渲的那几张同一个理由。

## 第二步:出图、出视频就按要的画幅出(同日)

摆正是兜底:方图交给竖屏视频会被裁掉两边,构图有损失。根治是出图那一步就出对的画幅。

问题出在**意图写在了模型参数里**:模板建图时按所选模型的尺寸表,把 `size: 720x1280` 这样的值写死进节点的 `parameters`;
前端换模型时只把新模型也认的参数带过去,gpt-image-2 ↔ 千问编辑这样换一圈,尺寸就没了,出回 1024×1024 的方图。

决定:

1. **「要几比几」是节点自己的一格**:`ai_generate` 新增 `frame_aspect`(界面上叫「目标画幅」),不在 `parameters` 里,换模型不丢。
2. **生成漏斗按选中的模型翻**(`domain/generation/aspect.parameters_for_aspect`,`create_generation_job(frame_aspect=…)`),
   先后:画幅选项(`aspect_ratios`,只认完全一致的那一档,不挑一个最近的冒充)→ 名字叫 `aspect_ratio` 的节点输入
   (ComfyUI 的 `10.aspect_ratio` / `115.aspect_ratio`,按选项挑)→ 尺寸表(`sizes`,同比例里面积最接近默认那一档)→
   任意尺寸(`custom_size`,按默认面积、`multiple_of` 取整)。**参数里写明了画幅或尺寸的以写明的为准**;都对不上就不加。
   在补模型默认值**之前**翻 —— 反过来模型的默认尺寸先占了位,就成了「写明了的」。翻成了什么记进请求的 `frame_aspect`。
3. 摆正(第一步)的目标画幅:参数里说的优先,参数没说时按 `frame_aspect`(模型由首帧定画幅的情形)。
4. 官方模板里「先出图、再拿它出视频」的那几个节点都写上 `frame_aspect`:整片的关键帧、这一镜、续写段跟着开始节点的画幅
   (`{{input.aspect_ratio}}`);带货口播 / 模特上身 / 数字人带货的画面和动起来那一步写 9:16。四个模板各升一版。
5. 画幅的读法、`size_for_aspect` 从模板模块挪到 `domain/generation/aspect`,模板、漏斗、摆正共用一份。

模型压根没有说画幅的地方(千问编辑 app 只收一张参考图)时,出图出不了对的画幅 —— 这时第一步的摆正兜底。

## 后果

- 首帧本来就是目标画幅的什么都不发生。
- 节点上换模型不用再管画幅;模板建图时写死的尺寸仍在(老图照旧),和 `frame_aspect` 说的是同一件事。
- 方图交给竖屏视频(出图模型没有画幅可选时)会被裁掉两边 —— 构图有损失,但不再变形。
