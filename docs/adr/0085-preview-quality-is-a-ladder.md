# 0085 预览画质按代理、设备像素与暂停静帧分层

- 状态：已采纳
- 日期：2026-10-27

## 背景

监视器里的画面一直被说“糊”。实测不是播放器滤镜，而是两段降采样叠加：

- 预览代理高度封顶 720，1080p 素材先被压成 1280×720；
- `CanvasCompositor` 又把画布后备像素设成序列分辨率，而不是 CSS 尺寸 × `devicePixelRatio`。Retina 上等于先画 1920 再交给浏览器放大。

2026-10-27 本机数据：序列 1920×1080，最近 1080p 素材的代理是 1280×720，3456×2168 的屏幕录制代理只有 1148×720。原片细节在代理阶段已经丢失，后两层再怎么放大都补不回来。

## 决策

预览画质是一条明确的阶梯，不在一条路径上同时追所有目标：

### 播放：1080p 代理

`PROXY_HEIGHT` 从 720 提到 1080。1080p 序列一对一，4K/Retina 屏幕录制降到 1920×1204，仍然保持短 GOP、无 B 帧和 faststart，WebCodecs 的确定性和 seek 成本不变。

代理规格用 `proxy_spec_version` 记录在 `media_info`。启动补齐扫描发现文件存在但版本旧时，重排一次代理任务。版本同时是迁移标记：旧素材不需要单独的 schema migration，也不会继续静默复用 720p 文件。

### 显示：CSS × DPR 的后备像素

`canvasBackingFor(css, dpr, sequence)` 返回真实后备像素和序列坐标到设备坐标的缩放。`paintScene` 继续用序列像素作画，合成器通过 `setTransform` 映射到设备像素。

Canvas 的阴影偏移和模糊按规范不受变换影响，因此 `paintScene` 读取当前矩阵并按 `shadowScaleX/Y` 补偿，否则 Retina 上元素变清晰、影子却缩成一半。导出侧是单位矩阵，行为不变。

### 暂停：原片静帧，仍进同一张 canvas

播放位置停住时，每个可见视频片段用原文件建一个隐藏 `<video>`，seek 到目标时刻后作为 `CanvasImageSource` 画进同一张 canvas。原片解不动（编解码不支持、文件缺失）时继续画代理帧，不会黑屏；原生 seek 尚未完成时也先保留代理帧，不闪断。

**只在暂停时使用。** 播放同步属于音频时钟，多个媒体元素各自缓冲会漂移；全屏播放仍走 1080p 代理。全屏暂停自动享受原片静帧，因为监视器尺寸和 DPR 变化后仍由同一个合成器绘制。

## 后果

- 旧代理会在下一次后端启动/重载时自动重建一次；重建期间 `proxy_status=pending`，预览按既有的四态机等待。
- 1080p 代理的解码和范围缓存成本高于 720p；缓存预算仍按代理自身码率换算，不需要新的全局配置。
- 原片暂停源可能让 canvas 变 tainted（Electron 的 `file://` origin 下不做严格 CORS）。预览只显示、不读回，导出仍在后端渲染，因此接受这个取舍。
- 预览画质现在是“播放清晰、暂停最清晰、导出原生”的阶梯，不再承诺播放路径与导出逐像素同源。像素一致性仍由 ADR-0004 的契约约束，画质上限由本条 ADR 说明。

## 被否决的方案

- **预览代理直接上 4K**：解码、内存和导入时间翻几倍，而监视器通常只有一千多 CSS 像素宽；收益低于成本。
- **只修 DPR**：画布变清晰，但源仍是 720p，只是把糊的画面放大得更平滑。
- **暂停时走后端截图**：每停一次就往返一次后端并落盘，交互延迟和磁盘垃圾都不可接受。
- **播放时也用原片 `<video>` 做多轨同步**：把音频时钟已经解决的同步问题重新交给多个独立缓冲的媒体元素。
