# ADR 0028:数字人 —— 一张脸、一把嗓子、一段话 → 一段会说话的视频

## Status

Accepted — 2026-09-28。维护者拍板了[数字人方案](../design/digital-humans.md)末尾的待定项:

- **首批只接阿里百炼**:`wan2.2-s2v`(说话照片)和 `videoretalk`(改口型),同一个百炼连接。火山 OmniHuman、可灵放以后。
- **导出时的「AI 生成」显式标识默认开、允许关。** 关的时候当场写明后果(见 §5)。
- **这一期不做本机**(ComfyUI 模板图放以后)。
- 「形象」不单独建表:它就是 [ADR 0027](0027-asset-library.md) 的**人物资产**(脸 = 参考图,嗓子 = 音色,授权 = consent)。

这是 ADR 0027 的阶段 5。实时互动数字人、3D 骨骼数字人、全身动作迁移不在这里(方案「本期不做」)。

## Context

方案文档写清了现状和缺口:素材角色 `first_frame` / `source_video` / `driving_audio` 已经有了,万相 2.7 图生视频今天就能
「首帧 + 驱动音频」,可是——

1. **时长不跟音频走**:万相 2.7 的驱动音频比所选时长长时自动截掉后面,不报错;描述符没法说「成片长度等于音频长度」,
   也没有按素材自身时长的上下限。
2. **没有能复用的「人」** —— 已由人物资产解决(ADR 0027 阶段 1)。
3. **没有授权门槛,没有 AI 标识。**

## Decision

### 1. 数字人是视频生成里的一种素材组合,不是新的 kind

两种模式,都在 `video` 下,**描述符声明了才出现**(ADR 0013 的正面证据原则):

| 模式 | 意思 | 素材角色 |
| --- | --- | --- |
| `speech-to-video` | 一张人像按音频说话 | `first_frame` + `driving_audio` |
| `video-lipsync` | 一段已有视频的嘴对上新的音频 | `source_video` + `driving_audio` |

不加新角色。

### 2. 描述符三条新规则

- **`duration_follows: "<角色>"`**:成片长度等于这份素材的长度。声明了的模型不收 `duration_seconds`(不在
  `parameter_keys` 里,界面就不画时长控件),界面写一句「时长跟着驱动音频」。
- **`source_duration_seconds: {"<角色>": [最短, 最长]}`**:按素材**自身的时长**(`media_info.duration`)给上下限。
  超出就在提交那一刻说人话(「驱动音频 72 秒,这个模型最长 20 秒」),不建一个注定失败的任务。时长读不出来的素材放行
  (不猜),交给供应商判。
- **`truncates_role: "<角色>"`**:这份素材比所选时长长时,后面会被截掉(万相 2.7 i2v 的驱动音频)。界面在所选时长
  短于它时提醒「后 N 秒会被截掉」。服务端不拦 —— 截掉是这家明写的行为,用户可能就是要前 5 秒。

三条都在生成漏斗里(`generation/operations.py`),界面、智能体、工作流、画板四条路都过它。

### 3. 适配器:百炼两个模型

- `wan2.2-s2v`:先调 `wan2.2-s2v-detect` 预检(清晰、单人、正面),通过了再提交;预检失败统一翻成 `genErr_noUsableFace`
  (「没找到清晰的正脸」)。预检在适配器内部,不暴露给用户;它的费用计进这一次。
- `videoretalk`:视频 + 音频,2–120 秒;音频比视频长时用 `video_extension` 补齐。
- 数字是 2026-09-26 读到的官方文档;**还没有拿真实密钥跑到终态**,按惯例以接口自己的报错为准,第一次真跑时校准。

### 4. 人物资产「让它说话」

- 一个节点 `entity_speak`:点名一个人物、写一段稿子(或接上游便签),用它的音色配音,再拿它的正面图(没有正面用挑图
  先后的第一张)和这段配音做「说话照片」。画板上是人物资产格的能力,资产详情页、工作流里是同一个执行器。
- **授权是硬门槛**:真人要有「这是我本人」或「已取得本人同意」的声明才能说话(`usable_for_digital_human`),
  起任务之前就拒。虚构人物照常。
- 画板图片格「让它说话」、视频格「对口型」:同一套,只是脸 / 片子由那一格给,嗓子在面板上挑。

### 5. 合规:AI 标识

- **显式标识**:成片里有数字人片段(生成记录的模式是 `speech-to-video` / `video-lipsync`)时,导出在片头和画面一角加
  「AI 生成」。**默认开,允许关**(维护者拍板);关的时候当场写明:按《互联网信息服务深度合成管理规定》第十七条和
  《人工智能生成合成内容标识办法》,对外发布的数字人内容要显著标识,关掉之后由发布的人负责。
- **隐式标识**:写进 MP4 元数据(`comment` / AIGC 标记),不随显式标识的开关变 —— 它不影响画面,没有关掉的理由。
- **音色授权**:克隆音色也要一份声明(方案 §5)。已有的克隆音色迁移成「未声明」,用于数字人之前要补上。

## 阶段 3 · 长稿(2026-09-28 起)

方案「分阶段」的阶段 3(模板与长稿)按下面几步落,第一步已做:

1. **长稿分段 + 「稿子 → 数字人口播」**(已做)。新节点「长稿分段配音」(`talking_segments`):**按句切、逐句配音、
   按实测时长分组** —— 相邻的句子凑成一组,每组配出来的总长不超过所选说话照片模型的驱动音频上限(描述符的
   `source_duration_seconds.driving_audio`,不写死),一组拼成一段音频;句子不从中间断开,估着太长的句子先按逗号断;
   一句配出来仍超上限就说是哪一句。字幕时间用配音的实测时长,不再转写。「让它说话」(`image_speak`)收上游的一段
   音频(和对口型同一条,`board_host: false`),接上时不再配音。模板把这两样和已有的循环、铺时间线、字幕、导出串起来;
   「让它说话」上的授权确认留空,由跑的人确认。智能体一侧 `generate_video` 的说明写清两种组合(阶段 1 里欠着的那一项)。
2. **视频翻译 · 改口型**(已做)。新节点「译配对口型」(`dub_lipsync`):把配音轨上的片段(各自的起点、截取、变速、增益)
   混成一段和原片等长的人声;原片按模型的 `source_duration_seconds.source_video`(百炼 2–120 秒)切块,**切点优先落在
   两句之间的空当**,没有空当才在上限处硬切,最后一块太短就把上一个切点往前挪;有配音的块改口型,一句都没有的块用原片、
   不花钱;各块接回整段(不带声音 —— 声音在配音轨和背景轨上),放到**最上面一条新视频轨**盖住原片。原片不动,删掉那条轨
   就回到原样。模板「视频翻译 · 改口型」就是「视频译配」那张图在导出之前多这一个节点(`translated_dub_graph(lipsync=True)`,
   不另抄一份);授权确认留空。方案里「从原说话人克隆音色」这一步没放进模板:克隆要本人或已获同意的声明,不该由模板替人
   在后台建一把别人的嗓子 —— 嗓子仍在配音节点上挑。
3. **带货口播升级**(已做)。模板「商品 → 数字人出镜带货口播」是带货口播那张图换掉口播那一段
   (`product_pitch_short_graph(presenter=True)`,不另抄一份):挑一位资产库里的人物(`entity_get`),开场钩子和
   收尾号召由它**出镜说**(`entity_speak`,脸、嗓子、授权声明都跟着资产走),中间每一拍仍是商品画面,口播用同一个
   嗓子念、对齐这一拍的开头;时间线上的先后(开场 → 各拍 → 收尾)由连线定。不出镜的那条模板不变。

阶段 3 三件都已做。

## 阶段 4 · 更多供应商(2026-09-28 维护者拍板)

接下来按这个顺序接:**火山 OmniHuman 1.5 → 可灵 Avatar 与对口型 → 海外 HeyGen / Hedra**。本机(ComfyUI 模板图)
这一期仍然不做。每一家都是一个适配器 + 一份描述符:模板和节点按描述符的 `modes`、`source_duration_seconds` 挑模型、
定分段上限,不为哪一家写分支。

未验证:说话照片的成片里是否自带那段音频(百炼文档没写明),模板按「自带」铺在视频轨上;第一次真跑时确认,不带的话
在循环里把这段音频同时铺到音频轨。

进度:火山 OmniHuman 1.5 已接(`adapters/bytedance/volcano/omnihuman.py`,说话照片)。可灵两个已接(2026-09-28,
`adapters/kuaishou/kling/avatar.py`,挂在可灵视频适配器下按模型分):

- `kling-avatar`(说话照片,`speech-to-video`):`/v1/videos/avatar/image2video` 一步提交,图和音频传**不带前缀的
  Base64**,所以不要 `url_only_roles`;音频不是 mp3/wav/m4a/aac 或超了 5MB 的先转单声道 64kbps mp3。1080p 映射到 pro。
- `kling-lipsync`(改口型,`video-lipsync`):先 `identify-face`(只收链接,故 `url_only_roles: [source_video]`),
  挑出现最久的脸;再 `advanced-lip-sync`,配音从那张脸出现的时刻插入,截到「配音长度」与「脸在的时长」短的那个
  (不足 2 秒提前报 `providerErr_klingFaceTooShort`),原声音量 0 —— 让人说**新的**这段话,原来的人声留着就是两段叠在一起。

两家都照文档写、还没拿真实密钥跑到终态。

海外两家已接(2026-09-28),各一个新供应商连接(`heygen`、`hedra`,只填 API Key):

- HeyGen(`adapters/heygen/video.py`):`heygen-avatar-iv`(说话照片,`POST /v3/videos` 的 `type: image`,人像内联
  Base64,配音走 HeyGen 直传 —— 预签名 PUT 不带 Key)与 `heygen-lipsync`(改口型,`POST /v3/lipsyncs`,精度模式;
  原片只收 mp4 / webm)。配音上限文档两处不一(30 分钟 / 10 分钟),描述符按严的 600 秒。
- Hedra(`adapters/hedra/video.py`):`hedra-character-3`(说话照片)。图和配音**只能**用它 `/v3/files` 发回的临时
  链接(外链一律拒),所以链接素材也先下到本地再传;提示词必填,用户没写给一句中性的;画幅没有 auto,按原图挑最近一档。
  Hedra 没有视频改口型的模型。
- 三家(可灵、HeyGen、Hedra)的本地素材都不需要用户的对象存储,只有可灵对口型的原片(认人脸只收链接)例外。
  配音 / 人像转格式共用 `media/vendor_formats`。

同样照文档写、还没拿真实密钥跑到终态。阶段 4 的三家到此接齐;本机(ComfyUI 模板图)仍不在这一期。

## 分步落地

- 第 4 步已做(2026-09-28):克隆音色的授权声明(`voices.consent_kind` / `consent_by` / `consent_at`,迁移
  `migrate-voices-declare-consent` 把已有的写成 `undeclared`;建音色时必选,配音库里补;数字人三个节点在配音之前
  拦 `executors/talking._require_voice_consent`)。导出:成片里有数字人片段(生成记录带驱动音频,`render.digital_human_assets`)
  时片头 3 秒正中、整片右上角烧「AI 生成」(导出框里默认开、允许关、不记住关,关时当场写明后果),MP4 元数据总写 `AIGC`
  (《标识办法》第五条的字段)和一句 comment。

- 第 3 步已做(2026-09-28):`entity_speak`(人物资产格的能力、资产详情页「让它说话」、工作流节点;门槛在
  `executors/talking.check_entity_speak`,详情页起任务之前先过它)、`image_speak`(图片格)、`video_lipsync`(视频格,
  音频字段 `board_host: false`:只从上游接,不让这一项挂到音频格上)。后两个没有资产上的声明可查,面板上有一格必选的
  「已取得授权」确认。

- 第 1、2 步已做(2026-09-28)。百炼两个适配器的本地素材走百炼自己的临时存储(`oss://`,48 小时,只绑这个模型),
  不借用户的对象存储 —— 配音出来的音频都是本地文件,要求先配对象存储才能让人物说话,门槛就太高了。

1. 本 ADR + 描述符三条规则与校验 + 界面(时长说明、截断提醒)。
2. 百炼两个适配器(`wan2.2-s2v` 带预检、`videoretalk`)。
3. `entity_speak` 与授权门槛;画板图片格「让它说话」、视频格「对口型」。
4. 音色授权迁移、导出的显式 / 隐式标识。

## 后续修正(2026-09-30)

一次现状调查找出的几处缺口,已修:

- **计量**:成片时长跟着驱动音频走,请求里没有 `duration_seconds`,此前按 5 秒记。现在请求没说时长的,按产出视频的
  真实时长记(`runner._record_generation_usage`,和音频同一条)。百炼 `wan2.2-s2v`(480P 0.5 元/秒)、`videoretalk`
  (0.08 元/秒)进了挂牌价表;其余几家官方价取不到原文或按积分计,不收。
- **授权收进漏斗**:§4、§5 的人物声明与克隆音色声明,此前只有数字人工作流节点查。现在
  `generation.operations.check_digital_human_rights` 在漏斗里查,所有入口一致;智能体开确认卡时就查。克隆音色配的
  音登记时记 `media_info.voice_id`(已有的由迁移从配音任务补)。
- **长稿分段的下限**:阶段 3 的分组只看上限,短于模型下限的一段(可灵数字人 2 秒)到提交时才被拒;现在末尾补静音到下限。
- **节点能挑分辨率**:「让它说话」(人物 / 图片)多一项分辨率,选项来自所选模型描述符的 `resolutions`。
- **官网**:新增「数字人」一页(`website/content/docs/*/guides/digital-humans.mdx`)。

仍未做:8 个模型都还没拿真实密钥跑到终态;说话照片的成片里带不带那段音频仍未验证。
