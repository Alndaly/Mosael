# ADR 0102 · 3D 场景里的物体可以只属于某几个镜头;白模同一个地点只搭一份布景

- 状态:**已采纳**(2026-11-15)
- 关联:ADR 0029(3D 场景当生成的参考)、ADR 0097(关键帧照白模的机位)、ADR 0101(漫剧单集)、
  `docs/design/scene-time-and-cameras.md`(镜头 = 用哪台机位、拍多久)。

## 背景

维护者看《长明灯》第 2 场的白模场景:「很多的建模为何都在同一个场景下建立了一堆相似的」—— 一排 20 个一模一样的灯铺,
254 个物体。

整片 / 漫剧模板「设计 3D 白模布景与机位」照 `blockout_rules` **每镜搭一个布景台**(`bay-<n>`,沿 x 每隔台距 D 摆一个)。
当初这么定有两个原因:

1. 分镜每一镜可能换地点;
2. 每一镜的人偶站位不一样 —— 第 3 镜沈青禾跪在供桌前、第 4 镜小满站在楼梯口;要是所有人偶摆在同一个布景里,
   每一镜的白模都会拍进别的镜头的人偶。

第 2 条才是根子:场景数据里**没有「这个物体只在第几镜出现」的说法**,只好整台复制。代价是同一个地点复制 N 份,
LLM 要逐镜重写同一套陈设(20 镜的布景比分镜还长,写到 7 万多字被截断过),编辑器里一排看不出区别的房间,
改一处陈设要改 20 遍。

## 决定

### 1. 场景数据:物体可以只属于某几个镜头

`SceneObject` 加 `shot_ids: list[str]`(默认空)。**空 = 每个镜头里都有**;写了就只在这几个镜头里出现。
放在物体上而不是镜头上:要问的总是「这个东西此刻在不在」,渲染、选中、物体列表都按物体走。

- 和 `hidden` 一样**沿父链继承**:组只属于第 3 镜,组里的东西也只在第 3 镜。父链上每一级写了的 `shot_ids` 都要包含当前镜头。
- 写的镜头 id 必须存在(`SceneContent` 校验);删镜头时从所有物体的 `shot_ids` 里摘掉它,摘空的那个物体随之被删 ——
  它原本只属于那一镜。
- 带默认值的新键,老场景读出来是空列表 = 原样,不需要迁移。

### 2. 「此刻在不在」只有一条规则

后端 `scenes.render._visible(obj, objects, shot)` 与前端 `sceneGraph.hiddenObjectIds(objects, shotId)` 同一条:
自己和任一上级没藏,且父链上每一级写了的 `shot_ids` 都含这个镜头。

- 白模参考帧、运镜视频、`figures_in_shot`(挑参考人物)、自由视角(按传入的那个镜头)都按它;
- 缩略图按第一个镜头;GLB 导出整份场景(交给 Blender 的是场景,不是某一镜);
- 编辑器视口按**当前镜头**显示,不在这一镜的物体像藏起来一样(选不中、不出操纵器);物体列表里淡下去,
  行尾写「只在镜头 3」;检查器里多一栏「出现在」,逐个镜头勾选。

### 3. 白模布景:每个地点一份,每镜只加相机和人偶

`blockout_rules` 改为:

- 每个地点一个组 `set-<k>`(`name` 写地点名),这个地点的 room、陈设、远景体块都挂在它下面,`shot_ids` 留空 ——
  在这里拍的每一镜都看得到;不同地点沿 x 按台距 D 分开(D 的算法不变);
- 每一镜只加**这一镜的相机**和**出镜的人偶**,`shot_ids` 写 `["shot-<n>"]`,摆在它那个地点的组里;
  人偶 `id` 写 `<角色id>-<n>`(同一个角色每镜一个,站位各不相同);
- 镜头数照旧和分镜一致(`json_match_field = "shots"`)。

画板的「按文字搭 3D 场景」(`single_set_rules`)本来就是一个布景、人物一份、几台相机拍同一段动作,`shot_ids` 一律留空。

## 后果

- 同一场戏在同一个地点时,3D 场景里只有一份布景;LLM 少写 N−1 份陈设,输出大约缩到原来的几分之一。
- 一镜的白模只有这一镜的人偶;另一镜的人偶就算站在镜头前面也不会被渲进去。
- 编辑器要按当前镜头看:切镜头时人偶会换,这是有意的;「俯瞰全场」按当前镜头。
- 整片模板 29、漫剧单集 7;已经建好的工作流照旧,需要时按新版重建。
