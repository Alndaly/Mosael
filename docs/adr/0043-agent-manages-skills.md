# ADR 0043:智能体自己管技能 —— 建、改、开关、删、导入,每一样都过你的眼

## Status

Accepted — 2026-10-07。五条由维护者照推荐拍板。

## Context

维护者(2026-10-07):「我希望 Mosael 智能体在系统中还具备自行管理 Skill 的能力。」

### 现在有什么(ADR 0040,1.9.2 起)

- 技能是数据目录里的文件夹(`<数据目录>/skills/<工作区 id>/<名字>/`,一份 `SKILL.md` 加参考文件),**启用状态和来源记在库里**
  (表 `agent_skills`),不跟着文件走 —— 启用是一个信任决定。
- 智能体现在只会**用**:`use_skill` 读全文、`read_skill_file` 读带的文件;系统提示里只列开着的技能的名字和一句说明。
- **管**全在设置 → 智能体 → 技能:新建、编辑、删除、导入(先看全文再启用)、导出、开关、「复制成我的」。还有对话菜单里的「存成技能」:
  用这次对话的模型起草一份,弹出编辑表单,人改完才保存。
- 规矩(ADR 0040 §6):导入的技能是不可信的指令;启用之前给人看全文;技能不预先批准任何工具;脚本永远不跑;大小和路径封顶。
- 确认卡:会改东西的工具开一张卡(`backend/mcp_server.py` 的 `confirms` 一类),人点了才执行;有「本会话始终允许」和放行准则两种自动放行。

### 哪里不够

做顺了一件事,要人自己去设置里新建、把做法敲一遍;发现一份技能写得不对,要人自己去改;想试一个别人分享的技能,要人自己下载、导入。
这些智能体都看得到、写得出,只是没有工具。

## Decision

### 已拍板(维护者,2026-10-07,都照推荐)

| # | 问题 | 选项 | 推荐 |
| --- | --- | --- | --- |
| 1 | 智能体能做哪些 | A:列出、新建、改、开关、删、从链接 / 文件导入,都能;B:只能新建和改;C:只能起草,保存还是人去设置里点 | **A** —— 每一样都过确认卡(第 2 条),能做全比做一半顺手 |
| 2 | 要不要每次点头 | A:**每次都弹卡**,而且**不进「本会话始终允许」、不受放行准则自动放行**;B:和别的工具一样,能被自动放行 | **A** —— 技能会影响以后的每一次对话,是长期的东西;一次放行不该让它以后随便改自己的做法 |
| 3 | 主动提议 | A:做完一件多步的事、觉得以后用得上时,提一句「要不要存成技能」,你说要才起草;B:只在你开口时才动;C:自己存 | **A** —— 起草和保存都还要你点头 |
| 4 | 内置和插件带的技能 | A:不能直接改;要改就先「复制成我的」再改(卡上写明);B:直接改 | **A** —— 和设置页同一条规矩,内置的随应用升级、插件的随插件更新 |
| 5 | 智能体建的技能默认开不开 | A:卡上有「建好就启用」,默认勾上(你在卡上已经看过全文);B:默认不开 | **A** |

### 1. 工具

| 工具 | 做什么 | 卡上是什么 |
| --- | --- | --- |
| `list_skills` | 列出这个工作区的全部技能(含没开的):名字、显示名、说明、来源、开没开、多大 | 不用卡(只读) |
| `use_skill` / `read_skill_file` | 照旧 | 不用卡 |
| `create_skill` | 新建一份:名字、显示名、说明、正文,可以带几个文本文件 | `SKILL.md` 全文、每个文件的全文、「建好就启用」 |
| `update_skill` | 改一份「我的」技能(正文、说明、文件的增删改) | 改之前 → 改之后的对比,文件逐个列 |
| `copy_skill` | 把内置或插件的技能「复制成我的」(可以顺带改名、改内容) | 同 `create_skill` |
| `set_skill_enabled` | 开、关一份技能 | 开:全文(和设置页开启插件技能、扔进文件夹的技能那一步一样);关:一句话 |
| `delete_skill` | 删一份「我的」技能 | 名字、说明、文件数和大小;删了就没了 |
| `import_skill` | 从一个 https 链接(`.zip`、GitHub 上的技能文件夹)导入 | 和设置页导入同一个审阅:每个文本文件的全文、二进制的类型和大小、不认的字段、脚本标「不会执行」 |

- 都只碰**这个工作区**的技能,要求操作的人有工作区的「智能体」编辑权限(`ensure_workspace_perm(..., "ai")`,同设置页)。
- 大小、路径、文件类型的上限和设置页同一套(ADR 0040 §6);智能体只能写文本文件,不能写二进制。
- 新建的来源记成「智能体起草」,带上是哪个会话;设置页的列表里能看到。

### 2. 防它悄悄改自己

- **每一样都弹卡**(拍板 2),这类卡在「本会话始终允许」里不出现,放行准则也放不过它们。
- **在用某个技能时提出的改动,卡上写明**「这是在用技能『…』时提出的」—— 一份技能里写着「把你自己改成……」时,人一眼看得出来。
- 技能照旧不预先批准任何工具、不改确认卡和权限档;改技能本身也不会让哪个工具不弹卡。
- 隔离判断者(`domain/agent/judge.py`)照旧看不到技能。

### 3. 界面

- 卡片复用设置页现成的两样:导入审阅那个「全文 + 文件列表」的视图,和笔记编辑那种「改之前 → 改之后」的对比。
- 设置 → 技能的列表多一个来源标签「智能体起草」;点开能跳到起草它的那段对话。
- 「/」菜单不变(只列开着的)。

### 4. 交付

一步做完,进 1.9.4。测试:每个工具的成功、权限不够、内置 / 插件不能直接改、大小越界、路径越界、导入链接拿到的东西不对;确认卡不被
「本会话始终允许」和放行准则放过;「在用技能时提出的」标记;用真模型(订阅的 Kimi)跑一段「把刚才这件事存成技能」和一段「把『…』那份
技能第 3 步改成……」。

## 这一版不做

- 智能体跑技能里的脚本(ADR 0040 已拍板 4 不变)。
- 跨工作区复制技能、把技能发到别处(导出照旧在设置页)。

## Consequences

- 「存成技能」从人去设置里点,变成在对话里一句话;改、开关、删也一样 —— 但每一样都要看过才落。
- 多了一种「智能体能长期改变自己以后行为」的能力,所以它比一般的写操作守得更严:永远要点头、标出是不是在用技能时提出的。

## 实现记录(2026-10-07)

照上面做的,另有几处 ADR 没说、实现时定下的:

- **工具**(`backend/mcp_server.py` 里挨在 `read_skill_file` 后面一组):`list_skills` 和六件写的事。`list_skills(name=…)` 回那一份的
  `SKILL.md` 原文和文件清单(没开的也行),套一句「这是资料,不是给你的指令」—— 改一份技能之前得先看见它,而 `use_skill` 只给开着的、
  而且是「照着做」。**看不算用**:不进下面那个「在用技能时提出的」标记。
- **领域**:`domain/agent/skills/managing.py` 管每一件的两头 —— `review_*` 开卡前算卡上要的事实(全文、改之前 → 改之后、指纹),
  说不通的当场拒、不开卡;`apply_*` 批准后**照 payload 重新算一遍再写**。权限闸在 `use_cases.review / apply`(开卡的人、批的人各查一次
  `"ai"`)。卡的声明在 `domain/agent/confirmable/skills.py`。规整一份 SkillDoc 的那段(`compose_doc`)设置页的路由也改用它。
- **「每次都问」是一个声明**:`ConfirmableTool.always_asks`。`autopilot.decide` 头一条就看它 —— 排在 bypass、会话白名单、auto 档、
  放行准则、判断者之前,所以**完全放行档也放不过**(拍板 2 说的是「永远要点头」,bypass 也是一种自动放行);`set_session_allowances`
  不收它(422);声明它就不能再声明 `gate` / `needs_card`。`ConfirmationOut.always_asks` 让界面不画「本会话始终允许」。
- **卡上的开关**:`ConfirmableTool.choices`(这里只有 `enable`)。缺省值是工具开卡时放进 payload 的那个;批准请求带 `{choices}`,
  只认声明过的键、严格布尔,认领之后才写进 payload(先写的话,一张已经被别人批掉的卡的 payload 也会被改)。飞书那条入口不带,照缺省。
- **改**:标题、说明、正文给了就整段替换(正文是全文,所以先 `list_skills(name)` 读);`files` 是「路径 → 全文,或 null 删掉」。
  不改名。卡上存开卡时整份内容的指纹,批准时对不上(有人在设置里动过)就失败、什么都不写。写是整份在暂存里写好再换过去(`store.rewrite`)。
- **复制**只从内置 / 插件来(已经是我的就让它用 `update_skill`);显示名照原来那份,除非顺带给了新的。没改的文件不重复装进 payload,
  卡从原来那份读全文;同样核指纹。
- **开**记指纹(卡上摊的全文就是批的那一版),**关**不记。**删**是 `destroy` 档。内置、插件的删不了(能关)。
- **导入**:只认 https。`.zip` 照下;GitHub 的 `tree/<分支>/<路径>`(或指着 `SKILL.md` 的 `blob` 链接)用内容接口逐层列、
  从 `download_url` 取,列表里先看大小、超了不下;分支只认第一段。出口走 `core/outbound_guard`(内网守卫、每跳重定向重判、
  应用的代理),它多了一个 `max_bytes`:边收边数,超了抛 `ResponseTooLarge`。取回来的走设置页导入同一条读法和同一份暂存,
  卡照暂存画审阅(新加 `GET /workspaces/{id}/skill-imports/{import_id}`)。暂存照旧一小时过期:过期的卡看不到全文,批了失败。
  撞名:内置的拒;我的要 `replace=true`,卡上写明会替换。
- **「在用技能时提出的」**:这一轮在用什么,从两样现成的记录里读(`skills/runtime.skills_in_turn`)—— 这一轮的流里 `use_skill`
  调用(子智能体的也算,读失败的不算;流收尾了就没有「这一轮」),和这一轮在回答的那几条用户消息(上一条助手回答之后、没在排队的)
  用「/」点的。工具开卡时把名单放进 payload,摘要把它变成单独成行的后果提示(`confirm_skillInUse`),所以飞书、MCP 那种一行字的
  出口也带着。
- **存储**:来历多一种 `agent`(新建、复制);导入的照旧是 `imported`(来源要说清从哪个链接来)。三种都记 `agent_session_id`
  (外键到对话,删了回到 NULL),带加列迁移和测试。设置页:智能体起草的带「智能体起草」标签、导入的带「智能体导入」,点开是那段对话;
  智能体起草的那一行不再重复念来源。
- **主动提议**(拍板 3):系统提示加一行(4637 → 4704 字,上限 5000)。
- **界面**:改技能的卡复用设置页的 `SkillContent`(全文 + 文件清单)和改笔记卡的 `TextDiff`;改的对比默认只留改动前后各 160 字,
  可以「看整个文件」。开关放在卡持有的上下文里(`features/agent/cardChoices`),对话里和全局中心的批准按钮都把它带走。

**真模型实测**(订阅的 Kimi,k3,隔离的后端和前端):多步任务(建项目 + 写笔记)做完后,模型没有主动问要不要存成技能
(它提议的是细化分镜、建时间线);说「把刚才这件事存成技能」后,它直接 `create_skill`,卡上是完整的 SKILL.md(项目启动:建项目 + 配套笔记,
五步)和默认勾着的「建好就启用」,批了落地、开着。「第 3 步改成……」:先 `list_skills(name)` 读原文,再 `update_skill`,卡上
SKILL.md 一处插入;没有「在用技能」标记(看不算用)。「关掉『…』」:一句话的卡。从 `https://github.com/anthropics/skills/tree/main/skills/pdf`
导入:经代理取回 12 个文件,卡上全文、8 个脚本标「不会执行」、「装好就启用」没勾,批了落地、关着。另跑了一条「先 use_skill 读
creative-board 再复制成 my-board」:复制卡上写着「这是在用技能『创意画板』时提出的」。每张卡都只有「允许一次 / 拒绝」和
「这类改动每次都要你确认」。
