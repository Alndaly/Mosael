# ADR 0067:「引用即发送」—— 提示词里引用到的图片素材,运行时并进「要模型看的图片」

## Status

Accepted — 2026-10-16。大模型节点的 `image_asset_ids` 这一格多了 `ref_assets_from` 声明 +
一份 `<那一格>_excluded` 排除清单;推导落在**绑定那一层**(`binding.with_referenced_assets`),
由引擎在每个节点跑起来时调一次。检查器里那一片照同一条声明把来源摆出来。

## Context

### 断层:提示词里「引用」了图,模型从没见过那张图

「要模型看的图片」(`image_asset_ids`)是发多模态消息时**唯一**会变成 `image_url` 的来源
(`executors/ai.py:_images_for_model`)。而提示词/系统提示词是模板字段,里面写 `{{画图.asset_id}}`
时,那条引用**只当文字**插值:发过去的是素材编号。

于是同一张图有两种写法,一种有效、一种无声地无效:

| 写法 | 模型看到 |
| --- | --- |
| 在「要模型看的图片」里挑一遍 | 那张图 |
| 提示词里 `{{画图.asset_id}}` | 一串十六进制 |

用户的心智模型是"我在提示词里点了一下那张图"。跑出来模型答得像没看图,是因为它确实没看 ——
而且没有任何地方会说这件事。

### 为什么不能只在保存/编辑时同步

"编辑时把引用到的 id 写进那一格"这条路上,有两个躲不开的东西:

1. **值到运行时才知道。** `{{画图.asset_id}}` 里的 `画图` 可能还没跑过,编辑时根本没有这个 id;
2. **老图。** 库里已经存在的工作流 config 里没有同步过的 id。编辑时同步意味着运行时要再补一条
   「config 里没有就现推」—— 同一条语义写两遍,而两遍迟早不一致(一处改了另一处忘了)。

## Decision

### 1. 「引用即发送」是这一格的语义本身,推导在运行时

声明写在字段上(大模型节点的 `image_asset_ids`):

```python
"ref_assets_from": ["prompt", "system"],
```

引擎在节点跑起来那一刻、手边有会话、有工作区、也有上游刚落定的值时调一次
`binding.with_referenced_assets`,把这几格**原文里** `{{…}}` 引用到、且解析出来真是本工作区
一张符合本格 `media` 的素材的 id 并进去。**不是兼容分支**:不管 config 里有没有 id,规矩都只有
这一条 —— 提示词点名要模型看的那张图,这一次调用就发给它。

顺序:手动挑的在前(用户排的顺序说了算),引用来的按 `prompt → system`、按引用出现的先后接在后面,
同一个 id 只发一次。

### 2. 引用认的是**原文**,不是插值结果

插值之后 `{{画图.asset_id}}` 和用户手打进去的一串 id 再也分不开,而"引用即发送"说的是引用。
所以引擎把 config 的原文一起递给这一步(`engine.run_node` 的 `written`)。

### 3. 不是素材的引用跳过,不报错、也不硬塞

两道线:

- 引用的那个输出**不可能装素材**(`output_data_type` 判成 text / number / json / sequence / scene,
  如 `{{llm.text}}`)—— 它本来就只是文字,不必往下解析;
- 解析出来不是本工作区的、不是图片的(视频 / 音频 / 删掉的)—— 跳过。

**跳过而不是报错**,和手动挑的那一格刚好相反:手动挑的图送不进去要当场说清(那是点名要看的);
而引用是提示词的自然写法,里面本来就有大半是文字。视频塞进 `image_url` 只会换来一次 400,
把整条工作流拦下来 —— 而用户的提示词没有任何问题。界面上那一行写着这条规矩:只发图片。

### 4. 手动可删,而且**不会被下一轮塞回来**

自动来的那几处引用在界面上按引用列出(名字是「节点 · 输出」),去掉一处写进
`<那一格>_excluded`(一条一个**引用路径**或素材 id)。运行时的取图先减掉这份清单,
所以删掉就是删掉;点回来即可恢复。

**没有做成"用户改不了"**:维护者说的是"自动同步",但自动带进来的东西必须能退掉 —— 否则用户唯一
的出路是改提示词(而那会改变送给模型的话)。排除清单是一份**记账**,由那一格的控件一起编辑
(声明 `edited_by`),不是给模型看的东西。

同理,手动加的那张不在引用里,原样保留;排除清单**只管自动那一半**,不影响手动挑的。

### 5. 界面照同一条声明算,不另抄一张表

`workflows/referencedImages.ts` 走的是同一份声明(`ref_assets_from` + 注册表的 `output_types`),
和运行时同一个集合。检查器把自动来的那几处**和手动挑的缩略图分开摆**:来源看得见,人一眼知道
模型为什么会看到它。静态就知道是哪张素材时(源节点是「素材」且写死了 id)顺带查一眼它的种类,
不是图片的当场标「不是图片,不会发送」。

## Consequences

- 老图**不用改 config**:推导在运行时,库里那份配置一个字节都不动;
- 上限仍是 8 张(`wfErr_llmTooManyImages`):手动 + 自动一起算,检查器在超了的时候当场说;
- 一条引用解析出多张图时,排除是按**整条引用**去的(排除清单里的路径记的是引用,不是某一帧);
- 同一个断层还有**一处同类**:`ai_generate` 的提示词引用图片素材时模型同样看不到(图只能走
  `source_assets` 的角色)。**这一次不动它** —— 那里"发哪一张、以什么角色发"由模型能力决定,
  猜错角色就是一次白花钱的生成,和这里"多带一张图"不是同一种风险。
