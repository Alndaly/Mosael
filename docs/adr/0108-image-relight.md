# 0108 给一张图重新打光：一个内置节点，任选能改图的模型，灯位翻成一段打光指令

- 状态：已采纳
- 日期：2026-11-24
- 相关：ADR 0025（画板：能力住在内容格上）、ADR 0094（画幅）、`domain/scenes` 的 `SceneLighting`

## 背景

维护者：「我注意到很多平台都支持打光这一操作，是否可以也补充一下」，附了两张图：图片格操作条上一项「灯光」，和一颗
方向球（绕着图转的一圈方位环、一条俯仰弧，拖光源点定光从哪来）。

打光要一个模型来做。两条路：专门的重打光工作流（IC-Light 一类，要在 ComfyUI 上装节点和模型），或任何能改图的模型
（收参考图的图片模型）照一段打光指令重画。维护者选了后者：**模型下拉里是他能用的、收参考图的图片模型**，灯位翻成文字。
以后在 ComfyUI 上装了专门的重打光工作流，它也是一个收参考图的图片模型，出现在同一个下拉里 —— 两条路不冲突。

## 决定

### 1. 一个内置节点 `image_relight`，画板上它就是图片格的一项能力

`surfaces: ["workflow", "board"]`：工作流里是一个节点，画板上照 ADR 0025 的规矩自动成了图片格操作条上的「灯光」，
智能体照样能调。产出落成右边新的一格，原图不动（能力的产出都是派生的）。不另写一个画板专用的产出者。

### 2. 灯位就是几个数，指令由后端翻

字段（相对**画面**，不是相对场景 —— 一张图没有场景）：

| 字段 | 范围 | 意思 |
| --- | --- | --- |
| `light_azimuth` | 0–359 | 光从哪个方向来：0 = 从镜头这边（顺光）、90 = 画面右侧、180 = 背后（逆光 / 轮廓光）、270 = 左侧 |
| `light_elevation` | 0–90 | 光的高度：0 = 与视线齐平，90 = 正顶光 |
| `light_temperature` | 1500–12000 K | 色温：3200 暖（白炽）、5500 日光、7500 冷（阴天） |
| `light_softness` | 0–1 | 0 = 硬光、影子边缘清楚；1 = 柔光、几乎没有硬影 |
| `light_intensity` | 0–100 | 亮度：低是暗调，高是亮调 |

`relight_instruction` 把这几个数翻成一段话：先说「只改光，人物、构图、细节都不动」，再说主光的方向和高度、软硬、
色温、亮度，最后接上用户补的那句（`prompt`，可空：「霓虹灯」「黄昏的窗光」）。按跑的那一刻的界面语言写。
**只有这一处翻**：界面、工作流、智能体给的都是数，不在前端另拼一份。

数比文字好：智能体、工作流能算能传；预设只是界面上一键摆好这几个数，不进数据。

### 3. 模型：`reference_image_models`，画幅跟着原图

模型下拉复用资产格「补全多角度」那个来源（收参考图的图片模型，留空用默认或第一个会的）。原图以参考图发出去；
要的画幅是原图自己的宽 × 高（ADR 0094 的 `frame_aspect`，漏斗按模型翻成它认的那一格）—— 不然模型按自己的默认
出一张 1:1，构图就变了。

### 4. 方向球：一个控件改五格，两个把手拿着走

节点表单里 `light_azimuth` 声明 `editor: "light_rig"`，另外四格 `edited_by: "light_azimuth"`。控件
（`features/nodeForms/LightRigField.tsx`）铺满卡片的宽：

- 方向球：绕着人那一圈方位环上一个把手管**光从哪个方向来**，左边那四分之一弧上一个把手管**光多高**，拿着走（点环或弧也直接
  跳过去）；光点只显示光现在在哪，转到人背后时画暗。方向键微调。读数（哪个方向、多少度）压在球的左下角。
  最早一版是「在球上任意拖，按位移转方位和高度」：光点转到背面以后往右拖它反而往左走，维护者说「交互很怪异」，改成现在这样；
- 下面一排常用打光（伦勃朗光、窗边侧光、逆光轮廓、顶光、黄金时刻、阴天柔光 —— 只是一键摆好这几个数），和色温、软硬、
  亮度三个滑杆。

**它是主控件，不是参数里的一格**：画板的能力面板把它摆在面板主体里（`nodeForms/stageEditors` 登记的编辑器，
`boards/composerFields` 的 `stage`），不收进「参数」弹层；工作流检查器里它照常是表单的一行。两处画的是同一个控件。

### 5. 挑模型：只给参考图就能跑的那些

「收参考图」不够：局部重绘的图也收参考图，却必须再给一份蒙版，挑它来打光一跑就是「必须给一份蒙版」（真界面里踩到了）。
`reference_models.works_from_reference_images` 再问一句 `requires_source` 的每一条都认参考图；资产格的「补全多角度」
「生成表情」用的是同一个判据，一起修了。挑模型这一段从 `executors/entities.py` 挪进 `executors/reference_models.py`，
报错的 key 随之改成通用的 `wfErr_referenceModel*`。

## 不做

- 不在浏览器里预览打光效果（3D 补光、法线估计）：预览不是真结果，和模型画出来的对不上反而误导。
- 不复用 3D 场景的打光预设数据：那套是**相对场景**的、强度是渲染器的瓦数；这里是相对画面的一套。界面上借它的分组
  和说法，数各是各的。

## 后果

- 效果看所选模型：通用改图模型按文字打光，方向未必每次都准；装了专门的重打光工作流就选它。
- 新增节点要进节点目录、文案表，官网节点文档跟着同步。
