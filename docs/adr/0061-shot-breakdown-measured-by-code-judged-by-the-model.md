# ADR 0061:拆镜头 —— 刀口和动静由代码量,景别运镜由模型判

## Status

Proposed — 2026-10-14。方向由维护者提(「优化当前 AI Studio 视频分析的机制,参考一下 reelbench-skills 这个技能,
以及相关的操作请你也转化为一套官方工作流,如果缺少相应的节点、能力、引擎的话请你补充即可」)。
本 ADR 写清方案、取舍和待拍板的几点;**第一步(最小闭环)已按本文实现**,后几步列在文末。

## Context

### 今天的视频分析是怎么做的

`domain/analysis/service.analyze_asset` 两条路:

- **原生**(Gemini / 通义 / Kimi 的 API Adapter):整段视频交给模型,模型自己看。
- **抽帧**(其余,以及 OAuth 走 Gateway 的会话模型):按时长**均匀**抽 4–16 帧(约 6 秒一帧),加上已有的转写。

两条路都只产出**一段回答**。问题有三:

1. **均匀抽帧会漏镜头。** 短视频平均一镜 1–3 秒,6 秒一帧意味着大半镜头一帧都没被看到;而真正决定节奏的
   正是这些短镜头。模型也不知道哪一帧在哪一镜 —— 它看到的是「从前到后 10 张图」。
2. **刀口、时长、动没动都是模型「看出来」的。** 这些是能**量**出来的事实,让模型猜既贵又不准(模型最常犯的错是
   把「固定机位、人在跑」写成「跟拍」)。
3. **结果不能复用。** 一段回答没法排序、没法跳转、没法拿去出分镜;下一次再问同一条视频,又从头看一遍。

工作流这边,官方模板「自媒体视频爆款拆解」的说明里明写着「关键帧没有抽:工作流里还没有『看画面』的节点」。

### reelbench-skills 的做法(Apache-2.0,只借方法与数据形状)

[eternityspring/reelbench-skills](https://github.com/eternityspring/reelbench-skills) 的 `video-shots` 把「拉片」
拆成**代码量**和**模型判**两半:

- **代码量**:ffmpeg 的 `scene` 分数找刀口(默认阈值 0.3,暗片慢片 0.15);同一遍里按 5Hz 算 64×36 小图的
  帧间差(`tblend=difference` + `signalstats` 的 YAVG)当「画面动了多少」;短于 0.3 秒的碎片并进前一镜;
  每镜取 15% 和 85% 两帧,拼成两张联系表(一张看内容,一张对照看运镜),一表不超过 25 镜。
- **模型判**:景别 / 类别 / 运镜 / 转场 / 节奏都是**封闭词表**,写表外的词当场拦;画面描述要 12 字起、
  不许空话(「氛围感」「高级感」……)。
- **门**:声称「推 / 摇 / 移」这类必然整幅画面在动的运镜,而实测帧间差接近 0 —— 判错了,拦;
  声称固定而实测很大 —— 只提示(固定机位前有人跳舞,差一样会爆);不到 1 秒的镜头不查。
- 另两个技能:`video-scrub`(**不是**洗文本,是剥视频元数据:白名单重封装、去掉 x264 SEI / AAC DSE 里
  的编码器指纹、按字节扫一遍验收)和 `video-sync`(把原片和「当前镜头信息面板」合成一条对照视频,面板用
  无头 Chrome 渲染)。

## Decision

### 1. 一份「镜头表」是素材的派生物,存库

新表 `shot_breakdowns`(`db/model_slices/shots.py`):**一份视频一份**(`asset_id` 唯一,素材删了级联删)。
重拆就覆盖 —— 镜头表是「这条视频长什么样」的事实,不是一次次的对话记录,没有要留历史的理由(见待拍板 2)。

| 列 | 内容 |
| --- | --- |
| `params` | 阈值、最短镜头秒数 |
| `meta` | 时长、帧率、宽高、有没有声音(探测得来) |
| `cuts` | 检测到的刀口(时间 + 分数) |
| `shots` | 逐镜:`id`(S01…)、`start` / `end` / `seconds`、`motion`(实测)、`size` / `category` / `camera[]` / `transition_in` / `subjects[]` / `frame` / `onscreen_text` / `audio` / `rhythm` / `rhythm_note` / `prompt`(模型判),`dialogue`(按时间重叠从逐字稿分到这一镜,代码做) |
| `sheets` | 联系表:每张覆盖哪几镜 |
| `describe` | 谁判的(连接、模型)、判了几批、几批失败 |
| `hints` | 门和提示:哪一镜被拦了什么、开篇 5 秒有没有钩子…… |

帧和联系表落在素材目录的 `shots/` 下(`frames/S01a.jpg`、`sheets/sheet-01a.jpg`),随素材目录一起删;
不进素材库 —— 它们是这份表的插图,不是用户的素材(工作流里可以选择存成素材,见 §4)。

**为什么不放进 `asset.media_info`**:media_info 是「这份文件的技术参数」,读的地方很多;
一份几十镜的表塞进去,每一次列素材都要把它搬一遍。和文档的解析结果(`asset_extractions`)同一个分法。

**数据形状**:新表由 `create-current-schema` 建出来,不改任何旧数据 —— **没有一次性迁移**,
`DATABASE_SCHEMA_VERSION` 不动(仍为 22)。老版本打开这个库,多一张它不认得的表,不影响它。

### 2. 代码量什么、模型判什么(`domain/shots/`)

- `detect.py`:**一遍 ffmpeg** 同时出刀口和动静(`split` 成两路,各写一个文件);`build_shots` 把刀口变成镜头、
  并掉碎片;每镜的 `motion` 取镜内中位数,掐掉两头 `min(0.4, max(0.1, 镜长×0.15))` 秒(刀口附近的差是切换本身,
  不是运镜)。方法出自 reelbench `video-shots`(Apache-2.0),代码是按 Mosael 的约定重写的,文件头注明出处。
- `frames.py`:每镜 15% / 85% 两帧;联系表用 PIL 拼(每格左上角压 `S03 0:12.4`),一张最多 25 镜。
  **不用 ffmpeg 的 drawtext**:那要 libfreetype,精简版 ffmpeg 没有(见 media_tools 的 ffmpeg-full)。
- `vocab.py`:五张封闭词表,和 reelbench 同名同义;运镜带「实测档」(strong / subtle / still)。
  **不复用**故事板那套(`templates_schemas.SHOT_SIZES`):那是「要怎么拍」给生成模型的词,这是「拍成了什么」
  拿来统计的词,两边各自演进,耦在一起改一边坏一边。
- `describe.py`:一批 ≤ 25 镜一次视觉调用(A、B 两张联系表 + 每镜的时间、实测动静、分到的台词)。
  回来之后**代码对账**:表外的词清空并记一条提示;strong 运镜而实测 < 1.5(且镜长 ≥ 1 秒)→ 去掉那个运镜、
  记一条「被拦」;固定而实测 > 12 → 只提示;画面描述太短 → 提示。节奏的三条提示(开篇 5 秒有没有钩子、
  兑现前面有没有铺垫、连着 6 镜同一个角色)也在这里算。
  **每批落一次库**:一批失败不连坐,已经判好的照样在;判到一半被取消,前面几批也在。
- `report.py`:镜头表 Markdown、分镜提示词 Markdown、统计(平均镜长、每分钟几刀、景别 / 运镜分布)—— 全是代码算的。

**比 reelbench 多的一样**:台词是**量**出来的。它没有语音识别,`audio` 靠模型看画面猜;Mosael 有逐字稿,
按时间重叠分到每一镜(`dialogue`),模型只需要判「这一镜里谁在说」。

**没有视觉模型时**:照样出机器那一半(刀口、时长、动静、帧、联系表、台词),`hints` 里说一句没判,界面和报告照常显示。

### 3. 视频分析(AI Studio)怎么变好

`analyze_asset` 不加新参数,里面换了喂法:

- **抽帧那条路按镜头抽**:先量刀口(只跑刀口那一路,短片一两秒),每镜至少一帧(取中点),镜头比帧数上限多时
  均匀挑镜头;每张图前面写明「S03 · 0:12.4–0:15.0」。模型知道每张图在哪一镜、这一镜多长。
- **有镜头表就带上**(两条路都带,原生那条也带):量好的刀口、时长和已经判过的景别运镜,模型不必再猜一遍。
- 智能体的工具说明一个字没加(工具定义预算几乎用满,见 `test_tool_definitions_budget`)。智能体要「拆镜头」,
  走官方工作流(`run_workflow`)或者照常问 `analyze_asset`;单独开一个工具要不要,见待拍板 1。

### 4. 三个节点和一张官方模板

| 节点 | 做什么 | 花钱 |
| --- | --- | --- |
| `detect_shots` 拆镜头 | 刀口、动静、逐镜两帧、联系表,存成这份视频的镜头表;可选把联系表存成素材(派生关系 `frame`,中间产物不进素材库列表) | 否 |
| `describe_shots` 逐镜看画面 | 用视觉模型判景别 / 类别 / 运镜 / 转场 / 节奏、写画面和分镜提示词,代码对账 | 是 |
| `shot_report` 镜头表报告 | 镜头表 Markdown、分镜提示词、统计,给下游写报告、存笔记 | 否 |

(「逐镜抽帧」和「联系表」并在 `detect_shots` 里:单独拆出来的话,中间要传一份几十镜的帧清单,而它们没有单独用的场景。)

官方模板 **「拆解参考视频:镜头表 + 联系表 + 报告 + 分镜提示词」**(`reference_video_shots`):

选视频 → 拆镜头 →(可选)转写口播 → 逐镜看画面 → 镜头表报告 → 写拆解总结(结构、节奏曲线、钩子、可复用的手法)
→ 存成笔记(总结 + 镜头表 + 分镜提示词)→ 交付。

### 5. 界面

素材详情(视频)右栏多一块「镜头」:没拆过是一个「拆镜头」按钮(后台任务,任务中心里看得到);拆过是一列镜头 ——
缩略图、`S03 0:12.4 · 2.6s`、景别 / 运镜、画面描述、台词;**点一行播放器跳到那一镜**。底下两个按钮:
「复制分镜提示词」「存成笔记」。

## reelbench 里没做的,和为什么

- **`video-sync`(原片 + 信息面板合成对照视频)**:要无头 Chrome 渲染面板。它解决的是「边看片边看这一镜的标注」,
  而详情页的「点一行跳到那一镜」已经是这件事,而且不用另外出一条视频。真要导出对照片,应走现成的渲染管线
  (时间线上铺字幕片段),不另起一套浏览器渲染 —— 列在后续。
- **`video-scrub`(剥元数据)**:和分析无关,是**导出**时的隐私问题(编码器指纹、拍摄设备、录屏软件名)。
  值得做,但应当是导出对话框的一个选项、或一个独立的「清除元数据」节点,不该挂在拆镜头上 —— 见待拍板 4。
- **`recut`(手动补刀 / 并镜)**:第一步只读。手动改刀口要一套编辑界面(在帧条上点),列在后续。
- **`cast`(角色表,按人归并)**:要跨镜认人,模型一批只看 25 镜,跨批认人不稳。列在后续。
- **门「拦住不让交」**:reelbench 是交给人改的工具,门不过不许交;这里是自动跑的流程,拦住等于整条失败。
  所以改成「对账时纠正 + 记在 hints 里给人看」。

## 后续步骤

1. **手动补刀 / 并镜**(recut):详情页帧条上点一下补一刀、两镜之间点一下并掉,只重判动过的那几镜。
2. **一镜去创作**:镜头行上「用这一镜生成」,把分镜提示词 + 这一镜的关键帧(当参考图)交给创作页。
3. **角色表**(cast):第二遍只看每镜的主体,跨批归并成「人物 A / B」,镜头表里引用。
4. **对照片导出**:时间线上按镜头铺字幕片段(镜号、景别、运镜),走现成的渲染。
5. **清除元数据**:导出选项或独立节点(白名单重封装 + 字节扫描验收),见待拍板 4。
6. **长片**:超过 240 镜时分段拆、分段判(今天截断并提示)。

## 待拍板

1. **智能体要不要单独一个「拆镜头」工具?** 第一步没加:工具定义预算几乎用满,而 `analyze_asset` 已经会读镜头表、
   按镜头抽帧,智能体也能跑官方工作流。要是觉得对话里「拆一下镜头」应该一步到位,可以给 `analyze_asset` 加一个
   `mode="shots"`(说明约 30 token,返回一个任务)。
2. **一份视频只留一份镜头表**(重拆覆盖)可以吗?要留历史(比如换个模型重判对比)就改成按时间多份、读最新的。
3. **界面上的「拆镜头」用哪个视觉模型?** 第一步用「分析」那条默认挑法(`select_analysis_connection`:Kimi → MiniMax →
   OpenAI → 兼容)。要不要在按钮旁边给一个选连接的下拉?
4. **清除元数据**做成导出选项还是独立节点?(或者都不做。)
5. **花费**:一镜不多花,25 镜一次调用;一条 1 分钟、30 镜的视频是两次视觉调用(两批),加模板里写总结的一次对话。
   这个量级可以默认就判,还是界面上先只做机器那一半、点「判画面」再花钱?第一步是默认就判。
