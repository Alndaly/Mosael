# 数字人接入方案

日期：2026-09-26。代码基线：`e3379b3c`。

**状态：提案，未开工。** 各家接口的数字都照抄 2026-09-26 读到的官方文档（出处附在每张表里），还没有拿真实密钥跑到终态。按本仓库的惯例，写进描述符的数字要以接口自己的报错为准（见 [ARCHITECTURE.md](../ARCHITECTURE.md) 的 `generation/` 一节），所以下面的数字只能当接入时的起点。动手之前，先把「决策」一节写成 ADR。

## 一句话

在 Mosael 里，数字人不是一个新模块，而是**「一张脸 + 一把嗓子 + 一段话 → 一段会说话的视频」**。

- **生成**：走现有的视频生成管线，用的是已有的素材角色组合：说话照片是「首帧 + 驱动音频」，改口型是「源视频 + 驱动音频」。
- **嗓子**：走现有的配音库。
- **长稿**：交给工作流和剪辑时间线去接。

要新补的东西只有这几样：

- 描述符里「时长跟着音频走」的规则；
- 可复用的「形象」；
- 肖像和声音的授权声明，以及 AI 生成标识；
- 几家接口的适配器；
- 画板上的两项内容格能力，以及几条工作流模板。

## 用户要拿它做什么

| 场景 | 输入 | 产出 | 频率 |
| --- | --- | --- | --- |
| 口播（讲解、带货、课程） | 一个形象 + 一段稿子 | 竖屏或横屏口播成片，带字幕 | 最高 |
| 视频翻译 / 改口型 | 一段真人视频 | 换成另一种语言、用原说话人的克隆音色、口型对上的视频 | 高 |
| 分镜里的角色开口 | 某一镜的角色图 + 一句台词 | 这一镜的说话片段 | 中 |
| 对话 / 播客可视化 | 两个形象 + 双人播客音频 | 双人对话视频 | 中，要多人能力 |

**本期不做：**

- 实时互动数字人：直播、对话式的实时驱动。延迟和推流是另一类系统，和 Computer Use 一样放到较后的版本单独立项。
- 3D 骨骼数字人：走 Blender 路线的话另外讨论。
- 全身动作迁移：万相 animate 这一类。

**缺的东西：**

1. **时长不跟音频走。**
   - 万相 2.7 的驱动音频比所选时长长时，文档写的是「自动截取」，视频时长也不跟随音频。
   - 用户挂上一段 12 秒的话，选了默认的 5 秒，出来的片子后 7 秒没了，而且不会报错。
   - 描述符现在没有办法表达「这个模型的成片长度等于音频长度」，也没有按素材时长做上下限校验。
2. **没有能复用的「人」。** 每次都要重新挂一张脸、重新挑一把嗓子，同一个人的形象在不同地方各挑各的。
3. **长稿没有办法接。** 单次上限从 15 秒到 5 分钟不等（见下表），一段三分钟的稿子必须能切段。
4. **没有授权声明，也没有 AI 标识。**
   - 音色表（`Voice`）里没有任何授权字段。
   - 导出的成片不带显式标识，也不写隐式标识。
   - 这两件事法规都有要求（见「合规」一节）。

**和直觉不一样、会影响设计的几条：**

- **火山 Seedance 2.x 默认拒收真人人脸参考图。** 真人素材要先走「真人认证」：本人扫码授权后入库，否则只能用平台的预置虚拟人像（[文档](https://www.volcengine.com/docs/82379/2315856)）。Mosael 已经接了 Seedance，今天挂真人照片做参考就会被拒。形象里的授权声明以后可以顺带引导用户去完成这一步认证。
- **万相 3.0 在首帧模式里去掉了驱动音频。** 它的 `reference_audio` 是「参考」，不是「驱动」。
- **Veo 3.1 不能输入驱动音频。** Sora 2 的 API 已经在 2026-09-24 下线。
- **厂商时长上限差两个数量级**：S2V 不到 20 秒，可灵 Avatar 300 秒，HeyGen 30 分钟。「长稿分段」必须是通用机制，不能按某一家的上限写死。
- **很多家的人脸预检是单独一次调用。** 它是适配器内部的一步（和可灵建主体是一回事），不暴露给用户，但预检失败要翻成人话，例如「没找到清晰的正脸」。

## 决策（待写成 ADR）

### 1. 数字人是视频生成里的一种素材组合，不是新的 kind

**模式**：两种，都挂在 `video` 这个 kind 下：

| 模式 id | 意思 | 素材角色 |
| --- | --- | --- |
| `speech-to-video` | 说话照片：一张人像按音频说话 | `first_frame` + `driving_audio` |
| `video-lipsync` | 改口型：一段已有视频的嘴对上新的音频 | `source_video` + `driving_audio` |

- 模式 id 只用来筛选和展示。按 [ADR 0013](../adr/0013-generation-declarations-per-model-kind.md) 的正面证据原则，**描述符里声明了才出现**。
- 角色一个都不加：`first_frame` 的意思本来就是「成片从这一格开始」，`source_video` 本来就是「被改的那一段」，`driving_audio` 本来就是「画面跟着它走」。三条互不相通的路（首尾帧 / 参考 / 视频输入）保持不动。

**描述符新增三条规则：**

- **`duration_follows: "driving_audio"`**：成片长度等于这段音频的长度。
  - 声明了的模型在界面上不显示「时长」。
  - 提交时不发 `duration_seconds`。
  - 计费预估按音频时长算。
- **`source_duration_seconds: {"driving_audio": [2, 60], "source_video": [2, 60]}`**：按素材**自身的时长**给上下限。
  - 时长读素材的 `media_info.duration`，不要读顶层字段（那里是 `None`）。
  - 超出时，提交就报人话，例如「驱动音频 72 秒，这个模型最长 60 秒」，而不是等任务失败。
- **`truncates_role: "driving_audio"`**：给万相 2.7 i2v 这类「音频长了就截」的模型用。
  - 界面在所选时长短于音频时提示「后 N 秒会被截掉」。
  - 或者直接把时长默认成音频长度（取整后夹进允许的范围）。

**校验**：三条都放进 `operations.py` 已有的那一串校验里（和 `_check_conditional_duration` 同层）。

**人脸预检**：留在适配器内部。适配器先调 detect，再提交。

- 预检失败统一翻成一条 `genErr_noUsableFace`。
- 预检费用计进这一次生成的预估。

### 2. 形象：一张脸、一把嗓子、一份授权

**新增工作区级的实体「形象」**（表名 `personas`）：

| 字段 | 说明 |
| --- | --- |
| `name` | 叫什么 |
| `portrait_asset_id` | 主图：清晰正脸，说话照片默认就用它 |
| `extra_asset_ids` | 可选，2–4 张多角度图，给可灵主体这类要多图建档的厂商 |
| `voice_id` | 默认嗓子，指向音色库 |
| `consent` | 授权声明（见第 4 节） |

**厂商侧的形象 id 不存。** 做法和可灵主体库一样，按素材内容哈希算出名字，生成前现查。这样就没有一张会和厂商那边漂移的映射表。

**为什么是独立实体，而不是「一张打了标签的图」：**

- 授权声明要挂在「人」身上。同一个人的脸和嗓子是一份授权，不是每张图、每把音色各声明一次。
- 「用张三讲这段话」要同时带出脸和嗓子。只有标签的话，两个都得每次重挑。

**出现在这些地方：**

- 素材库里的「形象」页；
- 画板上人像格的「让它说话」能力（见第 3 节），默认用这个形象的嗓子；
- 智能体的 `list_personas`；
- 工作流里的「形象」字段。

### 3. 放进已有的几个入口

**画板**：延续 ADR 0025 修订的内容格能力，不新增格子种类。

- **图片格 ·「让它说话」**
  - 面板正文写一句稿子，或者用 `@` 引用上游的便签格或音频格。
  - 底栏的芯片选「嗓子」和「模型」。
  - 写的是稿子时，先用配音合成出音频格，再驱动。音频格和视频格都落在右边，并连上线。这样不满意时可以只换一版配音。
- **视频格 ·「对口型」**：挑一段音频（上游音频格，或当场配音），结果是右边一格新视频。
- 能力列不列出来，看当前连接里有没有声明了对应模式的模型。

**生成页**：选到声明了 `duration_follows` 的模型时，时长控件换成「按音频长度」的只读说明。

**智能体**：

- `generate_video` 的说明里写清两种组合；
- 新增 `list_personas`；
- 「用某个形象说这段话」由智能体拆成先配音、再生成，不另开一个大工具。

**工作流模板**（全部由现有节点和新能力拼成）：

| 模板 | 链路 |
| --- | --- |
| 稿子 → 数字人口播 | 分段 → 逐段配音 → 逐段说话照片 → 铺上时间线 + 字幕 → 导出 |
| 视频翻译 · 改口型 | 分离人声 → 转写 → 翻译 → 从原说话人克隆音色 → 逐句配音 → 改口型 → 混回背景声 |
| 带货口播（升级） | 现有逐拍静帧的某几拍，换成形象口播 |

### 4. 长稿分段是通用机制

- **按什么切**：按句子和停顿，把稿子切成不超过所选模型上限的段。上限来自 `source_duration_seconds`，不是写死的 15 秒。
- **生成**：配音本来就逐句合成，每段各自生成，按顺序铺上时间线。
- **接缝**：
  - 每段都从形象主图开始，所以接缝处是同一张脸同一个姿势。剪辑里可以在接缝处加一个很短的叠化。
  - 支持长视频的模型（可灵 Avatar 300 秒、InfiniteTalk）不用切。分段数由上限自动决定，用户不用操心。
- **字幕**：直接用稿子加上配音的时间戳，不再转写一遍。

### 5. 合规：授权声明、AI 标识、留痕

| 要求 | 出处 | Mosael 怎么做 |
| --- | --- | --- |
| 提供人脸、人声编辑功能的，应提示使用者依法告知被编辑的个人，并取得其单独同意 | 《互联网信息服务深度合成管理规定》第十四条（[原文](https://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm)） | 见下方「授权声明」 |
| 人脸生成、替换、操控和合成人声要显著标识；不得删除或篡改标识 | 同上，第十七、十八条 | 见下方「导出」 |
| 显式标识：视频在起始画面和播放区域周边加显著提示；隐式标识写入文件元数据 | 《人工智能生成合成内容标识办法》第四、五条，2025-09-01 施行（[原文](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)） | 同上 |
| 深度伪造内容要披露；输出要做机器可读标记 | 欧盟 AI 法案第 50 条，2026-08-02 起适用（[FAQ](https://digital-strategy.ec.europa.eu/en/faqs/transparency-obligations-under-article-50-ai-act)） | 隐式标识同时满足这一条 |

**授权声明**：建形象、克隆音色时必须选一项：

- 「这是我本人」；
- 「已取得本人单独同意」；
- 「虚构人物（AI 生成或原创）」。

声明记下是谁、在什么时间做的。**没有声明的形象和音色不能用于生成**，这是硬门槛，不只是一条提示。已有的音色走一次迁移，把状态写成「未声明」，下次使用时要求补上。

**导出**：

- **显式标识**：成片里只要有数字人片段，导出时就在片头和画面角落加「AI 生成」标识。按法规，这一项不提供关闭的开关，只能调位置和样式。
- **隐式标识**：写入 MP4 元数据。火山返回的 AIGCMeta 要原样保留。

**留痕**：生成记录里记下用了哪个形象、授权声明是哪一份。
