# 3D 场景:时间与相机

日期:2026-09-08。代码基线:`0165b9b5`。

**状态:三个阶段都已实现。** 下面「悬而未决」那一节仍然有效。 分三阶段落地,每一阶段独立可用;下面每一段都注明它改动了什么、
需不需要迁移存量场景。

## 现在的模型错在哪

一句话:**"随时间变化"这件事只授予了相机,而且是以「镜头」为容器。**

整个 [`SceneContent`](../../backend/app/domain/scene_types.py) 里唯一带 `time` 的字段是
`shots[].frames[].time`。`SceneObject` 只有静态的 `position` / `rotation` / `scale`。于是:

- **场景本身不能动。** "一个人沿轨迹走"在当前数据结构里**没有地方可以存** —— 不是界面没做,
  是模型里没有这个概念。而这恰恰是交给视频模型最有价值的一类条件:参考视频里人在走,
  比在提示词里写"他向前走"强得多。
- **相机不是物体。** `shots` 和 `objects` 是两个平行数组。相机因此享受不到物体的通用能力:
  在视口里选不中、拖不动(只能用「记录此视角」把当前观察视角*采样*成关键帧)、不能编组、
  不能隐藏;「全局动线」画的是当前那一条路径加一个 `CameraHelper`,不是一个能操作的东西。

### 最硬的证据:我们自己已经在两种模型之间来回翻译

[`worker.py`](../../backend/app/domain/blender/worker.py) 的 `send` 把**每个 shot 变成一台
真正的 Blender 相机对象**,把运镜按 30fps 烘焙成它的关键帧,还得额外写一个
`mosael_target_distance` 自定义属性,才能在 `receive` 时把朝向还原回 Mosael 的 target 点。

也就是说:这套数据只要往外走一步,就必须变成"相机是物体、运镜是它的动画"。只有 Mosael
这一侧不是。而那个额外的自定义属性,正是两种模型不匹配时必须自己搬的那块砖 ——
它也是「从 Blender 取回当前场景」取不回相机的原因(别人的工程里没有这个属性)。

### 「组」是个半成品

`SceneObject.kind` 有 `group`,`parent_id` 有完整的循环与深度校验。但界面上:

- 「添加 → 组」建出来的是一个**空组,没有任何办法往里放东西** —— 列表不支持拖拽,
  也没有"移到某个组"的入口;
- 唯一能用的是检查器里的「编组对象」,而它只包**当前选中的那一个**,再按一次是再套一层。

所以那一项在菜单里是个建完就废的空盒子。数据模型是对的,缺的是入口。

## 目标模型

```
SceneObject.kind += "camera"        相机是一种物体(多一个 fov)
SceneObject.track?: Keyframe[]      任何物体都可以带一条时间轨(可选,没有就是静止)
SceneShot { camera_id, duration, aspect, easing }    镜头 = 用哪台机位、拍多久
```

运镜是相机这个物体的 track;人走路是人物那个物体的 track。**同一套东西,不是两套。**

这么做的连带好处:

- 相机自动获得选中、拖拽、编组、隐藏、复制 —— 不必为它再写一遍;
- Blender 桥**变简单**:不用再凭空合成相机对象,也不必靠自定义属性还原朝向;
- 「从 Blender 取回」可以真的把相机取回来了(那时两边都是"带动画的相机对象");
- 多机位可以同时站在场景里被看到、被摆位,而不只是下拉里的一行。

### 不做什么

- **不做完整的动画系统。** 没有曲线编辑器、没有骨骼、没有物理。track 是"若干个时刻的
  transform + 一个缓动",和现在的 `CameraFrame` 同一个复杂度。这一页是 previz,不是 DCC。
- **不追求和 Blender 逐帧一致。** 采样率、缓动近似仍按现有约定(30fps 烘焙、接收最多 100 帧)。

## 分三阶段

### 阶段一:把「组」补齐 —— **已实现**

**不动 schema,不需要迁移。** 只补入口:

- 物体列表支持拖进 / 拖出组;
- 多选之后「编组」把它们一起包进一个新组;
- 检查器给一个「移到…」的选择器(照顾拖不动的场合,比如触控板 + 长列表)。

如果结论是组本身不该存在,那就**去掉菜单里的空组入口**并把 `kind: "group"` 标记为
只由「编组」产生 —— 二选一,不能维持现状。

### 阶段二:相机变成场景物体 —— **已实现**

**要迁移存量场景。** 这是三段里唯一躲不过迁移的一步:`shots[].frames` 必须搬到新建的
camera 物体的 `track` 上,`shots` 只留 `camera_id` + 时长 / 比例 / 缓动。

按 [ADR-0006](../adr/0006-migrate-instead-of-branching.md),读取代码里不保留"老形状"这条
分支:迁移跑完,`shots[].frames` 就不存在了。

改动面:`scene_types.py`、迁移、`SceneViewport`(相机作为可选物体渲染 + 操纵器)、
`SceneCameraPanel`、时间条、`sceneObservation`(画出所有相机而不只是当前那台)、
Blender 桥(变简单)、生成交接(取哪台相机的哪段时间)。

### 阶段三:物体动画 —— **已实现**

**加字段,带默认值,不需要迁移。** `track` 从"相机专用"变成任何物体都能有;时间条从
"镜头时间"变成"场景时间";导出参考视频时场景里的物体跟着动。

界面上最小可用的形状:选中一个物体 → 在时间条上"记录此刻的位置" ——
和现在给相机记关键帧完全一样的手感,复用同一套控件。

## 悬而未决

- **时间的归属。** 阶段三之后,"场景时间"和"镜头时长"是两个东西:一段 12 秒的走位,可以被
  一个 5 秒的镜头截取其中一段。需要决定镜头是否带 `start_time`(倾向:带,默认 0)。
- **物体动画要不要送去 Blender。** glTF 支持动画,`export_animations` 现在是 `False`。
  打开它意味着往返时还要处理动画的合并,这一期先不做。
